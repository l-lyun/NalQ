# [Flow] 퀴즈 생성 결과 알림

- 관련 기능: [퀴즈 생성 결과 알림 PRD](../prd/prd-quiz-generation-notifications.md)
- 관련 화면: [알림 목록과 생성 결과 Snackbar](screen-notifications.md)
- 관련 생성 흐름: [퀴즈 생성부터 복습까지](flow-quiz-solving.md)

## 사용자 목표

사용자는 퀴즈 생성을 기다리는 동안 다른 화면에서 일을 계속하고, 생성이 끝났을 때 현재 작업을 빼앗기지 않은 채 결과와 다음 행동을 확인한다.

## 시작 조건

- 사용자가 로그인했고 퀴즈 생성 요청이 서버에 접수되었다.
- 생성 진행 화면을 떠나도 서버 생성은 계속된다.
- 서버 알림함은 QuizSet terminal 상태와 함께 결과 알림을 보존한다.

## 완료 조건

- 사용자가 Snackbar 또는 종의 알림 목록에서 생성 성공·실패를 알 수 있다.
- 사용자가 명시적으로 알림을 선택하면 성공 대상 또는 실패 복구 흐름으로 이동하고 읽음 상태가 저장된다.
- 사용자가 아무 행동을 하지 않으면 현재 화면과 작업이 그대로 유지된다.

## 기본 흐름

### 1. 생성 접수와 foreground 감시

1. 생성 접수 또는 활성 생성 복원 뒤 클라이언트는 현재 사용자의 이 기기 pending 대상으로 `quizSetId`를 기억한다.
2. 문서가 foreground이고 online이면 서버가 준 `pollAfterSeconds` 뒤 같은 QuizSet 상태를 다시 확인한다.
3. 상태가 계속 `GENERATING`이면 새 응답의 `pollAfterSeconds`를 기준으로 다음 확인을 예약한다.
4. 사용자가 다른 화면으로 이동해도 일반 인증 영역이 살아 있는 동안 감시는 계속되며 현재 화면을 변경하지 않는다.

### 2. terminal 확정과 알림 발견

1. 서버는 QuizSet을 `READY` 또는 `FAILED`로 확정하는 트랜잭션에서 생성 결과 알림을 한 건 만든다.
2. pending 상태 조회가 terminal을 발견하면 해당 QuizSet을 더는 polling하지 않고 알림 목록의 최신 상태를 다시 조회한다.
3. 로그인 완료, 새로고침, visible 복귀와 online 복귀에서도 pending 유무와 관계없이 최신 알림을 조회한다.
4. 클라이언트는 `notificationId`로 이미 표시한 Snackbar와 새 unseen 알림을 구분한다.

### 3. 방해하지 않는 Snackbar

1. 현재 화면이 생성 진행 화면이면 Snackbar를 생략하고 화면 자체가 성공·실패를 보여준다.
2. 다른 화면에서 새 unseen이 한 건이면 결과 종류에 맞는 단일 Snackbar를 보여준다.
3. 새 unseen이 두 건 이상이면 개별 결과를 연속으로 보여주지 않고 합산 Snackbar 한 건을 보여준다.
4. 사용자가 Snackbar 행동을 선택한 경우에만 내 퀴즈, 원본 자료 생성 흐름 또는 알림 목록으로 이동한다.
5. Snackbar를 닫거나 시간이 지나 사라져도 서버 알림은 읽지 않음으로 남는다.

### 4. 종과 알림 목록

1. 일반 인증 화면에서 사용자가 우측 상단 종을 선택한다.
2. 데스크톱·모바일 웹·WebView 모두 별도 알림 페이지로 이동해 최신순 알림 20개와 읽지 않은 수를 보여준다. 페이지 진입만으로 읽음 처리하지 않는다.
3. 사용자가 `더보기`를 선택하면 현재 목록을 유지한 채 다음 cursor의 알림을 이어 붙인다.
4. 사용자가 항목을 선택하면 해당 항목을 읽음 처리하고 결과 종류에 맞는 목적지로 이동한다.
5. 사용자가 `모두 읽음`을 선택하면 선택 시점까지 존재하던 읽지 않은 알림을 읽음 처리하되 이후 도착한 알림은 읽지 않음으로 남긴다.

## 분기

### 성공 알림

1. 단일 Snackbar는 positive `퀴즈가 완성됐어요.`를 보여준다.
2. `목록보기` 또는 알림 항목을 선택하면 `/learning/quizzes`에서 해당 QuizSet이 포함된 목록 맥락을 불러오고 대상 카드로 focus한다.
3. 현재 화면이 이미 내 퀴즈라면 Snackbar 행동은 생략한다. Snackbar만으로 scroll·focus를 바꾸지 않으며 사용자가 알림 항목을 선택했을 때만 대상 카드로 focus한다.

### 자료·조건 부족 실패

1. `SOURCE_INSUFFICIENT`는 critical `학습자료에서 문제를 만들지 못했어요.`를 보여준다.
2. `자료·조건 확인` 또는 알림 항목을 선택하면 원본 학습자료의 생성 조건 흐름으로 이동한다.
3. 이전 생성 조건은 서버에서 복원하지 않으며 사용자가 자료와 조건을 다시 확인한다.

### 생성 작업 실패

1. `GENERATION_FAILED`는 critical `퀴즈를 만들지 못했어요. 다시 시도해 주세요.`를 보여준다.
2. `다시 만들기` 또는 알림 항목을 선택하면 원본 학습자료의 생성 조건 흐름으로 이동한다.
3. 현재 화면이 내 퀴즈라면 Snackbar 행동은 생략한다.

### 복귀 시 여러 알림

1. 복귀 조회에서 새 unseen 알림이 두 건 이상이면 `새 퀴즈 알림이 N개 있어요.`를 한 번 보여준다.
2. `알림보기`를 선택하면 별도 알림 페이지로 이동한다. 이동은 사용자 선택으로만 일어난다.
3. 목록에서 각 결과를 확인하거나 `모두 읽음`을 선택한다.

### 대상이 없거나 접근할 수 없음

1. 항목 선택 시 대상 퀴즈 또는 학습자료를 찾을 수 없으면 다른 화면으로 이동하지 않는다.
2. `대상을 찾을 수 없어요.`와 동등한 안내를 현재 알림 맥락에서 전달한다.
3. 해당 항목은 읽음 처리한다.

### 여러 웹 탭

1. 각 탭은 같은 서버 알림 목록과 읽음 상태를 사용한다.
2. 새 알림 Snackbar는 현재 활성 탭 한 곳만 표시한다.
3. 다른 탭은 Snackbar를 중복 표시하지 않고 다음 조회에서 badge와 읽음 상태를 동기화한다.

## 실패와 복구

| 실패 조건 | 보존해야 할 정보 | 안내 | 복구 행동 |
| --- | --- | --- | --- |
| pending 상태 조회 실패 | `quizSetId`, 마지막 확인 상태 | 현재 화면에서는 조용히 유지; 생성 실패로 표시하지 않음 | foreground·online에서 재시도 |
| 알림 최신 목록 조회 실패 | 기존 목록, 읽음 상태, Snackbar 표시 기록 | 기존 목록이 있으면 유지; 처음 열었을 때만 목록 오류 | 다시 시도 또는 다음 visible·online 재확인 |
| 더보기 실패 | 이미 불러온 20개 단위 목록과 cursor | 목록 하단에 추가 조회 실패 | 같은 `더보기` 재시도 |
| 개별 읽음 저장 실패 | 서버의 기존 읽음 상태 | 목적지가 있으면 이동을 막지 않되 읽음이 저장되지 않았음을 과도하게 끼어들지 않음 | 다음 조회 뒤 다시 선택 가능 |
| 모두 읽음 실패 | 기존 개별 읽음 상태 | badge와 목록을 성공으로 추정하지 않음 | `모두 읽음` 재시도 |
| 인증 만료 | pending 식별자와 서버 알림 | 로그인이 필요함 | 재인증 뒤 최신 알림 조회 |

## 중단과 재개

- background에서는 상태·알림 polling과 Snackbar를 중단한다.
- foreground 복귀, 로그인 완료, 새로고침과 online 복귀는 최신 알림을 즉시 조회하는 재개 지점이다.
- 생성 화면 이탈은 서버 생성이나 알림 생성을 취소하지 않는다.
- 알림 페이지에서 이전 화면으로 돌아가도 읽지 않은 항목은 서버 원장에서 유지된다.
- OS 푸시가 없으므로 앱이 완전히 종료된 동안 즉시 알리지는 않는다. 다음 실행과 로그인 복구 뒤 서버 알림을 확인한다.

## 배포와 표시 기준

- 알림 기능이 포함된 최초 배포 이후 terminal 전이부터 알림을 생성하며 이전 terminal QuizSet은 소급하지 않는다.
- 목록의 대상 이름은 알림 생성 당시 `quizTitle` snapshot이며 이후 QuizSet 이름 변경으로 바뀌지 않는다.

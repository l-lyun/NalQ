# [Screen Spec] 학습 메인과 새 문제 만들기 진입

## 문서 책임과 범위

이 문서는 로그인한 사용자가 학습 메인에서 새 문제 만들기를 시작하고, 최근 틀린 문제 다시 풀기로 이동하고, 저장한 학습자료를 편집하는 화면 구조를 정의한다. `새 문제 만들기` 이후 기존 학습자료를 고르거나 새 학습자료를 저장해 문제 생성 조건 화면까지 이동하는 route-level 흐름도 포함한다.

문제 생성 조건의 세부 입력, 생성 오버레이, 생성된 QuizSet 목록, 문제 상세, 풀이와 결과 상세는 이 문서의 범위가 아니다. 제출 뒤 미완료 서술형 자기평가 재진입은 [미완료 서술형 자기평가 재진입](screen-quiz-resume.md), 다시 풀기 route 진입 뒤 문항 풀이는 [틀린 문제 다시 풀기](screen-review.md)가 책임진다. 기능 정책은 관련 기능명세를, 화면 간 중단·복구는 관련 흐름을, 요청·응답과 오류 의미는 공유 계약을 따른다.

## 홈과 학습 메인의 책임 분리

| 영역 | 책임 |
| --- | --- |
| 홈 | 이어 풀기, 활성 생성 상태, 준비된 문제, 결과·복습 등 여러 신호 중 지금 할 다음 학습 행동을 추천 |
| 학습 메인 | 새 문제 만들기 진입, 틀린 문제 다시 풀기 현황·진입, 학습자료 목록과 편집 진입 |

학습 메인에는 생성된 QuizSet 목록이나 별도 `계속할 학습` 영역을 두지 않는다. 학습자료와 QuizSet은 독립 리소스이며 학습자료 행에 문제 생성·풀이·결과 상태를 대표 행동으로 섞지 않는다.

## 요구사항 구분

### 사용자 확정 정책

- 학습 메인은 내부 탭 없이 하나의 세로 페이지다.
- 위에서 아래로 `새 문제 만들기`, `틀린 문제 다시 풀기`, `학습자료 관리`, 하단 전역 내비게이션 순서다.
- `새 문제 만들기`는 화면 최상단의 유일한 선명한 CTA다.
- 틀린 문제 다시 풀기는 가장 최근에 완료한 본 퀴즈 회차 하나의 미해결 문항만 대상으로 한다. 활성 review session이 있으면 그 세션을 재개한다.
- 학습자료는 일반 텍스트 직접 입력 또는 Notion 단일 페이지 일회성 복사로 만든다. 로컬 파일 입력과 Notion 동기화는 제공하지 않는다.
- `새 문제 만들기` 첫 화면에는 `기존 학습자료로 만들기`, `새 학습자료로 만들기` 두 선택만 둔다.
- 새 학습자료 방식은 `Notion에서 가져오기`, `직접 입력하기` 두 가지뿐이며 별도 파일 방식이 있는 것처럼 표현하지 않는다.
- 기존 QuizSet이 있어도 학습자료 제목과 본문을 수정할 수 있다.
- 같은 학습자료의 QuizSet이 `GENERATING`인 동안만 본문을 임시 잠근다. 생성이 성공하거나 실패해 종료되면 본문을 다시 편집할 수 있다.
- 생성 중에도 학습자료 제목은 수정할 수 있다.
- 학습자료 수정은 기존 QuizSet, 풀이와 결과를 바꾸지 않는다. 수정된 본문은 이후 새로 생성하는 QuizSet부터 사용한다.

### 설계 결정

- 학습 메인은 문서형 단일 열로 유지한다. 섹션마다 카드를 반복하지 않고 제목, 간격, 목록과 최소한의 구분선으로 위계를 만든다.
- `새 문제 만들기`만 brand solid 계열의 prominent CTA 후보로 둔다. `다시 풀기 시작·계속하기`, 오류 재시도와 자료 행은 목록 행동 또는 약한 버튼으로 표현한다.
- 학습자료 목록은 최근 수정 순이며 행 전체가 `자료 상세·편집` 전체 페이지로 이동한다. 행에는 제목, 출처와 수정 시각만 기본 노출하고, 생성 중일 때만 `본문 임시 잠금`을 상태 텍스트로 추가한다. 이번 GET 연결 단계에서는 읽기 전용 상세이고 `PATCH` 후속 연결 뒤 편집 행동을 활성화한다.
- 학습 메인의 학습자료 목록과 기존 학습자료 선택 목록은 모바일에서 한 페이지에 6개씩 표시한다. 목록 아래에는 `이전 · 현재/전체 · 다음` 순서의 페이지 이동을 둔다.
- 제목 검색은 현재 받아온 6개를 클라이언트에서 거르는 기능이 아니라 서버의 전체 사용자 자료를 대상으로 한다. 적용된 검색어가 바뀌면 1페이지로 돌아간다.
- 새 문제 만들기 하위 화면은 모바일에서 오른쪽에서 들어오는 route-level 전체 페이지다. 바텀시트로 축소하지 않는다.
- 기존 학습자료 선택은 자료가 많아질 가능성을 고려해 별도 전체 페이지로 두고 학습 메인과 같은 제목 검색·페이지 이동 규칙을 사용한다.
- 새 학습자료 저장이 성공하면 저장된 LearningMaterial을 유지한 채 문제 생성 조건 화면으로 진행한다. 같은 내용을 다시 저장하는 이전 입력 단계로 돌아가지 않는다.
- 학습 메인과 하위 전체 페이지는 각각 한 화면에서 하나의 선명한 CTA만 둔다. 선택 화면의 두 선택지는 solid 버튼 두 개가 아니라 동등한 목록 행으로 표현한다.

### 설계 가정과 향후 검증

- 학습자료 출처는 API의 `PASTE`, `NOTION`을 각각 `직접 입력`, `Notion에서 가져옴`으로 표시한다.
- Notion 연결·권한 승인은 WebView 밖 브라우저 또는 앱 브리지로 이동할 수 있다고 가정한다. 복귀 URI, 재연결과 선택 복원은 앱·웹 구현 원장에서 정한다.
- 하위 흐름의 미저장 입력은 같은 실행 세션에서 뒤로 갔다가 돌아올 때 보존한다고 가정한다. 앱·웹 종료 뒤 복원은 약속하지 않는다.
- 학습자료 제목은 필수이며 공백뿐인 제목에는 기본 제목을 자동 적용하지 않는다. 제목·본문 오류는 입력 가까이에서 안내하고 사용자가 작성한 값을 보존한다.

### 단계별 구현 범위

- 이번 API 연결 범위는 붙여넣기 학습자료 `POST` 생성, `GET` 목록, `GET` 상세까지다.
- 이번 범위에서 학습자료 행을 선택하면 상세 데이터를 조회해 제목과 본문을 확인할 수 있다. `PATCH` 수정 계약은 후속이므로 제목·본문을 편집하거나 저장할 수 있는 것처럼 보이지 않게 한다.
- 아래의 편집 가능 상태, 변경사항 저장, 미저장 변경 이탈 확인은 `PATCH` 연결 뒤의 목표 UX다. 이번 읽기 전용 상세 구현이 이 최종 목표를 삭제하거나 영구적인 읽기 전용 정책으로 바꾸지는 않는다.
- Notion 가져오기 연결은 후속 범위다. `sourceType=NOTION`인 기존 자료의 출처 표시는 가능하지만, 이번 범위가 새 Notion 복사 흐름의 완성을 의미하지 않는다.

## 사용자 목표와 완료 조건

### 사용자 목표

- 새 문제를 만들 때 기존 자료를 사용할지 새 자료를 만들지 빠르게 선택한다.
- 최신 완료 학습에서 남은 복습을 시작하거나 활성 복습을 계속한다.
- 저장한 학습자료의 제목과 본문을 확인하고 필요하면 수정한다.

### 완료 조건

- 새 문제 만들기: 기존 또는 새 LearningMaterial이 확정되어 문제 생성 조건 화면으로 이동한다.
- 틀린 문제 다시 풀기: 최신 대상의 새 review session을 시작하거나 활성 session을 재개한다.
- 학습자료 관리: 이번 GET 연결 단계에는 자료 상세를 확인하고 학습 메인으로 돌아온다. 후속 `PATCH` 연결 뒤에는 저장에 성공하거나 변경 없이 돌아오는 것까지 완료 조건에 포함한다.
- 오류가 발생하면 입력과 이미 확인한 선택을 가능한 범위에서 잃지 않고 같은 단계에서 복구할 수 있다.

## 학습 메인

### 진입과 이탈

- 하단 내비게이션의 `학습`으로 진입한다.
- 홈의 `새 문제 만들기` 맥락 행동이 있다면 새 문제 만들기 첫 화면으로 직접 진입할 수 있다.
- 문제 생성·복습·자료 편집에서 완료 또는 명시적 닫기 후 학습 메인으로 돌아올 수 있다.
- 하단 `홈` 또는 `프로필`을 선택하면 해당 최상위 화면으로 이동한다.
- 시스템 뒤로가기는 일반 탐색 기록을 따른다. 앱의 학습 최상위 진입점이라면 앱 셸이 정의한 종료·이전 탭 동작을 따른다.

### 정보 구조

1. **화면 머리말**: `학습` 제목으로 현재 위치를 알린다.
2. **새 문제 만들기**: 화면 최상단의 유일한 prominent CTA. 새 문제 만들기 route stack을 연다.
3. **틀린 문제 다시 풀기**: 최신 완료 회차의 미해결 수 또는 활성 세션 상태를 보여주고 다시 풀기 시작·계속 행동을 제공한다. 대상 없음과 조회 오류도 같은 위치에서 표현한다.
4. **학습자료 관리**: 제목 검색, 최근 수정 순의 자료 목록과 페이지 이동. 각 행은 제목, 출처, 수정 시각과 필요한 경우 생성 중 임시 잠금 안내를 제공하고 chevron으로 전체 페이지 이동을 암시한다.
5. **하단 내비게이션**: `홈`, `학습`, `프로필` 중 `학습`을 현재 페이지로 표시한다.

### 행동 우선순위

| 위치 | 우선순위 | 행동 | 발생 조건 | 결과 | 실패 시 |
| --- | --- | --- | --- | --- | --- |
| 화면 상단 | Primary | 새 문제 만들기 | 로그인 상태 | 오른쪽 push로 새 문제 만들기 첫 화면 | 학습 메인 유지, 다시 시도 가능 |
| 틀린 문제 다시 풀기 | Secondary | 다시 풀기 시작 | 최신 완료 회차에 미해결 문항이 있고 활성 세션 없음 | review session 생성 후 첫 문항 | 최신 상태 확인 후 중복 없이 재시도 |
| 틀린 문제 다시 풀기 | Secondary | 이어서 풀기 | 활성 review session 있음 | 같은 문제 세트를 첫 문항부터 다시 풀이 | 같은 session 재조회 |
| 틀린 문제 다시 풀기 | Tertiary | 다시 시도 | 현황 조회 실패 | 같은 현황 재조회 | 오류 상태 유지 |
| 학습자료 관리 | Row action | 자료 상세·편집 | 자료 행 선택 | 오른쪽 push로 해당 자료의 전체 페이지 | 기존 목록 유지 |
| 학습자료 관리 | Secondary | 이전·다음 페이지 | 이동 가능한 인접 페이지가 있음 | 해당 페이지의 자료 6개를 조회 | 현재 페이지와 목록 유지, 다시 시도 가능 |

### 틀린 문제 다시 풀기 상태

| 상태 | 보여줄 내용 | 가능한 행동 |
| --- | --- | --- |
| 다시 풀 문제 있음 | 부모 학습자료명, 최근 완료 시점과 틀린 문항 수 | 다시 풀기 시작 |
| 다시 풀기 진행 중 | 부모 학습자료명과 전체 대상 문항 수 | 이어서 풀기 |
| 완료 회차 없음 | 먼저 문제를 완료하면 다시 풀 문제가 생길 수 있다는 짧은 안내 | 상단 새 문제 만들기 사용; 별도 solid CTA 추가 없음 |
| 다시 풀 문제 없음 | 가장 최근 회차에서 현재 다시 풀 문항이 없다는 완료형 안내 | 별도 CTA 없음 |
| 조회 오류 | 결과가 사라졌다고 표현하지 않는 오류와 현재 상태를 확인하지 못했다는 안내 | 다시 시도 |

### 학습자료 관리 상태

| 상태 | 보여줄 내용 | 가능한 행동 |
| --- | --- | --- |
| 기본 | 제목, 출처, 수정 시각의 최근 수정 순 목록 | 행 전체를 눌러 자료 상세 확인 |
| 생성 중 자료 | 기본 정보와 `문제 생성 중 · 본문 임시 잠금` | 자료 상세 확인; 후속 편집 연결 뒤에도 본문은 생성 종료 전 읽기 전용 |
| 자료 없음 | 아직 저장한 학습자료가 없으며 새 문제 만들기에서 새 자료를 만들 수 있다는 안내 | 상단 새 문제 만들기 사용 |
| 검색 결과 없음 | 전체 자료가 없는 상태와 구분해 검색어와 일치하는 제목이 없다고 안내 | 검색어 지우기 |
| 페이지 이동 중 | 현재 목록과 페이지 맥락을 유지하고 이동 진행을 표시 | 반복 이동은 방지하고 기다리기 |
| 목록 갱신 실패 | 기존 목록이 있으면 유지하고 갱신 실패를 인라인으로 표시 | 다시 시도, 기존 자료 편집 유지 |
| 목록 전체 오류 | 자료가 삭제된 것처럼 표현하지 않는 영역 오류 | 다시 시도; 상단 새 문제 만들기는 인증이 유효하면 유지 |

### 목록 공통 검색과 페이지 이동

- 학습 메인과 기존 학습자료 선택 화면은 같은 목록 규칙을 사용한다. 적용된 검색어가 바뀌면 현재 페이지를 `1`로 초기화하고 서버에 새 목록을 요청한다.
- 기본 페이지 크기는 모바일 6개다. 목록 본문을 무한 스크롤로 이어 붙이지 않고 한 번에 한 페이지의 자료만 보여준다.
- 목록 아래에 `이전 · 현재 페이지/전체 페이지 · 다음` 순서로 배치한다. 첫 페이지의 `이전`과 마지막 페이지의 `다음`은 이동할 수 없음을 시각적 상태와 접근성 상태로 함께 전달한다.
- 전체 결과가 없거나 한 페이지만 있으면 불필요한 페이지 이동 행동을 노출하지 않는다. 검색 결과가 0건이면 페이지 수보다 검색 결과 없음 안내와 검색어 지우기를 우선한다.
- 페이지 이동 요청 중에는 현재 목록을 갑자기 빈 화면으로 바꾸지 않는다. 성공하면 새 목록과 페이지 표시를 함께 교체하고, 실패하면 기존 목록·현재 페이지·검색어를 유지한다.
- 자료 삭제 등으로 현재 페이지가 유효하지 않게 된 경우 빈 페이지를 최종 상태로 방치하지 않고 가능한 마지막 유효 페이지를 다시 보여준다. 정확한 재요청 방식은 웹 구현 원장에서 정한다.

### 학습 메인 로딩과 인증

- 최초 로딩에서도 `학습` 제목과 `새 문제 만들기` 위치는 안정적으로 유지하고, 복습과 자료 목록만 중립 Skeleton으로 표시한다.
- 복습과 자료 목록은 독립적으로 실패할 수 있다. 한 영역 실패 때문에 다른 성공 영역을 숨기지 않는다.
- 인증이 만료되면 목록이 사라졌다고 표현하지 않고 재인증을 안내한다. 서버의 문제 생성이나 복습 session 상태는 재인증 뒤 다시 확인한다.

## 새 문제 만들기 route stack

### 전체 흐름

```text
학습 메인
  → 새 문제 만들기
      ├─ 기존 학습자료로 만들기
      │    → 기존 학습자료 선택
      │    → 문제 생성 조건
      └─ 새 학습자료로 만들기
           → 새 자료 방식 선택
               ├─ Notion에서 가져오기
               │    → 연결·권한 안내
               │    → 단일 페이지 선택
               │    → 복사 결과 확인·수정
               │    → 학습자료 저장
               │    → 문제 생성 조건
               └─ 직접 입력하기
                    → 제목·본문 입력
                    → 학습자료 저장
                    → 문제 생성 조건
```

문제 생성 조건 이후의 상세 화면과 상태는 퀴즈 생성 화면 명세와 관련 기능·흐름 문서가 책임진다.

### 공통 route-level 동작

- 모바일 WebView에서 다음 단계는 현재 화면 오른쪽에서 들어오고, 이전 화면은 왼쪽으로 물러나는 push transition을 사용한다.
- pop에서는 현재 화면이 오른쪽으로 나가며 이전 화면의 동일한 맥락을 다시 드러낸다.
- 앱 바의 명확한 뒤로가기와 시스템 뒤로가기는 같은 한 단계 pop 결과를 만든다. 두 행동이 서로 다른 저장·취소 결과를 만들지 않는다.
- `prefers-reduced-motion: reduce` 또는 앱 셸의 모션 감소 설정이 있으면 큰 수평 이동을 제거하고 즉시 전환하거나 짧은 비이동 전환만 사용한다.
- 첫 화면에서 뒤로가면 학습 메인으로 돌아간다. 아직 입력이나 외부 복사 결과가 없으므로 확인을 요구하지 않는다.
- 미저장 제목·본문, Notion 복사 결과 수정 또는 변경된 생성 조건이 있으면 흐름 밖으로 나가기 전에 입력이 저장되지 않음을 확인한다.
- 같은 route stack 안에서 한 단계 뒤로 갔다 다시 진행하면 입력과 선택을 메모리에 보존한다. 사용자가 `처음부터` 또는 명시적 취소를 선택할 때만 버린다.
- 앱·웹 종료 뒤 미저장 입력 복원은 MVP에서 약속하지 않는다. 서버 임시 draft가 있는 것처럼 안내하지 않는다.
- 네트워크 실패는 현재 단계와 입력을 유지한다. 학습자료 저장은 기존 저장 멱등 키 규칙을 따르고, QuizSet 생성 접수 응답을 확인하지 못하면 같은 요청을 바로 반복하지 않고 자료의 활성 생성을 먼저 조회한다.

### 1. 새 문제 만들기 첫 화면

#### 정보 구조

1. 뒤로가기와 `새 문제 만들기` 제목
2. `기존 학습자료로 만들기` 선택 행: 저장한 원문을 고르는 흐름
3. `새 학습자료로 만들기` 선택 행: Notion 또는 직접 입력으로 원문을 먼저 저장하는 흐름

두 행은 동등한 선택이다. 보조 설명은 결과의 차이만 짧게 전달하며 파일 선택이나 동기화를 암시하지 않는다.

### 2. 기존 학습자료 선택

#### 정보 구조와 행동

1. 뒤로가기와 `학습자료 선택` 제목
2. 제목 검색: 서버가 보유한 전체 사용자 자료에서 원문 제목으로 좁힌다. 복잡한 출처·상태 필터는 두지 않는다.
3. 최근 수정 순 현재 페이지 목록: 최대 6개의 제목, 출처, 수정 시각
4. 페이지 이동: 목록 아래 `이전 · 현재/전체 · 다음`
5. 행 선택: 해당 LearningMaterial을 확정하고 문제 생성 조건 화면으로 push

같은 자료에서 QuizSet이 `GENERATING`이면 그 행에 `문제 생성 중 · 완료 후 선택 가능`을 텍스트로 표시하고 새 생성을 시작할 수 없게 한다. 단순 disabled 색상만 사용하지 않으며, 이유를 보조기기에도 전달한다.

#### 상태와 복구

| 상태 | 보여줄 내용 | 가능한 행동 |
| --- | --- | --- |
| 로딩 | 제목·검색 위치를 유지한 목록 Skeleton | 기다리기 |
| 기본 | 현재 검색어와 페이지에 해당하는 최대 6개의 목록 | 자료 선택 또는 이전·다음 페이지 이동 |
| 자료 없음 | 기존에 저장한 자료가 없다는 안내 | 새 학습자료로 만들기로 이동 |
| 검색 결과 없음 | 검색어와 일치하는 제목이 없다는 안내 | 검색어 지우기 |
| 페이지 이동 중 | 현재 목록·검색어·페이지 표시를 유지하고 이동 진행을 표시 | 기다리기 |
| 조회 오류 | 저장한 자료가 사라졌다고 표현하지 않는 오류. 이전에 확인한 목록이 있으면 유지 | 다시 시도, 뒤로가기 |
| 생성 중 자료 | 제목·출처와 선택 불가 이유 | 다른 자료 선택 또는 뒤로가기 |

### 3. 새 학습자료 방식 선택

#### 정보 구조

1. 뒤로가기와 `새 학습자료로 만들기` 제목
2. `Notion에서 가져오기` 선택 행: 허용한 단일 페이지를 한 번 복사한 뒤 확인·수정
3. `직접 입력하기` 선택 행: 제목과 본문을 직접 작성

두 선택 모두 저장 전까지 서버 학습자료나 draft를 만들지 않는다.

### 4. Notion에서 가져오기

1. **연결·권한 안내**: 어떤 접근이 필요한지, 한 페이지를 한 번 복사하며 이후 동기화되지 않음을 안내한다.
2. **단일 페이지 선택**: 허용된 범위에서 한 페이지를 선택한다.
3. **복사 중**: 완료 여부를 알 수 없는 진행 상태와 선택한 페이지 맥락을 보여준다.
4. **복사 결과 확인·수정**: 제목, 본문, 변환 경고와 현재 글자 수를 보여준다. 아직 저장된 LearningMaterial이 아님을 명확히 한다.
5. **저장**: 사용자가 확인한 제목·본문을 하나의 LearningMaterial로 저장한다.
6. **다음 단계**: 저장된 자료로 문제 생성 조건 화면에 push한다.

- 권한 거부·철회 시 재연결 또는 `직접 입력하기`로 전환할 수 있다.
- 복사 통신 실패 시 선택한 페이지를 가능한 범위에서 유지하고 같은 페이지를 다시 복사한다.
- 저장 실패 시 수정한 제목·본문과 확인한 경고를 유지한다.

### 5. 직접 입력하기

1. 뒤로가기와 `직접 입력하기` 제목
2. 제목 입력과 관련 기능명세에서 확정될 제목 규칙 안내
3. 필수 본문 입력, 현재 글자 수와 20,000자 제한
4. 한 개의 `학습자료 저장` CTA
5. 저장 성공 뒤 문제 생성 조건 화면으로 push

- 공백뿐인 본문과 20,000자 초과 본문은 해당 입력 가까이에 이유를 안내하고 값을 보존한다.
- 저장 중 반복 제출을 막되 로딩 상태와 비활성 의미를 구분한다.
- 저장 응답을 확인하지 못하면 새 자료를 다시 만들지 않고 같은 멱등 키로 결과를 확인하거나 재전송한다.

## 학습자료 상세·편집 전체 페이지

### 진입과 정보 구조

- 학습 메인의 학습자료 행을 선택하면 오른쪽 push로 진입한다.
- 이번 GET 연결 단계는 뒤로가기와 `학습자료 상세` 제목, 출처·생성 시각·수정 시각, 제목, 본문과 글자 수 순서로 읽기 전용 정보를 보여준다.
- 후속 `PATCH` 연결 뒤에는 같은 전체 페이지를 `학습자료 편집`으로 확장하고 제목 입력, 본문 입력, 저장 행동을 제공한다.
- 기존 QuizSet 목록, 풀이 기록과 결과는 이 페이지에 표시하지 않는다.

### 이번 GET 연결 상태

| 상태 | 보여줄 내용 | 가능한 행동 |
| --- | --- | --- |
| 상세 로딩 | 제목·메타데이터·본문의 읽기 구조를 유지한 Skeleton | 기다리기, 뒤로가기 |
| 기본 | 제목, 본문, 글자 수, 출처, 생성·수정 시각 | 뒤로가기 |
| 문제 생성 중 | 기본 상세와 `문제 생성 중 · 생성이 끝나면 본문을 다시 수정할 수 있어요.` | 상세 확인, 뒤로가기 |
| 조회 오류 | 자료가 삭제됐다고 단정하지 않고 상세를 확인하지 못했다는 안내 | 다시 시도, 뒤로가기 |
| 인증 만료 | 자료 없음과 구분되는 재인증 안내 | 재인증 |

제목과 본문은 모두 읽기 전용 콘텐츠로 표현한다. 입력처럼 보이는 스타일이나 비활성 저장 버튼으로 아직 제공하지 않는 편집 기능을 암시하지 않는다.

### 후속 `PATCH` 편집 상태

| 상태 | 제목 | 본문 | 안내와 행동 |
| --- | --- | --- | --- |
| 기본 | 편집 가능 | 편집 가능 | 수정된 내용 저장 |
| 같은 자료의 QuizSet 생성 중 | 편집 가능 | 읽기 전용 | `문제 생성 중에는 본문을 수정할 수 없어요. 생성이 끝나면 다시 수정할 수 있어요.` |
| 생성 종료 후 | 편집 가능 | 다시 편집 가능 | 새 수정은 이후 생성부터 사용됨 |
| 저장 중 | 현재 값 표시 | 현재 값 표시 | 중복 저장 방지와 진행 상태 표시 |
| 입력 오류 | 값 유지 | 값 유지 | 해당 필드 가까이에 이유와 해결 방법 |
| 저장 통신 실패 | 수정값 유지 | 수정값 유지 | 같은 내용으로 다시 시도 |
| 조회 오류 | 자료가 삭제됐다고 단정하지 않음 | 자료가 삭제됐다고 단정하지 않음 | 같은 자료 다시 조회 또는 뒤로가기 |

### 후속 편집의 불변성과 안내

- 저장 전, `수정해도 이미 만든 문제와 풀이 결과는 바뀌지 않아요. 다음에 만드는 문제부터 수정한 내용을 사용해요.`를 사용자가 행동을 판단할 위치에 안내한다.
- 생성 중 제목만 저장할 때 본문 값이 수정 요청에 포함된 것처럼 보이지 않게 한다. 정확한 요청 조립은 API 계약과 구현 원장에서 검증한다.
- 생성이 종료됐다는 최신 상태를 확인하면 본문 입력을 다시 활성화할 수 있다. 네트워크 오류만으로 생성 종료를 추정하지 않는다.
- 미저장 변경이 있을 때 뒤로가면 `계속 편집`, `변경사항 버리기`를 제공한다. 저장된 변경은 뒤로가기로 되돌리지 않는다.

## 대표 텍스트 와이어프레임

와이어프레임은 정보 순서와 행동 위계를 검토하기 위한 것이며 크기·색·정확한 컴포넌트 형태를 확정하지 않는다.

### 1. 학습 메인 기본

```text
┌──────────────────────────────────┐
│ 학습                              │
│                                  │
│        [ 새 문제 만들기 ]          │
│                                  │
│ 틀린 문제 다시 풀기                │
│ 네트워크 기초 · 미해결 문항 3개     │
│ 가장 최근 완료한 퀴즈를 복습해요     │
│                    다시 풀기 시작 › │
```

## 반응형·WebView 동작

- `base`는 320px 이상 모바일 WebView의 한 열 구조다. 학습 메인의 섹션 순서와 하위 route의 읽기 순서를 바꾸지 않는다.
- 메인 CTA는 콘텐츠 흐름 안에 두며 하단 내비게이션과 겹치는 별도 고정 CTA로 만들지 않는다.
- 하위 입력 화면에서 저장 행동을 하단에 고정한다면 WebView 안전 영역과 키보드 높이를 함께 반영하고 본문 마지막 입력을 가리지 않아야 한다. 고정이 불안정한 환경에서는 문서 흐름 안에 둔다.
- 하단 내비게이션은 학습 메인에만 보인다. 새 문제 만들기와 자료 편집의 route-level 전체 페이지에서는 숨기고 명시적 뒤로가기를 제공한다.
- `md` 이상에서도 기본은 한 열이다. 기존 자료 선택 목록은 읽기 폭을 제한하며 두 열 카드 그리드로 바꾸지 않는다.
- 페이지 이동은 320px 너비에서도 `이전 · 현재/전체 · 다음`이 한 행의 세 영역으로 구분되게 하고, 숫자 페이지 버튼을 여러 개 나열하지 않는다. 안전 영역에 닿거나 하단 내비게이션에 가리지 않게 목록 흐름 안에 둔다.
- 긴 한국어 제목과 오류 문구는 줄바꿈하고 텍스트 확대 시 행과 입력 영역이 함께 늘어난다. 중요한 상태와 행동을 말줄임으로만 숨기지 않는다.
- 키보드가 열린 동안 현재 입력과 오류 메시지가 보이도록 스크롤하며, 저장 CTA가 키보드 뒤에 가려지지 않게 한다.
- 터치 대상은 SEED가 더 큰 크기를 제공하지 않는 경우에도 최소 44×44 CSS px를 확보한다.

## 접근성

- 각 route-level 페이지에는 하나의 `h1`을 두고 학습 메인의 `틀린 문제 다시 풀기`, `학습자료 관리`는 순서에 맞는 하위 제목으로 제공한다.
- 선택·자료 행 전체를 하나의 링크 또는 버튼으로 만들고 chevron만 별도 포커스 대상으로 만들지 않는다.
- 접근 가능한 이름에서 제목, 보조 설명과 이동 목적이 함께 이해되게 한다. `기존 학습자료로 만들기`와 `새 학습자료로 만들기`는 이름만으로 결과가 구분된다.
- `문제 생성 중`, `본문 임시 잠금`, 복습 필요와 오류를 색이나 아이콘만으로 전달하지 않는다.
- 읽기 전용 본문은 disabled 입력처럼 대비가 지나치게 낮아지지 않게 하고, 잠금 이유를 입력 앞의 텍스트와 프로그램적으로 연결한다.
- push 후 새 화면 제목으로 읽기 맥락이 이동하되, reduced motion에서도 포커스 이동과 화면 제목 공지는 동일하게 유지한다.
- 뒤로가기로 확인 대화상자가 열리면 대화상자에 포커스를 가두고 닫은 뒤 뒤로가기 트리거로 복귀한다.
- 오류 메시지는 해당 입력이나 실패 영역과 인접하게 두고 재시도 성공을 적절한 live region으로 알린다.
- 제목 검색에는 화면에 보이거나 프로그램적으로 연결된 레이블을 제공한다. 적용된 검색 결과가 바뀌면 결과 수와 현재 페이지를 과도하지 않은 live region으로 알린다.
- 페이지 이동 영역에는 내비게이션 의미와 식별 가능한 이름을 제공한다. `이전`, `다음`은 대상 페이지를 알 수 있는 접근 가능한 이름을 사용하고 이동할 수 없는 상태를 `disabled` 의미로 전달한다.
- `현재/전체` 페이지 표시는 색이나 위치에만 의존하지 않고 텍스트로 읽힌다. 페이지 이동 뒤에는 새 목록의 시작 또는 목록 제목으로 예측 가능한 포커스 맥락을 제공한다.

## SEED 컴포넌트 역할 후보

아래는 UX 실현 가능성을 설명하는 후보다. 정확한 컴포넌트명, variant, props와 조립 방식은 현재 SEED Docs와 설치 버전을 구현 전에 다시 검증한다.

| UI 책임 | SEED 구성 후보 | 상태·접근성 요구 | 검증 상태 |
| --- | --- | --- | --- |
| 단일 열 문서 배치 | `Box`, `VStack`, `Flex`, `Text` | 의미 요소와 제목 단계, semantic spacing 우선 | 구현 시 확인 |
| 새 문제 만들기·저장 | `ActionButton` | 화면당 한 개 prominent solid CTA, loading과 disabled 의미 분리 | 구현 시 확인 |
| 복습·자료·선택 행 | `List`, `ListButtonItem` 또는 `ListLinkItem` 계열 후보 | 행 전체 한 행동, chevron 장식 처리, 중첩 버튼 금지 | 구현 시 확인 |
| route 상단 뒤로가기 | SEED 내비게이션 primitive 또는 레이아웃 조합 후보 | 접근 가능한 이름, 44px 이상, 시스템 back과 결과 일치 | 구현 시 확인 |
| 제목 검색·자료 입력 | `TextField` 계열 후보 | 항상 보이는 label, 설명·invalid·error 연결 | 구현 시 확인 |
| 페이지 이동 | 의미 있는 내비게이션 영역과 SEED 버튼 후보 | 이전·다음의 disabled 상태, 현재/전체 텍스트, 44px 이상 터치 영역 | 구현 시 확인 |
| 본문 입력 | `TextField`의 textarea 계열 후보 | 글자 수, 20,000자 제한, 읽기 전용과 잠금 이유 연결 | 구현 시 확인 |
| 입력 이탈 확인 | `AlertDialog` 후보 | 초기 포커스, focus trap, 계속 편집을 안전한 기본으로 | 구현 시 확인 |
| 로딩 | 중립 `Skeleton` 후보 | 실제 섹션·목록 구조와 유사 | 구현 시 확인 |
| 부분 오류·잠금 안내 | `PageBanner` 또는 인라인 조합 후보 | 콘텐츠 보존, 상태 텍스트와 복구 행동 인접 | 구현 시 확인 |
| 빈 상태·전체 오류 | `ResultSection` 후보 | 현재 상태와 가장 유용한 다음 행동 | 구현 시 확인 |

별도 범용 `Card`, 커스텀 버튼·입력·대화상자를 먼저 만들지 않는다. SEED 의미 컴포넌트와 레이아웃 primitive 조합을 우선한다.

## 데이터와 API 계약 검증

### 학습 메인에 필요한 데이터

- 다시 풀기 현황: 최근 완료 회차, 부모 학습자료명, 미해결 수와 활성 review session
- 학습자료 목록 항목: `materialId`, `title`, `sourceType`, `contentEditStatus`, `updatedAt`
- 페이지 정보: `page`, `size`, `totalElements`, `totalPages`. 기본 `size`는 6이며 제목 검색어는 서버 `query`로 전달한다.
- 목록에는 전체 `content`와 `contentLength`를 포함하지 않는다. 상세 진입 전 본문을 미리 가져오거나 목록에서 본문 미리보기를 만들지 않는다.
- `contentEditStatus`는 `EDITABLE | LOCKED_GENERATING`만 사용한다. 생성 중 표시를 위해 `activeQuizSetId`, `generating` 같은 중복 필드를 별도로 요구하지 않는다.

### 새 문제 만들기에 필요한 데이터와 입력

- 기존 LearningMaterial 선택도 같은 목록 항목과 페이지 정보를 사용한다. `contentEditStatus=LOCKED_GENERATING`이면 새 생성을 선택할 수 없다고 해석하므로 `selectable`을 별도로 요구하지 않는다.
- 적용된 제목 검색어가 바뀌면 `page=1`로 조회하고, 페이지 이동은 같은 검색어를 유지한다.
- Notion 연결 상태, 허용된 단일 페이지 목록, 복사된 제목·본문·변환 경고
- 직접 입력 또는 복사 결과의 제목·본문, 20,000자 검증과 저장 멱등 키
- 선택·저장된 LearningMaterial 식별자와 문제 생성 조건 화면으로 전달할 자료 맥락

### 학습자료 상세·편집에 필요한 데이터와 입력

- 상세 조회: `materialId`, `title`, `content`, `contentLength`, `sourceType`, `contentEditStatus`, `createdAt`, `updatedAt`
- 이번 GET 연결 단계에서는 상세 응답만 표시하고 수정값이나 저장 상태를 만들지 않는다.
- 후속 `PATCH` 연결 뒤에는 제목·본문 수정값과 저장 오류·경합 처리가 추가된다. 생성 중 여부는 상세의 `contentEditStatus`로 판단하고 별도 활성 생성 식별자를 요구하지 않는다.

### 이번 구현 범위에서 확인된 경계

- 붙여넣기 학습자료 저장
- 사용자 소유 학습자료의 제목 검색, 최근 수정 순 목록과 6개 단위 페이지 조회
- 사용자 소유 학습자료 상세 조회
- 목록과 상세의 `contentEditStatus=EDITABLE | LOCKED_GENERATING`
- 문제 생성 접수, 자료별 활성 생성 조회, QuizSet 상태 조회
- 틀린 문제 다시 풀기 현황과 활성 review session 생성·재개
- 빈 본문, 20,000자 초과, 소유권과 인증 오류

### 후속 계약·구현에서 확인할 항목

- 생성 중 제목만 수정하는 요청과 상태 경합 처리
- QuizSet이 생성 당시 참조한 학습자료 근거의 불변 보존 방식
- Notion 연결·권한, 페이지 목록과 WebView 복귀 계약
- 학습자료 `PATCH` 응답과 입력 오류·저장 경합 처리. 실제 수정 API를 연결하기 전 [학습자료 PRD의 임시 잠금 정책](../prd/prd-content-import.md#후속-계약구현-동기화-주의)과 공유 계약의 동기화 여부를 확인한다.

위 항목은 화면 명세에서 임의의 API, 상태 enum 또는 클라이언트 저장 구조로 확정하지 않는다. 관련 기능명세·공유 계약과 애플리케이션 TRD에서 검증한다.

학습자료 본문, 사용자 답안과 원문 근거는 민감한 학습 콘텐츠다. 학습 메인에는 목록 구분에 필요한 최소 요약만 노출하고 분석 이벤트나 일반 로그에 본문·답안을 넣지 않는다.

## 인수 조건

- [ ] 학습 메인은 내부 탭 없이 `새 문제 만들기` → `틀린 문제 다시 풀기` → `학습자료 관리`의 단일 세로 순서를 사용한다.
- [ ] `새 문제 만들기`만 학습 메인의 선명한 CTA이며 복습과 자료 관리 행동이 시각적으로 경쟁하지 않는다.
- [ ] 학습 메인에 QuizSet 목록이나 `계속할 학습` 영역이 없고 홈의 다음 행동 추천 책임과 중복되지 않는다.
- [ ] 틀린 문제 다시 풀기는 최신 완료 회차 하나의 미해결 문항과 활성 session만 다루며 시작 가능·진행·대상 없음·오류를 구분한다.
- [ ] 학습자료 행은 제목, 출처와 수정 시각을 중심으로 표시하고 chevron이 있는 전체 행으로 상세·편집 전체 페이지에 이동한다.
- [ ] 학습 메인과 기존 자료 선택 목록은 모바일 기본 6개 단위 페이지이며 `이전 · 현재/전체 · 다음`을 제공한다.
- [ ] 제목 검색은 현재 페이지 배열을 거르는 방식이 아니라 서버 전체 자료 검색이며, 적용된 검색어가 바뀌면 1페이지로 돌아간다.
- [ ] 페이지 이동 로딩·실패 시 기존 목록, 검색어와 페이지 맥락을 보존하고 전체 없음과 검색 결과 없음을 구분한다.
- [ ] 학습자료 행에 문제 풀이·결과 상태를 섞지 않으며 생성 중에는 본문 임시 잠금을 텍스트로 알린다.
- [ ] 새 문제 만들기 첫 화면에는 `기존 학습자료로 만들기`, `새 학습자료로 만들기` 두 선택만 있다.
- [ ] 기존 학습자료 선택은 별도 전체 페이지에서 이루어지고 자료 선택 뒤 문제 생성 조건 화면으로 이동한다.
- [ ] 새 학습자료 방식은 `Notion에서 가져오기`, `직접 입력하기`뿐이며 로컬 파일 관련 선택지가 없다.
- [ ] Notion 흐름은 연결·권한 → 한 페이지 선택 → 복사 결과 확인·수정 → 저장 → 생성 조건 순서다.
- [ ] 직접 입력 흐름은 제목·본문 입력 → 저장 → 생성 조건 순서이며 입력 오류·통신 실패에도 값을 보존한다.
- [ ] 기존 QuizSet이 있어도 제목·본문을 편집할 수 있고, `GENERATING` 동안만 본문이 임시 잠기며 제목은 수정할 수 있다.
- [ ] 이번 GET 연결 단계의 상세는 제목·본문·글자 수·출처·생성·수정 시각을 읽기 전용으로 표시하고 저장 행동을 노출하지 않는다. 후속 `PATCH` 연결 뒤 목표 편집 UX는 별도로 유지한다.
- [ ] 목록과 상세는 `contentEditStatus=EDITABLE | LOCKED_GENERATING`만 사용하며 `activeQuizSetId`, `selectable`, `generating` 같은 중복 표시용 필드를 요구하지 않는다.
- [ ] 자료 수정이 기존 QuizSet·풀이·결과를 바꾸지 않고 이후 생성부터 반영됨을 편집 화면에서 이해할 수 있다.
- [ ] 앱 바 뒤로가기와 시스템 back이 같은 단계로 이동하고, 미저장 입력 이탈 확인·세션 내 입력 보존·reduced motion이 정의되어 있다.
- [ ] 모바일 WebView 안전 영역, 키보드, 하단 내비게이션, 긴 문구, 텍스트 확대와 44×44 CSS px 터치 영역을 고려한다.
- [ ] 기능명세의 임시 잠금과 기존 QuizSet 불변 정책을 반영하고, 현재 흐름·API 계약·서버 상태 모델의 불일치와 후속 동기화 범위가 명시되어 있다.
- [ ] 정확한 SEED props·API와 미확정 데이터 경계는 구현 전 검증 항목으로 남아 있다.

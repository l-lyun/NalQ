# [Screen Spec] 퀴즈 생성 조건과 OpenAI 전송 확인

## 문서 정보

- 화면명: 퀴즈 생성 조건, OpenAI 전송 확인
- 대상 플랫폼: 반응형 웹과 앱 WebView, 모바일 우선
- 관련 기능: [퀴즈 생성·풀이·결과·복습](../prd/prd-quiz-learning.md)
- 관련 흐름: [퀴즈 생성부터 복습까지](flow-quiz-solving.md)
- 시각 기준: [NalQ Design System](../../DESIGN.md)

## 문서 책임

이 문서는 생성 조건을 정한 사용자가 학습자료를 OpenAI에 보내기 전에 전송 범위와 보관 가능성을 확인하거나 취소하는 화면 상태를 정의한다. 실제 전송 데이터와 공급자 정책은 PRD, API 모양은 Contract, 저장 방식은 구현 원장이 책임진다.

## 정보와 행동 위계

1. 선택한 학습자료 제목과 뒤로가기
2. 문제 유형, 난이도, 문제 수와 선택적 추가 요청
3. 주 행동 `문제 만들기`
4. 현재 본문 revision에 확인이 필요하면 요청 전에 여는 확인 dialog
   - 제목 `학습자료를 OpenAI로 전송할까요?`
   - 전송: 학습자료 본문 전체, 문제 유형·난이도·문제 수, 선택적 추가 요청
   - 미전송: 이메일·닉네임·비밀번호·인증정보·풀이답안
   - 안내: 기본 abuse monitoring에서 입력과 출력이 최대 30일 보관될 수 있음
   - 주 행동 `확인하고 문제 만들기`
   - 보조 행동 `취소`

확인 dialog는 생성 API 호출 전에 표시한다. `취소`, Escape, 시스템 back은 dialog만 닫고 입력 조건과 focus를 보존하며 네트워크 요청을 만들지 않는다. 확인 성공은 현재 학습자료 본문 revision에만 연결한다. 본문 수정 후 다시 확인하고 제목만 변경한 경우에는 기존 확인을 유지한다.

## 상태와 접근성

| 상태 | 사용자 표시 | 행동 |
| --- | --- | --- |
| 확인 불필요 | 선택한 생성 조건 | 바로 생성 요청 |
| 확인 필요 | 전송·미전송 항목과 최대 30일 보관 가능성 | 확인 후 요청 또는 취소 |
| 확인 후 접수 중 | dialog 행동 비활성 및 처리 중 표시 | 중복 요청 방지 |
| 접수 실패 | 조건과 확인 문맥 유지, 요청 실패 안내 | 재시도 또는 조건 수정 |

- dialog는 제목·설명과 연결된 modal semantics와 focus trap을 제공한다.
- 열릴 때 제목 또는 첫 설명으로 이동하고 닫히면 원래 `문제 만들기`로 focus를 돌린다.
- 최대 30일 가능성과 미전송 항목을 작은 각주나 링크 안에 숨기지 않는다.
- 320 CSS px와 큰 글자에서도 내용이 잘리지 않고 행동은 필요하면 한 열로 쌓인다.

## 관찰 가능한 인수 조건

- [ ] 확인이 필요한 본문 revision에서는 생성 API보다 전송 확인 dialog가 먼저 열린다.
- [ ] 사용자는 전송 항목, 미전송 항목과 최대 30일 보관 가능성을 같은 dialog에서 확인한다.
- [ ] 취소하면 생성 요청이 없고 입력 조건·스크롤·focus가 유지된다.
- [ ] 확인 후 한 번만 생성 요청하며 본문 수정 시 다시 확인하고 제목 변경만으로는 재확인하지 않는다.
- [ ] 키보드, 시스템 back, 320 CSS px, 큰 글자와 WebView safe area에서 dialog를 읽고 닫을 수 있다.

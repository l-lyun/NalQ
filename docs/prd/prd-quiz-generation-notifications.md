# [PRD] 퀴즈 생성 결과 알림

- 관련 제품 원장: [NalQ 제품 기반](../product.md)
- 관련 기능: [퀴즈 생성·풀이·결과·복습](prd-quiz-learning.md)
- 관련 흐름: [퀴즈 생성 결과 알림 흐름](../ux/flow-quiz-generation-notifications.md)
- 관련 화면: [알림 목록과 생성 결과 Snackbar](../ux/screen-notifications.md)
- 관련 계약: [알림 API](../contracts/contract-api-notifications.md), [알림 데이터](../contracts/contract-data-notifications.md)

## 문서 책임

이 문서는 사용자가 퀴즈 생성 화면을 떠난 뒤에도 생성 성공·실패를 놓치지 않고 확인하는 제품 행동과 성공 조건을 정의한다. 퀴즈 생성 자체의 성공·실패 의미는 [퀴즈 PRD](prd-quiz-learning.md)가, 화면 순서와 복귀 분기는 관련 Flow가, 표시 구조와 문구는 화면 명세가, HTTP와 데이터 수명주기는 Contract가 책임진다.

## 사용자 문제

퀴즈 생성은 화면을 떠난 뒤에도 서버에서 계속되지만 현재 화면을 벗어나면 상태 확인이 중단된다. 사용자는 다른 일을 하는 동안 생성이 끝났는지 알 수 없고, 앱이나 브라우저로 돌아온 뒤에도 결과를 다시 찾아야 한다. 여러 탭이나 복귀 시점에 같은 결과가 반복 노출되면 알림을 신뢰하기 어렵다.

## 목표

- 사용자는 일반 인증 화면 어디에서든 퀴즈 생성 성공·실패를 방해받지 않는 방식으로 알 수 있다.
- 사용자는 Snackbar를 놓쳐도 우측 상단 알림 목록에서 최근 90일의 결과와 읽음 상태를 다시 확인할 수 있다.
- 백그라운드 중 불필요한 조회를 하지 않으면서 로그인·새로고침·복귀·연결 회복 뒤 새 알림을 확인할 수 있다.
- 알림은 현재 화면을 자동으로 바꾸지 않고 사용자가 항목이나 행동을 선택했을 때만 이동한다.

## 범위

- 서버가 보존하는 퀴즈 생성 `READY`·`FAILED` 알림
- 일반 인증 화면 우측 상단 종, 읽지 않은 알림 수와 알림 목록
- 개별 읽음과 `모두 읽음`
- foreground 상태의 생성 상태 감시와 알림 목록 재확인
- 성공·원인별 실패·복수 결과 Snackbar와 중복 방지
- 웹과 실행 중인 앱 WebView에서 같은 사용자 경험

## 비범위

- FCM과 운영체제 푸시 알림
- WebSocket·SSE와 기타 실시간 서버 전송
- 알림 설정, 종류별 수신 선택과 방해 금지 시간
- 사용자의 알림 삭제, 검색, 분류와 필터
- 몰입형 퀴즈·결과·복습 화면의 종 버튼
- 네이티브 앱이 직접 API를 호출하거나 백그라운드 작업을 수행하는 것

## 핵심 규칙

### 서버 알림 원장

- QuizSet이 `GENERATING`에서 terminal `READY` 또는 `FAILED`로 처음 확정될 때 해당 QuizSet의 생성 결과 알림을 정확히 한 건 만든다.
- 유효 문제와 `READY`, 또는 실패 코드와 `FAILED`, 그리고 해당 알림은 같은 트랜잭션에서 확정한다. 어느 한쪽만 사용자에게 남겨서는 안 된다.
- 알림 목록과 읽음 상태는 서버가 사용자별로 보존한다. 알림은 생성 시각부터 90일 동안 제공하며 사용자가 직접 삭제하는 기능은 두지 않는다.
- 알림에는 생성 시점의 `quizTitle`을 대상 이름 snapshot으로 저장하고 90일 동안 바꾸지 않는다. 이후 QuizSet 이름 변경은 과거 알림 문구에 영향을 주지 않는다.
- 알림 기능을 포함한 최초 배포 이후 새로 terminal 전이한 QuizSet부터 알림을 만든다. 아직 배포 전이므로 기존 terminal QuizSet의 소급 알림과 migration은 두지 않는다.
- `FAILED` QuizSet은 생성 원인과 알림 대상 확인을 위해 서버에 유지하지만 `내 퀴즈` 목록에는 노출하지 않는다. 실패 결과와 복구 진입은 알림 목록이 책임진다.
- 네트워크 조회 오류나 아직 확인하지 못한 상태를 `FAILED` 알림으로 만들지 않는다.

### 전역 확인과 복귀

- 이 기기에서 생성 접수 또는 활성 생성 복원으로 알게 된 `quizSetId`는 현재 사용자 범위의 pending 대상으로 보존한다. pending은 감시 대상을 복원하기 위한 보조 정보이며 terminal 상태와 알림의 원장이 아니다.
- 문서가 foreground이고 온라인일 때만 pending QuizSet 상태를 조회한다. 다음 조회는 서버가 직전 `GENERATING` 응답에 준 `pollAfterSeconds`를 단일 기준으로 사용한다.
- background에서는 상태와 알림 polling을 중단한다. 로그인 완료, 새로고침, 문서가 다시 visible이 된 때와 offline에서 online으로 돌아온 때 알림 목록의 최신 상태를 즉시 다시 확인한다.
- pending 상태 조회에서 terminal 결과를 발견하면 관련 화면 데이터를 갱신하고 서버 알림을 다시 조회한다. 상태 응답만으로 별도의 로컬 알림을 만들어 서버 알림과 중복시키지 않는다.
- 조회가 실패하면 기존 pending과 알림 목록을 조용히 유지하고 foreground·online 조건에서 다시 시도한다. 현재 화면을 오류 화면으로 바꾸거나 생성 실패로 단정하지 않는다.

### 종과 알림 목록

- 종은 일반 인증 화면의 우측 상단 전역 utility다. 홈·학습·마이페이지와 일반 하위 화면에서 접근할 수 있지만 몰입형 퀴즈·결과·복습 화면에는 표시하지 않는다. 데스크톱·모바일 웹·WebView 모두 사용자가 종을 선택하면 별도 알림 페이지로 이동한다.
- badge는 읽지 않은 알림의 정확한 서버 개수를 기반으로 하되 화면에는 `1`부터 `99`까지 숫자, 100개 이상은 `99+`로 표시하고 0이면 숨긴다.
- 목록은 최신순으로 20개를 먼저 보여주고 `더보기`로 다음 항목을 이어 붙인다.
- 목록을 여는 것과 Snackbar가 표시되는 것은 읽음이 아니다. 사용자가 항목을 선택하면 해당 항목을 읽음 처리하고, `모두 읽음`은 현재 시점까지의 읽지 않은 알림을 한 번에 읽음 처리한다.
- 성공 알림을 선택하면 `내 퀴즈`에서 해당 `READY` 카드를 찾고 focus한다. 실패 알림을 선택하면 원본 학습자료의 퀴즈 생성 조건 흐름으로 이동한다.
- 대상 퀴즈나 학습자료에 더는 접근할 수 없으면 현재 맥락을 유지한 채 대상을 찾을 수 없다고 안내하고 해당 알림은 읽음 처리한다.

### Snackbar와 중복 방지

- 생성 진행 화면은 같은 화면에서 결과 상태를 직접 보여주므로 생성 결과 Snackbar를 표시하지 않는다.
- 그 밖의 화면에서 단일 성공은 positive `퀴즈가 완성됐어요.`와 `목록보기`를 제공한다. `내 퀴즈` 화면에서는 같은 문구를 보여주되 현재 목적지가 이미 목록이므로 행동을 생략한다.
- `SOURCE_INSUFFICIENT`는 critical `학습자료에서 문제를 만들지 못했어요.`와 `자료·조건 확인`을, `GENERATION_FAILED`는 critical `퀴즈를 만들지 못했어요. 다시 시도해 주세요.`와 `다시 만들기`를 제공한다. 두 행동은 사용자가 선택했을 때 원본 자료의 생성 조건 흐름으로 이동하며 이전 요청 조건의 서버 복원을 약속하지 않는다. `내 퀴즈` 화면에서는 행동을 생략한다.
- 복귀 또는 재확인에서 새로 표시할 unseen 알림이 2개 이상이면 개별 Snackbar를 연속 노출하지 않고 `새 퀴즈 알림이 N개 있어요.`와 `알림보기` 한 건으로 묶는다.
- Snackbar 표시는 알림을 읽음 처리하지 않는다. 같은 `notificationId`는 같은 사용자·기기에서 한 번만 Snackbar 대상으로 삼고, 여러 웹 탭이 열려 있으면 현재 활성 탭 한 곳만 표시한다.
- 어떤 Snackbar도 자동 이동, 입력 focus 강탈 또는 진행 중 작업 취소를 일으키지 않는다.

## 상태와 예외

| 상태/조건 | 사용자에게 보이는 동작 | 복구 행동 |
| --- | --- | --- |
| 읽지 않은 알림 없음 | 종은 보이고 badge는 숨김; 별도 알림 페이지는 빈 상태 | 이전 화면으로 돌아가기 |
| 새 성공 1건 | 조건에 맞으면 positive Snackbar; 목록에 읽지 않음 항목 | `목록보기` 또는 나중에 종에서 확인 |
| 새 실패 1건 | 실패 원인별 critical Snackbar; 목록에 읽지 않음 항목 | 자료·조건 확인 또는 다시 만들기 |
| 새 unseen 2건 이상 | 합산 Snackbar 한 건 | `알림보기` |
| 생성 화면에서 terminal 확정 | 생성 화면의 성공·실패 상태만 표시 | 화면 안의 기존 행동 사용 |
| background | polling과 Snackbar 중단 | 복귀 시 즉시 최신 알림 재확인 |
| 상태·알림 조회 실패 | 현재 화면과 기존 목록 유지; 생성 실패로 표시하지 않음 | foreground·online에서 재시도 |
| 대상 없음 | 이동하지 않고 짧은 안내 | 해당 알림 읽음 처리 |
| 여러 탭 활성 | 활성 탭 한 곳만 Snackbar | 다른 탭은 서버 목록과 읽음 상태 동기화 |

## 수용 기준

- [ ] QuizSet 하나가 `READY` 또는 `FAILED`로 확정되면 같은 트랜잭션에서 생성 결과 알림이 정확히 한 건 생긴다.
- [ ] 사용자는 일반 인증 화면 우측 상단 종에서 최신순 알림 20개와 읽지 않은 수를 확인하고 `더보기`로 이전 알림을 불러올 수 있다.
- [ ] 데스크톱·모바일 웹·WebView에서 종과 복수 알림 Snackbar의 `알림보기`는 동일한 별도 알림 페이지로 이동한다.
- [ ] badge는 0일 때 숨고 1~99는 숫자, 100 이상은 `99+`로 보인다.
- [ ] 목록 열기와 Snackbar 표시는 읽음으로 바뀌지 않으며 항목 선택과 `모두 읽음`만 서버 읽음 상태를 변경한다.
- [ ] 성공 알림 선택은 내 퀴즈의 대상 카드로, 실패 알림 선택은 원본 자료의 퀴즈 생성 조건으로 이동하며 자동 이동은 없다.
- [ ] 대상이 없으면 현재 맥락을 유지하고 안내한 뒤 해당 알림을 읽음 처리한다.
- [ ] 이 기기의 pending 생성은 foreground에서만 `pollAfterSeconds`에 따라 확인되고 background에서는 상태·알림 polling이 중단된다.
- [ ] 로그인·새로고침·visible 복귀·online 복귀 시 최신 알림을 즉시 다시 확인한다.
- [ ] 네트워크 오류는 `FAILED`로 표시되지 않고 기존 pending과 현재 작업을 유지한다.
- [ ] 생성 화면에서는 Snackbar를 생략하고, 그 밖의 화면은 단일 성공·원인별 실패 또는 복수 unseen 요약 중 한 가지를 표시한다.
- [ ] 같은 `notificationId`는 같은 사용자·기기에서 한 번만 Snackbar로 표시되고 여러 탭 중 활성 탭 한 곳만 표시한다.
- [ ] 알림은 생성 뒤 90일 동안 읽음 여부와 관계없이 조회되며 사용자 삭제·검색·분류 기능은 나타나지 않는다.
- [ ] FCM·OS 푸시·WebSocket·SSE가 없어도 웹과 실행 중인 WebView에서 전체 흐름을 완료할 수 있다.

## 계측 제안

- 알림 생성 결과 종류, Snackbar 표시·행동 선택, 종 열기, 항목 선택, 모두 읽음
- visible·online 복귀 뒤 새 알림 발견 여부와 발견까지 걸린 시간
- 알림에서 성공 퀴즈 또는 실패 재생성 흐름으로 이동한 비율
- `notificationId`, 공개 결과 종류와 시각만 기록하고 학습자료 본문·문제·사용자 답안·외부 생성 상세는 분석 사건에 넣지 않는다.

# [Flow] 퀴즈 생성부터 복습까지

- 관련 기능: [퀴즈 생성·풀이·결과·복습](../prd/prd-quiz-learning.md)
- 공유 계약: [학습자료·퀴즈 API 계약](../contracts/contract-api-quiz-learning.md)
- 관련 화면: [서술형 자기평가와 채점 결과](screen-quiz-feedback.md), [미완료 서술형 자기평가 재진입](screen-quiz-resume.md), [틀린 문제 다시 풀기](screen-review.md)
- 학습 진입 화면: [학습 메인·내 학습자료·내 퀴즈](screen-learning.md)
- 클라이언트 후속 동기화 대상: [웹 퀴즈 풀이 TRD](../../web/docs/trd/trd-quiz-solving.md), [앱 퀴즈 풀이 TRD](../../app/docs/trd/trd-quiz-solving.md)

## 문서 책임

이 문서는 화면과 상태 사이의 순서, 분기, 중단, 재개와 실패 복구를 정의한다. 문제 품질·채점·복습 대상 정책은 기능명세가, 요청·응답과 오류 코드는 API 계약이 책임진다.

## 사용자 목표

학습자료로 만든 퀴즈를 중단이나 실패에도 진행 상태를 이해하며 끝까지 풀고, 결과에서 필요한 문항을 복습한다.

## 시작 조건

- 로그인한 사용자가 자신이 소유한 유효한 학습자료를 선택했다.
- 학습자료 본문이 비어 있지 않고 20,000자를 넘지 않는다.
- 생성·평가 규칙은 [퀴즈 PRD의 확정 정책](../prd/prd-quiz-learning.md#확정-정책)을 따른다.
- 이미 만든 퀴즈는 학습 메인의 최근 퀴즈 또는 `/learning/quizzes`의 퀴즈 카드에서 다시 진입할 수 있다.

## 완료 조건

- 본 퀴즈: 자동 채점과 필요한 서술형 자기평가가 끝나 완료 결과를 볼 수 있다.
- 복습: 현재 세션의 모든 대상 문항을 한 번씩 평가해 해결·미해결 상태가 저장된다.

## 기본 흐름

### 0. 퀴즈 목록 탐색과 이름 변경

이 절은 사용자 승인 UX이며 QuizSet 제목·목록·수정 Contract가 추가된 뒤 구현할 목표 흐름이다.

1. 사용자가 학습 메인 `내 퀴즈 전체 보기`로 `/learning/quizzes`에 진입한다.
2. 시스템은 퀴즈 자체 제목을 기준으로 검색 가능한 목록을 보여준다. 부모 학습자료명과 생성 상태·문제 수는 보조 맥락으로 표시하고 최근 풀이·결과·복습 상태는 표시하지 않는다.
3. 사용자가 카드 header를 선택하면 학습자료 카드와 같은 규칙으로 상세가 펼쳐지고 `퀴즈 이름 변경`, `퀴즈 풀기`가 나타난다. 여러 카드를 동시에 펼칠 수 있으며 검색·페이지·URL 상태 보존도 학습자료 disclosure 규칙을 재사용한다.
4. `퀴즈 이름 변경`을 선택하면 현재 제목을 채운 modal이 열리고 저장 또는 취소할 수 있다. 저장 성공 뒤 목록·학습 메인·홈의 같은 QuizSet 제목을 갱신하며, 실패하면 기존 서버 제목과 입력값을 구분해 modal에서 다시 시도한다.
5. `퀴즈 풀기`를 선택하면 과거 회차와 무관하게 같은 QuizSet의 모든 문항을 새 `MAIN` 회차로 시작한다. 기존 회차·결과·복습 기록은 유지한다.
6. `GENERATING`·`FAILED` 카드는 펼칠 수 있지만 두 행동은 비활성화한다. 생성 중에는 옅은 차단 overlay와 진행 표시를, 생성 실패에는 같은 overlay와 정적 실패 표시를 보여주며 별도의 불가능 이유 설명은 추가하지 않는다.

결과·복습·미완료 자기평가 진입은 학습 메인이 책임진다. 상세 구조와 상태는 [학습 화면 명세](screen-learning.md#4-내-퀴즈)를 따른다.

### A. 생성

1. 사용자가 문제 유형을 하나 이상 선택하고 난이도와 최대 문제 수를 정한다.
2. 사용자가 생성을 요청하면 시스템은 요청을 접수하고 즉시 학습자료 본문을 잠근다.
3. 차단형 생성 오버레이가 열리고 완료 여부를 알 수 없는 진행 표시를 보여준다.
4. 클라이언트는 3초 뒤 처음 상태를 확인하고, 이후 5초 간격으로 확인한다. 생성 시작 후 2분이 지나면 10초 간격으로 낮춘다.
5. 성공하면 생성된 문제 목록에서 계산한 실제 문제 수와 포함 유형을 보여주고 본 퀴즈 시작 행동을 제공한다.
6. 실패하면 불완전한 문제를 노출하지 않고 생성 조건을 다시 확인한 뒤 새로 요청할 수 있게 한다.

### B. 본 퀴즈 풀이와 제출

1. 사용자가 본 퀴즈를 시작하면 첫 문항을 보여준다.
2. 사용자는 답을 작성하고 이전·다음으로 이동한다. 이동만으로 채점하지 않는다.
3. 풀이 중 현재 위치와 답안은 열린 화면의 메모리 상태로 유지된다.
4. 제출을 선택했을 때 미응답이 있으면 `남은 문제 풀기`와 `그대로 제출`을 제공한다.
5. `남은 문제 풀기`를 선택하면 번호가 가장 낮은 미응답 문항으로 이동한다.
6. `그대로 제출` 또는 모든 문항 응답 후 제출하면 클라이언트가 attempt UUID를 한 번 생성해 최종 제출한다. 현재 화면이 같은 UUID를 유지하는 동안의 재시도는 새 회차를 만들지 않는다.
7. 자동 채점 뒤 작성한 서술형이 있으면 자기평가 흐름으로, 없으면 결과로 이동한다. 미응답 서술형은 자기평가 없이 오답 처리한다.

### C. 서술형 자기평가

1. 첫 서술형에서는 자기평가 방식과 자동 점수 제외를 안내한다.
2. 사용자는 내 답과 모범 답안·핵심 포인트·해설·`학습자료 본문`을 비교한다. `학습자료 본문`에는 문제와 관련된 source excerpt를 보여준다.
3. 사용자는 `정답`, `보완 필요`, `오답` 중 하나를 선택해 저장한다. `보완 필요`는 API의 `PARTIAL` 상태를 표시하는 사용자 문구다.
4. 다음 미평가 서술형으로 이동한다.
5. 마지막 평가가 저장되면 본 퀴즈 회차가 완료되고 결과로 이동한다.

### D. 결과

1. 시스템은 단답형·빈칸 채우기의 현재 판정을 포함한 채점 점수, 서술형 자기평가 요약과 다시 풀 문제 수를 보여준다.
2. 그 아래에 모든 문항을 번호 오름차순으로 보여준다.
3. 사용자가 한 문항을 선택하면 결과 읽기 모드에서 내 답, 정답 또는 모범 답안, 판정, 해설과 `학습자료 본문`을 확인한다.
4. 답을 작성한 단답형·빈칸 채우기 상세에서는 현재 채점 결과와 `채점 수정`을 보여준다. 빈칸 채우기는 하나 이상의 빈칸에 답했으면 이 행동을 제공하고, 객관식과 완전 미응답 문항에는 제공하지 않는다.
5. 사용자가 `채점 수정`을 선택하면 내 답과 정답 예시를 비교하고 현재 판정을 `정답` 또는 `오답`으로 변경한다. 서버가 반환한 전체 최신 결과를 받은 뒤에만 판정·점수·다시 풀 문제 수를 함께 교체한다.
6. 사용자가 수정한 단답형·빈칸 채우기에도 `채점 다시 수정`을 제공한다.
7. 한 화면에서는 수정 요청을 하나씩 보내며, 다른 화면이나 탭의 변경과 경합하면 마지막으로 서버에 커밋된 판정이 현재 값이다. 사용자는 결과 재조회로 최종 상태를 확인한다.
8. 결과에 복습할 문제가 있으면 사용자는 하단 primary `복습하기`로 같은 QuizSet의 복습을 즉시 시작하거나 활성 복습을 이어간다. secondary `홈으로`는 홈으로 이동한다.
9. 복습할 문제가 없으면 복습 완료 상태를 보여주고 `홈으로`를 제공하며 빈 복습 세션을 만들지 않는다.

### D-0. 학습 메인에서 복습할 퀴즈 선택

1. 시스템은 전역 최신 완료 `MAIN`의 QuizSet을 `최근 퀴즈`로 보여주고, 전용 복습 후보 조회로 그 QuizSet을 제외한 최대 3개를 불러온다.
2. 서버는 QuizSet별 최신 완료 `MAIN`에 미해결 문항이 있는 항목만 활성 복습 우선·최근 학습 활동 순으로 반환한다.
3. 항목에 미완료 서술형 채점이 있으면 `채점이 남았어요`, 그 밖에는 활성 복습 여부와 관계없이 `틀린 문제 복습하기`를 보여준다.
4. 사용자가 새 복습을 선택하면 후보의 `sourceAttemptId`로 세션 생성을 요청하고 E 흐름으로 이동한다.

### D-1. 같은 문제 세트 전체 다시 풀기

1. 학습 메인의 최근 퀴즈에서 `전체 문제 다시 풀기`를 선택하거나 `내 퀴즈`의 펼친 카드에서 `퀴즈 풀기`를 선택하면 시스템은 같은 QuizSet의 모든 문항을 풀이 전 공개 형식으로 다시 불러온다.
2. 사용자는 본 퀴즈 기본 흐름과 같은 방식으로 첫 문항부터 풀며, 이전 답안·판정·해설은 노출하지 않는다.
3. 최종 제출 전에는 새 회차를 만들지 않는다. 제출 시 새 attempt UUID를 사용해 기존 회차와 독립된 `MAIN` 회차를 만든다.
4. 이전 `MAIN` 회차와 복습 기록은 덮어쓰지 않는다. 새 회차가 완료되면 이후 복습의 기준은 이 QuizSet의 최신 완료 회차로 바뀐다.
5. 전체 재풀이 중 이탈·미응답·제출 실패와 복구는 본 퀴즈 기본 흐름을 그대로 따른다.

### E. 복습

1. 최근 퀴즈 또는 `복습할 퀴즈`에서 복습 진입 시 시스템은 선택한 QuizSet의 가장 최근 완료 본 퀴즈 회차의 미해결 문항 수와 그 회차를 원본으로 한 활성 review session을 확인한다. 이 행동은 같은 QuizSet 전체를 새 `MAIN` 회차로 푸는 `전체 문제 다시 풀기`와 구분한다.
2. 활성 세션이 있으면 그 세션의 고정된 문제 세트를 다시 불러온다. 이전 미제출 답안과 위치는 복원하지 않는다.
3. 활성 세션 없이 대상이 있으면 클라이언트가 전달한 `sourceAttemptId`가 선택한 QuizSet의 사용자 최신 완료 `MAIN`인지 서버가 다시 검증한 뒤 복습 세션을 만들고, 미해결 문항만 담긴 문제 세트를 원래 번호 오름차순으로 보여준다.
4. 사용자는 본 퀴즈와 같은 이전·다음 구조로 모든 대상 문항을 먼저 푼다. 문항 이동만으로 저장·채점하지 않는다.
5. 마지막에 복습 세션 전체 답안을 한 번 제출하고 객관식·빈칸·단답형을 일괄 채점한다.
6. 작성한 서술형이 있으면 제출 뒤 모범 답안·핵심 포인트·근거를 보고 본 퀴즈와 같은 방식으로 자기평가한다.
7. 모든 채점과 필요한 자기평가가 끝나면 `정답`은 해결, 그 밖의 판정은 미해결로 확정하고 이번 재풀이 결과를 보여준다. 원래 본 퀴즈 답안과 최초 판정은 바꾸지 않는다.
8. 활성 복습 세션이 만들어진 뒤 원본 회차의 단답형·빈칸 채우기 판정이 수정돼도 현재 세션의 문항 snapshot은 유지한다. 문항을 중간에 추가하거나 제거하지 않고, 변경된 복습 대상 여부는 다음 복습 세션부터 반영한다.
9. 복습 판정으로 원본 회차의 복습할 문제 수가 바뀌면 이후 결과 조회가 현재 해결 상태로 요약을 다시 계산한다.

## 분기

### 생성 화면에서 나가기

1. 사용자가 생성 중 뒤로가기를 하면 시스템은 생성이 서버에서 계속됨을 알리는 이탈 확인을 연다.
2. 머물기를 선택하면 오버레이로 돌아간다.
3. 나가기를 선택하면 이전 화면으로 이동하고 서버 생성은 계속된다.
4. 같은 자료에 다시 진입하면 [자료의 활성 생성 조회](../contracts/contract-api-quiz-learning.md#자료의-활성-생성-조회)로 `GENERATING` QuizSet을 재발견한다.
5. 활성 QuizSet이 있으면 그 `quizSetId`의 상태 조회를 재개하고, 없을 때만 새 생성 가능 상태를 보여준다.

### 본 퀴즈 이탈 후 재진입

1. 최종 제출 전 화면을 새로고침하거나 이탈하면 미제출 답안과 위치의 복구를 보장하지 않는다.
2. 사용자가 다시 진입하면 첫 문항부터 새로 푼다.
3. 제출 요청 중 연결이 끊겨도 현재 화면이 답안과 attempt UUID를 유지하면 같은 UUID로 명시적으로 다시 제출할 수 있다.
4. 화면 상태와 UUID를 잃었다면 기존 요청을 자동 탐색하거나 합치지 않고 다시 풀어 새 UUID로 제출한다.

### 서술형 자기평가 재진입

1. 최종 제출 뒤 자기평가를 끝내기 전에 이탈했다면 [미완료 서술형 자기평가 회차 조회](../contracts/contract-api-quiz-learning.md#미완료-서술형-자기평가-회차-조회)로 이미 생성된 `attemptId`와 남은 서술형 문항을 찾는다.
2. 복원 대상이 있으면 문제 번호가 가장 낮은 미평가 서술형부터 자기평가 화면을 복원한다.
3. 복원 대상이 없으면 현재 attempt와 결과 상태 또는 본 퀴즈 시작 가능 상태를 다시 확인한다.

### 복습 서술형 자기평가 재진입

1. review session 상태가 `SELF_ASSESSMENT_REQUIRED`이면 결과 조회의 저장된 답·모범 답안·핵심 포인트·해설·학습자료 본문 관련 부분으로 번호가 가장 낮은 미평가 서술형 화면을 복원한다.
2. 그 서술형 자기평가를 저장하기 전에는 다른 복습 문항으로 건너뛰지 않는다.

### 복습 대상 없음

1. 최근 완료한 본 퀴즈는 있지만 최신 회차의 복습할 문제 수가 0이면 모두 해결한 상태와 같은 QuizSet `전체 문제 다시 풀기`를 보여준다. 틀린 문제 풀이 행동은 만들지 않는다.
2. 최근 완료한 본 퀴즈가 없으면 아직 완료한 퀴즈가 없다는 빈 상태를 보여주고 학습 메인의 `새 문제 만들기`를 사용하게 한다.

## 중단과 재개

- 생성 상태 조회는 첫 3초 후, 이후 5초마다, 2분 뒤부터 10초마다 수행한다. 화면 이탈 시 조회만 중단하며 서버 생성을 취소하지 않는다.
- 본 퀴즈 최종 제출 전 상태는 열린 화면의 메모리에만 유지하며 지속 저장을 제품 요구사항으로 두지 않는다.
- 현재 화면이 살아 있는 제출 응답 유실에서는 같은 attempt UUID를 재사용할 수 있다. 화면 상태를 잃은 뒤에는 자동 복구하지 않는다.
- 서술형 자기평가는 서버 상태를 기준으로 다음 미평가 문항을 복원한다. 복습 풀이 재진입은 서버의 고정 문제 세트만 다시 불러오며 미제출 답안과 위치는 복원하지 않는다.

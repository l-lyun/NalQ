# [Screen Spec] 전역 UI 밀도 조정

> 기준 브랜치: `dev` (`b441bcdc`)
>
> 이 문서는 폰트 크기와 컴포넌트 높이를 일괄 축소하는 확정 규칙이 아니라, 실제 화면을 더 정돈되고 정보 밀도 높게 만드는 승인된 밀도 조정 기준이다. 제품 동작과 화면 진입·이탈은 바꾸지 않는다.
>
> 승인: 2026-09-06 사용자 검토 후 구현 요청. 기존 외형과 바깥 테두리를 유지하고 textStyle·공식 size·padding·gap·불필요한 최소 높이만 조정한다. 검토용 HTML 시안은 실제 앱 구현 기준이 아니며 CSS를 이식하지 않는다.

## 목표와 범위

- 모바일 한 화면에서 다음 행동과 그 판단 근거를 함께 파악할 수 있게 한다.
- 큰 제목, 반복되는 큰 버튼, 중첩된 넓은 간격 때문에 모든 정보가 같은 강도로 보이는 문제를 줄인다.
- 학습 본문, 문제, 오류 복구 문구의 읽기 크기와 터치 안전성은 유지한다.
- 홈, 학습, 퀴즈, 마이페이지, 인증의 공통 표현 기준과 화면별 적용 우선순위를 정의한다.
- API, 라우팅, 상태 모델, 기능 수, 전역 내비게이션 구조는 범위 밖이다.

### 결정 상태

- **확정된 요구**: 전반적인 글자·컴포넌트 높이·가시 정보량을 검토하고, 사용자 제공 당근 앱 화면을 비교 근거로 사용한다. 기존 컴포넌트의 바깥 테두리·색·두께·radius는 이번 변경에서 유지한다.
- **설계 가정**: 이번 변경은 모바일 WebView와 최상위 탭을 우선하며 기존 기능 순서, 상태 의미, 진입·이탈을 보존한다.
- **승인 범위**: 아래 타입 역할과 간격 조정을 기존 SEED 코드에 적용한다. 목록 평탄화, 외형 변경, 문구·기능·상태 전환 변경은 제외한다.
- **유지 조건**: 기존 주 CTA·모바일 입력·하단 내비게이션 크기는 유지한다. 정량 밀도 효과는 실측 전까지 수치로 주장하지 않는다.

## 근거와 한계

### 확인한 근거

- [NalQ 디자인 기준](../../DESIGN.md), 관련 홈·학습·복습·마이페이지 화면 명세, 현재 `web/src`의 SEED 조합과 CSS를 확인했다.
- 사용자 제공 당근 앱 캡처 5장을 시각 검토했다. 이 문서에서는 개인정보와 게시글 내용을 옮기지 않고 다음 역할로만 참조한다.
  - 레퍼런스 A: 계정·서비스 기능 화면
  - 레퍼런스 B: 텍스트 중심 피드
  - 레퍼런스 C: 이미지와 메타데이터가 있는 탐색 피드
  - 레퍼런스 D: 상세 정보와 하나의 고정 CTA가 공존하는 화면
  - 레퍼런스 E: 긴 본문·가격·메타데이터·결정 행동이 있는 상세 화면
- 캡처 원본은 1080×2340 이미지다. 기기 DPR, 접근성 글자 크기, 실제 CSS px는 알 수 없어 캡처에서 픽셀 수치를 역산하지 않았다.
- 사용자 제공 저장 HTML은 앱 캡처와 다른 당근 웹 랜딩이므로 앱 실제 수치의 증거로 쓰지 않았다. 다만 저장본의 `kr-BGYai7QQ.css`에서 콘텐츠 제목 selector `._62nozy1`이 기본 `t7`(20px), 넓은 화면 `t9`(24px), 행 제목 DOM이 `t5Regular`(16px), 메타 TagGroup이 `t4`(14px)인 구조를 확인했다. `._62nozy6`은 `x2`(8px) gap, `._62nozy3`은 `x6`(24px) row-gap, `._62nozya`는 120px 이미지와 `r1_5` radius를 사용한다. 같은 랜딩의 hero는 32px/38px로 커서 당근 화면 전체가 작다는 결론은 내리지 않는다.
- 저장본의 `global-GFvnOdRD.css`와 `GlobalNavigationBar-CNqKoDFA.css`에는 버튼 recipe `small` `x9`(36px)/`r2`(8px), `medium` `x10`(40px)/`r2`, `large` `x13`(52px)/`r3`(12px)가 있다. 이는 저장 웹 bundle의 recipe 존재 근거이며 캡처된 앱 버튼의 실측값은 아니다.
- 현재 SEED Docs와 Rootage 2.9.0에서 `Text`, `ActionButton`, `TextField`, `List` 및 typography·dimension·component recipe를 다시 확인했다.

### 레퍼런스에서 가져올 원리

- 제목과 본문의 크기 차이를 절제하고 굵기·색·배치로 위계를 보완한다.
- 반복 정보는 기존 카드·목록의 외곽 표현을 유지하면서 한 줄 메타데이터와 내부 간격으로 정리한다.
- 한 행 전체를 하나의 목적지로 만들고 행 안의 큰 버튼 반복을 피한다.
- 큰 CTA는 핵심 전환점에만 남긴다. 레퍼런스 A도 프로필과 주요 결제 행동에는 충분한 높이와 여백을 사용하므로 화면 전체를 작게 만드는 방식은 따르지 않는다.
- 레퍼런스 D와 E처럼 상세 읽기 화면의 제목·본문·결정 CTA에는 충분한 호흡을 남기고, 상태·시간·개수 같은 보조 정보만 더 촘촘히 묶는다.
- 기능 그룹, 카테고리 탭, 이미지 그리드는 NalQ의 기능 요구가 있을 때만 쓴다. 캡처의 기능 구조를 그대로 복제하지 않는다.

### 아직 확인하지 못한 것

- 현행 NalQ와 제안 시안의 동일 조건 전후 캡처 및 실제 가시 정보량 측정
- 사용자 제공 기기에서 Pretendard 렌더링, WebView 배율, 시스템 큰 글자 설정 결과
- 개별 화면의 최종 SEED props와 조립 방식. 이는 승인 후 TRD 또는 구현 단계에서 확인한다.

## 제안하는 정보 위계

아래 타입 역할은 사용자 승인에 따라 `DESIGN.md`와 함께 적용한다. 전환·온보딩·공개 랜딩의 display 역할과 읽기 본문은 일괄 축소하지 않는다.

| 역할 | 현재 기준 | 1차 제안 | 사용 규칙 |
| --- | --- | --- | --- |
| 최상위 화면 제목 | `t12Bold` | 모바일 `t9Bold`, 넓은 화면에서 `t10Bold` 검토 | 화면당 하나. 앱 바와 별도 대형 제목을 중복하지 않는다. |
| 주요 섹션 제목 | `t10Bold` | `t7Bold` | 독립된 사용자 과업 단위에만 사용한다. |
| 목록 그룹 제목 | `t8Bold` | `t6Bold` | 우측 보조 행동은 `small`/ghost 수준으로 둔다. |

| 날짜·개수·상태 메타데이터 | `t3~t4` | `t3Regular/Medium` | 가능한 한 한 줄로 묶고 의미 순서를 고정한다. |

| 퀴즈 상단 바 | 현행 56px 바와 44px 뒤로가기 타깃 유지 | 몰입 화면의 이탈 가능성과 터치 타깃을 보존한다. |

### 이번 범위에서 유지하는 선·색·표면·형태

| 요소 | 제안 | 이유 |
| --- | --- | --- |
| 기본 표면 | 현재 `bg.layerDefault`와 각 화면의 배경 역할 유지 | 이번 비교는 textStyle·size·spacing 변화만 평가한다. |
| 다음 행동·조용한 그룹 | 현재 배경색과 outer border 유무·색·두께 유지 | 내부 padding과 타입만 조정한다. |
| 반복 목록 | 현재 outer outline, divider, 배경 유지 | 외형 차이가 밀도 평가를 왜곡하지 않게 한다. |
| 선택 control | 현재 recipe의 outline과 selected background 유지 | control의 상태 인지를 바꾸지 않는다. |
| 텍스트 색 | 현재 제목·본문·메타데이터 색 역할 유지 | 이번 단계에서는 color hierarchy를 변경하지 않는다. |
| radius | 현재 SEED recipe와 custom component radius 유지 | radius 변경은 사용자 검토 후 별도 범위로 다룬다. |
| elevation | 현재 shadow 유무와 단계 유지 | 이번 단계에서는 elevation을 변경하지 않는다. |

시각 높이 36px 또는 40px인 작은 보조 control이 필요하면 실제 클릭 가능한 hitbox는 44px 이상을 확보하고 배경만 안쪽에 그리는 구조를 검토한다. 정확한 SEED 조립 방식은 구현 단계에서 확인한다.

## 화면별 적용 우선순위

### P0 — 홈과 학습 메인

- 화면 제목을 1차 제안 스케일로 낮추고 인사말·설명과 경쟁하지 않게 한다.
- 홈 인사말은 현재 `t7`(20px)에서 `t5Bold`(16px) 후보로 낮추고, 현재 24px top padding과 20px populated section stack은 과도한 값으로 간주하지 않는다.
- `다음 학습 행동 → 복습 → 최근 학습자료` 순서는 유지한다.
- 다음 행동은 현재 20px panel padding, 22px title, 52px CTA의 기능 구조를 유지하면서 title을 `t5/t6`, padding을 `x4` 중심으로 조정한다. 핵심 CTA를 작은 인라인 버튼으로 바꾸지 않는다.
- 기존 홈 목록은 이미 `List.Title` 16px, `List.Detail` 13px, divider와 행 전체 탭을 사용한다. 이 잘된 부분과 outer outline을 유지하고 26px 섹션 제목과 내부 간격만 우선 조정한다.
- `전체 보기`는 이미 small ghost이므로 크기를 더 줄이지 않고, 섹션 제목 옆 보조 행동이라는 현재 역할을 유지한다.
- 학습 메인의 `새 퀴즈`는 핵심 CTA이므로 크기를 유지하되, 같은 화면의 다른 행동은 시각 무게를 낮춘다.

### P0 — 퀴즈 생성·풀이·결과

- 생성 폼의 `x8` 구간을 `x6` 중심으로 줄이고 연속된 label·설명·control은 한 그룹으로 묶는다.
- 문제 본문 `t5` 이상, 답안 타깃, 44px 상단 행동은 유지한다. 문제를 작게 만들어 한 화면에 억지로 더 넣지 않는다.
- 이전/다음 중 현재 가능한 주 행동 하나만 solid로 강조하고, 부차 행동은 약한 variant로 둔다.
- 결과 요약 수치는 강하게 유지하되 설명과 메타데이터를 한 단계 낮춰 질문·오답 이유가 먼저 읽히게 한다.

### P1 — 마이페이지와 관리 목록

- 레퍼런스 A처럼 `계정 요약 → 계정 → 서비스 정보 → 탈퇴`의 과업 그룹은 유지한다.
- 각 그룹 안에서는 행 전체를 탭 대상으로 하고, 아이콘·제목·chevron을 한 행에 정렬한다.
- 기존 그룹과 카드 외형을 유지하면서 큰 제목의 반복과 그룹 내부 간격만 조정한다.
- 로그아웃과 탈퇴처럼 영향이 다른 행동은 색과 위치뿐 아니라 문구·확인 단계로 구분한다.

### P1 — 인증, 회원가입, 가져오기

- 모바일 입력 높이는 그대로 두고 페이지 제목, 필드 그룹 간격, 중복 안내를 먼저 줄인다.
- 이메일 전송·연결처럼 시간이 걸리는 상태 설명과 오류 복구 행동은 항상 보이게 한다.
- Bottom Sheet/Dialog의 큰 확인 버튼은 유지하되 같은 영역의 취소·도움 행동은 보조 크기로 검토한다.

### P1 — 알림 목록

- 알림 제목과 생성 상태·시간을 한 정보 묶음으로 정리하되 읽음 상태, 재시도, 결과 화면 이동은 현재 의미와 행동을 유지한다.

### P2 — 온보딩과 공개 랜딩

- 전환·설명 화면은 의도적으로 여유가 필요한 영역이므로 전역 축소를 그대로 적용하지 않는다.
- 제목 대비와 CTA 개수만 공통 기준으로 점검하고 이미지·메시지 호흡은 별도 화면 목적에 따라 유지한다.

## 진입과 이탈

- 기존 URL, 하단 탭, 뒤로가기, Dialog/Bottom Sheet의 닫기 동작은 변경하지 않는다.
- 최상위 홈·학습·마이페이지의 document scrolling과 탭별 스크롤 복원은 유지한다.
- 고정 하단 CTA가 필요한 화면은 탭·키보드·`spacingY.screenBottom`과 겹치지 않아야 한다.

## 사용자에게 보이는 상태

- 로딩: 실제 최종 밀도와 비슷한 행 수와 높이의 Skeleton을 사용해 레이아웃 점프를 줄인다.
- 빈 상태: 큰 빈 일러스트보다 원인, 다음 행동, 보조 설명 순서로 짧게 구성한다.
- 오류: 오류 제목·설명·재시도는 축소 대상에서 제외하고 한 묶음으로 유지한다.
- 성공: 기존 흐름이 화면 전환과 지속되는 성공 정보를 요구하는 경우 그 동작을 유지한다. 같은 화면에서 즉시 확인만 필요한 피드백에 한해 인라인 상태나 Snackbar 후보를 검토하며, 기존 성공 동작 변경은 이번 밀도 범위에서 제외한다.
- 비활성·권한 제한: 색만 흐리게 하지 않고 이유와 가능한 복구 행동을 가까이 둔다.
- 긴 콘텐츠: 긴 한글 제목, 이메일, 문제 문장은 잘리지 않고 행이 세로로 커져야 한다.

## 접근성과 반응형

- SEED scalable text style을 사용하고 고정 `Static` 타입으로 밀도를 만들지 않는다.
- 의미 있는 heading 순서는 시각 크기를 줄여도 `h1 → h2 → h3`로 유지한다.
- 커스텀 클릭 영역은 최소 44×44 CSS px, `focus-visible`, pressed, disabled 상태를 제공한다. SEED recipe의 자체 상호작용 영역은 임의 CSS로 잘라내지 않는다.
- 320px 소형 WebView와 430×932 모바일 기준에서 가로 스크롤이 없어야 한다.
- 긴 한글 2줄, 200% 브라우저 확대, 시스템 큰 글자에서 CTA와 오류 복구 문구가 잘리거나 겹치지 않아야 한다.
- `md` 이상에서도 읽기 열을 무작정 넓히지 않는다. 목록 탐색이나 비교가 실제로 유리할 때만 2열을 검토한다.
- safe area가 native shell에서 이미 소비된 경우 웹이 중복 적용하지 않는 현재 계약을 유지한다.

## 검증 계획과 수용 기준

1. 동일 fixture·계정·스크롤 위치에서 현행과 제안 구현을 320px, 430×932, `md` 너비로 각각 캡처한다.
2. 첫 화면에 완전히 보이는 의미 단위 수, 첫 핵심 CTA 위치, 제목·본문·메타데이터의 구분을 기록한다. 이번 초안은 전후 실측이 없으므로 증가율이나 성공 수치를 주장하지 않는다.
3. 홈, 학습 메인, 퀴즈 생성, 퀴즈 풀이, 결과, 마이페이지에서 다음을 확인한다.
   - 제목이 본문보다 크지만 화면의 대부분을 차지하지 않는다.

   - 한 과업 영역에 solid CTA가 둘 이상 경쟁하지 않는다.
   - 터치, 키보드 초점, 로딩, 빈 상태, 오류, 비활성, 권한 제한을 모두 사용할 수 있다.
4. 사용자 제공 캡처와 나란히 비교할 때는 절대 픽셀 크기보다 위계 비율, 메타데이터 압축, 큰 CTA의 사용 빈도를 평가한다. 기존 outer border의 색·두께·radius는 비교 변수가 아니다.

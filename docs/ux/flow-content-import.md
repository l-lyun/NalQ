# [Flow] 학습자료 만들기

- 관련 기능: [학습자료 만들기](../prd/prd-content-import.md)
- 공유 계약: [학습자료·퀴즈 API 계약](../contracts/contract-api-quiz-learning.md)

## 문서 책임

이 문서는 붙여넣기와 노션(Notion) 일회성 복사에서 저장까지의 순서, 취소와 실패 복구를 정의한다. 입력 정책은 기능명세가, HTTP 경계는 공유 계약이 책임진다. 사용자 화면에는 `노션`을 사용하고 API 경로·공개 오류 코드에는 기존 기술 식별자를 유지한다.

## 사용자 목표

가진 글을 확인·수정해 퀴즈를 만들 수 있는 학습자료로 저장한다.

## 시작 조건

- 로그인한 사용자가 홈의 새 학습 또는 학습 영역의 자료 추가를 선택한다.
- `/learning/materials`에서 `학습자료 추가하기`를 선택하면 현재 검색어·페이지·펼친 자료·스크롤 맥락을 유지한 채 `노션에서 가져오기`와 `직접 입력하기`를 고른다.
- 저장한 자료를 바꾸려는 사용자는 `/learning/materials`의 확장 카드에서 `학습자료 수정`을 선택한다.

## 완료 조건

- 사용자가 확인한 제목과 20,000자 이하 본문이 하나의 학습자료로 저장되고, 자료 상세 또는 퀴즈 생성 단계로 이동할 수 있다.
- 기존 자료 수정은 저장 성공 뒤 검색어·페이지·카드 펼침 맥락을 유지한 `내 학습자료` 목록으로 돌아가 갱신된 제목과 수정 시각을 확인하면 완료된다.

## 공통 저장 흐름

1. 사용자는 붙여넣기 또는 Notion 중 하나를 선택한다.
2. 프론트 편집 화면에서 제목과 본문을 확인한다. 노션에서 가져온 Markdown은 렌더링 미리보기 없이 편집 가능한 `Textarea` 원문으로 표시한다.
3. 사용자가 제목과 본문을 수정한다.
4. 시스템은 빈 제목·본문과 20,000자 제한을 확인한다. 제한을 충족하지 않으면 `저장하고 퀴즈 만들기`와 `자료 저장`을 모두 실행할 수 없게 하되 편집 내용은 보존한다.
5. 사용자가 두 행동 중 하나를 선택하면 현재 제목·본문을 같은 학습자료 생성 요청으로 한 번 전송한다.
6. `저장하고 퀴즈 만들기`의 저장이 성공하면 해당 학습자료가 선택된 퀴즈 생성 조건 화면으로 이동한다. `자료 저장`이 성공하면 저장된 학습자료 상세 화면으로 이동한다.

저장 전 편집 화면에서 앱 내부 뒤로 가기를 선택하면 미저장 내용이 사라짐을 확인하고 `이어서 편집`과 `저장하지 않고 나가기`를 제공한다. `이어서 편집`이 안전한 기본 행동이다. 브라우저 새로고침·탭 닫기에는 별도 이탈 경고나 복원을 약속하지 않는다.

목록에서 시작한 추가 흐름은 원래 `/learning/materials`의 query·page·expanded 맥락을 복귀 목적지로 전달한다. `자료 저장` 성공 뒤 새 자료 상세로 이동하고 상세 back은 그 목록 맥락으로 돌아간다. 저장 전 `저장하지 않고 나가기`도 같은 목록으로 돌아가며, `저장하고 퀴즈 만들기`는 목록 복귀 없이 새 자료가 선택된 퀴즈 생성 조건으로 이동한다.

## 학습자료 목록의 추가 진입

1. 사용자가 `/learning/materials`의 검색 위에 항상 보이는 `학습자료 추가하기`를 선택한다.
2. 시스템은 목록 위에 맥락 보존형 선택 패널을 열고 `노션에서 가져오기`, `직접 입력하기`만 제공한다. 목록 로딩·오류·전체 0건·검색 결과 0건도 이 행동을 막지 않는다.
3. 패널을 닫으면 검색어·페이지·펼친 자료·스크롤 위치를 유지하고 `학습자료 추가하기`로 탐색 맥락을 돌린다.
4. `노션에서 가져오기`는 `/learning/import/notion`, `직접 입력하기`는 `/learning/materials/new`의 공통 편집 흐름으로 이동한다.
5. 목록에는 별도 노션 연결 관리 행동을 두지 않는다. 연결과 접근 페이지 관리는 노션 페이지 선택 화면이 계속 책임진다.

`/learning/new`는 문제 만들기 의도로 기존 자료 또는 새 자료를 고르는 흐름을 유지한다. `/learning/materials`의 추가 진입은 자료 관리 의도로 기존 자료 선택을 건너뛰며 `/learning/new`를 중간 경유하지 않는다.

## 저장한 학습자료 관리·수정 흐름

1. 사용자가 학습 메인 `내 학습자료 전체 보기`로 `/learning/materials`에 진입한다.
2. 제목 검색과 페이지 이동으로 자료를 찾고 카드 헤더를 눌러 펼친다.
3. 바로 새 퀴즈를 만들려면 `퀴즈 만들기`를 선택해 해당 자료가 이미 선택된 생성 조건으로 이동한다.
4. 제목이나 본문을 바꾸려면 `학습자료 수정`을 선택해 `/learning/materials/:materialId`로 이동한다.
5. 시스템은 최신 상세와 본문 편집 가능 상태를 확인한다. 같은 자료의 QuizSet이 생성 중이면 제목만 편집 가능하고 본문 잠금 이유를 안내한다.
6. 사용자가 저장하면 기존 QuizSet·풀이·결과는 바뀌지 않고 이후 생성부터 최신 본문이 사용됨을 안내한다.
7. 저장 성공 후 이전 목록의 검색어·페이지·펼침 맥락으로 돌아가 갱신된 항목을 보여준다.

미저장 변경이 있는 상태에서 나가려 하면 `계속 편집`과 `변경사항 버리기`를 제공한다. 저장 실패에는 입력값을 유지한다. 상세 화면과 카드 상태는 [학습 화면 명세](screen-learning.md#2-내-학습자료)를 따른다.

## 붙여넣기 분기

1. 사용자가 일반 텍스트를 붙여넣는다.
2. 프론트는 텍스트를 즉시 편집 상태에 두고 서버 import·preview 요청을 만들지 않는다.
3. 사용자는 공통 저장 흐름으로 진행한다.

## Notion 분기

1. 사용자가 `/learning/import/notion`에 진입하면 프론트는 현재 사용자의 Notion 연결 상태를 확인한다.
2. 연결이 없다면 웹은 `노션으로 로그인해 주세요`를 안내하고, 사용자가 `노션 연결하기`를 선택하면 서버가 발급한 OAuth 승인 URL로 full-page redirect한다. OAuth는 등록된 `/learning/import/notion`으로 복귀한다. 성공이면 callback query를 제거하고 연결 상태를 다시 확인한 뒤 같은 route의 페이지 선택 상태로 전환한다. 취소·실패이면 query를 제거하고 같은 route의 연결 전 상태에서 다시 연결하거나 직접 입력할 수 있게 한다.
3. 재인증이 필요한 기존 연결이라면 같은 워크스페이스의 권한을 다시 승인한다. 재인증 전에 선택했던 `pageId`는 보존·복원하지 않으며 복귀 뒤 반드시 페이지를 다시 선택한다. 다른 워크스페이스로 바꾸려는 사용자는 먼저 [연결 해제와 워크스페이스 변경](#연결-해제와-워크스페이스-변경)을 완료한다.
4. 프론트는 연결된 워크스페이스에서 접근 가능한 페이지를 수정 시각 최신순 20개씩 조회하고, 처음 5개를 공개한 뒤 `더 보기`마다 이미 받은 목록에서 5개씩 추가한다. 받은 20개를 모두 공개했고 `nextCursor`가 있을 때만 다음 20개를 요청하며, 새 응답도 5개 단위로 공개한다.
   - 제목 검색은 마지막 입력 300ms 뒤 자동 실행하고 Enter 입력 시 즉시 실행한다. 별도 검색 버튼은 두지 않으며 검색어가 바뀌면 이전 선택·항목·cursor를 초기화하고 cursor 없는 새 검색의 첫 목록부터 다시 조회한다.
   - 사용자가 명시적인 목록 새로고침 버튼을 선택하면 기존 목록과 현재 검색어를 유지한 채 선택과 cursor를 초기화하고 첫 목록을 다시 조회한다. 성공 시 목록을 교체하고, 실패 시 기존 목록을 유지한다. pull-to-refresh는 제공하지 않는다.
   - MVP의 연결 관리 행동인 `접근 페이지 추가`, `다른 워크스페이스 연결`, `연결 해제`는 이 페이지 선택 화면에만 둔다. `다른 워크스페이스 연결`은 현재 연결 해제 흐름을 먼저 시작한다. 마이페이지 연동 관리 화면은 후속 범위다.
5. 목록은 일반 페이지와 데이터베이스의 개별 행 페이지를 포함하고 데이터베이스 자체는 제외한다. 하위 페이지는 상위 페이지 본문에 자동 포함하지 않고 각각 선택 가능한 페이지로 다룬다.
6. 현재 목록에 없는 페이지 접근을 추가하려면 사용자가 같은 워크스페이스 OAuth 승인을 다시 진행한다. 복귀 뒤 목록을 새로고침하고 페이지를 다시 선택한다. 검색에서 접근 페이지가 누락되면 Notion URL에서 page UUID를 추출해 같은 복사 요청을 사용할 수 있다.
7. 사용자는 페이지 행 하나를 선택하고 활성화된 `이 페이지 가져오기`를 명시적으로 실행한다. 행 선택만으로 가져오기를 시작하지 않으며, 같은 페이지를 이전에 가져왔는지는 선택 가능 여부에 영향을 주지 않는다. 제목이 없는 페이지는 목록에서 `제목 없는 페이지`로만 표시하고 가져오기를 허용하되 이 대체 문구를 저장 제목으로 사용하지 않는다.
8. 서버는 그 페이지의 최신 제목을 확인한 뒤 Markdown 본문을 순차 조회한다. 미디어 본체와 녹취는 제외하되 캡션·대체 텍스트는 유지하고, 불완전 표시가 있으면 추가 회수나 부분 결과 없이 실패한다.
9. 프론트는 빈 본문을 포함한 성공 응답만 별도 편집 화면의 새 상태로 전환한다. 이 시점에는 학습자료·import job·서버 draft가 없고 Notion URL과 `pageId`를 저장하지 않는다. 제목이 비어 있으면 제목 입력도 빈 상태로 두고 사용자가 유효한 제목을 입력하기 전까지 두 저장 행동을 비활성화한다.
10. 프론트는 제목을 정리한 결과가 1..255 code point이고 본문이 비공백 문자를 포함한 1..20,000 code point일 때만 두 저장 행동을 활성화한다. 조건을 충족하지 않으면 전체 편집 상태를 보존하고 공통 저장 흐름으로 진행하지 않는다.
11. 연결·재인증·목록·복사·해제 요청이 진행 중인 동안 해당 요청을 중복 시작할 수 있는 관련 버튼을 비활성화한다.

### 연결 해제와 워크스페이스 변경

1. 사용자가 현재 Notion 연결 해제를 선택한다.
2. 서버는 Notion 쪽 접근 권한을 먼저 철회한다.
3. 철회가 완료됐거나 이미 철회된 상태임을 확인하면 서버가 로컬 연결 정보를 삭제하고 연결 없음 상태를 반환한다. 해제 전에 시작한 미완료 OAuth 승인 흐름도 종료되며, 늦게 도착한 callback은 연결을 다시 만들지 않고 실패로 복귀한다.
4. 일시적 장애로 철회 완료를 확인할 수 없으면 현재 연결 정보를 유지하고 사용자가 해제를 다시 시도할 수 있게 한다.
5. 해제가 완료된 뒤 사용자는 OAuth 연결 흐름에서 다른 워크스페이스를 선택할 수 있다. 연결이 남아 있는 동안 다른 워크스페이스 OAuth가 완료되면 서버는 새 자격을 폐기하고 기존 연결을 유지하며 `NOTION_WORKSPACE_MISMATCH`로 구분한다.

| 조건 | 보존해야 할 정보 | 안내 | 복구 행동 |
| --- | --- | --- | --- |
| 저장 전 편집 화면에서 앱 내부 뒤로 가기 | 프론트 제목·본문 | 저장하지 않은 내용이 사라짐을 확인 | `이어서 편집` 또는 `저장하지 않고 나가기` |
| 빈 제목·본문·20,000자 초과 | 프론트 제목·본문 | 실행할 수 없는 두 저장 행동과 수정 이유 | 편집 후 원하는 저장 행동 선택 |
| `NOTION_CONNECTION_REQUIRED` | 선택한 입력 방식과 기존 편집 상태 | 연결이 없거나 유효한 OAuth 승인 흐름을 계속할 수 없다는 의미 | 연결 상태 재조회 후 `DISCONNECTED`면 최초 연결, `CONNECTED|REAUTH_REQUIRED`면 해당 승인 흐름을 처음부터 다시 시작하거나 붙여넣기로 전환 |
| `NOTION_REAUTH_REQUIRED` | 연결된 워크스페이스와 기존 편집 상태. 이전 `pageId`는 저장·복원하지 않음 | 현재 연결의 재인증이 필요하다는 의미 | 같은 워크스페이스 재인증 뒤 페이지를 다시 선택하거나 붙여넣기로 전환 |
| `NOTION_WORKSPACE_MISMATCH` | 기존 워크스페이스 연결과 편집 상태. 새 자격은 저장하지 않음 | 현재 연결을 둔 채 다른 워크스페이스를 승인했다는 의미 | 기존 연결을 계속 사용하거나, 현재 연결을 해제한 뒤 다른 워크스페이스 연결을 새로 시작 |
| `NOTION_PAGE_NOT_ACCESSIBLE` | 선택한 입력 방식, 기존 편집 상태와 접근 실패한 페이지 식별 정보 | 현재 권한으로 선택 페이지를 가져올 수 없다는 의미 | 다른 접근 가능 페이지 선택, Notion 권한 확인 또는 붙여넣기로 전환 |
| `NOTION_CONTENT_INCOMPLETE` | 선택한 페이지 식별 정보와 기존 편집 상태. 실패한 부분 본문은 보존하지 않음 | 완전한 텍스트 복사를 확인할 수 없어 가져오지 않았다는 의미 | 같은 페이지 재시도 또는 붙여넣기로 전환 |
| `NOTION_TEMPORARILY_UNAVAILABLE` | 현재 연결, 선택한 페이지 식별 정보와 기존 편집 상태 | Notion 작업을 일시적으로 완료할 수 없다는 의미 | 같은 연결·목록·복사·해제 행동 재시도 또는 붙여넣기로 전환 |
| OAuth 취소·callback 실패 | 입력 방식 선택 맥락. 아직 Notion 제목·본문 편집 상태는 없음 | 연결이 완료되지 않았다는 의미 | 입력 방식 선택으로 돌아가 OAuth 다시 시작 또는 붙여넣기 선택 |
| 저장 통신 실패 | 프론트 제목·본문 | 저장 여부를 확인하지 못했다는 의미 | 같은 저장 요청 재시도 |
| 중복 저장 응답 유실 | 프론트 제목·본문과 멱등 키 | 같은 자료를 새로 만들지 않음 | 같은 키로 재전송 |
| 기존 자료 수정 실패 | 수정 중인 제목·본문과 이전 목록 맥락 | 저장된 기존 자료는 유지됨을 안내 | 같은 수정 다시 시도 또는 입력을 버리고 목록 복귀 |

## 중단과 재개

- 붙여넣기와 Notion 복사 결과는 저장 전 프론트 편집 상태다. MVP는 서버 초안이나 만료 후 복구를 제공하지 않는다.
- 앱·웹 종료 뒤 미저장 편집을 복원한다고 약속하지 않는다.
- 브라우저 새로고침·탭 닫기는 별도로 가로채지 않는다. 앱 내부 뒤로 가기에서만 미저장 이탈을 확인한다.
- 웹 OAuth는 Notion 복사 결과를 편집 상태로 만들기 전에 시작하므로 redirect 전에 보존해야 할 Notion 제목·본문이 없다. OAuth 복귀 뒤 연결 상태와 첫 페이지 목록을 다시 조회하며, 이전 `pageId`도 저장하거나 선택 상태로 복원하지 않는다.
- callback 복귀 query는 결과 확인 직후 주소에서 제거한다. 성공은 페이지 선택, 취소·실패는 입력 방식 선택으로 이어지며 query 자체를 연결 상태로 보존하지 않는다.
- 네이티브 앱의 OAuth 외부 브라우저 복귀는 후속 범위다. 서버의 연결 상태·페이지 목록·복사 의미는 웹 전용 값에 의존하지 않는다.
- 저장 성공 뒤 본문은 편집할 수 있다. 같은 학습자료의 QuizSet이 `GENERATING`인 동안에만 본문 편집을 임시 차단하고, 생성이 `READY` 또는 `FAILED`로 끝나면 다시 허용한다. 생성 접수 이후 상태 확인과 복구는 [퀴즈 생성부터 복습까지](flow-quiz-solving.md)가 책임진다.

## 폐기된 흐름

- 로컬 파일 선택·파싱, import job 대기, `importId`로 preview 조회, 서버 draft 만료와 동기화 새로고침은 이번 MVP 흐름에 포함하지 않는다.

## 열린 질문

- 흐름의 열린 질문은 없다. 여섯 공개 오류 상태의 사용자 문구와 화면 내 배치, 입력 counter와 구체적인 화면 구성은 [노션 가져오기 화면 명세](screen-notion-import.md)가 책임진다.

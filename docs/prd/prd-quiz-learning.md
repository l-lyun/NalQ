## 문서 책임

이 문서는 학습자료로 퀴즈를 만들고, 풀고, 결과를 이해하고, 다시 볼 퀴즈를 찾아 복습하는 제품 정책과 성공 조건을 정의한다. 화면 간 중단·복구·분기는 관련 흐름이, HTTP 입출력·권한·상태·멱등성·오류는 공유 계약이 책임진다.

## 사용자 문제

사용자는 읽은 자료를 실제로 이해했는지 확인할 문제를 직접 만들기 어렵고, 단순 점수만으로는 무엇을 다시 봐야 하는지 알기 어렵다. 서술형은 기계가 임의로 점수를 확정하면 결과를 신뢰하기 어렵고, 틀린 문제를 다시 풀 기회가 없으면 결과 확인이 학습으로 이어지지 않는다.

## 목표

- 사용자가 학습자료에 근거한 퀴즈를 원하는 유형·난이도·최대 문제 수로 생성해 끝까지 풀 수 있다.
- 자동 채점 가능한 답과 서술형 자기평가를 구분해 결과를 이해할 수 있다.
- 사용자는 같은 문제 세트 전체를 새 본 퀴즈 회차로 다시 풀거나, 각 문제 세트에서 가장 최근에 완료한 본 퀴즈 회차의 미해결 문항만 다시 풀어 해결 상태로 바꿀 수 있다.
- 사용자는 학습 메인에서 최근 퀴즈와 별도로 복습할 퀴즈를 우선순위에 따라 찾아 바로 이어갈 수 있다.

## 성공 원칙

1. **근거 우선:** 질문·정답·해설은 학습자료에서 근거를 찾을 수 있어야 한다.
2. **정직한 진행 상태:** 생성 시간을 가짜 퍼센트로 포장하지 않고, 네트워크 문제와 생성 실패를 구분한다.
3. **평가 방식의 투명성:** 자동 채점과 서술형 자기평가의 범위가 다름을 실제 평가가 필요한 첫 서술형과 결과에서 알린다.
4. **학습 기록 보존:** 재생성·복습이 이전 문제 세트와 본 퀴즈 회차를 덮어쓰지 않는다.

## 범위

- 학습자료별 퀴즈 생성, 상태 확인과 실패 후 재시도
- OpenAI API를 사용한 첫 배포의 실제 문제 생성과 처리 안내
- 객관식, 빈칸 채우기, 단답형, 서술형 문제
- 한 문항씩 풀이하고 현재 화면에서 답안을 유지한 뒤 최종 일괄 제출
- 자동 채점과 서술형 자기평가
- 결과 요약, 문항별 판정·해설·학습자료 본문의 관련 부분
- 같은 문제 세트 전체 다시 풀기
- 각 QuizSet에서 가장 최근 완료한 본 퀴즈 회차의 미해결 문항 복습
- 학습 메인의 최근 퀴즈와 최대 3개의 복습할 퀴즈 진입
- 사용자가 소유한 퀴즈 목록의 제목 검색과 퀴즈 이름 변경
- 첫 서술형과 결과에서 평가·복습 방식 안내

## 비범위

- 로컬 파일 업로드
- 서버의 중간 풀이 초안 저장과 여러 기기 이어 풀기
- 새로고침·앱 종료 뒤 미제출 답안과 위치의 지속 복구 보장
- 문제의 Markdown, 코드, 표 렌더링
- 서술형 LLM 채점, 부분 점수 또는 자동 점수 반영
- 일일 생성·풀이 한도
- 과거 회차 선택과 여러 회차를 합친 누적 복습
- 경험치, 랭킹, 포인트 지급 정책
- 학습자료, 문제 세트와 풀이 결과의 친구 공유·공개 배포

## 확정 정책

### 생성 조건과 결과

- 사용자는 문제 유형을 하나 이상 선택한다. 유형은 `객관식`, `빈칸 채우기`, `단답형`, `서술형`이다.
- 난이도는 `쉬움`, `보통`, `어려움` 중 하나다.
- 최대 문제 수는 필수이며 `5`, `10`, `15`, `20` 중 하나다. UI의 초기 선택값은 `10`이지만 생성 요청에서 생략하지 않는다.
- 사용자는 출제 초점이나 스타일을 최대 300 Unicode code point의 추가 요청으로 선택 입력할 수 있다. 이 요청은 학습자료·문제 유형·문제 수·출력 구조·보안 규칙을 바꾸지 못하며 서버 DB와 로그에 저장하지 않는다.
- 서버는 선택한 유형과 최대 문제 수를 기준으로 유형별 선호 문항 수를 계산해 LLM에 명시한다. 유형별 가중치는 객관식 5, 단답형 3, 빈칸형 3, 서술형 2이며, 나머지 동률은 사용자가 선택한 순서로 배분한다. 특정 유형이 부족하면 선택된 다른 유형으로 보충할 수 있지만 선택하지 않은 유형은 추가하지 않는다.
- 최종 유효 문제가 요청 수의 80% 이상일 때만 생성 성공이다. 최소 성공 수는 각각 `4/8/12/16`이며, 기준에 달한 유효 문제만 저장한다.
- 첫 응답이 80%에 미달하면 부족한 선호 유형과 전체 문항 수를 기준으로 한 번 보완 생성한다. 보완에서도 선택된 다른 유형으로 부족분을 채울 수 있으며, 이후에도 미달하면 불완전한 문제 세트를 저장하지 않고 생성을 실패 처리한다.
- 외부 생성 결과는 저장 대상이 아니라 후보 목록이다. 서버는 후보가 제시한 문제 번호를 신뢰하지 않고 공통 정보와 유형별 상세 구조가 모두 유효한 후보만 원래 배열 순서대로 선택한다.
- 서버는 선택된 유효 후보에 최종 문제 번호 `1..N`을 새로 부여한다. 검증에서 제외된 후보는 공통 문제를 포함해 어떤 행도 남기지 않는다.
- 두 번의 정상 구조 응답이 모두 학습자료 근거 부족을 표시하고 최종 80%에 미달할 때 `SOURCE_INSUFFICIENT`다. 자료 부족과 모델 품질 문제가 애매하면 사용자 자료 탓을 하지 않고 `GENERATION_FAILED`로 처리한다.
- 같은 사용자는 학습자료와 관계없이 동시에 하나의 생성만 진행할 수 있다.
- 재생성은 허용한다. 매번 새로운 불변 문제 세트를 만들고 이전 문제 세트와 본 퀴즈 회차를 보존한다.
- 오답 선택지는 필요한 경우 일반 지식을 활용할 수 있다. 질문, 정답과 해설은 학습자료 근거가 필수다.

### OpenAI 처리와 책임 경계

- 첫 배포의 실제 문제 생성 공급자는 OpenAI API이며, 확인된 기본 model ID는 `gpt-5.6-luna`, reasoning effort는 `low`다. MVP는 고정 snapshot을 별도로 pin하지 않고 환경설정으로 model ID와 운영 제한을 바꾸며 서버 재시작 후 반영한다.
- OpenAI API에는 사용자가 선택한 학습자료 본문 전체, 문제 유형·난이도·최대 문제 수와 선택적 추가 요청만 전송한다. 추가 요청은 초점과 스타일 선호이며 학습자료·서버 생성 설정·보안 규칙이 우선한다. 본문 전체가 전송될 수 있음을 생성 직전에 투명하게 안내한다.
- 이메일, 닉네임, 비밀번호, 인증정보, 약관 동의정보와 사용자 풀이답안은 OpenAI 문제 생성 입력에 포함하지 않는다. 서술형을 포함한 사용자 답안은 OpenAI로 채점하지 않는다.
- OpenAI의 데이터 공유 opt-in을 사용하지 않는다. Responses API 요청은 `store: false`를 원칙으로 하며, 다른 endpoint나 기능을 선택하더라도 동일한 비저장 목적을 유지할 수 있는지 먼저 확인한다.
- Zero Data Retention 승인을 받지 않은 상태에서는 OpenAI가 전송 데이터를 즉시 삭제하거나 전혀 보관하지 않는다고 안내하지 않는다. 기본 abuse monitoring 과정에서 입력과 출력이 최대 30일 보관될 수 있음을 개인정보처리방침과 생성 직전 안내에 반영한다.
- NalQ는 사용자 의무를 이유로 책임을 포괄적으로 면제하지 않는다. 필요한 데이터만 전송하고 접근을 보호하며, 확정된 삭제 정책과 침해 신고 조치를 수행하고, 외부 생성 후보의 구조와 학습자료 근거를 검증한 뒤 유효한 결과만 저장한다.
- 생성된 문제와 해설에는 AI 생성 결과임을 알리고 원문과 함께 확인하도록 안내한다. 생성 결과가 항상 정확하거나 독창적이고 권리 침해가 없다고 보장하지 않는다.
- 국외 이전 국가·리전과 OpenAI 재위탁자 세부는 출시 전에 확정해 개인정보처리방침과 생성 직전 안내에 일관되게 반영한다.
- 첫 배포의 실제 문제 생성 공급자는 OpenAI API다. 실제 모델명과 갱신 정책은 출시 전에 확정한다.
- OpenAI API에는 사용자가 선택한 학습자료 본문 전체와 문제 유형·난이도·최대 문제 수를 전송한다. 본문 전체가 전송될 수 있음을 생성 직전에 투명하게 안내한다.
- 이메일, 닉네임, 비밀번호, 인증정보, 약관 동의정보와 사용자 풀이답안은 OpenAI 문제 생성 입력에 포함하지 않는다. 서술형을 포함한 사용자 답안은 OpenAI로 채점하지 않는다.
- OpenAI의 데이터 공유 opt-in을 사용하지 않는다. Responses API 요청은 `store: false`를 원칙으로 하며, 다른 endpoint나 기능을 선택하더라도 동일한 비저장 목적을 유지할 수 있는지 먼저 확인한다.
- Zero Data Retention 승인을 받지 않은 상태에서는 OpenAI가 전송 데이터를 즉시 삭제하거나 전혀 보관하지 않는다고 안내하지 않는다. 기본 abuse monitoring 과정에서 입력과 출력이 통상 최대 30일 보관될 수 있고, 법률상 의무나 서비스·제3자 보호에 합리적으로 필요한 경우 더 오래 보관될 수 있음을 개인정보처리방침과 생성 직전 안내에 반영한다.
- NalQ는 사용자 의무를 이유로 책임을 포괄적으로 면제하지 않는다. 필요한 데이터만 전송하고 접근을 보호하며, 확정된 삭제 정책과 침해 신고 조치를 수행하고, 외부 생성 후보의 구조와 학습자료 근거를 검증한 뒤 유효한 결과만 저장한다.
- 생성된 문제와 해설에는 AI 생성 결과임을 알리고 원문과 함께 확인하도록 안내한다. 생성 결과가 항상 정확하거나 독창적이고 권리 침해가 없다고 보장하지 않는다.
- 실제 모델명, 국외 이전 국가·리전과 OpenAI 재위탁자 세부는 출시 전에 확정해 개인정보처리방침과 생성 직전 안내에 일관되게 반영한다.

### 학습자료 잠금

- 생성 요청이 접수되는 순간부터 학습자료 본문을 잠근다.
- 같은 학습자료의 생성이 진행 중인 동안에만 본문 수정을 임시 차단한다. 생성이 성공 또는 실패로 끝나면 본문을 다시 수정할 수 있다.
- 제목은 생성 진행 여부와 관계없이 수정할 수 있다.
- 생성 중 잠금은 진행 중 작업이 참조하는 본문을 고정하기 위한 것이다. 학습자료를 나중에 수정해도 이미 생성된 문제 세트·풀이·결과는 바뀌지 않으며, 이후 새 문제 세트는 생성 접수 시점의 최신 저장 본문을 근거로 한다.

### 퀴즈 이름과 관리

- 사용자는 자신이 만든 퀴즈를 학습자료와 분리된 퀴즈 이름으로 식별한다.
- 퀴즈 이름은 부모 학습자료의 현재 제목과 별도 값이며, 학습자료 제목을 바꿔도 기존 퀴즈 이름은 자동으로 바뀌지 않는다.
- 퀴즈 목록에서 퀴즈 이름을 검색하고, 항목을 펼쳐 `퀴즈 이름 변경` 또는 `퀴즈 풀기`를 선택할 수 있다.
- `퀴즈 이름 변경`은 현재 제목을 채운 modal에서 수행하며, `퀴즈 풀기`는 같은 QuizSet의 모든 문항을 새 `MAIN` 회차로 시작한다. 기존 회차·결과·복습 기록은 덮어쓰지 않는다.
- 퀴즈 이름 변경은 생성 상태, 문제·정답, 풀이 회차, 결과와 복습 기록을 바꾸지 않는다.
- 목록의 최근 풀이·결과·복습·미완료 자기평가 맥락은 노출하지 않는다. 결과 확인과 복습·미완료 자기평가 진입은 학습 메인이 책임진다.
- 내 퀴즈 목록에는 `READY`와 현재 `GENERATING`인 QuizSet만 노출한다. `READY`에서 이름 변경과 새 풀이를 허용하고 `GENERATING`은 옅은 차단 overlay와 진행 표시 아래 두 행동을 비활성화한다. `FAILED` QuizSet은 서버에 유지하되 목록에서 제외하고 실패 결과와 복구 진입은 [퀴즈 생성 결과 알림](prd-quiz-generation-notifications.md)이 책임진다.
- 새 퀴즈의 기본 이름은 생성 접수 시점의 학습자료 제목 뒤에 ` 퀴즈`를 붙인 `{학습자료명} 퀴즈`다. 255 Unicode code point를 넘으면 학습자료 제목 부분만 앞에서부터 줄여 ` 퀴즈` 접미사를 보존한다.
- 기존 QuizSet도 전환 migration 시점에 연결된 학습자료 제목으로 같은 규칙을 적용해 backfill한다. 이후 학습자료 제목이 바뀌어도 퀴즈 이름은 자동으로 바뀌지 않는다.

### 생성 경험

- 생성 중에는 현재 작업이 명확한 차단형 오버레이를 보여주고, 완료 여부를 알 수 없는 진행 표시를 사용한다. 가짜 퍼센트는 표시하지 않는다.
- 뒤로가기는 생성 취소가 아니라 이탈 확인을 연다. 사용자가 명시적으로 나가면 화면 이탈을 허용하되 서버 생성은 계속한다.
- 사용자가 다시 진입하면 서버 상태를 기준으로 생성 중·성공·실패를 복원한다.
- 서버는 선택 유형·난이도·최대 문제 수를 생성 조건 이력으로 보존하지 않는다. 프론트는 생성 POST에 사용한 조건을 응답의 `quizSetId`와 연결해 같은 사용자·기기의 로컬 상태에 보존하고 생성 중·성공 화면에서 사용한다.
- 로컬 생성 조건이 없더라도 상태 복원을 막지 않는다. 생성 중에는 일반 진행 상태를 보여주고, 성공 뒤 실제 문제 수와 포함 유형은 생성된 문제에서 계산하며, 실패에는 일반 실패 안내와 새 조건 선택 행동을 제공한다.
- 네트워크 통신 실패와 서버에서 확정된 생성 실패를 서로 다른 상태와 복구 행동으로 안내한다. 세부 분기와 조회 간격은 [퀴즈 흐름](../ux/flow-quiz-solving.md#생성-중단과-복구)이 책임진다.
- 생성 화면 밖의 전역 감시, foreground 복귀, 알림 목록과 Snackbar는 [퀴즈 생성 결과 알림 PRD](prd-quiz-generation-notifications.md)를 따른다.

### 문제 유형

| 유형 | 문제 규칙 | 평가 규칙 |
| --- | --- | --- |
| 객관식 | 보기 3개 이상 5개 이하, 단일 정답 | 선택한 보기와 정답 보기를 서버가 비교하며 사용자가 판정을 수정하지 않음 |
| 빈칸 채우기 | 빈칸 1개 또는 2개, 텍스트와 식별 가능한 빈칸이 순서대로 이어지는 문장 | 각 빈칸 답을 정답 기준과 비교하고, 답을 하나 이상 작성한 사용자는 결과에서 판정을 수정할 수 있음 |
| 단답형 | 짧은 일반 텍스트 응답 | 서버가 허용 답안과 규칙 기반으로 먼저 비교하고, 답을 작성한 사용자는 결과에서 판정을 수정할 수 있음. Unicode NFC·Unicode 공백의 ASCII 공백 변환/축약과 앞뒤 제거·언어 독립 소문자 변환만 적용하며 LLM이나 의미 유사도 판정을 사용하지 않음 |
| 서술형 | 일반 텍스트 응답, 모범 답안과 핵심 포인트 제공 | 사용자가 `정답`, `보완 필요`, `오답`으로 자기평가. 저장값은 `PARTIAL`을 유지한다. 자동 점수에서 제외 |

- 문제 본문은 MVP에서 일반 텍스트만 지원한다.
- 각 문제는 결과와 복습에서 같은 학습 주제를 식별할 수 있는 간결한 주제명을 가진다.
- 풀이 전에는 정답, 허용 답안, 모범 답안, 핵심 포인트, 해설과 학습자료 본문의 관련 부분을 노출하지 않는다.
- 서술형에는 부분 점수를 부여하지 않는다. API의 `PARTIAL`은 복습 대상을 정하는 학습 상태이지 점수가 아니다. 화면 권장 문구 `보완 필요`의 최종 승인은 [퀴즈 피드백 화면](../ux/screen-quiz-feedback.md#요구사항-구분)이 책임진다.

### 본 퀴즈 풀이와 제출

- 이미 완료한 문제 세트도 다시 풀 수 있다. `전체 문제 다시 풀기`는 같은 QuizSet의 모든 문항을 처음부터 보여주며, 최종 제출 시 이전 회차를 덮어쓰지 않고 새 `MAIN` 회차를 만든다.
- `전체 문제 다시 풀기`와 복습은 서로 다른 행동이다. 전자는 같은 QuizSet 전체를 새 회차로 풀고, 후자는 해당 QuizSet의 가장 최근 완료 `MAIN` 회차에서 미해결 문항만 별도 복습 세션으로 푼다.
- 한 화면에 한 문항을 보여주며 사용자는 이전·다음 문항으로 이동할 수 있다.
- 서버는 최종 제출 전의 현재 위치와 답안을 저장하거나 알지 못한다.
- 최종 제출 전 답안과 현재 위치는 열린 풀이 화면의 메모리 상태로만 유지한다. 새로고침·앱 종료·다른 기기 재진입 뒤 복구를 MVP 요구사항으로 두지 않는다.
- 풀이 중 이탈하려 하면 미제출 답안이 사라지고 다시 풀어야 함을 안내한다.
- 본 퀴즈는 마지막에 한 번에 제출하고, 이때만 불변 본 퀴즈 회차를 만든다.
- 본 퀴즈 회차 식별자는 최종 제출 직전에 클라이언트가 생성한 UUID v4를 사용한다. 현재 화면이 같은 식별자를 유지하는 동안의 재요청은 새 회차를 만들지 않고 먼저 확정된 회차를 반환한다.
- 연결 단절이나 새로고침으로 답안과 UUID를 잃으면 복구를 보장하지 않는다. 사용자는 다시 풀어 새 UUID로 제출할 수 있으며, 서로 다른 UUID의 같은 답안을 서버가 중복으로 추정해 합치지 않는다.
- 제출 시 미응답 문항이 있으면 경고한다. `남은 문제 풀기`는 번호가 가장 낮은 미응답 문항으로 이동하며, 사용자는 미응답을 남긴 채 제출할 수도 있다.
- 제출에서 빠진 응답은 미응답 오답으로 확정한다. 미응답을 별도 성과 범주로 만들지 않는다.

### 채점 수정과 서술형 자기평가

- 객관식·빈칸·단답형은 최종 제출 시 서버가 일괄 자동 채점한다.
- 객관식 판정은 서버 채점 결과로 확정하며 사용자가 수정할 수 없다.
- 단답형 자동 판정은 문제에 저장된 허용 답안 각각과 정규화한 사용자 답이 완전히 같은지만 비교한다. 정규화는 Unicode NFC, Unicode 공백 변환·축약과 앞뒤 제거, 언어 독립 소문자 변환만 수행한다. 구두점 제거, 번역, 약어 확장, 오타·의미 유사도 보정과 LLM 판정은 하지 않는다. 예를 들어 허용 답안이 `fifo` 하나라면 `FIFO`는 자동 정답이지만 `선입선출`, `first in first out`은 의미가 같더라도 자동 오답이다. 해당 표현이 허용 답안 목록에 함께 저장돼 있으면 자동 정답이다.
- 답을 작성한 단답형과 빈칸 채우기는 서버 자동 판정을 초기값으로 사용하되, 사용자가 결과 상세에서 `정답` 또는 `오답`으로 수정할 수 있다. 빈칸 채우기는 일부 빈칸이라도 답을 작성했으면 수정할 수 있고, 완전 미응답 단답형·빈칸 채우기는 수정할 수 없다.
- 서버의 최초 자동 판정은 불변으로 보존한다. 사용자가 단답형·빈칸 채우기 판정을 수정하면 최신 사용자 판정이 해당 문항의 현재 채점 결과가 되며, 채점 점수와 다시 풀 문제 수도 현재 판정으로 함께 다시 계산한다.
- 단답형·빈칸 채우기 채점 결과는 다시 수정할 수 있다. 저장에 실패하면 변경 전 판정과 요약을 유지한다.
- MVP에서는 단답형·빈칸 채우기 사용자 수정 이력 전체를 만들지 않는다. 최초 자동 판정과 최신 사용자 판정만 보존한다.
- 자동 채점 판정 수정은 원하는 현재 판정을 저장하는 `PUT`이며 마지막으로 커밋된 요청을 현재 값으로 사용한다. 별도 멱등 키, 공개 revision과 충돌 해결 UI를 두지 않는다.
- 사용자 수정은 해당 사용자의 해당 본 퀴즈 회차에만 적용한다. 문제의 허용 답안이나 다른 사용자의 결과에는 전파하지 않는다.
- 작성한 서술형이 하나라도 있으면 자동 채점 결과와 함께 문항별 자기평가를 요구한다.
- 서술형 자기평가 화면은 내 답, 모범 답안, 핵심 포인트, 해설과 `학습자료 본문`이라는 제목의 관련 excerpt를 제공한다.
- 작성한 서술형은 문항별 자기평가를 저장하고 마지막 평가 후 본 퀴즈 회차를 완료한다.
- 미응답 서술형은 자동으로 `오답`이 되며 별도 자기평가 없이 복습 대상에 포함한다.
- 객관식·빈칸·단답형만 채점 점수의 분자·분모에 포함한다. 단답형·빈칸 채우기 사용자 수정이 있으면 수정 판정을 분자 계산에 사용하고 서술형은 포함하지 않는다.

### 결과

- 결과는 단답형·빈칸 채우기의 현재 판정을 포함한 `채점 점수`, `서술형 자기평가 요약`, `다시 풀 문제 수`를 구분해 보여준다.
- 요약 아래에 모든 문항을 원래 번호 오름차순으로 보여준다.
- 문항을 선택하면 풀이 화면을 결과 읽기 모드로 재사용한다. 비활성 입력 폼처럼 보이게 하지 않고 `내 답`, `정답 또는 모범 답안`, `판정`, `해설`, `학습자료 본문`을 읽는 구조로 제공한다. `학습자료 본문`은 전체 자료가 아니라 문제와 관련된 source excerpt다.
- 답을 작성한 단답형·빈칸 채우기 상세에는 현재 판정을 보여주고 `채점 수정`을 제공한다. 수정 뒤에도 `채점 다시 수정`을 제공한다.
- 해당 결과가 같은 QuizSet의 최신 완료 `MAIN`이고 다시 풀 문제가 하나 이상 있거나 그 회차의 활성 복습이 있으면, 하단의 주 행동 `복습하기`로 복습을 즉시 시작하거나 이어가고 보조 행동 `홈으로`로 홈에 이동한다. 과거 `MAIN` 결과에서는 남아 있는 당시의 문제 수와 관계없이 `복습하기`를 노출하지 않는다. 최신 결과에도 복습 대상과 활성 세션이 모두 없으면 불가능한 복습을 시작하지 않고 완료 안내와 `홈으로`를 제공한다.
- 미응답 요약은 별도로 만들지 않는다. 미응답은 오답과 복습 수에 포함한다.

### 복습

- 한 QuizSet의 `틀린 문제 다시 풀기`는 그 QuizSet에서 가장 최근에 완료한 본 퀴즈 회차 하나의 미해결 문항만 대상으로 한다. 과거 회차를 선택하거나 여러 회차를 합치지 않는다.
- 객관식의 서버 오답과 미응답, 단답형·빈칸 채우기의 반영 판정이 오답인 문항과 미응답, 서술형의 `PARTIAL`(`보완 필요`)과 `오답`이 복습 대상이다.
- 복습 문항은 원래 번호 오름차순으로 제공한다.
- 복습을 시작하면 서버에 별도 복습 세션을 만든다. 원래 본 퀴즈 회차와 판정은 바꾸지 않는다.
- 활성 복습 세션은 생성 시점의 문항 snapshot을 유지한다. 세션이 시작된 뒤 원본 회차의 단답형·빈칸 채우기 판정이 수정돼도 진행 중인 문항을 추가하거나 제거하지 않고, 수정된 복습 대상 여부는 다음 복습 세션부터 반영한다.
- 복습도 본 퀴즈처럼 모든 대상 문항을 먼저 풀고 마지막에 한 번 제출한다. 제출 전에는 문항별 정오답·해설·모범 답안을 공개하지 않는다.
- 복습 제출 뒤 객관식·빈칸·단답형을 일괄 자동 채점하고, 작성한 서술형이 있으면 본 퀴즈와 같은 자기평가 흐름을 진행한다.
- 맞거나 서술형을 `정답`으로 평가하면 `해결`, 그 밖에는 `미해결`이다.
- 한 복습 세션의 채점에서 다시 틀린 문항은 같은 세션에서 재출제하지 않고 다음 복습에 남긴다.

### 학습 메인의 최근 퀴즈와 복습 목록

- 학습 메인은 `최근 퀴즈` → `새 문제 만들기` → `복습할 퀴즈` → `내 퀴즈 전체 보기` → `내 학습자료 전체 보기` 순서로 다음 학습 행동과 관리 진입점을 제공한다.
- `최근 퀴즈`는 현재 사용자가 가장 최근에 완료한 본 퀴즈 회차의 QuizSet 하나다. 이 QuizSet은 아래 `복습할 퀴즈` 목록에서 중복 노출하지 않는다.
- 최근 퀴즈에는 같은 QuizSet 전체를 새 회차로 시작하는 `전체 문제 다시 풀기`와 현재 상태에 맞는 맥락 행동을 함께 제공한다.
- 최근 퀴즈의 맥락 행동은 미완료 서술형 채점이 있으면 `채점이 남았어요`, 활성 복습 세션 또는 새로 복습할 미해결 문항이 있으면 `틀린 문제 복습하기`, 복습 대상이 없으면 `결과 보기`다. 미완료 서술형 채점은 복습 행동보다 우선한다.
- `복습할 퀴즈`는 최근 퀴즈를 제외한 QuizSet 중, 각 QuizSet의 최신 완료 `MAIN` 회차에 미해결 문항이 하나 이상 남은 항목을 최대 3개 보여준다. 현재 미해결 문항이 0개가 되면 목록에서 제거한다.
- 복습 목록은 활성 복습 세션이 있는 QuizSet을 먼저 보여주고, 그 안과 나머지 항목은 가장 최근 학습 활동 순으로 정렬한다. 같은 시각에는 `quizSetId` 오름차순으로 안정 정렬하며 QuizSet 이름 변경 시각은 학습 활동 순서에 사용하지 않는다.
- 복습 목록 항목에도 미완료 서술형 채점이 있으면 복습보다 `채점이 남았어요`를 우선하고, 그 외에는 `틀린 문제 복습하기`를 제공한다.
- `내 퀴즈 전체 보기`와 `내 학습자료 전체 보기`는 메인 안의 미리보기 목록이 아니라 각각의 전체 관리 화면으로 이동하는 낮은 위계의 진입 행이다.

### 안내

- 로그인 전 공개 랜딩은 가입 전 가치 설명만 책임지며 자동 채점·서술형 자기평가와 복습 정책을 안내하지 않는다.
- [첫 진입 온보딩과 NalQ 가이드](../ux/screen-onboarding.md)의 2장은 문제 유형·난이도·문제 수를 고르는 학습 통제감만 안내하고 채점·자기평가 정책을 대신 설명하지 않는다.
- 사용자가 실제 첫 서술형에 도달하면 모범 답안·핵심 포인트를 보고 스스로 평가하는 방식과 자동 점수 제외를 안내한다.
- 결과에서 자동 채점 점수와 서술형 자기평가를 구분하고, 복습 대상의 기준과 복습하면 해결 상태가 갱신되는 방식을 안내한다.

## 수용 기준

- [ ] 사용자는 네 유형 중 하나 이상, 세 난이도 중 하나, 최대 5·10·15·20문제 중 하나와 선택적 300자 추가 요청을 생성 조건으로 보낼 수 있고 초기 선택값 10도 요청에 명시된다.
- [ ] 첫 배포의 실제 문제 생성은 OpenAI API를 사용하고, 자료별 최초 생성 또는 재확인이 필요한 시점에 전송 항목·제외 항목과 기본 abuse monitoring 최대 30일 가능성을 확인할 수 있다.
- [ ] OpenAI 요청에는 해당 학습자료 본문과 생성 조건만 포함되고 이메일·닉네임·비밀번호·인증/동의정보·풀이답안은 포함되지 않는다.
- [ ] OpenAI 데이터 공유 opt-in을 사용하지 않고 Responses API 요청은 `store: false`로 수행하며, Zero Data Retention 미승인 상태를 즉시 삭제·무보관으로 표시하지 않는다.
- [ ] 각 생성 문제와 해설이 AI 생성 결과임을 확인할 수 있고 중요한 학습 내용은 원문과 함께 검토하도록 안내된다.
- [ ] 유효 문제가 요청 수의 80% 이상일 때만 성공하고, 첫 응답이 미달하면 부족한 유형을 한 번 보완한 뒤 최종 미달 시 빈 문제 세트를 노출하지 않고 실패한다.
- [ ] 사용자당 `GENERATING` QuizSet은 학습자료와 관계없이 하나만 존재한다.
- [ ] 사용자는 네 유형 중 하나 이상, 세 난이도 중 하나, 최대 5·10·15문제 중 하나를 선택해 생성을 요청할 수 있고 초기 선택값 10도 요청에 명시된다.
- [ ] 유효 문제가 1개 이상이면 선택 유형 일부가 빠지거나 최대값보다 적어도 성공하며, 유효 문제가 0개일 때만 빈 문제 세트를 노출하지 않고 실패한다.
- [ ] 첫 배포의 실제 문제 생성은 OpenAI API를 사용하고, 자료별 최초 생성 또는 재확인이 필요한 시점에 전송 항목·제외 항목과 기본 abuse monitoring의 통상 최대 30일 및 예외적 장기 보관 가능성을 확인할 수 있다.
- [ ] OpenAI 요청에는 해당 학습자료 본문과 생성 조건만 포함되고 이메일·닉네임·비밀번호·인증/동의정보·풀이답안은 포함되지 않는다.
- [ ] OpenAI 데이터 공유 opt-in을 사용하지 않고 Responses API 요청은 `store: false`로 수행하며, Zero Data Retention 미승인 상태를 즉시 삭제·무보관으로 표시하지 않는다.
- [ ] 각 생성 문제와 해설이 AI 생성 결과임을 확인할 수 있고 중요한 학습 내용은 원문과 함께 검토하도록 안내된다.
- [ ] 외부 후보의 문제 번호와 무효 후보를 저장하지 않고, 유효 후보만 원래 배열 순서대로 `1..N` 번호를 부여해 빈 번호 없이 제공한다.
- [ ] 객관식은 단일 정답과 3~5개의 보기가 있을 때만 유효하며 풀이·결과 화면은 세 길이를 모두 처리한다.
- [ ] 생성 접수부터 해당 생성이 성공 또는 실패로 끝날 때까지만 본문이 잠기며, 생성 중에도 제목은 수정할 수 있다.
- [ ] 생성 종료 후 학습자료 본문을 수정해도 기존 문제 세트·풀이·결과는 바뀌지 않고 이후 생성부터 최신 저장 본문이 사용된다.
- [ ] 퀴즈 목록과 복습 요약에서 퀴즈 이름과 부모 학습자료명이 서로 다른 정보로 표시된다.
- [ ] 사용자는 퀴즈 이름으로 목록을 검색하고 카드를 펼쳐 modal에서 이름을 변경할 수 있으며, 변경 결과가 홈·학습·풀이 맥락에 일관되게 반영된다.
- [ ] `READY` 카드의 `퀴즈 풀기`는 같은 QuizSet의 새 `MAIN` 회차를 시작하며 기존 회차·결과·복습 기록을 유지한다.
- [ ] 내 퀴즈 목록에는 최근 풀이·결과·복습·미완료 자기평가 행동이 나타나지 않고, 해당 행동은 학습 메인에 유지된다.
- [ ] `GENERATING` 카드는 상태 overlay 아래 이름 변경과 풀이 행동이 비활성화되고, `FAILED` QuizSet은 서버에 남지만 내 퀴즈 목록에서 제외되어 알림에서 실패와 복구 행동을 확인할 수 있다.
- [ ] 생성 화면을 나가도 작업은 계속되고, 재진입 시 네트워크 오류와 서버 생성 실패가 구분된다.
- [ ] 같은 사용자·기기에서는 생성 요청 조건을 `quizSetId`와 연결한 로컬 값으로 생성 중·성공 화면에 복원하고, 로컬 값이 없어도 서버 상태와 실제 문제 목록만으로 각 화면을 표시할 수 있다.
- [ ] 풀이 전에 어떤 유형에서도 정답·해설·학습자료 본문의 관련 부분이 노출되지 않는다.
- [ ] 서버에는 최종 제출 전 중간 답안이 생기지 않으며, 새로고침·앱 종료 뒤 미제출 답안 복구를 보장하지 않고 다시 풀기를 허용한다.
- [ ] 같은 QuizSet의 `전체 문제 다시 풀기`는 모든 문항을 처음부터 제공하고 최종 제출 시 기존 회차를 덮어쓰지 않는 새 `MAIN` 회차를 만든다.
- [ ] `전체 문제 다시 풀기`와 각 QuizSet 최신 완료 회차의 복습은 진입 문구와 대상 범위가 명확히 구분된다.
- [ ] 현재 화면이 같은 client-generated attempt UUID를 유지하는 동안의 제출 재시도는 새 회차를 만들지 않는다. UUID를 잃고 새 UUID로 다시 제출한 회차를 서버가 합치지는 않는다.
- [ ] 미응답 제출 경고에서 가장 낮은 미응답으로 이동하거나 그대로 제출할 수 있고, 제출한 미응답은 오답·복습 대상에 포함된다.
- [ ] 객관식은 서버 판정만 사용하고, 답을 작성한 단답형·빈칸 채우기는 결과 상세에서 판정을 양방향으로 다시 수정할 수 있다.
- [ ] 단답형·빈칸 채우기 판정 수정 뒤에는 수정한 판정이 현재 채점 결과가 되고, 저장 성공 후 채점 점수와 다시 풀 문제 수가 함께 갱신된다.
- [ ] 활성 복습 세션을 시작한 뒤 원본 단답형·빈칸 채우기 판정을 수정해도 진행 중 문항 snapshot은 바뀌지 않고, 변경된 복습 대상 여부는 다음 세션부터 반영된다.
- [ ] 작성한 서술형이 있으면 문항별 자기평가 후 완료되며, 서술형은 자동 점수와 부분 점수에 포함되지 않는다.
- [ ] 결과는 모든 문항을 번호 오름차순으로 제공하고, 각 문항에서 내 답·정답/모범 답안·판정·해설·`학습자료 본문`을 확인할 수 있다.
- [ ] 결과에 다시 풀 문제가 있으면 같은 결과 화면 하단의 `복습하기`로 학습 메인을 경유하지 않고 복습을 시작하거나 이어갈 수 있고, `홈으로`로 홈에 이동할 수 있다.
- [ ] 복습은 선택한 QuizSet에서 가장 최근 완료한 회차의 미해결 문항만 번호순으로 제공하고, 모든 문항을 제출한 뒤 일괄 채점하며 원본 회차의 답안·최초 판정은 변경하지 않는다.
- [ ] 학습 메인은 `최근 퀴즈` → `새 문제 만들기` → `복습할 퀴즈` → `내 퀴즈 전체 보기` → `내 학습자료 전체 보기` 순서로 표시한다.
- [ ] 최근 퀴즈는 복습 목록에서 제외되고, 복습 목록은 미해결 문항이 있는 QuizSet만 최대 3개까지 활성 복습 우선·최근 학습 활동 순으로 표시한다.
- [ ] 최근 퀴즈와 복습 목록에서 미완료 서술형 채점은 복습보다 우선하며, 상태에 따라 `채점이 남았어요`, `틀린 문제 복습하기`, `결과 보기` 중 관찰 가능한 다음 행동을 제공한다.
- [ ] 공개 랜딩과 온보딩 2장에 채점 정책을 선행 노출하지 않고, 실제 첫 서술형과 결과에서 자동 채점·자기평가·복습 방식을 사용 시점에 맞게 확인할 수 있다.

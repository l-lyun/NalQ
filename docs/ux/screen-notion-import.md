# [Screen Spec] 노션 학습자료 가져오기

## 문서 정보

- 화면명: 노션 연결·페이지 선택, 가져온 학습자료 확인·편집
- 문서 상태: `review`
- 대상 플랫폼: 모바일 웹·WebView
- 관련 기능: [학습자료 만들기](../prd/prd-content-import.md)
- 관련 흐름: [학습자료 만들기](flow-content-import.md)
- 공유 계약: [학습자료·퀴즈 API](../contracts/contract-api-quiz-learning.md)
- 시각 기준: [OpenMD Design System](../../DESIGN.md)
- 최종 수정일: 2026-09-02

## 요구사항 구분

### 확정 사항

- 노션 연결 안내와 연결된 페이지 선택은 하나의 화면에서 연결 상태에 따라 전환한다.
- 사용자에게 보이는 브랜드 명칭은 제목·설명·버튼·오류에서 모두 `노션`으로 쓴다. `NOTION_*` 오류 코드, API와 환경 변수 같은 기술 식별자만 영문을 유지한다.
- 연결 전에는 `노션에서 가져오기` 화면 제목, `노션으로 로그인해 주세요` 안내 제목과 연결 필요·비동기화 설명을 보여주고 `노션 연결하기`, `직접 입력하기`를 제공한다. 직접 입력은 공통 편집 화면의 빈 상태로 이동한다.
- OAuth 취소로 복귀하면 연결 전 화면에 `노션 연결을 취소했어요.`를 인라인으로 표시하고 `다시 연결하기`, `직접 입력하기`를 제공한다. 실패 복귀도 같은 위치에서 공개 오류 코드에 맞는 안내와 복구 행동을 제공한다.
- 사용자가 페이지 행 하나를 선택한 뒤 `이 페이지 가져오기`를 명시적으로 실행한다. 행을 누르는 즉시 가져오지 않는다.
- 가져오기에 성공하면 페이지 선택 화면에 머무르지 않고 제목·본문 확인·편집 화면으로 이동한다.
- 페이지 목록은 처음 5개를 노출하고 `더 보기`로 같은 검색 결과의 다음 항목을 이어서 보여준다.
- 서버에서 받은 최대 20개 묶음은 클라이언트가 5개씩 추가 공개한다. 현재 묶음을 모두 공개한 뒤에만 `nextCursor`로 다음 묶음을 요청하며, 추가 로딩 중에는 기존 목록과 선택을 유지한다.
- 페이지 목록 행은 공통 문서 아이콘, 최대 두 줄 제목, `오늘`, `어제`, `3일 전` 형식의 상대 시각과 단일 선택 표시로 구성한다. 시각 뒤에 `수정`을 붙이지 않는다. 서버가 페이지별 실제 아이콘을 반환하지 않으므로 실제 노션 아이콘은 표시하지 않는다.
- 제목이 빈 페이지는 목록에서만 `제목 없는 페이지`로 표시하고 선택·가져오기를 허용한다. 이 대체 문구를 저장 제목으로 사용하지 않으며 편집 화면의 제목은 빈 상태로 둔다.
- 페이지 검색은 입력 후 300ms 동안 추가 입력이 없으면 자동 실행하고 Enter 입력 시 즉시 실행한다. 검색어가 바뀌면 선택과 cursor를 초기화하며 별도 검색 버튼과 입력 내부 검색 아이콘을 두지 않는다.
- 목록 새로고침은 pull-to-refresh가 아니라 페이지 목록 제목 오른쪽의 명시적인 아이콘 버튼으로 제공한다. 현재 검색어는 유지하되 선택·cursor를 초기화하고 첫 목록을 다시 요청한다.
- 페이지 가져오기 중에는 선택한 페이지를 유지하고 버튼 문구를 `페이지 가져오는 중`으로 바꿔 진행 상태를 표시한다. 관련 검색·선택·관리·링크 행동의 중복 실행을 막고 별도 취소는 제공하지 않는다.
- 연결된 워크스페이스 옆의 `관리`에서 접근 페이지 추가, 다른 워크스페이스 연결, 연결 해제를 제공한다.
- 목록에서 페이지를 찾지 못한 사용자는 `노션 페이지 링크로 가져오기` Bottom Sheet를 열어 간단한 복사 방법을 확인하고 링크를 입력할 수 있다.
- 링크 가져오기에 성공하면 페이지 목록을 거치지 않고 가져온 제목·본문 편집 화면으로 이동한다.
- 첫 구현의 본문은 Markdown 문자열을 textarea에서 직접 편집한다. Markdown 렌더링 미리보기는 제공하지 않는다.
- 제목·본문 글자 수는 항상 표시한다. 직접 입력의 최초 빈 상태는 중립 안내를 사용하고, 사용자가 값을 비우거나 제한을 넘긴 뒤부터 field 오류를 표시한다. 노션 가져오기 결과가 비어 있으면 저장 불가 이유를 진입 즉시 표시한다.
- 편집 화면의 저장 행동 문구는 `자료 저장`, `저장하고 퀴즈 만들기`다. 후자를 prominent primary action으로 둔다.
- 편집 화면의 두 저장 버튼은 모바일 콘텐츠 너비를 각각 100% 사용해 세로로 배치하고 `저장하고 퀴즈 만들기`를 아래에 둔다. 두 버튼 모두 고정하지 않고 textarea 다음의 일반 스크롤 흐름에 둔다.
- 저장 중에는 사용자가 누른 `ActionButton`의 loading 표시(Activity Indicator)와 `저장 중`을 보여주고 두 저장 행동을 모두 비활성화한다. 제목·본문은 잠시 읽기 전용으로 두며 실패하면 전체 입력과 선택한 저장 행동을 복구한다.
- `자료 저장` 성공 시 저장된 학습자료 상세 화면으로 이동하고, `저장하고 퀴즈 만들기` 성공 시 방금 저장한 자료가 선택된 퀴즈 생성 조건 화면으로 이동한다.
- 가져온 편집 화면은 진입 직후부터 미저장 초안으로 취급한다. back으로 이탈하면 확인창을 열고 안전한 기본 행동을 `이어서 편집`으로 둔다.
- 미저장 이탈 확인은 화면의 back처럼 앱이 제어하는 이동에만 적용한다. 브라우저 새로고침·탭 닫기 경고와 미저장 내용 복원은 이번 범위에서 제공하지 않는다.
- 연결 해제 확인은 저장된 학습자료가 유지됨을 안내하고 `연결 유지`, `연결 해제`를 제공한다.
- 다른 워크스페이스 연결은 현재 연결을 먼저 해제해야 함을 안내하고 `취소`, `연결 해제하고 변경`을 제공한다. 해제 성공 후에만 새 OAuth 연결을 시작한다.
- 연결 관리와 링크 입력은 Bottom Sheet로 제공한다. 연결 해제와 미저장 편집 이탈처럼 확인이 필요한 행동은 Alert Dialog를 사용한다. 별도 데스크톱 레이아웃 최적화는 이번 범위에서 제공하지 않는다.
- 연결된 워크스페이스는 목록 위의 작은 정보 행에 `연결된 워크스페이스`, 표시 이름과 `관리`를 보여준다. 이름이 없으면 `연결된 노션 워크스페이스`를 사용하고 페이지 선택보다 낮은 시각 위계로 둔다.
- 화면 경로는 기존 서버 OAuth 복귀 계약에 맞춰 연결·페이지 선택 `/learning/import/notion`, 공통 신규 자료 편집 `/learning/materials/new`를 사용한다. 저장 후에는 자료 상세 `/learning/materials/{materialId}` 또는 자료가 선택된 퀴즈 생성 `/learning/{materialId}/quiz`로 이동한다.

### 설계 가정

- 페이지 선택 목록은 radio 의미의 단일 선택 목록으로 표현하고 선택된 행 전체에 선택 상태를 전달한다.

## 사용자 목표

- 연결되지 않은 사용자는 자신의 노션 워크스페이스를 연결한다.
- 연결된 사용자는 접근 가능한 페이지 하나를 찾아 선택하거나 노션 링크로 지정한다.
- 가져온 제목과 본문을 확인·수정한 뒤 `자료 저장`을 선택하거나 이어서 퀴즈를 만든다.
- 페이지 가져오기 성공은 편집 화면에 전체 제목과 본문이 존재할 때 완료되고, 학습자료 저장은 사용자가 두 저장 행동 중 하나를 실행해야 완료된다.

## 진입과 이탈

- 진입점: `/learning/new`의 `새 학습자료로 만들기 → 노션에서 가져오기`에서 `/learning/import/notion`으로 이동
- OAuth 복귀: callback query를 처리한 뒤 주소에서 제거하고 연결 상태를 다시 조회한다.
- 다음 화면: 가져오기 성공 시 `/learning/materials/new`의 제목·본문 확인·편집 화면
- 뒤로 가기: 페이지를 가져오기 전에는 입력 방식 선택으로 돌아간다. 편집 화면에서는 진입 직후부터 미저장 이탈 확인을 제공한다.
- 로그인·권한 조건: OpenMD 로그인이 필요하며 노션 연결과 페이지 접근 권한은 OAuth로 확인한다.

## 정보 구조

### 1. 연결·페이지 선택

1. back과 `노션에서 가져오기` 화면 제목
2. 연결 전에는 `노션으로 로그인해 주세요` 안내 제목, `노션 페이지를 가져오려면 워크스페이스 연결이 필요해요. 가져온 내용은 원본 페이지와 자동으로 동기화되지 않아요.` 설명, `노션 연결하기`, `직접 입력하기`
3. 연결 후에는 작은 `연결된 워크스페이스` label, 워크스페이스 표시 이름과 오른쪽 `관리`. 이름이 없으면 `연결된 노션 워크스페이스`
4. 페이지 목록 제목 오른쪽의 새로고침 아이콘 버튼과, 항상 보이는 `노션 페이지 제목 검색` 입력·검색어 지우기. 입력 후 300ms 자동 검색, Enter 즉시 검색
5. 수정 시각 최신순 페이지 단일 선택 목록 5개와 `더 보기`. 각 행은 공통 문서 아이콘, 최대 두 줄 제목, `오늘`, `어제`, `3일 전` 같은 상대 시각과 선택 표시로 구성. 빈 제목은 `제목 없는 페이지`로 표시
6. 목록 아래 `원하는 페이지가 없나요?`와 `노션 페이지 링크로 가져오기`
7. 화면 하단 작업 영역의 전체 너비 `이 페이지 가져오기`; 선택 전 비활성, 선택 후 활성

#### 연결 관리 overlay

1. `접근할 페이지 추가`: 현재 워크스페이스 OAuth를 다시 시작하고 복귀 후 목록을 새로고침
2. `다른 워크스페이스 연결`: `다른 워크스페이스를 연결할까요?` 확인창과 `현재 워크스페이스 연결을 먼저 해제해야 해요. 이미 저장한 학습자료는 그대로 유지돼요.` 안내
3. 다른 워크스페이스 확인 버튼은 `취소`, `연결 해제하고 변경`; 해제 성공 후 새 OAuth 연결 시작
4. `연결 해제`: `노션 연결을 해제할까요?` 확인창과 `이미 저장한 학습자료는 그대로 유지돼요. 다시 가져오려면 노션을 연결해야 해요.` 안내
5. 연결 해제 확인 버튼은 `연결 유지`, `연결 해제`; 전자를 안전한 기본 행동으로 둠

### 2. 노션 페이지 링크 Bottom Sheet

1. `노션 페이지 링크로 가져오기` 제목
2. `노션에서 가져올 페이지를 열어요.`, `오른쪽 위 공유에서 링크 복사를 눌러요.`, `복사한 링크를 아래에 붙여넣어요.`의 3단계 안내
3. `노션 페이지 링크` 입력 label과 `https://www.notion.so/...` 예시
4. `취소`, `링크로 가져오기`. 키보드가 열린 상태에서도 두 행동에 스크롤로 접근할 수 있어야 함
5. 빈 값은 `노션 페이지 링크를 입력해 주세요.`, 잘못된 형식은 `올바른 노션 페이지 링크를 입력해 주세요.`를 입력 바로 아래에 표시
6. 접근 불가 시 입력값을 유지하고 `이 페이지에 접근할 수 없어요.`, `접근 페이지 추가하기`를 제공
7. 성공하면 페이지 목록을 거치지 않고 가져온 제목·본문 편집 화면으로 이동

### 3. 가져온 학습자료 확인·편집

1. back과 `학습자료 확인` 화면 제목
2. `노션에서 가져옴` 출처와 `원본 페이지와 자동으로 동기화되지 않아요.` 안내
3. 필수 제목 입력과 `현재/255`
4. 필수 Markdown 본문 textarea와 `현재/20,000`
5. 콘텐츠 너비 100%의 보조 행동 `자료 저장`
6. 콘텐츠 너비 100%의 prominent primary action `저장하고 퀴즈 만들기`; 바로 위 버튼과 세로로 쌓고 고정하지 않음
7. back 선택 시 `가져온 내용을 나갈까요?` 확인창. 버튼은 `이어서 편집`, `저장하지 않고 나가기` 두 개를 제공하며 전자를 안전한 기본 행동으로 둠

## 행동

| 우선순위 | 행동 | 발생 조건 | 결과 | 실패 시 |
| --- | --- | --- | --- | --- |
| Primary | 이 페이지 가져오기 | 페이지 하나 선택 | 최신 제목·본문을 가져와 편집 화면으로 이동 | 선택 유지, 오류와 재시도 제공 |
| Primary | 저장하고 퀴즈 만들기 | 제목·본문 저장 조건 충족 | 자료 저장 후 해당 자료가 선택된 퀴즈 생성 조건 화면으로 이동 | 편집값 유지, 같은 저장 재시도 |
| Secondary | 자료 저장 | 제목·본문 저장 조건 충족 | 저장된 학습자료 상세 화면으로 이동 | 편집값 유지, 같은 저장 재시도 |
| Secondary | 노션 연결하기 | 연결 없음 또는 재인증 필요 | full-page OAuth 시작 | 입력 방식 선택 또는 다시 연결 |
| Secondary | 직접 입력하기 | 연결 전 | 제목·본문이 빈 공통 편집 화면으로 이동 | 연결 전 화면 유지 |

## 노션 오류 문구와 배치

프론트는 서버의 `error.message` 문자열이 아니라 안정 공개 필드인 `error.code`로 분기한다. 제공자 원시 오류나 내부 예외는 노출하지 않는다.

| 서버 오류 코드 | 사용자 문구 | 배치 | 복구 행동 |
| --- | --- | --- | --- |
| `NOTION_CONNECTION_REQUIRED` | `노션 연결이 필요해요` | 연결 상태 재조회 결과에 맞는 연결·목록 영역 | `DISCONNECTED`면 `노션 연결하기`; `CONNECTED\|REAUTH_REQUIRED`면 현재 상태에 맞는 승인 다시 시작 |
| `NOTION_REAUTH_REQUIRED` | `노션을 다시 연결해 주세요` | 워크스페이스 아래, 목록 대신; 이전 페이지 선택은 해제 | 같은 워크스페이스 `다시 연결하기` 뒤 페이지 재선택 |
| `NOTION_WORKSPACE_MISMATCH` | `현재 연결된 워크스페이스와 달라요` | 기존 워크스페이스와 목록 위 PageBanner | 기존 연결 계속 사용 또는 관리에서 워크스페이스 변경 |
| `NOTION_PAGE_NOT_ACCESSIBLE` | `이 페이지에 접근할 수 없어요` | 선택한 페이지와 가져오기 행동 가까이; 링크 Bottom Sheet면 입력 아래 | `접근 페이지 추가하기` 또는 다른 페이지 선택 |
| `NOTION_CONTENT_INCOMPLETE` | `페이지를 전부 가져오지 못했어요` | 선택한 페이지와 가져오기 행동 가까이 | `다시 시도` 또는 직접 입력 |
| `NOTION_TEMPORARILY_UNAVAILABLE` | `지금은 노션에서 가져올 수 없어요` | 실패한 목록·가져오기·연결 관리 영역 | `다시 시도` 또는 직접 입력 |

노션 URL 형식 오류는 서버 노션 오류와 별개인 클라이언트 입력 오류로 링크 Bottom Sheet 입력 바로 아래에 표시하고 입력값을 유지한다.

제목 없는 페이지를 가져오면 편집 화면의 제목 입력을 빈 상태로 두고 `제목을 입력해 주세요`를 표시한다. 유효한 제목을 입력하기 전에는 두 저장 행동을 실행할 수 없다.

### 편집 입력 검증

- 제목·본문 counter는 각각 `현재/255`, `현재/20,000` 형식으로 항상 표시한다. `현재`는 UTF-16 code unit 수가 아니라 사용자에게 보이는 Unicode code point 수를 기준으로 한다.
- 제목은 앞뒤 Unicode 공백을 제거한 결과가 1..255 code point일 때 유효하고, 본문은 Unicode 비공백 문자를 하나 이상 포함하며 전체가 1..20,000 code point일 때 유효하다.
- 직접 입력으로 진입한 최초 빈 상태는 빨간 오류 대신 중립 안내와 비활성 저장 행동을 제공한다.
- 사용자가 입력을 시작한 뒤 값을 비우면 제목은 `제목을 입력해 주세요.`, 본문은 `내용을 입력해 주세요.`를 표시한다.
- 제한을 넘으면 제목은 `제목은 255자까지 입력할 수 있어요.`, 본문은 `내용은 20,000자까지 저장할 수 있어요.`를 표시한다.
- 제한 안으로 돌아오면 해당 오류와 오류 counter 색을 즉시 해제한다.
- 노션 가져오기 결과의 제목 또는 본문이 비어 있거나 제한을 넘으면 서버 성공 응답을 자르지 않고 textarea에 전체 내용을 유지하며, 해당 필드 오류를 편집 화면 진입 즉시 표시한다.

## 반응형·WebView 동작

- 이번 화면은 모바일 웹·WebView만 최적화한다. `base` 한 열과 기존 모바일 앱 셸의 콘텐츠 폭·global gutter를 따르며 별도 데스크톱 재배치 규칙을 만들지 않는다.
- `이 페이지 가져오기`는 페이지 선택 화면의 하단 작업 영역에서 사용 가능한 콘텐츠 너비 100%를 차지한다. 이 영역만 기존 앱 셸의 하단 행동 관례에 따라 화면 하단에 유지할 수 있으며, 하단 내비게이션과 safe area만큼 콘텐츠 여백을 확보해 목록 마지막 항목을 가리지 않는다.
- 편집 화면의 두 저장 행동은 각각 사용 가능한 콘텐츠 너비 100%로 세로로 쌓고 `저장하고 퀴즈 만들기`를 아래에 둔다.
- 편집 화면의 두 저장 행동은 sticky·fixed로 고정하지 않고 textarea 뒤의 일반 스크롤 영역에 둔다.
- 링크 Bottom Sheet와 긴 본문 편집은 키보드가 열려도 현재 입력, 오류와 실행 버튼을 스크롤로 접근할 수 있어야 한다.
- 모바일 브라우저와 WebView에서는 고정 `100vh`에 의존하지 않고 동적 viewport와 safe area를 반영한다. 키보드 표시·해제 뒤 focus된 제목·textarea, counter와 오류가 가려지지 않고 필요한 위치로 스크롤되어야 한다.
- 제목에서 본문으로 focus를 이동하거나 키보드를 닫아도 페이지가 화면 상단으로 튀지 않고 마지막 편집 위치를 유지한다. 긴 textarea는 페이지 스크롤과 경쟁하는 불필요한 이중 스크롤 영역을 만들지 않는다.
- 링크 Bottom Sheet는 키보드가 열리면 사용 가능한 높이 안에서 body를 스크롤하고, 입력 오류와 `링크로 가져오기`까지 도달할 수 있게 한다. 닫은 뒤에는 `노션 페이지 링크로 가져오기` trigger로 focus를 복원한다.
- 한글 조합 중에는 검색을 확정하거나 Enter 즉시 검색을 실행하지 않는다. 조합이 끝난 입력값을 기준으로 300ms 자동 검색 또는 Enter 즉시 검색을 적용한다.
- 웹·WebView 공통 화면에서는 pull-to-refresh를 제공하지 않는다. 브라우저 기본 새로고침·스크롤과 충돌하지 않는 명시적 새로고침 버튼을 사용한다.

## 접근성

- 각 route에는 하나의 `h1`을 두고 화면 제목, 안내, 검색, 목록, 하단 행동 순으로 읽는다.
- 페이지 목록은 하나의 이름 있는 radio group으로 제공한다. 각 페이지 행은 radio의 이름·선택 상태를 프로그램적으로 전달하며 행 전체가 최소 44px 터치 대상이다. 키보드에서는 Tab으로 group에 진입하고 방향키로 항목을 바꿀 수 있어야 한다.
- 가져오기·저장 진행 상태를 색이나 spinner만으로 표현하지 않고 상태 문구와 `aria-busy`를 제공한다.
- 비활성 버튼에는 제목·본문 또는 페이지 선택이 필요한 이유를 인접 설명으로 제공한다.
- Bottom Sheet는 제목·설명·입력 label을 연결하고 열릴 때 링크 입력으로, 닫힐 때 원래 trigger로 focus를 돌린다. 연결 관리 Bottom Sheet는 첫 관리 행동으로 focus를 이동한다.
- 확인 Dialog는 제목과 설명을 연결하고 열릴 때 `이어서 편집`, `연결 유지`, `취소` 같은 안전한 행동에 기본 focus를 둔다. 파괴 행동은 색뿐 아니라 명시적인 버튼 문구로 구분한다.
- 새로고침 아이콘 버튼에는 `페이지 목록 새로고침` 접근성 이름을 제공하고, 진행 중에는 같은 자리의 loading 표시와 상태 문구를 제공한다.
- 상대 시각은 보이는 문구를 `오늘`, `어제`, `3일 전`으로 유지하되 스크린 리더가 실제 날짜·시각도 확인할 수 있는 의미 있는 time 정보와 연결한다.
- OAuth 복귀, 목록 갱신, 가져오기 성공과 오류는 과도하지 않은 live region으로 전달한다.
- 페이지 선택 상태는 행의 radio 상태와 활성화된 `이 페이지 가져오기`로 표현하며 `선택됨` 보조 문구를 화면에 별도로 노출하지 않는다.
- OAuth 복귀의 `outcome`과 `error` query는 결과를 읽은 즉시 주소에서 제거한다.

## 미결정 사항

- 제품 행동과 사용자 문구의 열린 질문은 없다.
- 정확한 SEED variant·props와 새로고침·문서 아이콘 이름은 제품 결정이 아니라 구현 직전 현재 SEED 문서에서 검증할 항목이다. 이 검증이 위의 정보 위계, 버튼 문구, 상태 보존과 접근성 의미를 바꾸지는 않는다.

## 데이터와 계약

- 필요한 표시 데이터: 연결 상태, 워크스페이스 표시 이름, 페이지 ID·제목·수정 시각, cursor
- 페이지별 실제 아이콘은 현재 페이지 목록 계약에 없으므로 클라이언트의 공통 문서 아이콘을 사용한다.
- 서버의 최대 20개 응답은 클라이언트 표시 단위 5개와 분리한다. 로컬에 아직 공개하지 않은 항목이 있으면 API 호출 없이 5개를 더 보여주고, 모두 공개했으며 `nextCursor`가 있을 때만 다음 20개를 요청한다.
- 사용자 입력: 검색어, 선택한 페이지, Notion URL, 편집한 제목·본문, 저장 후속 행동
- 관련 API: Notion 연결 상태·승인 시작·페이지 목록·연결 해제·페이지 가져오기와 기존 학습자료 저장 계약
- access token, refresh token, OAuth code와 state는 프론트 상태·URL·로그에 노출하지 않는다.
- URL fallback은 클라이언트에서 page UUID만 추출해 같은 가져오기 API를 사용하고 URL과 page ID를 가져오기 기록으로 저장하지 않는다.

## 인수 조건

- [ ] 연결 없음에서 OAuth를 시작하고 성공 복귀 후 페이지 선택으로 전환할 수 있다.
- [ ] 연결 전 안내에서 직접 입력을 선택하면 제목·본문이 빈 공통 편집 화면으로 이동한다.
- [ ] 페이지 5개 목록, 검색, 더 보기, 새로고침과 단일 선택을 사용할 수 있다.
- [ ] 명시적인 `이 페이지 가져오기` 성공 후 별도 편집 화면으로 이동한다.
- [ ] 페이지 가져오기 중 선택과 진행 상태를 보여주고 관련 중복 실행을 막으며, 실패하면 같은 선택으로 다시 시도할 수 있다.
- [ ] 링크 입력 안내와 형식·접근 오류 복구를 제공한다.
- [ ] 연결 해제와 워크스페이스 변경 전 저장 자료 유지와 현재 연결 해제를 안내하며, 해제 성공 후에만 새 워크스페이스 OAuth를 시작한다.
- [ ] 제목·본문 전체를 textarea에서 수정하고 두 저장 행동을 구분해 실행할 수 있다.
- [ ] 편집 화면의 두 저장 버튼은 모바일에서 각각 전체 너비이며 textarea 아래 일반 스크롤 흐름에 있고, 키보드 표시·해제 뒤에도 접근할 수 있다.
- [ ] 제목 없는 페이지는 목록에서만 대체 문구를 보여주고, 가져온 뒤 사용자가 유효한 제목을 입력하기 전까지 저장할 수 없다.
- [ ] 제목·본문 counter와 저장 가능 여부는 Unicode code point 기준으로 계산하고, 제한을 넘는 가져오기 결과도 자르지 않은 전체 내용으로 수정할 수 있다.
- [ ] 편집 화면에서 back을 선택하면 미저장 이탈 확인을 제공하고 `이어서 편집`을 안전한 기본 행동으로 제공한다.
- [ ] 로딩, 빈 상태, 입력 오류와 요청 오류에서 필요한 사용자 상태를 보존한다.
- [ ] 작은 화면, 큰 글자와 키보드 탐색에서 핵심 행동을 수행할 수 있다.
- [ ] 검색 입력은 아이콘과 별도 검색 버튼 없이 300ms debounce·Enter 즉시 검색을 제공하고, 한글 조합 중 잘못된 요청을 보내지 않는다.
- [ ] iOS·Android 모바일 브라우저와 Expo WebView 후보 환경에서 키보드 표시·해제, viewport resize, safe area, textarea focus와 스크롤 복귀를 확인한다.

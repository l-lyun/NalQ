# [Screen Spec] 알림 목록과 생성 결과 Snackbar

## 문서 정보

- 화면명: 전역 알림 utility, 알림 페이지, 생성 결과 Snackbar
- 문서 상태: `review`
- 대상 플랫폼: 반응형 웹과 앱 WebView
- 관련 기능: [퀴즈 생성 결과 알림](../prd/prd-quiz-generation-notifications.md)
- 관련 흐름: [퀴즈 생성 결과 알림](flow-quiz-generation-notifications.md)
- 최종 수정일: 2026-09-03

## 요구사항 구분

### 확정 사항

- 일반 인증 화면의 Top Navigation 우측에 종을 두고 몰입형 퀴즈·결과·복습 화면에서는 숨긴다.
- 종은 `IconBellLine` 의미의 아이콘과 접근 가능한 이름 `알림`을 가진다.
- 읽지 않은 수는 `NotificationBadge`와 `NotificationBadgePositioner`를 사용해 종에 연결한다. 0이면 숨기고 1~99는 숫자, 100 이상은 `99+`다.
- 데스크톱·모바일 웹·WebView 모두 종 또는 `알림보기`를 선택하면 별도 알림 페이지로 이동한다. anchored layer와 Bottom Sheet는 사용하지 않는다.
- 목록은 최신순 20개와 `더보기`, 개별 읽음, `모두 읽음`을 제공한다.
- 항목은 결과 문구, 대상 이름, 상대 시각 순으로 읽히며 긴 대상 이름은 최대 두 줄까지 보여준다.
- 대상 이름은 알림 생성 당시 `quizTitle` snapshot이며 90일 보존 중 QuizSet 이름이 바뀌어도 갱신하지 않는다.
- 목록 열기와 Snackbar 표시는 읽음이 아니다.
- 현재 화면 자동 이동과 입력 focus 강탈은 없다.

### 설계 가정

- 상대 시각은 사용자가 목록을 연 시점과 foreground 복귀 시점에 갱신하고 서버 원장 시각은 변경하지 않는다.

## 사용자 목표

- 이 화면에 들어온 사용자가 해결하려는 일: 생성 화면을 떠난 사이 끝난 퀴즈 결과를 빠르게 훑고 필요한 결과로 이동한다.
- 화면이 성공했다고 판단할 수 있는 완료 조건: 사용자가 결과를 확인하고 개별 또는 전체 읽음을 선택하거나 현재 작업을 유지한 채 닫을 수 있다.

## 진입과 이탈

- 진입점: 일반 인증 화면 Top Navigation 우측 종, 복수 unseen Snackbar의 `알림보기`; 모두 별도 알림 페이지로 이동한다.
- 다음 화면: 성공은 내 퀴즈 대상 카드, 실패는 원본 자료의 퀴즈 생성 조건
- 뒤로 가기 동작: 이전 화면으로 돌아간다. 알림 페이지 진입 전 route와 가능한 탐색 맥락을 복원하되 읽음은 명시적 항목 선택 또는 `모두 읽음`에 의해서만 바뀐다.
- 로그인·권한 조건: 인증 사용자 본인의 알림만 표시한다.

## 정보 구조

1. `[일반 화면 Top Navigation]`: 화면 제목 또는 뒤로가기 맥락과 우측 종. 몰입형 route에서는 전체 utility를 노출하지 않는다.
2. `[별도 알림 페이지 머리말]`: 이전 화면으로 돌아가기, `알림` 제목, 읽지 않은 항목이 있을 때만 `모두 읽음`.
3. `[알림 목록]`: 최신순 항목. 각 항목은 읽지 않음 상태, 결과 문구, 대상 이름, 상대 시각을 한 행동 영역으로 제공한다.
4. `[목록 하단]`: 다음 cursor가 있을 때 `더보기`, 추가 로딩과 추가 조회 오류.
5. `[전역 Snackbar]`: 현재 화면 위에서 짧게 결과와 선택 행동을 제공하되 알림 목록의 대체물이 아니다.

## 알림 항목 문구

| 종류 | 결과 문구 | 대상 이름 | 선택 결과 |
| --- | --- | --- | --- |
| 생성 성공 | `퀴즈가 완성됐어요.` | 알림의 퀴즈 이름, 최대 두 줄 | 내 퀴즈 대상 카드 focus |
| 자료·조건 부족 | `학습자료에서 문제를 만들지 못했어요.` | 실패한 퀴즈 이름, 최대 두 줄 | 원본 자료 생성 조건 |
| 생성 작업 실패 | `퀴즈를 만들지 못했어요. 다시 시도해 주세요.` | 실패한 퀴즈 이름, 최대 두 줄 | 원본 자료 생성 조건 |

상대 시각은 `방금 전`, `N분 전`, `N시간 전`, 날짜처럼 현재 로케일에서 이해 가능한 형태로 표시한다. 정확한 구간과 포맷은 구현 표현 결정이며 서버 계약으로 고정하지 않는다.

## 행동

| 우선순위 | 행동 | 발생 조건 | 결과 | 실패 시 |
| --- | --- | --- | --- | --- |
| Primary | 알림 항목 선택 | 항목이 존재 | 개별 읽음 처리 후 결과별 목적지 이동 | 대상 없음은 안내 후 읽음; 읽음 저장 실패는 이동을 막지 않음 |
| Secondary | 모두 읽음 | 읽지 않은 항목 1개 이상 | 선택 시점까지의 알림을 읽음 처리 | 현재 상태 유지, 다시 시도 |
| Secondary | 더보기 | 다음 cursor 존재 | 다음 20개를 아래에 이어 붙임 | 기존 목록 유지, 하단 재시도 |
| Secondary | 뒤로가기 | 알림 페이지 | 이전 화면과 가능한 탐색 맥락으로 복귀 | 해당 없음 |
| Contextual | Snackbar 행동 | 생성 화면이 아니고 해당 행동이 유효 | 목록·성공 대상·실패 복구로 명시적 이동 | 현재 화면 유지 |

## 화면 상태

| 상태 | 진입 조건 | 보여줄 내용 | 가능한 행동 |
| --- | --- | --- | --- |
| 로딩 | 첫 목록 조회 중 | 제목, 목록 skeleton; 기존 badge를 성공으로 추정해 지우지 않음 | 뒤로가기 |
| 기본 | 알림 1개 이상 | 최신순 항목, 읽음 구분, 필요 시 모두 읽음·더보기 | 항목 선택, 모두 읽음, 더보기, 뒤로가기 |
| 빈 상태 | 90일 내 알림 없음 | `아직 알림이 없어요.` | 뒤로가기 |
| 추가 로딩 | 더보기 요청 중 | 기존 목록과 하단 진행 상태 | 뒤로가기 |
| 부분 오류 | 더보기 또는 읽음 저장 실패 | 기존 목록과 실패한 행동 가까이 재시도 | 다시 시도, 다른 항목 선택, 뒤로가기 |
| 전체 오류 | 첫 목록 조회 실패 | 알림을 삭제된 것처럼 보이지 않는 오류와 재시도 | 다시 시도, 뒤로가기 |
| 대상 없음 | 선택한 리소스 없음·권한 없음 | `대상을 찾을 수 없어요.` | 확인 후 현재 맥락 유지 |

## Snackbar 상태

| 조건 | tone·문구 | 행동 |
| --- | --- | --- |
| 성공 1건 | positive `퀴즈가 완성됐어요.` | `목록보기`; 내 퀴즈에서는 생략 |
| `SOURCE_INSUFFICIENT` 1건 | critical `학습자료에서 문제를 만들지 못했어요.` | `자료·조건 확인`; 내 퀴즈에서는 생략 |
| `GENERATION_FAILED` 1건 | critical `퀴즈를 만들지 못했어요. 다시 시도해 주세요.` | `다시 만들기`; 내 퀴즈에서는 생략 |
| 복귀 시 unseen 2건 이상 | neutral 또는 informative `새 퀴즈 알림이 N개 있어요.` | `알림보기` |
| 생성 진행 화면 | 표시하지 않음 | 화면 자체의 결과 행동 사용 |

Snackbar는 `notificationId` 기준으로 같은 사용자·기기에서 한 번만 표시하고, 여러 웹 탭 중 활성 탭 한 곳만 표시한다. 표시·닫기·시간 만료는 읽음 상태를 바꾸지 않는다.

## 반응형·WebView 동작

- 기준이 되는 작은 화면 너비: 320 CSS px에서 종, badge, 목록 항목과 행동이 가로 overflow 없이 동작한다.
- 넓은 화면에서 달라지는 배치: 별도 페이지의 콘텐츠 최대 폭과 여백만 조정하며 결과 순서와 행동 의미는 바꾸지 않는다.
- 키보드, 안전 영역, 고정 내비게이션과 스크롤 처리: 별도 페이지는 safe area를 침범하지 않고 문서 흐름에서 스크롤한다.
- 긴 문구·다국어·텍스트 확대 처리: 대상 이름은 기본 최대 두 줄이며 텍스트 확대에서 결과 문구·시각·행동을 가리지 않는다. 전체 이름은 접근 가능한 이름에서 생략하지 않는다.
- WebView가 background로 가면 polling과 Snackbar를 중단하고 visible 복귀 뒤 최신 목록을 다시 확인한다.

## 접근성

- 제목 구조와 읽기 순서: `알림` 제목 뒤 최신순 항목을 읽고 각 항목 안에서는 결과, 대상, 시각 순이다.
- 컨트롤 이름과 상태 전달: 종은 `알림`, badge는 `읽지 않은 알림 N개`를 전달한다. `99+` 시각 표기와 무관하게 정확한 개수를 보조기술에 전달한다.
- 키보드·포커스 동작: 별도 페이지 진입 뒤 `알림` 제목 또는 첫 유효 위치로 이동한다. 뒤로가기는 가능한 경우 이전 화면의 종으로 탐색 맥락을 복원한다. 항목 전체는 한 개의 이동 행동이다.
- 색상 외 상태 구분: 읽지 않음은 색만으로 구분하지 않고 텍스트·굵기·표식 중 접근 가능한 신호를 함께 사용한다.
- 동적 피드백 전달 방식: Snackbar와 대상 없음 안내는 polite live region을 기본으로 하며 진행 중 입력을 가로채지 않는다. critical tone이 곧 강제 alert를 뜻하지 않는다.

## 데이터와 계약

- 필요한 표시 데이터: 알림 식별자, 종류, 대상 이름, 생성 시각, 읽음 시각, 대상 접근 가능 여부, 실패 코드, unread count, next cursor
- 사용자 입력: 종 열기, 항목 선택, 모두 읽음, 더보기, Snackbar 행동
- 관련 API 계약: [알림 API](../contracts/contract-api-notifications.md), [내 퀴즈 목록](../contracts/contract-api-quiz-learning.md#내-퀴즈-목록-조회이름-검색)
- 개인정보·민감정보 고려: 학습자료 본문, 문제, 정답과 사용자 답안을 알림에 포함하지 않는다.
- mock을 사용할 경우 실제 계약과의 경계: fixture의 지연·다중 완료는 화면 검토용이며 서버 polling 또는 보존 계약이 아니다.

## 인수 조건

- [ ] 일반 인증 화면에는 우측 종과 정확한 unread badge가 있고 immersive 퀴즈·결과·복습에는 종이 없다.
- [ ] 데스크톱·모바일 웹·WebView의 종과 `알림보기`는 anchored layer나 Bottom Sheet 없이 같은 별도 알림 페이지로 이동한다.
- [ ] 최신 20개, 더보기, 개별 읽음, 모두 읽음, 빈 상태와 오류 상태가 정의되어 있다.
- [ ] 각 항목은 결과 문구·두 줄 이내 대상명·상대 시각을 제공하고 항목 전체를 한 행동으로 사용할 수 있다.
- [ ] 목록 열기와 Snackbar는 읽음 처리하지 않는다.
- [ ] Snackbar가 생성 화면·내 퀴즈·단일 결과·복수 복귀 조건에 맞는 문구와 행동을 제공한다.
- [ ] 320px, 큰 글자, 키보드와 WebView safe area에서 핵심 정보를 확인하고 닫을 수 있다.
- [ ] 기능 명세·Flow·API·Data Contract와 충돌하지 않는다.

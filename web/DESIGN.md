# OpenMD Web Design Guide

## 제품 디자인 방향

OpenMD UI는 다음 특성을 지향한다.

- 콘텐츠 중심
- 차분하고 신뢰할 수 있는 인상
- 처음 사용하는 사람도 이해하기 쉬운 구조
- 모바일 우선이며 데스크톱에서도 자연스러운 레이아웃
- 로딩, 빈 상태, 성공과 오류 상태가 명확한 인터페이스

사용자가 목적을 달성하는 데 도움이 되지 않는 장식적 복잡성은 피한다.

## 기준의 우선순위

기준이 충돌하면 다음 우선순위를 사용한다.

1. 제품 요구사항과 인수 조건
2. 이 문서
3. 기존 OpenMD 화면 패턴
4. SEED Design 컴포넌트와 공식 문서
5. 에이전트의 판단

현재 Figma는 필수 설계 원본이 아니다. 요구사항에 판단의 여지가 있으면 다음 조건을 만족하는 가장 단순한 패턴을 선택한다.

- 기존 SEED 컴포넌트를 사용한다.
- 주 행동이 분명하다.
- 사용자 입력을 최소화한다.
- 접근성을 보존한다.
- 다른 화면에서도 재사용할 수 있다.

## 필수 디자인 절차

새 화면을 구현하기 전에 다음을 수행한다.

1. 사용자의 목표를 정의한다.
2. 대표 흐름과 주 행동을 정의한다.
3. 필요한 콘텐츠와 상호작용 상태를 나열한다.
4. SEED Docs MCP에서 적용 가능한 컴포넌트를 검색한다.
5. 간단한 컴포넌트 매핑을 작성한다.
6. 매핑이 정리된 후 구현한다.

예시:

| UI 책임 | SEED 후보 | 선택 기준 |
| --- | --- | --- |
| 주요 제출 | ActionButton | 가장 중요한 행동 하나를 강조한다. |
| 텍스트 입력 | TextFieldInput | label과 오류 상태를 함께 제공한다. |
| 빈 결과 | ContentPlaceholder | 상태 설명과 다음 행동을 제시한다. |
| 요청 실패 | ErrorState | 복구 가능한 경우 재시도 행동을 제공한다. |
| 일시적 피드백 | Snackbar | 사용을 막는 오류에는 사용하지 않는다. |

SEED 컴포넌트 이름, props, 토큰과 아이콘을 추측하지 않는다. SEED Docs MCP로 확인한다.

## 컴포넌트 선택 원칙

외관뿐 아니라 의미와 상호작용을 기준으로 선택한다.

- 페이지 구조: Box, Flex, Grid, Stack, HStack, VStack
- 타이포그래피: Text
- 주 행동과 보조 행동: ActionButton
- 짧은 선택과 필터: Chip, ActionChip, ControlChip, Tabs
- 폼: TextFieldInput, TextFieldTextarea, Checkbox, RadioGroup, Select, DatePicker와 Field 계열
- 확인: AlertDialog
- 모바일 보조 행동: BottomSheet 또는 ActionSheet
- 피드백: InlineBanner, Callout, Snackbar, ErrorState
- 로딩: Skeleton 또는 ProgressCircle
- 빈 콘텐츠: ContentPlaceholder
- 반복 콘텐츠: List와 composition primitive

위 목록은 후보 매핑이다. 실제 선택 전 현재 SEED 문서를 확인한다.

## 시각적 위계

일반적인 화면은 다음을 갖는다.

1. 하나의 페이지 목적
2. 시각적으로 가장 명확한 하나의 주 행동
3. 분명한 섹션 그룹
4. 강조가 낮은 보조 행동과 파괴적 행동
5. 주요 콘텐츠보다 낮은 위계의 메타데이터

다음을 피한다.

- 같은 강조도를 가진 여러 버튼
- 모든 영역을 카드로 감싸는 구성
- 정보 위계가 없는 중첩 패널
- 임의의 그림자, 테두리와 색상
- 가변 텍스트를 포함한 컨테이너의 고정 높이

## 토큰 정책

- SEED semantic token을 사용한다.
- 색상을 추가하기 전에 Rootage 또는 SEED 색상 변수를 검색한다.
- Figma나 외부 시안의 hex 값을 그대로 복사하지 않는다.
- 토큰 이름을 임의로 만들지 않는다.
- 가능한 경우 SEED 타이포그래피와 간격 관례를 사용한다.
- 피할 수 없는 custom 값은 이 문서의 예외 기록에 남긴다.

## 필수 화면 상태

각 페이지에서 다음 상태의 필요 여부를 판단한다.

- 최초 로딩
- 추가 로딩
- 빈 상태
- 성공
- 복구 가능한 오류
- 진행을 막는 오류
- 비활성화
- 입력 검증 오류
- 권한 없음

데이터가 정상적으로 채워진 이상적인 상태만 구현하지 않는다.

## 반응형 동작

- 지원하는 가장 작은 viewport에서 시작한다.
- 콘텐츠에 따라 높이가 자연스럽게 변하게 한다.
- 일반적인 문서 흐름을 우선한다.
- 콘텐츠 구조가 바뀌어야 할 때만 breakpoint를 추가한다.
- 제품 또는 사용성 근거 없이 데스크톱 sidebar나 모바일 bottom sheet를 만들지 않는다.

## Custom 컴포넌트 정책

custom UI 컴포넌트를 만들기 전에 다음을 확인한다.

1. SEED 컴포넌트 문서를 검색한다.
2. 여러 SEED primitive를 조합할 수 있는지 확인한다.
3. `web/src/shared`의 기존 컴포넌트를 확인한다.
4. 위 선택지가 부족한 이유를 기록한다.

custom 컴포넌트는 SEED primitive를 조합할 수 있지만 SEED의 상호작용 동작을 처음부터 재구현해서는 안 된다.

## 설계 결론

별도의 복습 풀이 체계를 만들지 않는다. 서버가 가장 최근 본 퀴즈에서 미해결인 문항만 골라 문제 세트와 같은 공개 형식으로 제공하고, 사용자는 기존 본 퀴즈 화면에서 모든 문제를 푼 뒤 한 번 제출한다.

사용자에게는 세션·snapshot·해결 상태 관리보다 `틀린 문제 N개를 다시 푼다`는 의미만 전달한다. 저장 위치, 자동 재시도와 중복 방지 방식은 화면에 노출하지 않는다.

## 확정 사항

- 객관식·빈칸·단답형의 오답·미응답과 서술형의 `PARTIAL`(`보완 필요`)·`오답`만 포함한다.
- 이전에 `정답`으로 평가한 서술형은 포함하지 않는다.
- 문항은 원래 본 퀴즈 번호 오름차순으로 제공한다.
- 사용자는 본 퀴즈와 동일하게 이전·다음으로 이동하며 대상 문항을 모두 먼저 푼다.
- 문제를 이동할 때 채점하지 않는다. 제출 전에는 정답·모범 답안·해설·학습자료 본문의 관련 부분을 보여주지 않는다.
- 마지막에 전체 답안을 한 번 제출하고 자동 채점한 뒤, 작성한 서술형이 있으면 방금 작성한 답을 자기평가한다.
- 이전 서술형 판정을 다시 고르는 화면은 없다.
- 현재 화면의 답안 유지·제출 재시도·처리 성공은 별도 사용자 상태로 표시하지 않는다.

## 기존 본 퀴즈에서 그대로 사용하는 것

- 단일 열 immersive 퀴즈 shell과 상단 header
- 진행률, 이전·다음 이동과 전체 문항 목록
- 문제 유형·주제, 문제 본문, 답 입력 또는 선택 영역
- 미응답 문항 표시와 최종 제출 확인
- 하단 고정 CTA, 키보드와 safe area 대응
- 전체 제출 뒤 자동 채점 결과
- `답 작성 → 전체 제출 → 서술형 자기평가 → 결과` 순서
- 결과의 내 답, 정답 또는 모범 답안, 판정, 해설과 `학습자료 본문`

## 다시 풀기에서만 달라지는 것

- 풀이 화면 헤더: 기존 학습자료 제목 뒤에 ` · 복습`만 붙인다. 예: `자료구조 핵심 개념 · 복습`
- 진행 정보와 문항 보조 정보, 입력 UI, 이전·다음 이동, 마지막 제출 CTA는 기존 본 퀴즈 표현을 그대로 사용한다.
- 결과 제목: `복습 결과`

풀이 단계에서 사용자가 보는 구조적 차이는 헤더 접미사뿐이다. `복습 세션`, `해결 상태`, `서버에서 불러온 문제` 같은 내부 용어를 설명하지 않는다.

## 풀이와 제출

1. 첫 문항부터 기존 본 퀴즈 입력 구조로 답한다.
2. `이전 / 다음`과 문항 목록으로 세 문제를 자유롭게 확인한다.
3. 마지막 문항에서 `채점하기`를 선택한다.
4. 미응답 문항이 있으면 본 퀴즈와 같은 제출 확인을 사용한다.
5. 제출하는 동안 중복 탭만 막는다. 현재 화면이 유지하는 UUID나 내부 재시도 상태는 보여주지 않는다.
6. 자동 채점이 끝나고 자기평가할 서술형이 없으면 결과로 이동한다.

## 서술형 자기평가

- 다시 풀기 대상 서술형도 제출 전에는 일반 서술형 입력만 보여준다.
- 전체 제출 뒤 방금 작성한 답, 모범 답안, 핵심 포인트, 해설과 `학습자료 본문`을 보여준다.
- 사용자는 방금 작성한 답을 `정답 / 보완 필요 / 오답`으로 자기평가한다. 내부 저장값은 `PARTIAL`을 유지한다.
- 모든 대상 서술형 평가가 끝나면 결과로 이동한다.
- 이전 본 퀴즈의 답과 판정은 선택지로 보여주지 않는다.

## 결과

기존 본 퀴즈 결과 읽기 구조를 사용하되 이번에 다시 푼 문항만 보여준다.

- 자동 채점 점수
- 서술형 자기평가 요약
- 이번에 맞힌 문제 수
- 다음 다시 풀기에 남은 문제 수
- 문항별 내 답, 정답 또는 모범 답안, 판정, 해설과 `학습자료 본문`
- 다음 다시 풀기에 남은 문제가 있으면 Primary: `복습하기`
- Secondary: `홈으로`
- 남은 문제가 없으면 완료 안내 뒤 `홈으로`를 유일한 prominent 행동으로 제공한다.

원래 본 퀴즈의 점수나 제출 답이 바뀐 것처럼 표현하지 않는다.

## 사용자에게 보이는 예외

| 조건 | 문구 | 행동 |
| --- | --- | --- |
| 제출 결과를 확인하지 못함 | `채점 결과를 불러오지 못했어요. 다시 시도해 주세요.` | `다시 시도` |
| 서술형 자기평가 반영 실패 | `평가를 반영하지 못했어요. 다시 시도해 주세요.` | `다시 시도` |
| 작성 중인 답이 있는 상태에서 나가기 | `작성 중인 답이 사라져요. 나갈까요?` | `계속 풀기`, `나가기` |

현재 화면이 남아 있는 동안의 재시도는 같은 문제 풀이와 답을 유지한다. 화면을 벗어나 상태를 잃으면 같은 세션의 문제를 첫 문항부터 다시 푼다. 성공하면 별도 성공 알림 없이 원래 흐름을 계속한다.

## 인수 조건

- [ ] 틀린 문제 다시 풀기가 기존 본 퀴즈와 같은 풀이·문항 이동·최종 제출 구조를 사용한다.
- [ ] 풀이 화면은 기존 본 퀴즈 화면을 그대로 재사용하고 헤더에만 기존 학습자료 제목 뒤 ` · 복습`을 표시한다.
- [ ] 세 문제라면 세 문제를 모두 푼 뒤 한 번 채점한다.
- [ ] 제출 전에는 어떤 문항도 정답·판정·해설을 보여주지 않는다.
- [ ] 이전에 정답으로 평가한 서술형은 나타나지 않는다.
- [ ] 포함된 서술형은 새 답을 작성하고 전체 제출 뒤 그 새 답을 자기평가한다.
- [ ] 이전 판정을 고르는 UI가 없다.
- [ ] 남은 미해결 문항이 있으면 결과 하단 `복습하기`로 다음 복습을 시작하고, `홈으로`로 홈에 이동한다.
- [ ] 정상 흐름에서 저장·응답 복구·중복 방지 상태가 노출되지 않는다.
- [ ] 320px, 큰 글자, 키보드와 WebView safe area에서도 본 퀴즈와 같은 읽기·행동 순서를 유지한다.

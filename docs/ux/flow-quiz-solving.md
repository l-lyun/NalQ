# [Flow] 퀴즈 생성부터 복습까지

- 관련 기능: [퀴즈 생성·풀이·결과·복습](../prd/prd-quiz-learning.md)
- 공유 계약: [학습자료·퀴즈 API 계약](../contracts/contract-api-quiz-learning.md)
- 관련 화면: [미완료 서술형 자기평가 재진입](screen-quiz-resume.md), [틀린 문제 다시 풀기](screen-review.md)
- 클라이언트 후속 동기화 대상: [웹 퀴즈 풀이 TRD](../../web/docs/trd/trd-quiz-solving.md), [앱 퀴즈 풀이 TRD](../../app/docs/trd/trd-quiz-solving.md)

## 문서 책임

이 문서는 화면과 상태 사이의 순서, 분기, 중단, 재개와 실패 복구를 정의한다. 문제 품질·채점·복습 대상 정책은 기능명세가, 요청·응답과 오류 코드는 API 계약이 책임진다.

## 사용자 목표

학습자료로 만든 퀴즈를 중단이나 실패에도 진행 상태를 이해하며 끝까지 풀고, 결과에서 필요한 문항을 복습한다.

## 시작 조건

- 로그인한 사용자가 자신이 소유한 유효한 학습자료를 선택했다.
- 학습자료 본문이 비어 있지 않고 20,000자를 넘지 않는다.
- 생성·평가 규칙은 [퀴즈 PRD의 확정 정책](../prd/prd-quiz-learning.md#확정-정책)을 따른다.

## 완료 조건

- 본 퀴즈: 자동 채점과 필요한 서술형 자기평가가 끝나 완료 결과를 볼 수 있다.
- 복습: 현재 세션의 모든 대상 문항을 한 번씩 평가해 해결·미해결 상태가 저장된다.

## 기본 흐름

### A. 생성

1. 사용자가 문제 유형을 하나 이상 선택하고 난이도와 최대 문제 수를 정한다.
2. 사용자가 생성을 요청하면 시스템은 요청을 접수하고 즉시 학습자료 본문을 잠근다.
3. 차단형 생성 오버레이가 열리고 완료 여부를 알 수 없는 진행 표시를 보여준다.
4. 클라이언트는 3초 뒤 처음 상태를 확인하고, 이후 5초 간격으로 확인한다. 생성 시작 후 2분이 지나면 10초 간격으로 낮춘다.
5. 성공하면 실제 생성 문제 수와 조건을 보여주고 본 퀴즈 시작 행동을 제공한다.
6. 실패하면 불완전한 문제를 노출하지 않고 기존 생성 조건을 유지한 채 재시도를 제공한다.

### B. 본 퀴즈 풀이와 제출

1. 사용자가 본 퀴즈를 시작하면 첫 문항을 보여준다.
2. 사용자는 답을 작성하고 이전·다음으로 이동한다. 이동만으로 채점하지 않는다.
3. 풀이 중 현재 위치와 답안은 열린 화면의 메모리 상태로 유지된다.
4. 제출을 선택했을 때 미응답이 있으면 `남은 문제 풀기`와 `그대로 제출`을 제공한다.
5. `남은 문제 풀기`를 선택하면 번호가 가장 낮은 미응답 문항으로 이동한다.
6. `그대로 제출` 또는 모든 문항 응답 후 제출하면 클라이언트가 attempt UUID를 한 번 생성해 최종 제출한다. 현재 화면이 같은 UUID를 유지하는 동안의 재시도는 새 회차를 만들지 않는다.
7. 자동 채점 뒤 작성한 서술형이 있으면 자기평가 흐름으로, 없으면 결과로 이동한다. 미응답 서술형은 자기평가 없이 오답 처리한다.

### C. 서술형 자기평가

1. 첫 서술형에서는 자기평가 방식과 자동 점수 제외를 안내한다.
2. 사용자는 내 답과 모범 답안·핵심 포인트·해설·원문 근거를 비교한다.
3. 사용자는 `정답`, `부분 이해`, `오답` 중 하나를 선택해 저장한다.
4. 다음 미평가 서술형으로 이동한다.
5. 마지막 평가가 저장되면 본 퀴즈 회차가 완료되고 결과로 이동한다.

### D. 결과

1. 시스템은 단답형의 현재 판정을 포함한 채점 점수, 서술형 자기평가 요약과 다시 풀 문제 수를 보여준다.
2. 그 아래에 모든 문항을 번호 오름차순으로 보여준다.
3. 사용자가 한 문항을 선택하면 결과 읽기 모드에서 내 답, 정답 또는 모범 답안, 판정, 해설과 원문 근거를 확인한다.
4. 답을 작성한 단답형 상세에서는 현재 채점 결과와 `채점 수정`을 보여준다. 객관식에는 판정 수정 행동을 제공하지 않는다.
5. 사용자가 `채점 수정`을 선택하면 내 답과 정답 예시를 비교하고 현재 판정을 `정답` 또는 `오답`으로 변경한다. 서버가 반환한 전체 최신 결과를 받은 뒤에만 판정·점수·다시 풀 문제 수를 함께 교체한다.
6. 사용자가 수정한 단답형에도 `채점 다시 수정`을 제공한다.
7. 한 화면에서는 수정 요청을 하나씩 보내며, 다른 화면이나 탭의 변경과 경합하면 마지막으로 서버에 커밋된 판정이 현재 값이다. 사용자는 결과 재조회로 최종 상태를 확인한다.
8. 사용자는 결과 목록으로 돌아오거나 학습 영역의 복습으로 이동한다.

### E. 복습

1. `틀린 문제 다시 풀기` 진입 시 시스템은 가장 최근 완료한 본 퀴즈 회차의 미해결 문항 수와 활성 review session을 확인한다.
2. 활성 세션이 있으면 그 세션의 고정된 문제 세트를 다시 불러온다. 이전 미제출 답안과 위치는 복원하지 않는다.
3. 활성 세션 없이 대상이 있으면 최신 완료 회차를 원본으로 서버 복습 세션을 만들고, 미해결 문항만 담긴 문제 세트를 원래 번호 오름차순으로 보여준다.
4. 사용자는 본 퀴즈와 같은 이전·다음 구조로 모든 대상 문항을 먼저 푼다. 문항 이동만으로 저장·채점하지 않는다.
5. 마지막에 복습 세션 전체 답안을 한 번 제출하고 객관식·빈칸·단답형을 일괄 채점한다.
6. 작성한 서술형이 있으면 제출 뒤 모범 답안·핵심 포인트·근거를 보고 본 퀴즈와 같은 방식으로 자기평가한다.
7. 모든 채점과 필요한 자기평가가 끝나면 `정답`은 해결, 그 밖의 판정은 미해결로 확정하고 이번 재풀이 결과를 보여준다. 원래 본 퀴즈 답안과 최초 판정은 바꾸지 않는다.
8. 활성 복습 세션이 만들어진 뒤 원본 회차의 단답형 판정이 수정돼도 현재 세션의 문항 snapshot은 유지한다. 문항을 중간에 추가하거나 제거하지 않고, 변경된 복습 대상 여부는 다음 복습 세션부터 반영한다.
9. 복습 판정으로 원본 회차의 복습할 문제 수가 바뀌면 이후 결과 조회가 현재 해결 상태로 요약을 다시 계산한다.

## 분기

### 생성 화면에서 나가기

1. 사용자가 생성 중 뒤로가기를 하면 시스템은 생성이 서버에서 계속됨을 알리는 이탈 확인을 연다.
2. 머물기를 선택하면 오버레이로 돌아간다.
3. 나가기를 선택하면 이전 화면으로 이동하고 서버 생성은 계속된다.
4. 같은 자료에 다시 진입하면 [자료의 활성 생성 조회](../contracts/contract-api-quiz-learning.md#자료의-활성-생성-조회)로 `GENERATING` QuizSet을 재발견한다.
5. 활성 QuizSet이 있으면 그 `quizSetId`의 상태 조회를 재개하고, 없을 때만 새 생성 가능 상태를 보여준다.

### 본 퀴즈 이탈 후 재진입

1. 최종 제출 전 화면을 새로고침하거나 이탈하면 미제출 답안과 위치의 복구를 보장하지 않는다.
2. 사용자가 다시 진입하면 첫 문항부터 새로 푼다.
3. 제출 요청 중 연결이 끊겨도 현재 화면이 답안과 attempt UUID를 유지하면 같은 UUID로 명시적으로 다시 제출할 수 있다.
4. 화면 상태와 UUID를 잃었다면 기존 요청을 자동 탐색하거나 합치지 않고 다시 풀어 새 UUID로 제출한다.

### 서술형 자기평가 재진입

1. 최종 제출 뒤 자기평가를 끝내기 전에 이탈했다면 [미완료 서술형 자기평가 회차 조회](../contracts/contract-api-quiz-learning.md#미완료-서술형-자기평가-회차-조회)로 이미 생성된 `attemptId`와 남은 서술형 문항을 찾는다.
2. 복원 대상이 있으면 문제 번호가 가장 낮은 미평가 서술형부터 자기평가 화면을 복원한다.
3. 복원 대상이 없으면 현재 attempt와 결과 상태 또는 본 퀴즈 시작 가능 상태를 다시 확인한다.

### 복습 서술형 자기평가 재진입

1. review session 상태가 `SELF_ASSESSMENT_REQUIRED`이면 결과 조회의 저장된 답·모범 답안·핵심 포인트·해설·원문 근거로 번호가 가장 낮은 미평가 서술형 화면을 복원한다.
2. 그 서술형 자기평가를 저장하기 전에는 다른 복습 문항으로 건너뛰지 않는다.

### 복습 대상 없음

1. 최근 완료한 본 퀴즈가 없거나 최신 회차의 복습할 문제 수가 0이면 빈 상태를 보여준다.
2. 새 본 퀴즈를 시작하거나 학습자료로 돌아가는 행동을 제공한다.

| 사용자가 명시적으로 이탈 | 서버 생성 식별자 | 생성이 백그라운드에서 계속됨을 안내 | 자료 재진입 시 진행 상태 복원 |

## 중단과 재개

- 생성 상태 조회는 첫 3초 후, 이후 5초마다, 2분 뒤부터 10초마다 수행한다. 화면 이탈 시 조회만 중단하며 서버 생성을 취소하지 않는다.
- 본 퀴즈 최종 제출 전 상태는 열린 화면의 메모리에만 유지하며 지속 저장을 제품 요구사항으로 두지 않는다.
- 현재 화면이 살아 있는 제출 응답 유실에서는 같은 attempt UUID를 재사용할 수 있다. 화면 상태를 잃은 뒤에는 자동 복구하지 않는다.

# [API Contract] 홈 방문 요약

## 문서 책임과 구현 상태

이 문서는 홈의 연속 방문 문구에 필요한 웹·앱·서버 경계를 정의한다. 닉네임은 기존 [인증 API 계약](contract-api-authentication.md)의 `GET /api/v1/users/me`를 사용한다.

아래 endpoint는 **목표 계약이며 아직 서버·웹에 구현되지 않았다.** 구현 전까지 홈은 방문일 숫자를 추정하거나 `0일째`로 대체하지 않고 `오늘도 반가워요`처럼 닉네임만 사용하는 문구를 표시한다.

## 엔드포인트

| 사용자 행동 | Method / Path | 성공 |
| --- | --- | --- |
| 오늘 방문 기록과 연속 방문일 조회 | `POST /api/v1/home-visits` | `200 OK` |

## 오늘 방문 기록과 연속 방문일 조회

`POST /api/v1/home-visits`

- Access Token이 필요하다.
- 요청 body는 없다.
- 서버의 서비스 날짜를 기준으로 현재 사용자의 오늘 방문을 기록하고 연속 방문일을 반환한다.
- 같은 사용자·같은 서비스 날짜의 반복 요청은 방문을 중복 생성하지 않고 같은 현재 결과를 반환한다.
- 이 API는 홈 진입 때 네트워크 재시도나 여러 기기 호출이 발생해도 안전해야 한다.

```json
{
  "success": true,
  "data": {
    "visitDate": "2026-08-28",
    "consecutiveVisitDays": 4
  },
  "error": null
}
```

- `visitDate`는 서버가 이번 방문에 적용한 서비스 날짜의 `YYYY-MM-DD` 값이다.
- `consecutiveVisitDays`는 오늘을 포함한 1 이상의 연속 방문 날짜 수다. 첫 방문은 `1`이며 데이터 없음이나 오류를 뜻하는 `0`을 반환하지 않는다.
- 방문이 하루 이상 끊긴 뒤의 다음 방문은 `1`부터 다시 시작한다.
- 날짜 경계는 서비스 운영 시간대 `Asia/Seoul`의 자정을 사용한다. 클라이언트 시계나 클라이언트가 보낸 날짜를 신뢰하지 않는다.
- 같은 날짜의 여러 로그인·새로고침·기기 진입은 일수에 한 번만 반영한다.

## 오류와 클라이언트 처리

| 조건 | HTTP / code | 클라이언트 처리 |
| --- | --- | --- |
| 인증 없음·만료 | 인증 공통 계약 | 인증 복구 또는 로그인 이동 |
| 일시적 저장·조회 실패 | `500 COMMON_999` | 방문일 문구만 숨기고 나머지 홈 유지, 명시적 재시도 가능 |

클라이언트는 오류를 `0일째`로 바꾸지 않고, 이전 기기 로컬 값으로 서버 연속 방문일을 영구 대체하지 않는다. 성공 응답은 같은 서비스 날짜 동안 캐시할 수 있으며 세션 전환·로그아웃 때 폐기한다.

## 개인정보와 계측

- 일별 방문 원장은 사용자 식별자와 서비스 날짜만으로 충분하며 페이지 이동 이력이나 학습자료 본문을 포함하지 않는다.
- 분석 이벤트와 제품 원장의 연속 방문일이 다를 수 있으므로 분석 로그를 화면 숫자의 원장으로 사용하지 않는다.

## 구현 전 확인

- 서버 저장 모델의 unique 제약은 사용자와 서비스 날짜 조합의 중복 방문을 막아야 한다.
- 웹은 성공 뒤 같은 날짜에 재진입할 때 불필요한 쓰기 호출을 줄일 수 있지만, 클라이언트 캐시는 서버 멱등성을 대체하지 않는다.
- 앱 WebView와 브라우저가 같은 사용자로 호출해도 하나의 연속 방문 원장을 사용한다.

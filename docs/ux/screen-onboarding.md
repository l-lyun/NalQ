# [Screen Spec] 첫 진입 온보딩과 NalQ 가이드

> 이 문서는 가입 직후 한 번 보여주는 모바일 우선 온보딩과 마이페이지에서 다시 여는 가이드의 화면 구조를 정의한다. 회원가입 정책, 공개 랜딩과 퀴즈 학습 정책 자체를 다시 정의하지 않는다.

## 문서 정보

- 화면명: 첫 진입 온보딩, NalQ 가이드
- 문서 상태: `approved`
- 대상 플랫폼: 반응형 웹과 앱 WebView, 모바일 우선
- 관련 기능: [이메일 기반 자체 인증](../prd/prd-local-authentication.md), [퀴즈 학습](../prd/prd-quiz-learning.md), [마이페이지 계정 관리](../prd/prd-mypage-account-management.md)
- 관련 흐름: [인증 흐름](flow-authentication.md)
- 관련 화면: [회원가입](screen-signup.md), [홈](screen-home.md), [마이페이지](screen-mypage.md)
- 관련 공개 화면: [로그인 전 공개 랜딩](screen-public-landing.md)
- 시각 기준: [NalQ 디자인 기준](../../DESIGN.md)
- 최종 수정일: 2026-09-03

## 목표와 범위

- 가입을 마친 신규 사용자가 NalQ의 기본 학습 흐름을 세 장 안에서 부담 없이 훑고 홈으로 이동할 수 있게 한다.
- 설명을 다 읽거나 별도의 과제를 완료하도록 요구하지 않는다. 이 온보딩은 학습 완료 과정이 아니라 한 번 제공되는 제품 소개다.
- 자동 온보딩을 닫은 뒤에도 마이페이지의 `NalQ 가이드`에서 같은 세 장의 핵심 콘텐츠를 다시 볼 수 있게 한다.
- 공개 랜딩의 가입 설득, 회원가입 폼, 실제 학습자료 생성과 퀴즈 풀이는 이 화면의 범위가 아니다.

## 요구사항 구분

### 확정 사항

- 사용자에게 보이는 제품명은 `NalQ`다.
- 자동 온보딩은 가입 성공과 자동 로그인 직후 신규 사용자에게만 한 번 제안한다. 일반 로그인한 기존 사용자는 로컬 표시값 유무와 관계없이 자동 진입시키지 않는다.
- 자동 온보딩은 인증 사용자 전용 단일 route `/onboarding`에서 세 장의 전체 화면 캐러셀로 제공한다. 웹과 앱 WebView가 같은 웹 화면을 사용한다.
- 계정별 로컬 `auto-shown` 값은 첫 화면을 표시하기 직전에 기록한다. 끝까지 봤는지와 현재 장은 기록하지 않는다.
- `건너뛰기`, 브라우저·시스템 뒤로 가기, 새로고침, 브라우저나 앱 종료는 모두 이번 자동 온보딩의 종료로 본다. 다음 인증 진입은 온보딩을 재개하지 않고 홈으로 이동한다.
- 세 장 모두 하단 고정 영역에 primary `건너뛰기`를 유지한다. `이전`과 `다음`은 낮은 위계의 ghost 행동이다.
- 현재 장을 알리는 페이지 인디케이터를 제공한다. 자동 재생과 끝에서 처음으로 돌아가는 순환은 사용하지 않는다.
- 터치 스와이프뿐 아니라 `이전`·`다음`, 키보드 방향키로도 장을 이동할 수 있다. 장 이동은 브라우저 history에 쌓지 않는다.
- 마이페이지의 `NalQ 가이드`는 인증 사용자 전용 `/profile/guide`에서 같은 세 장의 카피와 비주얼을 수동으로 다시 보여준다. 이 진입은 자동 노출 값을 읽거나 변경하지 않는다.
- 자동 온보딩의 화면·문구·버튼과 토큰은 현재 SEED 기준을 사용한다. 캐러셀의 정확한 구현 도구와 옵션은 웹 구현 원장이 책임진다.
- 비주얼은 장식용 카드, 스톡 사진이나 일반적인 AI 일러스트가 아니라 해당 단계의 실제 NalQ 앱 화면을 핵심 영역 중심으로 크게 자른 캡처 슬롯이다. 실제 캡처 준비 전에는 슬롯의 크기와 초점만 검토한다.

### 확정된 화면 결정

- 자동 온보딩은 회원가입 route를 대체 이동한 뒤 표시하고, 이 화면에서 나갈 때도 홈을 대체 이동한다. 자동 노출 대상 판단과 표시값 기록을 마친 같은 중단 없는 이동에서만 `/onboarding`을 렌더링하며, 새로고침처럼 그 이동 맥락이 사라지면 기록된 값에 따라 홈으로 간다.
- 로컬 저장소에 계정별 표시값을 기록할 수 없으면 자동 온보딩을 반복 노출하기보다 홈으로 이동하고, 사용자는 `/profile/guide`에서 내용을 다시 볼 수 있게 한다.
- `/profile/guide`는 같은 콘텐츠를 재사용하되 자동 온보딩 문맥의 `건너뛰기` 대신 `가이드 닫기`를 primary로 보여주고, 닫으면 마이페이지로 돌아간다.
- 페이지 인디케이터의 점은 상태 표시이며 별도의 작은 클릭 대상으로 만들지 않는다. 특정 장 직접 이동이 필요해지면 각 점의 최소 터치 영역과 이름을 갖춘 컨트롤로 다시 설계한다.
- 실제 앱 캡처에는 실사용자 정보가 아닌 검수용 샘플 자료를 사용하고, 시스템 상태바·브라우저 chrome처럼 장의 의미와 무관한 부분은 제거한다.

### 미결정 사항

- 실제 앱 캡처의 최종 asset과 장별 crop 범위. 확정된 슬롯 의미와 개인정보 제외 기준을 바꾸지 않는 범위에서 별도 시각 검수가 필요하다.

## 사용자 목표

- 자동 온보딩: 가입을 마친 사용자가 NalQ에서 글을 가져오고, 문제 방식을 고르고, 헷갈린 부분을 다시 보는 흐름을 짧게 이해한 뒤 홈으로 간다.
- 수동 가이드: 로그인한 사용자가 필요할 때 같은 기본 흐름을 다시 확인하고 마이페이지로 돌아간다.
- 화면 성공 조건: 사용자가 스와이프 없이도 세 장을 탐색할 수 있고, 어느 장에서든 화면을 나갈 수 있다. 끝까지 읽기나 학습 행동은 성공 조건이 아니다.

## 진입과 이탈

### 자동 온보딩 `/onboarding`

- 진입점: 최종 회원가입 성공, 세션 복원과 현재 사용자 식별 완료, 해당 신규 계정의 자동 노출 대상 확인 뒤 진입한다.
- 표시값: 계정별 `auto-shown` 값을 첫 화면 진입 직전에 기록한다. 같은 브라우저나 WebView 저장소에서도 사용자 ID가 다른 계정은 서로 영향을 주지 않는다.
- 다음 화면: 모든 이탈 행동은 로그인된 홈으로 이동한다.
- `건너뛰기`: 어느 장에서 선택해도 홈으로 대체 이동한다.
- 뒤로 가기: 브라우저 Back과 앱의 시스템 Back 모두 온보딩을 종료하고 홈으로 이동한다. 이전 회원가입 단계로 돌아가지 않는다.
- 새로고침·프로세스 종료: 진행 장을 복원하지 않는다. 다시 앱이나 웹을 열면 인증 확인 뒤 홈을 보여준다.
- 로그인·권한 조건: 인증된 사용자만 접근한다. 인증 확인 중에는 온보딩을 먼저 번쩍여 보여주지 않는다. 세션이 없거나 만료됐으면 로그인으로 보내고 안전한 원래 URL의 복귀 가능 범위는 인증 정책을 따른다.
- 기존 사용자: 일반 로그인, refresh 복원, 배포 후 첫 방문만을 이유로 자동 진입시키지 않는다. 재가입으로 새 사용자 ID가 만들어지고 회원가입 성공 흐름을 거치면 새 계정으로 취급한다.

### 수동 가이드 `/profile/guide`

- 진입점: 마이페이지 서비스 영역의 `NalQ 가이드` 행.
- 다음 화면: `가이드 닫기`, 헤더 뒤로 가기와 시스템 뒤로 가기는 마이페이지로 돌아간다. 직접 URL 진입처럼 유효한 이전 마이페이지 이력이 없어도 마이페이지를 안전한 목적지로 사용한다.
- 표시값: 자동 온보딩의 계정별 표시값을 조회, 생성, 갱신, 삭제하지 않는다.
- 로그인·권한 조건: 인증된 사용자만 접근한다. 세션 만료는 인증 흐름을 따른다.

## 정보 구조와 콘텐츠

각 장은 `실제 앱 캡처 슬롯 → 제목 → 한 문단 설명` 순으로 읽힌다. 카드 여러 개로 설명을 나누지 않고, 한 장에는 하나의 장면과 하나의 메시지만 둔다.

### 공통 상단

- 제품명 `NalQ`를 간결하게 표시한다.
- 자동 온보딩에서는 하단 탭과 일반 앱 헤더를 숨겨 한 번에 하나의 안내에 집중시킨다.
- 수동 가이드에는 현재 위치를 알리는 `NalQ 가이드`와 마이페이지로 돌아가는 행동을 제공한다.

### 1장 — 글에서 문제로

- 제목: `읽은 글로 바로 문제를 만들어요`
- 설명: `노션에 정리해 둔 글이나 텍스트를 가져오면, 그 내용에 맞는 문제를 만들 수 있어요.`
- 비주얼 슬롯: 학습자료 본문의 핵심 일부가 문제 화면으로 이어지는 실제 NalQ 화면을 보여준다. `Notion에서 가져오기`와 `텍스트 붙여넣기` 중 적어도 하나의 입력 맥락과 만들어진 문제의 일부가 한눈에 연결되도록 크게 자른다.
- 피할 것: 긴 본문 전체, 작은 글씨가 많은 전체 화면 축소, 문서·문제·설명을 각각 별도 카드로 반복하는 구성.

### 2장 — 학습 방식 선택

- 제목: `공부할 방식은 직접 골라요`
- 설명: `문제 유형과 난이도, 문제 수를 원하는 대로 정할 수 있어요.`
- 비주얼 슬롯: 실제 문제 만들기 화면에서 문제 유형, 난이도와 문제 수 선택 영역을 크게 자른다. 예시 값은 실제 지원 범위 안의 `객관식`, `보통`, `10문제`를 사용할 수 있다.
- 피할 것: 모든 선택지를 설명 문장으로 다시 나열하거나, 실제 제품에 없는 장식용 설정 카드를 만드는 구성.

### 3장 — 결과와 다시 보기

- 제목: `헷갈린 부분만 다시 보면 돼요`
- 설명: `결과와 관련 내용을 함께 확인하고, 틀린 문제만 모아 다시 풀어보세요.`
- 비주얼 슬롯: 결과의 다시 볼 문제 수, `학습자료 본문` 확인과 현재 제품 문구에 맞는 복습 행동이 연결되는 핵심 영역을 크게 자른다.
- 피할 것: 점수 경쟁을 강조하는 그래프, 축하 장식, 실제 복습 정책과 다른 임의 문구.

### 공통 하단 고정 영역

1. 현재 위치: 시각적 점과 보조기술용 `3개 중 N번째` 텍스트로 현재 장을 알린다.
2. 장 이동: 가능한 경우에만 `이전`, `다음` ghost 행동을 보여준다. 첫 장의 `이전`과 마지막 장의 `다음`은 비활성 컨트롤로 자리를 차지시키기보다 노출하지 않는다.
3. 이탈 행동: 자동 온보딩은 모든 장에서 primary `건너뛰기`, 수동 가이드는 설계 가정에 따라 primary `가이드 닫기`를 제공한다.

## 행동

| 우선순위 | 행동 | 발생 조건 | 결과 | 실패 시 |
| --- | --- | --- | --- | --- |
| Primary | `건너뛰기` | 자동 온보딩의 모든 장 | 홈으로 대체 이동 | 같은 화면에 머물며 홈 이동을 다시 시도할 수 있게 한다. 자동 노출 값은 되돌리지 않는다. |
| Primary | `가이드 닫기` | 수동 가이드의 모든 장 | 마이페이지로 이동 | 같은 화면에 머물며 다시 시도할 수 있게 한다. |
| Secondary | `다음` | 1·2장 | 다음 장으로 이동 | 현재 장 유지 |
| Secondary | `이전` | 2·3장 | 이전 장으로 이동 | 현재 장 유지 |
| Secondary | 수평 스와이프 | 터치·포인터 사용, 이동 가능한 방향 | 인접한 장으로 이동 | 경계 장에서는 더 이동하지 않으며 탄성 순환을 만들지 않는다. |
| Secondary | 키보드 방향키 | 캐러셀 영역에 탐색 맥락이 있음 | 왼쪽은 이전, 오른쪽은 다음 장 | 경계 장에서는 현재 장 유지 |
| System | 브라우저·앱 뒤로 가기 | 자동 온보딩 | 홈으로 이동하고 온보딩 종료 | 이전 가입 화면을 노출하지 않는다. |

`이전`·`다음`과 스와이프는 모두 같은 현재 장 상태만 변경하며 URL과 history 항목을 만들지 않는다. 빠른 연속 입력이 들어오면 중간 이동을 쌓지 않고 마지막으로 유효한 인접 장을 안정적으로 확정한다.

| 기본 1장 | 자동 또는 수동 가이드 시작 | 1장 콘텐츠, `3개 중 1번째`, `다음`, primary 이탈 | 다음, 스와이프, 이탈 |

| 기본 3장 | 2장에서 다음 이동 | 3장 콘텐츠, `3개 중 3번째`, `이전`, primary 이탈 | 이전, 스와이프, 이탈 |
| 이미지 준비 전 | 실제 앱 캡처가 아직 없음 | 실제 화면이 들어갈 비율과 초점이 드러나는 중립 placeholder. 완성 제품처럼 보이는 임의 UI는 만들지 않음 | 장 이동과 이탈 |
| 이미지 로드 실패 | 배포된 캡처 asset을 읽지 못함 | 레이아웃이 무너지지 않는 중립 슬롯과 해당 장의 제목·설명 | 장 이동과 이탈 |
| 로컬 기록 실패 | 저장소 차단·예외 | 온보딩 반복 노출을 피하기 위해 홈으로 이동 | 마이페이지에서 가이드 열기 |
| 세션 만료 | 인증이 유효하지 않음 | 개인 화면을 노출하지 않고 인증 필요 상태 | 로그인 |

별도 빈 상태, 성공 축하 화면과 완료 상태는 만들지 않는다. 사용자가 나가면 그대로 종료된다.

## 반응형·WebView 동작

- 기준이 되는 작은 화면 너비는 `320px`다. 기본은 한 열이며 캡처 슬롯과 카피를 세로로 쌓는다.
- 모바일 화면에서는 한 장이 가능한 한 한 뷰포트에 들어오게 하되, 작은 높이와 큰 글자에서 콘텐츠를 줄이거나 자르지 않는다. 콘텐츠 영역만 세로로 스크롤하고 하단 행동 영역은 고정한다.
- 넓은 화면에서도 세 장을 동시에 펼치지 않고 한 장씩 보여준다. 읽기 너비와 캡처 최대 너비를 제한하고 남는 공간은 바깥 여백으로 사용한다.
- 앱 WebView에서는 네이티브 상·하단 safe area를 반영하고, 웹 브라우저에서는 실제 inset이 있을 때만 적용한다. 하단 고정 영역은 `건너뛰기`와 기기 홈 인디케이터가 겹치지 않아야 한다.
- 본문 마지막에는 현재 하단 고정 영역의 실제 높이와 safe area를 합친 여백을 확보해 마지막 문장이 가려지지 않게 한다.
- 이 화면에는 텍스트 입력이 없으므로 소프트 키보드를 열지 않는다. 외부 키보드와 스위치 입력으로 모든 행동에 도달할 수 있어야 한다.
- 큰 글자에서는 제목·설명과 버튼이 줄바꿈되고 컨테이너 높이가 늘어난다. 320px에서도 버튼 레이블을 축소하거나 잘라 한 줄에 억지로 맞추지 않는다.
- 캡처 슬롯은 화면 전체 축소본이 아니라 장별 핵심 영역을 우선한다. 좁은 화면에서는 잘라내는 영역이 바뀌어도 해당 장의 의미 있는 조작과 레이블은 남긴다.
- 자동 온보딩은 앱 스플래시와 인증 확인 다음에 표시하며, 기존 로그인 사용자에게 랜딩이나 온보딩이 잠깐 나타났다 사라지는 전환을 만들지 않는다.

## 모션

- 자동 재생하지 않는다. 사용자의 명시적 스와이프, `이전`·`다음` 또는 방향키 입력으로만 이동한다.
- 기본 이동은 짧고 절제된 수평 전환이며 한 번의 이동에 웹 또는 네이티브 한 계층만 모션을 소유한다.
- `prefers-reduced-motion: reduce` 또는 앱 셸의 모션 감소 설정에서는 수평 이동을 제거하고 즉시 교체하거나 짧은 불투명도 변화만 사용한다.
- 캡처 이미지 자체에 자동 영상, 깜빡임과 장식 애니메이션을 넣지 않는다.
- 순환, 자동 되감기, 무한 스크롤과 사용자의 현재 장을 바꾸는 타이머를 사용하지 않는다.

## 접근성

- 화면에는 하나의 `h1`에 해당하는 접근 가능한 이름 `NalQ 시작 가이드`를 두고, 각 장 제목은 읽기 순서에 맞는 하위 제목으로 제공한다. 현재 보이지 않는 장은 탐색과 낭독 순서에서 제외한다.
- 캐러셀 영역은 이름과 `3개 중 N번째` 상태를 제공한다. 현재 장 변경은 짧은 polite live region으로 알리되 장 전체 문장을 매번 강제로 다시 읽지 않는다.
- 시각적 인디케이터는 색상과 길이만으로 끝내지 않고 보조기술용 현재 순서를 함께 제공한다.
- `이전`, `다음`, `건너뛰기`와 `가이드 닫기`는 최소 `44×44 CSS px` 터치 영역, 명확한 accessible name과 visible focus를 가진다.
- Tab 키는 현재 보이는 장의 실제 컨트롤에만 순서대로 이동한다. 방향키를 지원하더라도 ghost 버튼을 제거하거나 키보드 사용을 강요하지 않는다.
- 스와이프 임계값은 세로 스크롤과 충돌하지 않아야 하며, 스와이프를 사용할 수 없는 사용자에게 동일한 결과의 버튼을 제공한다.
- 실제 앱 캡처가 본문과 같은 의미만 반복하면 장식 이미지로 처리한다. 캡처만이 전달하는 필수 정보가 있으면 짧은 대체 설명을 제공하되 화면 안의 작은 문자열을 모두 나열하지 않는다.
- 포커스는 장이 바뀔 때 예고 없이 버튼에서 제거하지 않는다. `다음`을 실행한 뒤 새 장 제목을 알리고, 다음 Tab 순서가 현재 화면 안에서 이어지게 한다.

## SEED 컴포넌트 매핑

2026-09-03 현재 SEED React Docs와 Rootage에서 `ActionButton`의 `brandSolid`·`ghost`, `Box`·`Flex`·`VStack`과 mobile-first 반응형 prop을 확인했다. `TabsCarousel`은 탭 콘텐츠 전환 역할이므로 온보딩 의미에 맞지 않게 재사용하지 않는다. 정확한 props와 설치 버전은 구현 직전 현재 SEED Docs에서 다시 확인한다.

## 데이터와 개인정보

- 필요한 표시 데이터: 현재 사용자 ID 또는 계정별 로컬 키를 안정적으로 구분할 식별자, 자동 온보딩 진입이 최종 가입 성공에서 시작됐는지 여부.
- 로컬 데이터: `이 계정에 자동 온보딩을 표시하기로 결정했다`는 boolean 또는 버전 값만 저장한다. 현재 장, 마지막 장 도달, 닫은 방식과 완료 여부는 저장하지 않는다.
- 정확한 로컬 키 형식과 버전 갱신 전략은 웹 구현 원장에서 정한다. 이 명세는 같은 저장 공간에서도 계정별 표시 여부가 섞이지 않아야 한다는 사용자 가시 결과만 확정한다.
- 사용자 입력: 없음. 스와이프·버튼 선택은 화면 내 탐색과 이탈 명령일 뿐 서버 데이터로 저장하지 않는다.
- 관련 API 계약: 새 서버 API는 요구하지 않는다. 인증된 사용자 식별과 세션 판정은 [인증 API](../contracts/contract-api-authentication.md)를 따른다.
- 개인정보·민감정보: 캡처에는 실제 사용자 이름, 이메일, 학습자료 원문과 답안을 넣지 않는다. 로컬 표시값과 장 이동을 분석 사건으로 수집하려면 별도 계측 승인이 필요하다.
- 수동 가이드 경계: `/profile/guide` 진입과 장 이동은 자동 표시 여부를 판단하는 로컬 데이터의 근거로 사용하지 않는다.

## 인수 조건

- [ ] 가입 성공과 자동 로그인 뒤 신규 계정의 표시값이 없을 때만 첫 화면 표시 직전에 계정별 값을 기록하고 `/onboarding`을 한 번 보여준다.
- [ ] 일반 로그인한 기존 사용자와 refresh로 복원된 기존 세션은 로컬 표시값이 없어도 자동 온보딩으로 보내지 않는다.
- [ ] 자동 온보딩은 세 장, 단일 route, 비순환·비자동재생이며 장 이동이 URL이나 브라우저 history에 쌓이지 않는다.
- [ ] 각 장은 하나의 핵심 앱 캡처 슬롯, 확정 제목과 짧은 설명만 보여주며 스톡 사진, 장식용 카드와 긴 기능 설명을 사용하지 않는다.
- [ ] 모든 자동 온보딩 장의 하단 고정 영역에 brand 위계 `건너뛰기`가 보이고, 선택하면 홈으로 대체 이동한다.
- [ ] 1·2장의 `다음`, 2·3장의 `이전`, 수평 스와이프와 키보드 방향키가 같은 인접 장 이동을 제공한다.
- [ ] `건너뛰기`, 뒤로 가기, 새로고침과 앱·브라우저 종료 뒤 현재 장이나 완료 상태를 복원하지 않고 다음 인증 진입은 홈을 보여준다.
- [ ] `/profile/guide`는 마이페이지에서 같은 세 장을 열 수 있고 자동 온보딩 표시값을 읽거나 변경하지 않는다.
- [ ] 320px, 작은 높이, 큰 글자와 WebView safe area에서 콘텐츠와 고정 행동이 겹치거나 잘리지 않는다.
- [ ] 모션 감소 설정에서는 수평 이동 없이 장을 바꿀 수 있고, 스와이프 없이도 모든 장 탐색과 이탈이 가능하다.
- [ ] 현재 장은 색상 외 텍스트로 전달되고, 보이지 않는 장은 포커스와 보조기술 탐색에서 제외된다.
- [ ] 이미지 asset 로드 실패와 로컬 표시값 기록 실패에도 화면이 멈추거나 자동 온보딩이 반복되지 않으며 사용자는 홈과 수동 가이드에 도달할 수 있다.
- [ ] 인증·퀴즈·마이페이지 원장은 이 문서의 승인 동작과 같은 진입·안내 책임을 사용한다.

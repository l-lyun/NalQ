## 문서 책임

이 문서는 Expo 앱의 WebView 실행 환경에서 본 퀴즈 미제출 기록을 임시 보존하는 방법만 정의한다. 풀이 상태 모델은 웹 원장이, 사용자 흐름과 서버 계약은 상위 원장이 책임진다.

## 확정 구현 매핑

- MVP에서는 웹 브라우저와 앱 WebView 모두 WebView 내부 `localStorage`를 사용한다.
- 저장 키의 논리 범위는 `userId + quizSetId`이며, 레코드 필드와 7일 만료 규칙은 [웹 임시 보존 원장](../../../web/docs/technical/quiz-solving.md#확정-구현-매핑)과 같은 의미를 사용한다.
- 기록은 제출 성공, 처음부터 시작 또는 로그아웃 시 삭제한다. 제출 요청만으로는 삭제하지 않고 성공 응답을 확인한 뒤 삭제한다.
- WebView가 최종 제출 payload를 만들 때도 웹 원장의 `questionId` 중심 응답과 `blankAnswers` 매핑을 사용한다. HTTP 계약에 없는 `type`이나 누락 빈칸의 빈 문자열을 추가하지 않는다.
- 이 기록은 서버 중간 draft가 아니며 다른 기기로 동기화하지 않는다. WebView 데이터 삭제·초기화 또는 기기 변경 시 유실될 수 있다.

## 현재 앱 구조와 수명주기

- 현재 `app/`은 WebView 셸이므로 웹과 동일한 저장 로직을 WebView 문서 컨텍스트 안에서 실행한다.
- 복원할 때는 현재 인증된 `userId`와 `quizSetId`가 모두 일치하고 만료되지 않은 기록만 사용한다. 계정 전환이나 로그아웃 시 이전 사용자의 기록을 복원하지 않는다.
- 저장소 접근 실패나 손상된 레코드는 서버로 전송하지 않고 폐기하며, 복원 불가 가능성은 상위 사용자 흐름의 이탈 안내를 따른다.

## 향후 확장

- 다기기 이어풀기나 더 강한 복구 보장이 필요해지면 별도 제품·API 결정을 거쳐 서버 draft 방식으로 발전시킬 수 있다. MVP에는 포함하지 않는다.

## 기술 검증 기준

- 앱 종료·재실행 뒤 같은 `userId + quizSetId` 기록만 7일 안에 복원한다.
- 계정 전환, 로그아웃, 만료, 손상된 레코드와 다른 문제 세트 기록은 복원하지 않는다.
- 처음부터 시작과 제출 성공 시 삭제하고, 제출 응답이 유실된 경우에는 삭제하지 않는다.
- WebView 데이터 삭제·초기화 또는 기기 변경 뒤에는 기록이 복원되지 않는다.
- 저장·복원·삭제가 반복되거나 제출 응답이 유실돼도 다른 사용자의 기록을 노출하거나 중복 서버 attempt를 만들지 않는다.

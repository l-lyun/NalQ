# [Execution Plan] 로그인 사용자 배포 전 E2E 점검

이 문서는 첫 운영 배포 전에 기존 로그인 사용자의 핵심 학습 여정을 GPT가 인앱 브라우저에서 직접 조작해 한 차례 검증하는 실행 원장이다. 전용 E2E 러너 도입 전의 탐색형 점검이며, 결과가 반복 자동화 테스트를 대체하지는 않는다.

- 관련 제품 기반: [NalQ 제품 기반](../product.md)
- 관련 PRD: [학습자료 만들기](../prd/prd-content-import.md), [퀴즈 생성·풀이·결과·복습](../prd/prd-quiz-learning.md), [마이페이지와 계정 관리](../prd/prd-mypage-account-management.md)
- 관련 UX: [학습자료 만들기 흐름](../ux/flow-content-import.md), [퀴즈 생성부터 복습까지](../ux/flow-quiz-solving.md), [홈](../ux/screen-home.md), [학습](../ux/screen-learning.md), [마이페이지](../ux/screen-mypage.md)
- 관련 Contract: [인증 API](../contracts/contract-api-authentication.md), [학습·퀴즈 API](../contracts/contract-api-quiz-learning.md), [알림 API](../contracts/contract-api-notifications.md)

## 목표와 완료 조건

### 목표

- 기존 사용자가 로그인해 학습자료를 만들고, 퀴즈 생성·풀이·결과·복습까지 완료할 수 있는지 확인한다.
- 정상 흐름과 함께 실제 사용 중 흔히 발생하는 입력 누락, 미응답 제출, 화면 이탈, 뒤로 가기, 중복 실행 시도를 확인한다.
- 홈·학습·마이페이지와 로그아웃의 기본 내비게이션 및 인증 경계를 확인한다.
- 실패 시 재현 가능한 화면 상태, URL, 조작 단계와 콘솔 오류를 남긴다.

### 완료 조건

- 모든 P0 케이스가 `PASS` 또는 사전에 합의한 `BLOCKED`로 분류된다.
- `BLOCKED`가 아닌 P0 실패가 하나도 없다.
- 생성한 자료·QuizSet·attempt·review session을 제목과 URL로 식별할 수 있다.
- 실패마다 기대 결과, 실제 결과, 마지막 성공 단계와 증거가 기록된다.

## 요구사항 구분

### 확정된 실행 기준

- 기존 가입 계정을 사용하며 회원가입·이메일 인증·비밀번호 변경·비밀번호 재설정은 실행하지 않는다.
- 회원 탈퇴 화면은 진입 여부까지만 확인할 수 있으며 현재 비밀번호 입력과 최종 탈퇴 요청은 실행하지 않는다.
- 실제 배포 후보 웹과 실제 API를 사용한다. 개발용 mock 또는 fixture 화면을 성공 근거로 사용하지 않는다.
- 정상 핵심 흐름 약 70%, 현실적인 엣지케이스 약 30%로 구성한다.
- 개인정보·기밀정보·저작권 문제가 있는 원문은 입력하지 않는다.

### 테스트 가정

- 테스트 계정은 이메일 인증이 완료된 활성 계정이고 로그인할 수 있다.
- 테스트 환경에 퀴즈 생성 공급자, 데이터베이스, Redis 등 실제 의존성이 연결되어 있다.
- 계정에 남은 생성 한도 또는 비용 제한이 테스트 퀴즈 한 세트를 허용한다.
- 선택한 문제 유형마다 반드시 한 문제 이상 생성된다는 보장은 별도 계약으로 확인되지 않았다. 선택 유형 누락은 우선 `COVERAGE GAP`으로 기록하고 생성 요청 자체의 실패와 구분한다.

### 열린 질문

- 테스트 대상이 운영 환경인지 운영과 같은 스테이징 환경인지
- 테스트 계정과 로그인 후 온보딩 완료 여부
- 생성된 테스트 학습자료와 퀴즈를 UI 또는 관리 도구에서 삭제할 수 있는지
- Notion 연결을 이번 배포 게이트에 포함할지 여부

## 범위와 비범위

### P0 범위

- 기존 계정 로그인과 인증된 기본 진입
- 홈·학습·마이페이지 내비게이션
- 텍스트 붙여넣기 학습자료 생성
- 퀴즈 생성 요청, 생성 중 이탈, 완료 알림과 결과 진입
- 문항 이동, 답안 유지, 미응답 안내, 전체 제출
- 자동 채점, 서술형 자기평가, 결과와 복습
- 내 학습자료·내 퀴즈 검색과 생성 항목 식별
- 로그아웃과 보호 화면 접근 차단

### P1 범위

- 퀴즈 이름 변경 후 검색 및 상세 반영
- 풀이 중 새로고침 정책
- 검색 결과 없음에서 정상 목록 복귀
- 작은 모바일 화면에서 핵심 행동 완료
- 이미 연결된 테스트용 Notion 계정이 있을 때 단일 페이지 가져오기

### 비범위

- 회원가입, 이메일 코드 발송·검증, 비밀번호 변경·재설정
- 회원 탈퇴 최종 실행과 실제 데이터 삭제
- CAPTCHA 해결, 소셜 로그인, 결제
- 쿠키·토큰 변조, 침투 테스트, 권한 우회 시도
- 서버 강제 중단, 패킷 손실, 극단적으로 느린 네트워크와 대량 동시 요청
- 20,000자 정확 경계 등 극단값 검증
- 여러 브라우저·기기 동시 편집
- Playwright, MSW 또는 CI 자동화 구축

## 환경과 사전조건

1. 배포 후보 URL과 API가 준비되어 있다.
2. GPT가 조작할 브라우저에서 해당 URL을 열 수 있다.
3. 사용자가 로그인 화면에서 테스트 계정 자격정보를 직접 입력한다. 비밀번호는 채팅에 공유하거나 테스트 기록에 남기지 않는다.
4. 브라우저 콘솔의 기존 오류를 테스트 시작 전에 한 번 기록한다.
5. 화면 너비는 기본 데스크톱으로 시작하며 모바일 검증에서만 임시로 변경한다.
6. 테스트 시작 시각과 배포 commit 또는 버전을 기록한다.

## 테스트 데이터

### 식별 규칙

- 실행 ID: `E2E-YYYYMMDD-HHmm`
- 학습자료 제목: `[E2E-YYYYMMDD-HHmm] 스마트 온실 운영 규칙`
- 변경할 퀴즈 이름: `[E2E-YYYYMMDD-HHmm] 온실 복습`
- 검색어: 실행 ID 전체 또는 `스마트 온실`

### 학습자료 본문

아래처럼 정답 근거가 분명한 합성 자료를 사용한다. 실제 사용자 자료를 복사하지 않는다.

> 스마트 온실은 토마토 모종의 생육 환경을 일정하게 유지하기 위해 센서를 사용한다. 온도 센서는 10분마다 값을 측정한다. 내부 온도가 28도 이상이면 천장 창을 열고, 24도 이하가 되면 창을 닫는다. 토양 수분이 35퍼센트 미만이면 관수 장치를 20초 동안 작동한다. 물탱크 잔량이 15퍼센트 미만이면 관수를 중단하고 관리자에게 점검 알림을 보낸다. 관리자는 매일 오전 9시에 센서 상태와 물탱크 잔량을 확인한다. 이 규칙의 목적은 과열과 수분 부족을 예방하면서 물 사용량을 불필요하게 늘리지 않는 것이다.

### 퀴즈 생성 조건

- 문제 유형: 객관식, 빈칸 채우기, 단답형, 서술형
- 난이도: 보통
- 최대 문제 수: 5문제
- 답안 전략: 자동 채점 문항 중 하나는 의도적으로 오답, 하나는 최초 제출 시 미응답, 나머지는 자료 근거로 응답한다.
- 서술형이 생성되면 자료의 규칙과 목적을 한두 문장으로 설명하고 자기평가를 수행한다.

AI 생성 결과가 매번 달라질 수 있으므로 특정 질문 문구를 기대값으로 고정하지 않는다. 대신 모든 문항이 입력 자료와 관련 있는지, 답안·판정·결과·복습 대상이 같은 문항을 일관되게 가리키는지 확인한다.

## 판정과 증거 규칙

### 결과 상태

- `PASS`: 단계와 기대 결과를 모두 확인했다.
- `FAIL`: 기대 결과와 다른 사용자 가시 동작을 재현했다.
- `BLOCKED`: 테스트 환경, 계정, 생성 한도 또는 외부 의존성 때문에 실행하지 못했다.
- `COVERAGE GAP`: 생성 결과에 특정 문제 유형이 없어 해당 유형을 관찰하지 못했다.
- `NOT RUN`: 시간 또는 선행 실패로 실행하지 않았다.

### 실패 증거

실패마다 다음을 남긴다.

- 케이스 ID와 실패 단계
- 현재 URL과 화면 제목
- 마지막으로 성공한 조작
- 기대 결과와 실제 결과
- 사용자에게 표시된 오류 문구
- 관련 콘솔 `error` 또는 `warning`
- 시각 문제가 핵심일 때만 스크린샷
- 재시도 결과와 중복 데이터 생성 여부

## 실행 시나리오

### E2E-P0-01 로그인과 인증 기본 진입 — 4분

사전조건: 로그아웃 상태이며 기존 테스트 계정을 사용할 수 있다.

1. 배포 후보 URL의 로그인 화면으로 이동한다.
2. 사용자가 이메일과 비밀번호를 직접 입력하고 로그인을 완료한다.
3. 홈 화면의 제목, 환영 영역과 하단 탭을 확인한다.
4. 페이지를 한 번 새로고침한다.

기대 결과:

- 로그인 요청은 한 번만 처리되고 인증된 기본 화면으로 이동한다.
- 새로고침 후에도 세션이 유지되고 개인 홈이 정상 복원된다.
- 로그인 화면으로 즉시 되돌아가거나 빈 화면이 나타나지 않는다.

### E2E-P0-02 전역 내비게이션 — 3분

사전조건: 로그인된 홈 화면이다.

1. 하단 탭으로 `학습`에 이동한다.
2. 학습 화면의 최근 퀴즈, 새 문제 만들기, 복습, 전체 보기 영역을 확인한다.
3. `마이페이지`로 이동해 계정 요약과 서비스 정보가 보이는지 확인한다.
4. `홈`으로 돌아온다.

기대 결과:

- 선택한 탭, 화면 제목과 URL이 일치한다.
- 탭 이동 중 인증 화면, 빈 화면 또는 전체 오류가 끼어들지 않는다.
- 각 화면에서 다른 두 탭을 계속 사용할 수 있다.

### E2E-P0-03 학습자료 필수 입력과 취소 복구 — 4분

사전조건: 학습 탭에 있다.

1. `새 문제 만들기`에서 텍스트 입력 방식을 선택한다.
2. 제목과 본문을 비운 채 저장을 시도한다.
3. 제목만 입력하고 다시 저장을 시도한다.
4. 브라우저 또는 화면의 뒤로 가기로 이전 화면에 복귀한다.

기대 결과:

- 필수값이 없을 때 자료가 저장되지 않고 부족한 필드 근처에 이해 가능한 안내가 표시된다.
- 오류가 색상만으로 전달되지 않는다.
- 취소 후 학습 화면으로 돌아오며 빈 자료가 목록에 추가되지 않는다.

### E2E-P0-04 학습자료 저장과 퀴즈 생성 화면 연결 — 5분

사전조건: 학습자료 생성 화면에 다시 진입할 수 있다.

1. 테스트 제목과 합성 본문을 입력한다.
2. `저장하고 퀴즈 만들기`를 한 번 선택한다.
3. 저장 중 버튼과 입력 상태를 관찰한다.
4. 퀴즈 생성 조건 화면에 표시된 학습자료 제목을 확인한다.

기대 결과:

- 저장 중 같은 행동이 비활성화되어 중복 제출이 방지된다.
- 학습자료가 한 건만 생성된다.
- 생성 조건 화면에서 방금 저장한 자료를 올바르게 식별한다.
- 오류가 발생하면 입력값이 유지되고 재시도할 수 있다.

### E2E-P0-05 퀴즈 생성 요청과 생성 중 이탈 — 7분

사전조건: 새 자료의 퀴즈 생성 조건 화면이다.

1. 네 가지 유형, 보통, 5문제를 선택한다.
2. OpenAI 전송 안내에서 자료 본문과 생성 조건이 전송 대상임을 확인한다.
3. 생성 버튼을 한 번 선택하고 처리 중 중복 실행이 막히는지 확인한다.
4. 생성 중 홈 또는 학습 탭으로 이동한다.
5. 내 퀴즈에서 생성 중 항목을 확인할 수 있으면 이름 변경과 풀이 행동이 비활성화되는지 확인한다.

기대 결과:

- 생성 요청은 한 번만 접수된다.
- 생성 중 가짜 완료 퍼센트 없이 진행 상태가 표시된다.
- 화면에서 이탈해도 생성 작업이 계속된다.
- 생성 중인 같은 자료를 다시 요청할 수 없고 이유를 이해할 수 있다.

### E2E-P0-06 생성 완료 알림과 퀴즈 진입 — 최대 8분

사전조건: 퀴즈 생성이 서버에서 진행 중이다.

1. 다른 기본 화면에 머물며 완료 알림을 기다린다.
2. 전역 알림 또는 알림 목록에서 생성 결과를 확인한다.
3. 완료 알림의 행동을 선택한다.
4. 퀴즈 제목, 부모 학습자료명, 문항 수를 확인한다.

기대 결과:

- 생성 성공과 단순 네트워크 조회 실패가 같은 실패로 표시되지 않는다.
- 완료 알림은 해당 QuizSet으로 연결된다.
- 퀴즈와 부모 학습자료가 서로 다른 정보로 구분된다.
- 제한 시간 내 끝나지 않으면 무한 대기하지 않고 `BLOCKED` 또는 실제 생성 실패로 기록한다.

### E2E-P0-07 풀이 이동과 답안 유지 — 5분

사전조건: READY QuizSet의 본 퀴즈를 시작할 수 있다.

1. 첫 문항에 답한다.
2. 다음 문항으로 이동해 답을 입력한다.
3. 이전 문항으로 돌아가 첫 답이 유지되는지 확인한다.
4. 다시 앞으로 이동한다.
5. 자동 채점 문항 하나는 의도적으로 틀리게 답하고, 다른 하나는 비워 둔다.

기대 결과:

- 문항 번호, 전체 문항 수와 현재 위치가 일치한다.
- 앞뒤 이동만으로 이미 입력한 답이 사라지지 않는다.
- 제출 전에는 정답·해설·정오답 판정이 노출되지 않는다.

### E2E-P0-08 미응답 제출 경고와 전체 제출 — 4분

사전조건: 한 문항이 미응답인 상태로 마지막 문항까지 이동했다.

1. 전체 제출을 선택한다.
2. 미응답 안내와 가능한 행동을 확인한다.
3. 가장 낮은 미응답 문항으로 이동하는 행동을 선택한다.
4. 미응답 위치가 정확한지 확인한 뒤 다시 제출하고, 이번에는 미응답을 포함한 제출을 확정한다.

기대 결과:

- 경고 없이 즉시 제출되지 않는다.
- 안내에서 미응답이 오답과 복습 대상에 포함됨을 이해할 수 있다.
- 가장 낮은 미응답 문항으로 정확히 이동한다.
- 최종 확정 뒤 중복 attempt가 생성되지 않는다.

### E2E-P0-09 채점·자기평가·결과 일관성 — 6분

사전조건: 본 퀴즈 제출이 완료되었다.

1. 작성한 서술형이 있으면 자기평가 화면을 확인한다.
2. 내 답, 모범 답안, 핵심 포인트, 해설과 `학습자료 본문`을 비교한다.
3. `정답`, `보완 필요` 또는 `오답` 중 근거에 맞는 값을 저장한다.
4. 마지막 평가 후 결과 화면으로 이동한다.
5. 자동 채점 점수, 서술형 자기평가 요약과 다시 풀 문제 수를 확인한다.

기대 결과:

- 서술형 자기평가는 자동 점수와 분리된다.
- 저장한 자기평가가 다음 문항 또는 결과에 반영된다.
- 의도적 오답과 미응답이 결과 및 다시 풀 문제 수에 포함된다.
- 문항별 판정과 결과 요약이 모순되지 않는다.

서술형이 생성되지 않았다면 자기평가 부분만 `COVERAGE GAP`으로 기록하고 결과 검증은 계속한다.

### E2E-P0-10 결과에서 즉시 복습 — 5분

사전조건: 최신 MAIN 결과에 다시 풀 문제가 하나 이상 있다.

1. 결과 하단의 `복습하기`를 선택한다.
2. 복습 문항 수와 원래 오답·미응답 문항이 대응하는지 확인한다.
3. 모든 복습 문항을 자료 근거에 맞게 답한다.
4. 전체 제출하고 필요한 자기평가를 완료한다.
5. 복습 결과와 남은 미해결 문항 수를 확인한다.

기대 결과:

- 학습 메인을 경유하지 않고 복습을 시작한다.
- 최신 본 퀴즈의 미해결 문항만 원래 번호 순으로 제시된다.
- 복습에서도 제출 전 즉시 정답을 노출하지 않는다.
- 모두 해결했다면 다음 복습 대상에서 제거되며 원본 회차의 최초 결과가 덮어써지지 않는다.

### E2E-P0-11 관리 목록 검색과 데이터 식별 — 4분

사전조건: 테스트 자료와 QuizSet이 생성되어 있다.

1. `학습 > 내 학습자료 전체 보기`로 이동한다.
2. 실행 ID로 검색해 테스트 자료를 찾고 상세 화면을 연다.
3. 뒤로 가서 검색 맥락 또는 목록 복귀가 자연스러운지 확인한다.
4. `내 퀴즈 전체 보기`로 이동해 같은 실행 ID 또는 제목으로 퀴즈를 찾는다.

기대 결과:

- 검색 결과에 테스트 항목이 한 건만 나타난다.
- 학습자료와 퀴즈의 제목·상태가 올바르게 구분된다.
- 상세 진입과 뒤로 가기에서 엉뚱한 화면으로 이동하지 않는다.

### E2E-P0-12 마이페이지, 공개 정보와 로그아웃 — 5분

사전조건: 로그인 상태이고 모든 쓰기 흐름을 마쳤다.

1. 마이페이지에서 닉네임과 이메일이 현재 테스트 계정과 일치하는지 확인한다.
2. NalQ 가이드를 열었다가 마이페이지로 돌아온다.
3. 이용약관, 개인정보처리방침, 문의, 오픈소스 라이선스 진입점을 확인한다.
4. 회원 탈퇴 화면은 안내 첫 단계까지만 열고 뒤로 나온다. 비밀번호나 `회원탈퇴` 문구를 입력하지 않는다.
5. 로그아웃을 선택하고 확인 대화상자를 승인한다.
6. 브라우저 뒤로 가기와 보호 URL 직접 진입을 각각 시도한다.

기대 결과:

- 다른 사용자의 계정 정보가 보이지 않는다.
- 공개 정보 화면에서 다시 앱으로 복귀할 수 있다.
- 회원 탈퇴는 확인 입력이나 최종 요청 없이 안전하게 이탈한다.
- 로그아웃 후 개인 캐시와 인증 상태가 제거되고 보호 화면은 로그인 흐름으로 이동한다.

## P1 추가 시나리오

### E2E-P1-01 퀴즈 이름 변경 — 3분

READY 퀴즈를 펼쳐 테스트용 변경 제목으로 저장한다. 목록·검색·상세에서 새 제목이 반영되고 부모 학습자료명, 문제와 풀이 기록은 바뀌지 않아야 한다.

### E2E-P1-02 검색 결과 없음 복구 — 2분

내 학습자료와 내 퀴즈에서 존재하지 않는 문자열을 검색한다. 결과 없음 안내가 표시되고 검색어를 지우면 전체 목록과 테스트 항목이 다시 나타나야 한다.

### E2E-P1-03 풀이 중 새로고침 — 3분

새 본 퀴즈 회차를 시작해 첫 답을 입력한 뒤 새로고침한다. 현재 제품 정책대로 열린 화면의 미제출 답안은 복원되지 않고 첫 문항부터 시작해야 하며, 완료되지 않은 attempt가 결과처럼 노출되어서는 안 된다.

### E2E-P1-04 작은 화면 — 4분

일반적인 모바일 너비에서 학습자료 입력, 퀴즈 풀이, 자기평가와 마이페이지를 확인한다. 가로 스크롤 없이 핵심 CTA를 누를 수 있고 키보드가 입력·제출 행동을 가리지 않아야 한다.

### E2E-P1-05 Notion 단일 페이지 가져오기 — 별도 5~10분

테스트 전용 Notion 계정이 이미 연결되어 있고 사용자가 해당 페이지 전송을 승인한 경우에만 수행한다. OAuth 신규 연결이나 개인 페이지 접근은 이번 기본 실행에 포함하지 않는다.

## 실행 순서와 시간 상한

```text
준비·기존 오류 기록 (3분)
  → 인증·내비게이션 (P0-01~02, 7분)
  → 자료 입력·생성 (P0-03~06, 최대 24분)
  → 풀이·결과·복습 (P0-07~10, 20분)
  → 관리·마이페이지·로그아웃 (P0-11~12, 9분)
```

- 목표 시간: 45~60분
- 생성 대기가 길어져 60분을 넘기면 P1은 실행하지 않는다.
- 선행 P0 실패가 후속 흐름을 막으면 억지로 URL이나 DB 상태를 조작하지 않고 후속 케이스를 `BLOCKED`로 기록한다.

## 배포 차단 기준

### 즉시 차단

- 다른 사용자의 계정, 학습자료, 퀴즈 또는 결과가 노출된다.
- 로그아웃 후 보호 화면이나 개인 캐시에 접근할 수 있다.
- 한 번의 사용자 행동으로 자료, QuizSet 또는 attempt가 중복 생성된다.
- 결과 요약과 문항별 판정이 모순되거나 원본 풀이 기록이 복습으로 덮어써진다.
- 회원 탈퇴 최종 요청처럼 승인하지 않은 파괴 행동이 실행된다.

### P0 실패로 차단

- 로그인 후 홈에 도달하지 못한다.
- 텍스트 자료 저장, 퀴즈 생성, 풀이 제출, 필요한 자기평가, 결과 또는 복습 중 하나를 완료할 수 없다.
- 생성 완료 후 알림과 실제 QuizSet을 연결할 수 없다.
- 사용자가 복구할 수 없는 빈 화면, 무한 로딩 또는 반복 오류가 발생한다.

### 조건부 판단

- P1만 실패하면 핵심 흐름 영향과 우회 가능성을 확인해 배포 여부를 별도 판단한다.
- 외부 생성 공급자나 테스트 환경 설정 문제는 제품 결함과 분리해 `BLOCKED`로 기록하되, 운영 환경에도 같은 설정이면 배포를 차단한다.
- 콘솔 경고만 있고 사용자 흐름과 데이터에 영향이 없으면 증거를 남기고 심각도를 별도 평가한다.

## 중단과 안전 기준

- 실제 사용자 데이터 또는 다른 계정 정보가 보이면 즉시 조작을 중단한다.
- 회원 탈퇴 최종 버튼, 비밀번호 변경, 이메일 발송 또는 외부 OAuth 승인 단계에는 진입하지 않는다.
- 예상하지 못한 유료 결제, 권한 부여, 외부 전송 또는 데이터 삭제 확인이 나타나면 사용자 확인 전 진행하지 않는다.
- 같은 실패 행동을 세 번 이상 반복하거나 중복 데이터를 추가로 만들지 않는다.

## 정리

1. 실행 결과에 생성한 학습자료명, 퀴즈명과 관련 URL을 기록한다.
2. 변경한 퀴즈 이름이나 닉네임이 있으면 원래 값으로 복구한다.
3. 삭제 기능이 검증 범위에 없으므로 테스트 자료는 자동 삭제하지 않는다. 삭제 방법이 승인되면 식별된 `[E2E-*]` 항목만 별도 정리한다.
4. 마지막 단계에서 로그아웃한다.
5. 테스트용 브라우저 탭과 임시 모바일 viewport를 원래 상태로 되돌린다.

# [Screen Spec] 공개 서비스 정보와 푸터

> 이 문서는 NalQ의 공개·인증 화면 푸터와 로그인 없이 읽을 수 있는 서비스 정보 화면의 UX 기준을 정의한다. 법률 문서의 실제 조항, 개인정보 처리 항목·보유기간과 법적 적정성은 이 문서가 확정하지 않는다.

## 문서 정보

- 화면명: 공개 푸터, 이용약관, 개인정보처리방침, 문의하기, 오픈소스 라이선스
- 문서 상태: `draft`
- 요구사항 상태: 공개 브랜드·운영자·문의 채널·정보 구조·기준 경로는 사용자 확정, 실제 법률 전문과 운영자 주소는 미확정
- 대상 플랫폼: 반응형 웹과 앱 WebView, 모바일 우선
- 관련 기능: [마이페이지 계정 관리](../prd/prd-mypage-account-management.md), [이메일 기반 자체 인증](../prd/prd-local-authentication.md)
- 관련 화면: [마이페이지](screen-mypage.md), [회원가입](screen-signup.md)
- 최종 수정일: 2026-09-03

## 요구사항 구분

### 확정 사항

- 사용자 대면 서비스명은 `NalQ`다. 개인 운영자 이름은 `김도현`, 공개 문의 이메일은 `kimdohyun032@gmail.com`이다.
- 이용약관, 개인정보처리방침, 문의하기와 오픈소스 라이선스는 로그인하지 않은 사용자도 직접 열 수 있다.
- 공개·인증 화면은 본문 뒤에 NalQ와 네 개의 서비스 정보 링크, 운영자·문의 이메일, 저작권 정보를 담은 비고정 푸터를 제공한다.
- 로그인 후 홈·학습 같은 주 기능 화면에는 같은 푸터를 반복하지 않는다. 로그인 사용자는 마이페이지 `서비스 정보`에서 동일한 목적지에 접근한다.
- 첫 배포에는 광고·마케팅 이메일과 선택 동의 기능이 없으므로 푸터·서비스 정보·공개 문서에 마케팅 동의 메뉴를 두지 않는다.
- SEED Design 고지는 로그인 후 `마이페이지 > 서비스 정보 > 오픈소스 라이선스`와 공개 `/open-source-licenses` 화면에서 제공한다. 앱 일반 화면, 메인 푸터와 앱스토어·플레이스토어 설명에는 `SEED 사용`이나 `Powered by 당근`을 반복 표기하지 않는다.
- SEED 항목에는 `SEED Design`, `Copyright 2025 주식회사 당근마켓`, Apache License 2.0 전문과 공식 원문 링크, 공식 NOTICE를 제공한다. 저장소 README의 표기는 보조 고지일 뿐 배포 사용자에게 고지를 전달하는 유일한 수단으로 보지 않는다.
- 웹·앱 배포 산출물에도 SEED의 LICENSE와 NOTICE를 포함한다. 당근 로고·캐릭터를 사용하지 않고 당근과 제휴·후원 관계로 오인될 표현을 쓰지 않는다.
- 사용자에게 보이는 서비스명에 `OpenMD`를 사용하지 않는다. 저장소명·패키지명 같은 기술 식별자는 이 화면 범위가 아니다.

### 설계 가정

- 공개 정보의 기준 경로는 짧고 인증 상태와 무관한 `/terms`, `/privacy`, `/support`, `/open-source-licenses`로 둔다.
- 문의 화면은 별도 문의 폼 없이 기본 메일 앱을 여는 행동과 주소 복사를 함께 제공한다. 첫 배포에서 운영 가능한 채널이 이메일 하나이기 때문이다.
- 법률 문서는 한 열의 긴 글 읽기 화면으로 제공한다. 넓은 화면에서도 본문 줄 길이를 제한하고, 목차는 조항 수가 충분할 때만 보조 탐색으로 제공한다.
- 푸터의 저작권 연도는 첫 공개연도인 `2026`을 사용한다. 연도 갱신 방식은 구현에서 정하되 사용자에게 `© 2026 NalQ`로 표시한다.

### 미결정 사항

- 이용약관과 개인정보처리방침의 승인된 전문, 실제 시행일과 첫 운영 버전 식별자
- 개인정보처리방침과 이용약관에 공개할 개인 운영자의 주소. 현재 제공되지 않았으므로 임의 주소, 저장소 경로나 기술 프로젝트명을 대신 표시하지 않는다.
- 약관·방침 변경을 알릴 앱 내 위치와 사전 고지 기간. 최소 원칙은 시행일 전에 변경 내용과 시행일을 사용자가 확인할 수 있게 고지하는 것이며, 법률 검토에서 더 강한 기준이 정해지면 그 기준을 따른다.
- 문의 대응 가능 시간과 목표 응답 기간. 확정 전에는 즉시 응답을 약속하지 않는다.

## 사용자 목표

- 가입 전후와 로그인 여부에 관계없이 현재 적용되는 약관·개인정보처리방침, 운영자와 문의 방법, 제3자 오픈소스 고지를 확인한다.
- 문의가 필요하면 자신의 환경에서 메일 작성을 시작하거나 이메일 주소를 복사할 수 있다.
- 각 문서의 버전과 시행일을 확인하고 현재 적용 문서인지 판단할 수 있으면 화면 목적을 달성한 것으로 본다.

## 기준 경로와 호환 원칙

| 목적지 | 기준 경로 | 로그인 | 기존 경로 호환 |
| --- | --- | --- | --- |
| 이용약관 | `/terms` | 불필요 | `/profile/terms`는 로그인 요구 없이 `/terms`로 대체 이동한다. |
| 개인정보처리방침 | `/privacy` | 불필요 | `/profile/privacy`는 로그인 요구 없이 `/privacy`로 대체 이동한다. |
| 문의하기 | `/support` | 불필요 | `/profile/inquiry`는 로그인 요구 없이 `/support`로 대체 이동한다. |
| 오픈소스 라이선스 | `/open-source-licenses` | 불필요 | 첫 배포 이전 신규 경로이므로 기존 별칭은 없다. |

- 마이페이지와 푸터는 모두 기준 경로를 직접 사용한다. `/profile/*` 법률·문의 경로는 기존 북마크와 배포된 딥링크를 깨지 않기 위한 호환 진입점일 뿐 새 링크에 사용하지 않는다.
- 호환 진입점은 인증 화면으로 우회시키지 않고 기준 공개 경로에 도착시킨다. 사용자가 로그아웃했거나 세션이 만료돼도 문서 열람을 막지 않는다.
- `/profile/marketing`은 첫 배포 범위에 대응하는 공개 목적지가 없다. 메뉴와 정상 진입 경로를 제거하고, 과거 직접 접근은 마이페이지 또는 적절한 공개 시작 화면으로 안전하게 안내한다. 마케팅 동의가 존재하는 것처럼 빈 상태를 노출하지 않는다.
- 공개 문서에서 뒤로 가기는 유효한 이전 화면이 있으면 그 화면으로 돌아간다. 직접 URL·외부 링크로 진입해 이전 이력이 없으면 공개 시작 화면으로 이동할 수 있는 `NalQ로 돌아가기`를 제공한다.

## 공개·인증 화면 푸터

- 로그인 후 앱 셸, 몰입형 퀴즈, 마이페이지 하위 화면에는 반복 노출하지 않는다.

### 정보 순서

1. 서비스명 `NalQ`
2. 링크: `이용약관` · `개인정보처리방침` · `문의하기` · `오픈소스 라이선스`

푸터는 인증 폼의 완료 행동보다 시각적으로 낮은 위계에 두고, 본문과 충분히 구분하되 카드나 고정 바처럼 강조하지 않는다. 본문이 짧아도 화면 하단 방향에 머물 수 있으나 viewport에 고정해 입력, 키보드 또는 주 행동을 덮지 않는다.

## 공개 문서 공통 구조

1. **공개 헤더**: `NalQ`와 `NalQ로 돌아가기` 또는 문맥에 맞는 뒤로 가기
2. **문서 제목**: 이용약관, 개인정보처리방침, 문의하기 또는 오픈소스 라이선스
3. **문서 메타정보**: 법률 문서는 `시행일`과 `버전`을 제목 가까이에 표시한다. 초안·임시본을 운영 중인 문서처럼 표시하지 않는다.
4. **본문**: 승인된 전문 또는 문의·라이선스 정보. 제목 계층과 문단 구조를 유지한다.
5. **관련 행동**: 다른 법률 문서 이동, 문의 메일 열기·주소 복사 등 현재 문서에 필요한 행동만 제공한다.
6. **공개 푸터**: 공통 서비스 정보와 운영자 정보를 반복 제공한다.

### 이용약관

- 화면 제목, 시행일, 버전, 승인된 약관 전문을 표시한다.
- 회원가입에서 `서비스 이용약관 보기`를 선택하면 같은 운영 전문을 현재 가입 맥락을 잃지 않는 방식으로 보여준다. 별도 임시 전문을 두 원장처럼 운영하지 않는다.
- 변경 시 변경된 내용과 시행일을 사용자가 시행 전에 확인할 수 있게 고지한다. 재동의가 필요한 변경의 판단은 법률·제품 정책에서 별도 확정한다.

### 개인정보처리방침

- 화면 제목, 시행일, 버전, 승인된 개인정보처리방침 전문을 표시한다.
- 실제 수집·이용 항목, 목적, 보유·파기, 회원탈퇴 처리, 법령상 별도 보존, 위탁·외부 제공, 이용자 권리와 문의 방법은 실제 서비스 동작을 기준으로 작성돼야 한다. 이 화면 명세가 내용을 발명하지 않는다.
- 탈퇴 데이터 처리는 [마이페이지 계정 관리 PRD](../prd/prd-mypage-account-management.md#회원-탈퇴와-데이터-처리--확정)의 즉시 접근 차단과 최대 30일 처리 완료 기준과 모순되지 않아야 한다.
- 변경 고지는 이용약관과 같은 공통 원칙을 따르되 법령상 별도 기준이 있으면 그것을 우선한다.
- 첫 배포의 OpenAI API 처리에 관해 전송 항목·제외 항목, 처리 목적, 데이터 공유 opt-in 미사용, Responses API `store: false` 원칙과 기본 abuse monitoring의 통상 최대 30일 보관 가능성을 실제 운영 조건에 맞게 알린다. 법률상 의무나 서비스·제3자 보호에 합리적으로 필요한 경우 더 오래 보관될 수 있는 예외도 함께 밝히며, Zero Data Retention 승인을 확인하기 전에는 즉시 삭제나 무보관으로 표현하지 않는다.

### 문의하기

- `NalQ 문의`, 운영자 `김도현`, 공개 문의 이메일을 명시한다.
- 주 행동 `이메일로 문의하기`는 `mailto:kimdohyun032@gmail.com`을 열고 제목에 `[NalQ 문의]`를 미리 채울 수 있다. 사용자가 입력하지 않은 개인정보, 계정 정보, 학습내용을 제목이나 본문에 자동 삽입하지 않는다.
- `이메일 주소 복사`를 항상 함께 제공한다. 메일 앱이 없거나 WebView가 외부 앱 전환을 허용하지 않아도 주소를 직접 선택하거나 복사할 수 있어야 한다.
- 메일 앱 열기 성공을 확정적으로 감지할 수 없는 환경에서는 성공 토스트를 거짓으로 표시하지 않는다. 복사 성공은 짧은 상태 메시지로 알리고, 클립보드 권한 거부 시 선택 가능한 원문 이메일과 수동 복사 안내를 유지한다.
- 긴급 대응, 24시간 응답 또는 특정 처리기한은 운영 기준이 확정되기 전 약속하지 않는다.
- 같은 공개 이메일에서 일반 문의와 `저작권 침해 신고`를 구분해 시작할 수 있게 한다. 신고 안내는 대상 자료·문제 식별 정보와 권리 근거 등 처리에 필요한 정보만 요청하고, 신고 접수 뒤 임시 제한·사용자 소명·삭제 또는 복원·반복 악의 위반의 단계 조치가 가능함을 알린다.

### 오픈소스 라이선스

- 앱 배포물에 포함된 오픈소스 소프트웨어의 이름, 사용 버전, 저작권 고지, 라이선스 종류와 라이선스·NOTICE 전문 또는 전문을 확인할 수 있는 배포 내 경로를 제공한다.
- SEED Design 항목에는 `SEED Design`, `Copyright 2025 주식회사 당근마켓`, `Licensed under the Apache License, Version 2.0`을 표시하고 Apache License 2.0 전문과 공식 원문 링크, SEED 공식 NOTICE를 확인할 수 있게 한다.
- 이 고지는 오픈소스 라이선스 화면과 배포 산출물에서 제공한다. 저장소 README에 같은 내용을 둘 수 있지만 README만으로 배포 사용자 고지를 대신하지 않는다.
- 앱 일반 화면, 메인 푸터와 스토어 설명에는 SEED 또는 `Powered by 당근`을 반복 표시하지 않는다. 화면과 푸터에서 당근 로고·캐릭터를 사용하지 않고 `당근 제공`, `당근 공식`, `당근과 함께`처럼 제휴·보증·후원으로 읽힐 표현을 금지한다.

## 반응형·WebView 동작

- 작은 WebView에서는 한 열로 쌓고 링크는 두 줄 이상으로 자연스럽게 줄바꿈한다. 링크 사이 구분 기호를 보조기기가 반복해 읽지 않게 한다.
- 푸터는 고정하지 않고 안전 영역을 포함한 화면 하단 여백 뒤에 놓는다. 가상 키보드가 열리면 인증 입력과 주 행동이 먼저 보이도록 푸터가 아래로 밀려난다.
- 넓은 화면에서는 푸터 링크를 한 줄 또는 짧은 두 줄로 배치할 수 있지만 정보 순서와 키보드 순서는 모바일과 같다. 문서 본문은 읽기 폭을 제한하고 남는 너비는 바깥 여백으로 사용한다.
- WebView에서 `mailto:` 외부 이동이 차단되거나 앱이 설치되지 않은 경우 현재 화면과 입력 맥락을 유지한다. 외부 전환 실패의 유일한 복구책을 시스템 뒤로 가기로 두지 않는다.
- 200% 텍스트 확대, 긴 이메일·라이선스 이름에서도 가로 스크롤 없이 읽을 수 있어야 한다. 컨테이너와 링크 높이는 내용에 따라 늘어난다.

## 접근성

- `main`과 `footer` 영역을 구분하고 문서 제목은 유일한 1단계 제목으로 둔다. 전문의 조항 제목은 순서를 건너뛰지 않는다.
- 푸터 링크는 시각적 나열 순서와 DOM·키보드 순서가 같다. 현재 문서 링크에는 현재 위치를 텍스트 또는 적절한 접근성 상태로 전달한다.
- 링크의 포커스 표시를 유지하고, 링크·복사 버튼의 터치 영역은 최소 44×44 CSS px를 확보한다.
- 이메일 주소는 화면에 텍스트로도 제공해 `mailto:` 성공 여부나 색상만으로 문의 경로를 전달하지 않는다.
- 문서 로딩·오류와 복사 결과는 상태 텍스트로 전달한다. 장시간 유지돼야 할 오류를 일시적 알림에만 넣지 않는다.
- 라이선스 고지의 접기·펼치기 상태, 문서 내 목차와 대상 제목의 관계를 보조기기에 전달하고 포커스가 예측 가능하게 이동해야 한다.

## 데이터와 계약

- 필요한 표시 데이터: 공개 서비스명, 운영자 이름, 문의 이메일, 저작권 연도, 문서 제목·버전·시행일·전문, 오픈소스 이름·버전·저작권·LICENSE·NOTICE
- 사용자 입력: 메일 앱에서 사용자가 직접 작성하는 문의. NalQ 화면은 별도 문의 본문을 수집하지 않는다.
- 개인정보: `mailto:`에 사용자 이메일, 계정 ID, 학습자료명이나 진단 정보를 자동 첨부하지 않는다. 주소 복사 행동에는 사용자 개인정보가 추가되지 않는다.
- 운영 문서 경계: 가입 동의와 공개 페이지가 같은 승인 버전을 가리켜야 한다. 개발·검수용 임시 문안을 운영 배포의 현재 문서로 사용하지 않는다.
- 이 화면에는 별도 API 계약을 확정하지 않는다. 원격 문서 조회나 라이선스 생성 방식은 구현 원장의 책임이다.

## 출시 차단 조건

- 승인된 이용약관·개인정보처리방침 전문과 가입 동의 버전이 확정되기 전에는 운영 빌드에서 법률 문서 경로, 링크와 회원가입 진입을 노출하지 않는다. 개발 빌드의 임시 전문은 화면 검수에만 사용한다.
- 회원탈퇴는 비밀번호 재설정 흐름과 30일 내 연결 데이터 삭제·비식별화 작업이 모두 구현되기 전에는 운영 빌드에서 진입 경로를 노출하지 않는다. 개발 빌드에서는 서버 계약 검증을 위해 접근할 수 있다.
- 문의와 오픈소스 라이선스는 위 출시 차단과 무관하게 공개한다.

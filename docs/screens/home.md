# 홈 화면 명세

## 문서 정보

- 문서 상태: `draft`
- 요구사항 상태: 핵심 역할과 하단 탭은 확인됨, 다음 행동 우선순위와 세부 표현은 UX 초안
- 대상 플랫폼: 모바일 WebView 우선
- 관련 기능: `docs/features/00-home.md`
- 관련 내비게이션: `docs/product/navigation.md`

## 요구사항 구분

### 확정 사항

- 최상위 하단 내비게이션은 `홈`, `학습`, `프로필` 세 영역으로 시작한다.
- 학습 자료, 복습과 문제 만들기는 별도 하단 탭으로 분리하지 않고 `학습` 영역에서 함께 다룬다.
- 홈의 핵심은 통계 전시가 아니라 사용자가 `지금 할 일`을 빠르게 선택하도록 돕는 것이다.
- 홈에는 새 학습 진입, 복습 요약, 최근 학습 자료, 오늘의 학습 요약이 필요하다.

### 설계 가정

- 한 번에 가장 우선인 다음 행동 하나를 큰 카드로 강조하고, 나머지는 아래 섹션에서 보조한다.
- 대표 다음 행동은 `풀던 중인 퀴즈 → 복습할 문제 → 문제를 만들지 않은 학습 자료 → 최근 학습 → 첫 학습 시작` 순서로 제안한다. 데이터와 사용성 검토 후 확정한다.
- 새 학습은 `Notion`, `파일`, `텍스트 붙여넣기`의 세 진입 방법을 한 번에 선택할 수 있게 한다.
- 오늘의 요약은 MVP에서 풀이 수와 정답 현황처럼 실제로 제공 가능한 학습 데이터만 사용한다. 경험치가 도입되기 전에는 XP를 빈 값이나 잠금 상태로 노출하지 않는다.
- 하단 내비게이션은 최상위 화면에서 유지되고, 퀴즈 풀이처럼 집중이 필요한 하위 흐름에서는 숨길 수 있다.

### 미결정 사항

- `복습할 문제`의 발생 기준: 오답 즉시, 일정 기반, 사용자가 저장한 문제 중 무엇을 우선할지 결정이 필요하다.
- 같은 우선순위의 항목이 여러 개일 때 최근성, 마감 시점 또는 학습 진행률 중 어떤 기준으로 정렬할지 결정이 필요하다.
- 최근 학습을 자료 기준으로 보여줄지 퀴즈 세트 기준으로 보여줄지 결정이 필요하다.
- 경험치·연속 학습일 같은 게임화 정보를 MVP 홈에 포함할지 이후 단계까지 숨길지 결정이 필요하다.

## 사용자 목표

- 앱을 열었을 때 현재 학습 상태를 해석하느라 탐색하지 않고 가장 가치 있는 다음 행동을 시작한다.
- 필요한 경우 새 자료를 가져오거나 최근 학습으로 곧바로 돌아간다.

완료 조건은 사용자가 홈 진입 후 대표 행동 또는 새 학습 방법을 선택해 다음 흐름으로 이동하는 것이다.

## 진입과 이탈

- 진입점: 로그인 완료 후 기본 화면, 하단 `홈` 탭, 다른 흐름 완료 후 홈 이동
- 다음 화면: 퀴즈 이어 풀기, 복습 시작, 문제 생성 설정, 최근 자료 상세, 새 학습 입력
- 로그인 조건: 자체 로그인 세션 필요
- 뒤로 가기: 최상위 홈에서는 WebView 컨테이너 정책을 따르며 임의로 이전 인증 화면으로 돌아가지 않는다.

## 정보 구조

1. **화면 헤더**: 현재 위치와 계정 맥락을 짧게 제공한다. 설정 진입은 프로필과 중복되지 않게 검토한다.
2. **지금 할 일**: 우선순위 규칙으로 선택한 대표 행동 하나와 필요한 최소 맥락을 보여준다.
3. **새 학습**: Notion 연동, 텍스트·Markdown 파일 업로드, 직접 붙여넣기로 진입한다.
4. **복습 요약**: 복습 가능한 문제가 있을 때 수량과 시작 행동을 제공한다. 대상이 없으면 긍정적인 완료 상태 또는 섹션 축약을 사용한다.
5. **최근 학습 자료**: 최근 항목 일부와 전체 학습 목록 진입을 제공한다.
6. **오늘의 학습 요약**: 오늘 풀이 수와 정답 현황 등 확인 가능한 요약을 낮은 위계로 제공한다.
7. **하단 내비게이션**: `홈`, `학습`, `프로필`을 표시하고 홈을 현재 위치로 전달한다.

## 지금 할 일 결정 규칙 제안

| 순위 | 조건 | 표시할 맥락 | 대표 행동 |
| --- | --- | --- | --- |
| 1 | 제출 전인 퀴즈 세션이 있음 | 자료명, 진행 문항, 마지막 활동 | `이어서 풀기` |
| 2 | 복습 대상이 한 개 이상 있음 | 대상 수와 복습 범위 | `복습 시작` |
| 3 | 가져왔지만 퀴즈가 없는 자료가 있음 | 자료명과 가져온 시점 | `문제 만들기` |
| 4 | 완료했거나 열어본 최근 학습이 있음 | 최근 자료 또는 퀴즈 맥락 | `최근 학습 보기` |
| 5 | 위 조건이 모두 없음 | 세 입력 방식 안내 | `첫 학습 시작` |

이 표 전체는 UX 초안이다. 순서, 각 조건을 계산하는 데이터와 동률 정렬 규칙은 기능·데이터 명세에서 확정해야 한다.

## 주요 행동

| 우선순위 | 행동 | 결과 | 실패 시 |
| --- | --- | --- | --- |
| Primary | 지금 할 일 실행 | 해당 퀴즈·복습·생성·학습 흐름으로 이동 | 현재 맥락을 유지하고 재시도 또는 대체 진입 제공 |
| Secondary | 새 학습 방법 선택 | 선택한 입력 흐름으로 이동 | 입력 방식별 오류 안내 |
| Secondary | 최근 자료 선택 | 자료 상세 또는 마지막 학습 맥락으로 이동 | 목록을 새로 불러오거나 학습 탭으로 이동 |
| Tertiary | 복습 전체·학습 전체 보기 | 학습 영역의 해당 목록 상태로 이동 | 홈 상태 유지 |

## 화면 상태

| 상태 | 조건 | 표현과 행동 |
| --- | --- | --- |
| 초기 로딩 | 홈 요약 데이터 확인 중 | 화면 골격을 유지하고 대표 카드·목록 자리에 로딩 표현을 사용한다. 하단 탭은 유지한다. |
| 첫 사용자 | 학습 이력과 가져온 자료가 없음 | 첫 학습 시작을 대표 행동으로 두고 세 입력 방식을 설명한다. 통계용 빈 차트는 보이지 않는다. |
| 기본 | 한 개 이상의 다음 행동이 있음 | 가장 높은 우선순위 하나를 강조하고 보조 섹션을 표시한다. |
| 학습 완료 | 복습·미완료 항목이 없음 | 완료 메시지와 새 학습 또는 최근 학습 행동을 제공한다. |
| 부분 오류 | 일부 요약이나 최근 목록만 실패 | 정상 섹션과 대표 행동은 유지하고 실패한 섹션 안에서 재시도한다. |
| 전체 오류 | 대표 행동을 판단할 데이터를 불러오지 못함 | 새 학습처럼 서버 요약에 덜 의존하는 안전한 행동과 전체 재시도를 제공한다. |
| 세션 만료 | 인증이 유효하지 않음 | 입력 상태를 보호할 수 있는 범위에서 로그인 흐름으로 이동하고 원인을 안내한다. |

## 반응형·WebView 동작

- 작은 모바일 너비에서 단일 열과 세로 스크롤을 기본으로 한다.
- 하단 내비게이션은 기기 안전 영역을 침범하지 않고, 마지막 콘텐츠가 가려지지 않도록 스크롤 여백을 확보한다.
- 넓은 화면에서도 `지금 할 일`의 시각적 우선순위를 유지한다. 최근 자료와 요약은 공간이 충분할 때만 나란히 배치할 수 있다.
- 긴 자료명은 핵심 정보를 잃지 않게 줄바꿈 또는 제한된 말줄임을 사용하고 접근 가능한 전체 이름을 제공한다.
- 브라우저·WebView 뒤로 가기는 진행 중인 퀴즈의 이탈 확인 정책과 일관돼야 한다.

## 접근성

- 화면 제목 다음에 `지금 할 일`이 먼저 탐색되도록 DOM과 시각 순서를 일치시킨다.
- 카드 전체를 불명확한 클릭 영역으로 만들지 않고 행동 이름이 분명한 컨트롤을 제공한다.
- 하단 탭은 현재 선택 상태를 색상 외 속성과 레이블로 전달한다.
- 로딩 완료, 오류와 재시도 결과는 포커스를 빼앗지 않는 방식으로 보조기기에 전달한다.
- 정답률이나 진행률은 색상뿐 아니라 텍스트·수치로도 표현한다.

## 필요한 데이터 경계

- 인증된 사용자 표시 맥락
- 제출 전 퀴즈 세션과 진행 위치
- 복습 대상 수와 대표 대상
- 퀴즈가 없는 학습 자료
- 최근 학습 자료 또는 퀴즈 이력
- 오늘의 풀이 수와 정답 현황

정확한 필드, 실패 코드와 캐시 정책은 API 계약 문서에서 정의한다. 설계용 mock은 실제 서버 계약으로 간주하지 않는다.

## 인수 조건

- [ ] 홈 진입 시 규칙에 맞는 대표 다음 행동 하나가 표시된다.
- [ ] 미완료 퀴즈가 있으면 다른 후보보다 이어 풀기가 우선한다.
- [ ] 학습 이력이 없는 사용자가 세 입력 방법 중 하나로 첫 학습을 시작할 수 있다.
- [ ] 복습, 최근 학습과 오늘 요약이 대표 행동을 방해하지 않는 위계로 제공된다.
- [ ] 일부 데이터가 실패해도 사용할 수 있는 섹션과 새 학습 진입이 유지된다.
- [ ] 하단 탭의 현재 위치와 작은 WebView의 안전 영역이 올바르게 전달된다.

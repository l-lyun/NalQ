# [PRD] 마이페이지와 계정 관리

- 담당/검토자: 제품 기획 / 사용자 검토 대기
- 관련 제품 원장: [NalQ 제품 기반](../product.md)
- 관련 요구사항: [이메일 기반 자체 인증](prd-local-authentication.md)
- 관련 화면/계약: [마이페이지 화면 명세](../ux/screen-mypage.md), [첫 진입 온보딩과 NalQ 가이드](../ux/screen-onboarding.md), [사용자·인증 데이터 계약](../contracts/contract-data-authentication.md)

## 문서 책임

이 문서는 로그인한 사용자가 `마이페이지`에서 자신의 계정과 서비스 정보를 확인하고 NalQ 가이드를 다시 열며, 로그아웃 또는 회원 탈퇴를 완료하는 제품 행동과 정책을 정의한다. 구체적인 화면 배치, API 경로, 데이터베이스 구조와 세션 폐기 구현 방식은 정의하지 않는다.

이번 사용자 승인으로 세 번째 하단 탭의 사용자 노출 명칭을 `프로필`에서 `마이페이지`로 변경했다. 전역 내비게이션과 화면 구조는 [제품 기반](../product.md#전역-내비게이션)과 [마이페이지 화면 명세](../ux/screen-mypage.md)에 동기화한다.

또한 [자체 인증 PRD](prd-local-authentication.md#비범위)는 마케팅 수신 동의를 목적과 정책 확정 전 미노출로 두고 있다. 첫 배포에는 회원 탈퇴만 계정 종료 범위로 추가하고, 광고·마케팅 이메일과 선택 동의 기능은 후순위로 둔다.

## 단계별 구현 범위

- PR #38은 마이페이지 명칭·정보 구조, 계정 요약, 로그아웃, 닉네임 변경과 후속 기능의 진입점까지만 구현한다.
- 개인정보처리방침은 승인된 운영 문서가 확정되기 전 임시 개인정보 수집·이용 동의서를 대신 노출하지 않고 준비 중 상태로 둔다.
- 회원 탈퇴는 확정된 정책과 인증 API·데이터 계약에 따라 별도 변경으로 구현하며 PR #38의 완료 조건에는 포함하지 않는다.
- 첫 배포에는 마케팅 목적의 개인정보 처리, 광고성 이메일 발송, 선택 동의 UI·API·DB 필드와 동의·철회 이력을 구현하거나 노출하지 않는다.

## 사용자 문제

로그인한 사용자는 현재 자신의 계정이 어떤 정보로 식별되는지 확인하고, 계정 사용을 끝내고 싶을 때 안전하게 로그아웃하거나 탈퇴할 수 있는 한곳의 진입점이 필요하다. 현재 홈의 테스트 로그인·로그아웃 수단은 실제 사용자용 계정 관리 경험을 대신할 수 없다.

## 목표

사용자가 마이페이지에서 닉네임과 이메일을 확인하고 NalQ의 기본 학습 흐름을 다시 보며, 약관·개인정보·문의·앱 정보를 찾게 한다. 사용 중단을 원하는 사용자는 승인된 방법으로 본인을 다시 확인한 뒤 탈퇴 결과와 데이터 처리 영향을 이해하고 계정을 종료할 수 있어야 한다.

## 범위

### 확정

- 세 번째 하단 탭과 화면의 사용자 노출 명칭을 `프로필` 대신 `마이페이지`로 사용한다.
- 상단 계정 요약에서 현재 닉네임과 로그인 이메일을 보여준다.
- 마이페이지에서 `계정 관리`, `로그아웃`, `NalQ 가이드`, `서비스 이용약관`, `개인정보 처리방침`, `문의하기`, `앱 버전`, `회원 탈퇴`에 접근할 수 있다.
- 첫 배포에는 마케팅 수신 동의 메뉴나 상태를 노출하지 않는다.
- 회원 탈퇴의 영향과 처리 결과를 확인하고 계정 사용을 종료할 수 있다.
- 회원 탈퇴는 현재 비밀번호, 정확한 `회원탈퇴` 문구 입력과 삭제 영향에 대한 최종 확인을 거친다.
- 탈퇴 확정 즉시 계정 접근을 차단하고 모든 로그인 세션을 무효화하며, 연결 데이터와 운영 백업은 최대 30일 이내에 삭제하거나 비식별화한다.

- 프로필 사진, 캐릭터, 경험치·레벨, 랭킹, 친구, 상점과 꾸미기
- 소셜 로그인 계정의 연결·해제와 소셜 계정 재인증
- 이메일 변경, 계정 병합과 다중 프로필
- 비밀번호 변경·재설정의 상세 정책과 행동
- 마케팅 목적의 개인정보 수집·이용, 광고성 이메일 발송과 모든 마케팅 채널
- 선택 동의 UI·API·DB 필드와 동의·철회 이력
- 학습 통계와 학습 기본 설정
- 운영자용 동의 이력 조회·복구 도구의 상세 설계
- 화면의 픽셀 배치, 구체적인 UI 컴포넌트, API 경로와 저장 구조

## 핵심 규칙

### 마이페이지와 계정 정보 — 확정

- 마이페이지는 로그인한 사용자만 접근할 수 있다.
- 닉네임은 사용자에게 보이는 대표 계정명, 이메일은 로그인 계정 식별 정보로 표시한다.
- 계정 정보가 일부 누락되거나 조회에 실패해도 확인되지 않은 값을 임의로 채우지 않는다.
- `계정 관리`는 계정 관련 기능의 진입점으로 제공한다. 이번 범위에서는 닉네임 확인·변경과 이메일 확인을 제공하고 이메일은 읽기 전용으로 둔다.
- 닉네임 변경은 가입과 같은 2~10자 한글·영문·숫자 형식, NFC 정규화와 대소문자를 구분하지 않는 전역 중복 규칙을 사용한다.
- 서비스 이용약관과 개인정보 처리방침은 사용자가 현재 적용되는 전문과 버전을 확인할 수 있는 문서로 연결한다.
- 서비스 정보의 `NalQ 가이드`는 신규 가입자에게 제공하는 온보딩과 같은 세 장을 사용자가 원할 때 다시 볼 수 있게 한다. 수동 가이드 진입·열람·이탈은 신규 가입자 자동 온보딩의 로컬 표시값을 읽거나 변경하지 않는다.
- 서비스 이용약관, 개인정보처리방침과 문의 안내에서 공개 서비스명은 `NalQ`, 운영 주체 유형은 개인, 운영자 성명은 `김도현`, 공개 문의 이메일은 `kimdohyun032@gmail.com`으로 일관되게 표시한다. 미제공 주소는 확정 전 임의의 값으로 채우지 않는다.
- 앱 버전은 사용자가 문의 시 자신의 실행 버전을 식별할 수 있도록 표시한다.
- 홈에 있는 테스트 로그인·로그아웃 수단은 마이페이지의 실제 로그아웃이 제공되는 시점에 사용자 화면에서 제거한다.

### 계정 정보 — 설계 제안

- 기존 사용자에게 닉네임이 없다면 이메일을 대표 식별 정보로 보여주고 `닉네임 미설정`과 보완 행동을 제공한다.
- 임의 닉네임을 만들지 않으며, 일회성 닉네임 완료의 입력·중복 확인 계약은 구현 전에 확정한다.

### 로그아웃 — 확정

- 로그아웃은 현재 사용자의 계정에 영향을 주는 행동임을 확인할 수 있게 안내한 뒤 실행한다.
- 로그아웃이 성공하면 현재 인증 자격과 기기에 남은 개인 학습 정보를 제거하고 로그인 전 공개 랜딩으로 대체 이동한다.
- 로그아웃 뒤 뒤로가기를 하더라도 마이페이지나 개인 학습 화면을 다시 볼 수 없어야 한다.
- 로그아웃 요청의 성공 여부와 관계없이 현재 기기의 인증 정보와 개인 캐시를 제거하고 공개 랜딩으로 대체 이동한다. 서버 세션 종료를 확인하지 못한 경우에도 개인 화면을 계속 노출하지 않으며, 필요한 재로그인 안내를 제공한다.

### 서비스 필수 이메일과 마케팅 제외 — 확정

- 가입 이메일 인증과 비밀번호 재설정 메일은 사용자가 요청한 인증·계정 복구를 완료하기 위한 서비스 제공 목적의 필수 메시지다.
- 계정 보안이나 서비스 운영에 반드시 필요한 알림도 광고·마케팅 이메일과 구분한다. 구체적인 발송 사유와 내용은 해당 기능 정책과 개인정보처리방침에서 정한다.
- 첫 배포에서는 마케팅 목적으로 이메일이나 다른 개인정보를 수집·이용하지 않고 광고성 이메일을 발송하지 않는다.
- 미래에 마케팅을 도입하려면 별도 제품·법률 검토를 거쳐 목적과 채널을 확정하고, 필수 동의와 분리된 선택 동의, 동의·철회 이력, 철회 후 발송 중단 기준을 새로운 범위로 정의해야 한다.

### 회원 탈퇴 — 확정

- 마이페이지 MVP에 회원 탈퇴를 포함한다.
- 사용자는 탈퇴의 영향을 확인하고 명시적으로 계정 종료를 요청할 수 있다.
- 최종 탈퇴 확정 전에는 언제든 취소하고 계정을 계속 사용할 수 있다.
- 탈퇴를 확정하기 전에 즉시 접근 차단, 데이터 삭제·비식별화와 복구 불가 영향을 안내하고 현재 비밀번호를 다시 입력받아 계정 소유를 확인한다.
- 현재 비밀번호 확인을 통과한 사용자가 정확한 확인 문구 `회원탈퇴`를 직접 입력해야 최종 탈퇴 확인을 진행할 수 있다. 띄어쓰기나 다른 문자가 포함된 값은 일치로 보지 않는다.
- 현재 비밀번호를 잊은 사용자는 탈퇴 화면 안에서 이메일 코드 등 다른 재인증 수단으로 우회하지 않는다. 기존 비밀번호 재설정 흐름을 완료하고 새 비밀번호로 다시 로그인한 뒤 탈퇴 흐름을 처음부터 다시 진행한다.
- MVP에는 현재 비밀번호 확인 외의 추가 재인증 단계나 이메일 인증 코드를 추가하지 않는다.
- 사용자가 최종 탈퇴를 확정하면 계정은 즉시 `WITHDRAWN` 상태로 전환하고 `withdrawn_at`에 처리 시각을 기록한다.
- `WITHDRAWN` 전환과 동시에 해당 계정의 로그인과 모든 보호 기능 접근을 차단하고, 현재 기기를 포함한 모든 로그인 세션을 무효화한다.
- 탈퇴 후 `WITHDRAWN` 상태는 복구를 기다리는 유예 상태가 아니며, 사용자가 계정을 다시 활성화하거나 이전 학습 기록을 복구할 수 없다.
- 이메일·닉네임 같은 직접 계정 식별정보와 비밀번호 해시·인증 토큰 같은 계정 자격정보는 탈퇴 확정 즉시 파기하거나 개인을 식별할 수 없도록 처리한다.
- 탈퇴 확정 트랜잭션에서 원 이메일을 더 이상 계정 식별자로 사용할 수 없도록 제거하거나 비식별화하고, 해당 정규화 이메일의 고유값 점유를 해제한다. 감사용 `WITHDRAWN` 기록을 남기더라도 이메일 원문이나 되돌릴 수 있는 값을 포함하지 않는다.
- 닉네임도 탈퇴 확정 즉시 원문과 고유값 점유를 제거해 다시 사용할 수 있게 한다. 탈퇴 계정과 새 계정을 이메일이나 닉네임으로 연결하지 않는다.
- 탈퇴 확정이 성공하면 같은 이메일로 즉시 신규 가입할 수 있다. 재가입은 새로운 내부 사용자 ID를 가진 완전히 새 계정을 생성하며, 탈퇴한 계정의 학습자료, 문제 세트, 풀이·복습 기록과 필수 약관 동의 상태를 연결하거나 복구하지 않는다.
- 학습자료, 문제 세트, 풀이·복습 기록과 이에 연결된 데이터는 가능한 한 신속히 처리하고 탈퇴일로부터 최대 30일 이내에 물리 삭제하거나 비식별화한다.
- 운영 백업에 남은 사본도 가능한 한 신속히 정리하고 탈퇴일로부터 최대 30일 이내에 물리 삭제하거나 개인을 식별할 수 없도록 처리한다. 해당 사본은 탈퇴 계정이나 이전 학습 기록을 복구하는 데 사용하지 않는다.
- 30일은 탈퇴 데이터를 보관하기 위한 기간이 아니라 물리 삭제·비식별화를 완료해야 하는 최대 처리 기한이다.
- 법령상 별도 보존이 필요한 항목이 확인되면 그 대상, 보존 근거와 기간을 개인정보처리방침에서 다른 탈퇴 데이터와 구분해 알리고 분리 보관한 뒤, 정해진 기간이 끝나면 파기한다. 구체적인 대상과 기간은 별도 검토를 거쳐 확정한다.

### 회원 탈퇴 — 설계 제안

- 회원 탈퇴는 로그아웃이나 일반 계정 설정과 구분되는 위험 행동으로 제공한다.
- 탈퇴는 계정 복구나 일시 중지가 아니다. 같은 이메일로 다시 가입해도 이전 계정을 되살리지 않고 새로운 계정으로 취급한다.
- 사용자 소유 학습자료, 문제 세트, 풀이·복습 기록과 계정 식별 정보는 확정된 보존 정책에 따라 삭제하거나 개인과 연결할 수 없도록 비식별화한다.
- 법령상 별도 보존 대상은 일반 사용자 데이터와 분리하여 정해진 목적과 기간 동안만 보존하고, 개인정보처리방침에서 그 범위를 알린다.
- 데이터 처리 중 일부 단계가 지연되더라도 탈퇴 계정의 로그인과 서비스 접근을 다시 허용하지 않는다.

#### 후속 데이터 처리 — 열린 항목과 구현 경계

- 이메일·정규화 이메일·닉네임·비밀번호 해시는 탈퇴 확정 시 `null`로 전환하는 공유 데이터 계약을 따르며, 구체적인 순방향 migration과 애플리케이션 구조는 서버 TRD에서 정한다.
- 필수 약관 동의 버전·시각을 탈퇴 후 얼마 동안 어떤 형태로 보존할지는 별도로 결정한다.
- 법령상 별도 보존이 필요한 구체적인 항목, 보존 근거와 기간은 별도 검토를 거쳐 확정한다.
- 탈퇴 완료 화면에는 `계정이 탈퇴 처리되었고 이전 학습 기록은 복구되지 않는다`는 결과를 표시한 후 로그인 전 화면으로 이동한다.

## 수용 기준

아래 기준은 사용자가 확정한 기능 범위와 이 문서의 설계 제안을 함께 검토하기 위한 목표다. 탈퇴 데이터의 세부 처리 방식처럼 열린 질문에 의존하는 항목은 해당 결정이 승인된 뒤 구현 수용 기준으로 확정한다.

- 로그인한 사용자가 세 번째 하단 탭에서 `마이페이지`라는 명칭을 확인하고 진입할 수 있다.
- 마이페이지에 진입한 사용자는 자신의 현재 닉네임과 로그인 이메일을 확인할 수 있다.
- 닉네임이 없는 기존 사용자는 임의 이름 대신 이메일과 닉네임 미설정 상태를 확인하고 보완 행동을 찾을 수 있다.
- 사용자는 계정 관리, 로그아웃, NalQ 가이드, 서비스 이용약관, 개인정보 처리방침, 문의하기, 앱 버전과 회원 탈퇴 진입점을 찾을 수 있다.
- `NalQ 가이드`를 선택하면 자동 온보딩과 같은 세 장을 다시 볼 수 있고, 수동 열람 전후의 자동 노출 표시값은 바뀌지 않는다.
- 서비스 이용약관 또는 개인정보 처리방침을 선택하면 현재 적용되는 전문과 버전을 확인할 수 있다.
- 첫 배포 화면에는 마케팅 수신 동의 메뉴·상태·입력이 나타나지 않고 광고성 이메일을 보내기 위한 선택 동의가 수집되지 않는다.
- 가입 이메일 인증과 비밀번호 재설정 메일은 광고성 안내가 아니라 사용자가 요청한 인증·계정 복구 메시지로 제공된다.
- 로그아웃 요청 결과와 관계없이 로그인 전 화면으로 이동하고 뒤로가기로 개인 계정·학습 화면을 다시 볼 수 없다.
- 잘못된 현재 비밀번호를 입력하면 계정과 데이터는 변경되지 않는다.
- 현재 비밀번호를 기억하지 못한 사용자는 탈퇴 화면 안의 이메일 코드로 우회할 수 없으며, 비밀번호 재설정과 새 비밀번호 재로그인을 완료한 뒤 탈퇴 흐름을 처음부터 다시 진행한다.
- 현재 비밀번호 확인을 통과해도 정확한 `회원탈퇴` 문구 입력과 삭제 영향에 대한 최종 확인 전에는 탈퇴되지 않는다.
- `회원탈퇴`와 정확히 일치하지 않는 문구를 입력하면 최종 탈퇴 확인을 진행할 수 없다.
- 사용자가 최종 탈퇴를 확인하면 모든 기존 로그인 세션에서 더 이상 보호된 데이터에 접근할 수 없다.
- 사용자가 최종 탈퇴를 확인하면 계정 상태와 탈퇴 처리 시각이 즉시 기록되며, 이후 계정 복구를 전제로 한 유예 상태로 안내되지 않는다.
- 탈퇴 확정이 성공하면 같은 이메일로 즉시 다시 가입할 수 있으며, 재가입한 계정은 이전과 다른 내부 사용자 ID를 가진다.
- 재가입한 계정에는 탈퇴한 계정의 학습자료, 문제 세트, 풀이·복습 기록과 필수 약관 동의 상태가 나타나거나 이어지지 않는다.
- 감사용 탈퇴 기록이 남는 경우에도 원 이메일이나 되돌릴 수 있는 이메일 값으로 이전 계정과 새 계정을 연결할 수 없다.
- 탈퇴한 사용자의 닉네임도 즉시 다시 사용할 수 있으며 새 사용자가 같은 닉네임을 선택해도 이전 계정이나 학습 기록과 연결되지 않는다.
- 일부 데이터가 법령상 보존되는 경우 사용자는 삭제되지 않는 데이터의 범위, 목적과 보존 기간을 탈퇴 전에 확인할 수 있다.
- 마이페이지의 실제 로그아웃을 사용할 수 있게 되면 홈의 테스트 로그인·로그아웃 수단은 사용자 화면에 나타나지 않는다.

## 계측 제안

- 마이페이지 진입, 계정 관리·NalQ 가이드·약관·개인정보·문의 진입, 로그아웃 성공·실패를 민감 정보 없이 기록한다.
- 탈퇴 진입, 본인확인 실패, 최종 확인 전 취소, 탈퇴 확정 성공·실패를 기록하되 비밀번호와 개인 학습 데이터는 기록하지 않는다.
- 탈퇴 흐름의 이탈 지점을 확인하되 목표 수치는 실제 사용 데이터 수집 후 정한다.

# [PRD] 마이페이지와 계정 관리

- 담당/검토자: 제품 기획 / 사용자 검토 대기
- 관련 제품 원장: [NalQ 제품 기반](../product.md)
- 관련 요구사항: [이메일 기반 자체 인증](prd-local-authentication.md)
- 관련 화면/계약: [마이페이지 화면 명세](../ux/screen-mypage.md), [사용자·인증 데이터 계약](../contracts/contract-data-authentication.md)

## 문서 책임

이 문서는 로그인한 사용자가 `마이페이지`에서 자신의 계정과 서비스 정보를 확인하고, 이메일 마케팅 수신 동의를 관리하며, 로그아웃 또는 회원 탈퇴를 완료하는 제품 행동과 정책을 정의한다. 구체적인 화면 배치, API 경로, 데이터베이스 구조와 세션 폐기 구현 방식은 정의하지 않는다.

이번 사용자 승인으로 세 번째 하단 탭의 사용자 노출 명칭을 `프로필`에서 `마이페이지`로 변경했다. 전역 내비게이션과 화면 구조는 [제품 기반](../product.md#전역-내비게이션)과 [마이페이지 화면 명세](../ux/screen-mypage.md)에 동기화한다.

또한 [자체 인증 PRD](prd-local-authentication.md#비범위)는 탈퇴를 비범위로, 마케팅 수신 동의는 목적과 정책 확정 전 미노출로 두고 있다. 이번 PRD는 두 기능을 마이페이지 MVP 범위로 변경하지만, 마케팅 목적·법정 고지와 데이터 보존 정책 중 미결정 사항은 운영 출시 전에 별도로 확정해야 한다.

## 단계별 구현 범위

- PR #38은 마이페이지 명칭·정보 구조, 계정 요약, 로그아웃, 닉네임 변경과 후속 기능의 진입점까지만 구현한다.
- 개인정보처리방침은 승인된 운영 문서가 확정되기 전 임시 개인정보 수집·이용 동의서를 대신 노출하지 않고 준비 중 상태로 둔다.
- 마케팅 수신 동의 조회·변경과 회원 탈퇴는 아래 미결정 정책 및 공유 계약이 승인된 후 별도 변경으로 구현한다. 이 두 기능의 인수 조건은 PR #38의 완료 조건에 포함하지 않는다.

## 사용자 문제

로그인한 사용자는 현재 자신의 계정이 어떤 정보로 식별되는지 확인하고, 선택적인 연락 수신 여부를 통제하며, 계정 사용을 끝내고 싶을 때 안전하게 로그아웃하거나 탈퇴할 수 있는 한곳의 진입점이 필요하다. 현재 홈의 테스트 로그인·로그아웃 수단은 실제 사용자용 계정 관리 경험을 대신할 수 없다.

## 목표

사용자가 마이페이지에서 닉네임과 이메일을 확인하고, 약관·개인정보·문의·앱 정보를 찾으며, 마케팅 수신 동의를 언제든 선택 또는 철회할 수 있게 한다. 사용 중단을 원하는 사용자는 승인된 방법으로 본인을 다시 확인한 뒤 탈퇴 결과와 데이터 처리 영향을 이해하고 계정을 종료할 수 있어야 한다.

## 범위

### 확정

- 세 번째 하단 탭과 화면의 사용자 노출 명칭을 `프로필` 대신 `마이페이지`로 사용한다.
- 상단 계정 요약에서 현재 닉네임과 로그인 이메일을 보여준다.
- 마이페이지에서 `계정 관리`, `로그아웃`, `서비스 이용약관`, `개인정보 처리방침`, `마케팅 수신 동의`, `문의하기`, `앱 버전`, `회원 탈퇴`에 접근할 수 있다.
- 마케팅 수신 동의의 현재 상태를 확인하고 동의하거나 철회할 수 있다.
- 회원 탈퇴의 영향과 처리 결과를 확인하고 계정 사용을 종료할 수 있다.

### 설계 제안

- 초기 마케팅 채널은 가입 시 검증한 이메일 하나로 제한한다.
- 회원 탈퇴 전에 승인된 방식으로 계정 소유를 재확인하고 별도의 최종 확인을 받는다.
- 탈퇴 확정 뒤에는 계정 접근을 즉시 차단하고 모든 로그인 세션을 종료한다.
- 탈퇴 계정에 연결된 사용자 데이터는 확정될 삭제·비식별화 정책에 따라 처리한다.

## 비범위

- 프로필 사진, 캐릭터, 경험치·레벨, 랭킹, 친구, 상점과 꾸미기
- 소셜 로그인 계정의 연결·해제와 소셜 계정 재인증
- 이메일 변경, 계정 병합과 다중 프로필
- 비밀번호 변경·재설정의 상세 정책과 행동
- 푸시, SMS 등 이메일 외 마케팅 채널
- 학습 통계와 학습 기본 설정
- 운영자용 동의 이력 조회·복구 도구의 상세 설계
- 화면의 픽셀 배치, 구체적인 UI 컴포넌트, API 경로와 저장 구조

## 핵심 규칙

### 마이페이지와 계정 정보 — 확정

- 마이페이지는 로그인한 사용자만 접근할 수 있다.
- 닉네임은 사용자에게 보이는 대표 계정명, 이메일은 로그인 계정 식별 정보로 표시한다.
- 계정 정보가 일부 누락되거나 조회에 실패해도 확인되지 않은 값을 임의로 채우지 않는다.
- `계정 관리`는 계정 관련 기능의 진입점으로 제공한다. 이번 범위에서는 닉네임 확인·변경과 이메일 확인을 제공하고 이메일은 읽기 전용으로 둔다.
- 닉네임 변경은 가입과 같은 2~10자 한글·영문·숫자 형식, NFC 정규화와 대소문자를 구분하지 않는 전역 중복 규칙을 사용한다.
- 서비스 이용약관과 개인정보 처리방침은 사용자가 현재 적용되는 전문과 버전을 확인할 수 있는 문서로 연결한다.
- 앱 버전은 사용자가 문의 시 자신의 실행 버전을 식별할 수 있도록 표시한다.
- 홈에 있는 테스트 로그인·로그아웃 수단은 마이페이지의 실제 로그아웃이 제공되는 시점에 사용자 화면에서 제거한다.

### 계정 정보 — 설계 제안

- 기존 사용자에게 닉네임이 없다면 이메일을 대표 식별 정보로 보여주고 `닉네임 미설정`과 보완 행동을 제공한다.
- 임의 닉네임을 만들지 않으며, 일회성 닉네임 완료의 입력·중복 확인 계약은 구현 전에 확정한다.

### 로그아웃 — 확정

- 로그아웃은 현재 사용자의 계정에 영향을 주는 행동임을 확인할 수 있게 안내한 뒤 실행한다.
- 로그아웃이 성공하면 현재 인증 자격과 기기에 남은 개인 학습 정보를 제거하고 로그인 전 화면으로 이동한다.
- 로그아웃 뒤 뒤로가기를 하더라도 마이페이지나 개인 학습 화면을 다시 볼 수 없어야 한다.
- 로그아웃 요청의 성공 여부와 관계없이 현재 기기의 인증 정보와 개인 캐시를 제거하고 로그인 전 화면으로 이동한다. 서버 세션 종료를 확인하지 못한 경우에도 개인 화면을 계속 노출하지 않으며, 필요한 재로그인 안내를 제공한다.

### 마케팅 수신 동의 — 확정

- 마이페이지 MVP에 마케팅 수신 동의를 포함한다.
- 사용자는 현재 동의 상태를 확인하고 동의하거나 철회할 수 있다.

### 이메일 마케팅 수신 동의 — 설계 제안

- 마케팅 수신 동의는 서비스 이용을 위한 필수 동의와 분리된 선택 동의다. 동의하지 않거나 철회해도 가입, 로그인과 핵심 학습 기능 사용을 제한하지 않는다.
- MVP의 마케팅 채널은 이메일 하나로 제한한다.
- 사용자는 현재 `동의` 또는 `미동의` 상태와 최근 변경일을 확인할 수 있다.
- 명시적인 동의 이력이 없는 사용자는 마케팅 발송 대상이 아니며 화면에는 `미동의`로 표시한다. 이때 최근 변경일을 임의로 만들지 않고 `변경 기록 없음`으로 구분한다.
- 사용자는 동의 대상, 발송 채널과 현재 동의 문구를 확인한 뒤 동의하거나 철회할 수 있다.
- 동의와 철회는 사용자가 명시적으로 선택한 경우에만 반영한다. 화면 진입, 약관 열람 또는 다른 필수 동의를 마케팅 동의로 간주하지 않는다.
- 동의 또는 철회가 성공하면 변경된 상태와 최근 변경일을 즉시 확인할 수 있어야 한다.
- 동의와 철회의 각 변경에는 당시 사용자에게 제시된 문구 버전과 변경 시각을 이력으로 남긴다. 새 문구가 적용되어도 과거 이력을 현재 문구로 덮어쓰지 않는다.
- 철회 후에는 철회 시점 이후의 신규 마케팅 발송 대상에서 제외한다. 이미 발송 처리된 이메일의 취소 가능 범위와 반영 지연은 법률·운영 정책에 맞춰 별도 고지한다.
- 보안 알림, 약관 변경처럼 서비스 제공에 필요한 필수 안내는 마케팅 수신 상태와 구분한다.

#### 목적·실행 제안

- 마케팅 목적은 `학습 활용 팁`, `새 기능 소식`, `이벤트·혜택 안내`로 제한하고 목적이 추가될 때는 문구 버전을 변경한다.
- 철회는 동의보다 어렵지 않은 단계 수로 제공한다.
- 상태 변경 실패 시 사용자의 기존 상태를 유지하고, 실패 원인과 재시도 방법을 안내한다.

### 회원 탈퇴 — 확정

- 마이페이지 MVP에 회원 탈퇴를 포함한다.
- 사용자는 탈퇴의 영향을 확인하고 명시적으로 계정 종료를 요청할 수 있다.
- 최종 탈퇴 확정 전에는 언제든 취소하고 계정을 계속 사용할 수 있다.

### 회원 탈퇴 — 설계 제안

- 회원 탈퇴는 로그아웃이나 일반 계정 설정과 구분되는 위험 행동으로 제공한다.
- 탈퇴 전에 현재 비밀번호를 다시 입력해 계정 소유를 확인한다. 비밀번호가 일치하지 않으면 탈퇴를 진행하지 않는다.
- 재인증 후에도 삭제·비식별화되는 데이터, 복구 불가 여부, 재가입 시 이전 기록이 복구되지 않는다는 영향을 안내하고 별도의 최종 확인을 받는다.
- 탈퇴 요청이 확정되면 계정 접근을 즉시 차단하고 현재 기기를 포함한 모든 로그인 세션을 폐기한다.
- 탈퇴 완료 후에는 해당 계정으로 로그인하거나 보호된 학습 데이터에 접근할 수 없다.
- 탈퇴는 계정 복구나 일시 중지가 아니다. 같은 이메일로 다시 가입할 수 있게 되더라도 새 계정으로 취급하며 이전 학습자료, 문제 세트와 풀이 기록을 복구하거나 연결하지 않는다.
- 사용자 소유 학습자료, 문제 세트, 풀이·복습 기록과 계정 식별 정보는 확정된 보존 정책에 따라 삭제하거나 개인과 연결할 수 없도록 비식별화한다.
- 법령상 보존 의무가 있는 데이터는 일반 사용자 데이터와 분리하여 정해진 목적과 기간 동안만 보존하고, 사용자에게 예외 범위를 알린다.
- 데이터 처리 중 일부 단계가 지연되더라도 탈퇴 계정의 로그인과 서비스 접근을 다시 허용하지 않는다.

#### 처리 기한 제안

- 계정 접근 차단은 즉시 적용하되 사용자 데이터 삭제·비식별화는 탈퇴 확정 후 30일 이내 완료한다. 이 기간은 사용자 확정 사항이 아니며 법률 검토와 운영 가능성 확인 후 승인해야 한다.
- 동일 이메일 재가입은 기존 계정의 접근 차단과 이메일 식별자 해제가 안전하게 완료된 뒤 허용한다.
- 탈퇴 완료 화면에는 `계정이 탈퇴 처리되었고 이전 학습 기록은 복구되지 않는다`는 결과를 표시한 후 로그인 전 화면으로 이동한다.

| 마케팅 동의 변경 성공 | 변경된 상태와 최근 변경일을 표시한다. | 마이페이지로 복귀 또는 다시 변경 |
| 마케팅 동의 변경 실패 | 기존 상태가 유지됐음을 알린다. | 재시도 |
| 로그아웃 서버 응답 실패 | 현재 기기의 인증 정보와 개인 캐시를 제거하고 공개 화면에서 서버 세션 종료를 확인하지 못했음을 필요한 범위에서 안내한다. | 다시 로그인하거나 지원되는 세션 관리 행동 사용 |
| 탈퇴 비밀번호 불일치 | 계정 소유를 확인하지 못했음을 알리고 탈퇴를 진행하지 않는다. | 비밀번호 재입력 |
| 탈퇴 최종 확인 전 취소 | 계정과 데이터에 변화가 없다. | 마이페이지로 복귀 |
| 탈퇴 확정 처리 중 | 중복 요청을 막고 계정 종료 처리 중임을 알린다. | 완료까지 대기 |
| 탈퇴 확정 성공 | 더 이상 계정에 접근할 수 없고 이전 기록을 복구할 수 없음을 알린다. | 로그인 전 화면으로 이동 |
| 탈퇴 결과 불명확 | 성공 또는 실패를 임의로 단정하지 않고 계정 접근 상태를 다시 확인한다. | 결과 확인 후 로그인 전 화면 또는 안전한 재시도 안내 |

## 수용 기준

아래 기준은 사용자가 확정한 기능 범위와 이 문서의 설계 제안을 함께 검토하기 위한 목표다. 마케팅 채널·이력 정책, 탈퇴 재인증·데이터 처리처럼 열린 질문에 의존하는 항목은 해당 결정이 승인된 뒤 구현 수용 기준으로 확정한다.

- 로그인한 사용자가 세 번째 하단 탭에서 `마이페이지`라는 명칭을 확인하고 진입할 수 있다.
- 마이페이지에 진입한 사용자는 자신의 현재 닉네임과 로그인 이메일을 확인할 수 있다.
- 닉네임이 없는 기존 사용자는 임의 이름 대신 이메일과 닉네임 미설정 상태를 확인하고 보완 행동을 찾을 수 있다.
- 사용자는 계정 관리, 로그아웃, 서비스 이용약관, 개인정보 처리방침, 이메일 마케팅 수신 동의, 문의하기, 앱 버전과 회원 탈퇴 진입점을 찾을 수 있다.
- 서비스 이용약관 또는 개인정보 처리방침을 선택하면 현재 적용되는 전문과 버전을 확인할 수 있다.
- 사용자는 현재 이메일 마케팅 수신 상태와 최근 변경일을 확인할 수 있다.
- 마케팅 동의 변경 이력이 없는 사용자는 `미동의`와 `변경 기록 없음`을 확인할 수 있고 마케팅 이메일 발송 대상에 포함되지 않는다.
- 미동의 사용자가 현재 동의 문구를 확인하고 명시적으로 동의하면 상태가 `동의`로 바뀌고 해당 시각과 문구 버전이 이력에 남는다.
- 동의 사용자가 철회하면 핵심 학습 기능 사용에는 영향이 없고 상태가 `미동의`로 바뀌며 해당 시각과 문구 버전이 이력에 남는다.
- 마케팅 상태 변경이 실패하면 변경 전 상태가 유지됐음을 확인하고 다시 시도할 수 있다.
- 로그아웃 요청 결과와 관계없이 로그인 전 화면으로 이동하고 뒤로가기로 개인 계정·학습 화면을 다시 볼 수 없다.
- 제안된 현재 비밀번호 재인증을 사용할 때 잘못된 비밀번호를 입력하면 계정과 데이터는 변경되지 않는다.
- 현재 비밀번호를 기억하지 못한 로그인 사용자는 승인된 대체 재인증 방법으로 탈퇴를 계속하거나 이용 가능한 복구 방법을 확인할 수 있다.
- 승인된 재인증을 완료한 사용자도 데이터 처리 영향에 대한 최종 확인 전에는 탈퇴되지 않는다.
- 사용자가 최종 탈퇴를 확인하면 모든 기존 로그인 세션에서 더 이상 보호된 데이터에 접근할 수 없다.
- 탈퇴 후 같은 이메일로 재가입이 허용되는 경우 새 계정에는 이전 계정의 학습자료와 풀이 기록이 나타나지 않는다.
- 일부 데이터가 법령상 보존되는 경우 사용자는 삭제되지 않는 데이터의 범위, 목적과 보존 기간을 탈퇴 전에 확인할 수 있다.
- 마이페이지의 실제 로그아웃을 사용할 수 있게 되면 홈의 테스트 로그인·로그아웃 수단은 사용자 화면에 나타나지 않는다.

## 계측 제안

- 마이페이지 진입, 계정 관리·약관·개인정보·문의 진입, 로그아웃 성공·실패를 민감 정보 없이 기록한다.
- 마케팅 동의 상태 조회와 동의·철회 성공·실패를 기록하되 이메일 주소와 동의 문구 전문은 분석 속성으로 보내지 않는다.
- 탈퇴 진입, 재인증 실패, 최종 확인 전 취소, 탈퇴 확정 성공·실패를 기록하되 비밀번호와 개인 학습 데이터는 기록하지 않는다.
- 마케팅 동의 관리와 탈퇴 흐름의 이탈 지점을 확인하되 목표 수치는 실제 사용 데이터 수집 후 정한다.

## 열린 질문

- 이메일 마케팅의 정확한 목적, 발송 콘텐츠 범위, 발신 주체와 발송 빈도는 무엇인가?
- 법률 검토를 거친 마케팅 동의 문구, 문구 식별자·버전 정책, 철회 반영 기한과 동의 이력 보존 기간은 무엇인가?
- 서비스 이용약관과 개인정보 처리방침의 운영용 전문, 식별자·버전과 제공 방식은 무엇인가?
- `문의하기`는 이메일, 외부 고객지원 페이지, 앱 내 문의 중 어떤 채널로 연결할 것인가?
- 탈퇴 시 각 사용자 데이터 유형을 물리 삭제할지 비식별화할지, 법령상 예외 보존 대상과 기간은 무엇인가?
- 데이터 삭제·비식별화 완료 기한을 제안한 30일로 승인할 것인가?
- 탈퇴 후 동일 정규화 이메일의 재가입을 언제 허용할 것인가? 탈퇴 즉시, 데이터 처리 완료 후, 별도 유예기간 후 중 하나를 결정해야 한다.
- 삭제·비식별화 처리가 실패하거나 지연될 때 사용자 고지와 운영 복구 책임은 무엇인가?
- 비밀번호 변경을 `계정 관리`의 첫 출시 범위에 포함할 것인가?
- 회원 탈퇴 재인증은 현재 비밀번호만 사용할지, 비밀번호를 잊은 사용자를 위해 검증된 이메일 코드 또는 다른 복구 수단을 함께 제공할지?
- 닉네임이 없는 기존 사용자의 일회성 닉네임 완료를 마이페이지 첫 출시 범위에 포함할 것인가?

# [Screen Spec] 마이페이지와 계정 관리

> 이 문서는 마이페이지의 화면 구조와 사용자에게 보이는 상태를 정의한다. 회원 탈퇴의 제품 정책은 [마이페이지 계정 관리 PRD](../prd/prd-mypage-account-management.md)가 책임지며, 요청·응답은 [인증 API 계약](../contracts/contract-api-authentication.md), 데이터 보존 의미는 [사용자·인증 데이터 계약](../contracts/contract-data-authentication.md)이 책임진다.

## 문서 정보

- 화면명: 마이페이지, NalQ 가이드 진입, 회원 탈퇴
- 문서 상태: `draft`
- 요구사항 상태: 마이페이지 명칭, 필수 메뉴, 탈퇴 본인확인과 최대 데이터 처리 기한은 사용자 확정, 법률 문구와 별도 보존 세부사항은 미확정
- 대상 플랫폼: 반응형 웹과 앱 WebView, 모바일 우선
- 관련 기능: [마이페이지 계정 관리](../prd/prd-mypage-account-management.md), [이메일 기반 자체 인증](../prd/prd-local-authentication.md)
- 관련 흐름: [인증 흐름](flow-authentication.md)
- 관련 화면: [공개 서비스 정보와 푸터](screen-public-service-information.md)
- 관련 계약: [인증 API](../contracts/contract-api-authentication.md), [사용자·인증 데이터](../contracts/contract-data-authentication.md)

## 현재 구현 단계

- PR #38은 마이페이지 메인, 계정 설정의 닉네임 변경, 로그아웃과 각 후속 메뉴의 안전한 진입 상태를 구현한다.
- 현재 구현의 개인정보처리방침·문의하기 준비 중 화면과 마케팅 메뉴는 첫 배포 목표와 다르다. 공개 서비스 정보는 [공개 서비스 정보와 푸터](screen-public-service-information.md)의 기준 경로로 교체해야 한다.
- 아래 회원 탈퇴 상세와 인수 조건은 후속 구현의 기준이며 PR #38의 인수 범위에서는 제외한다.

## 요구사항 구분

### 확정 사항

- 로그인 후 세 번째 하단 탭의 사용자 표시 명칭은 `프로필`이 아니라 `마이페이지`다.
- 마이페이지 상단은 현재 사용자의 닉네임과 이메일을 보여준다.
- 마이페이지에는 계정 관리, 로그아웃, NalQ 가이드, 서비스 이용약관, 개인정보 처리방침, 문의하기, 오픈소스 라이선스, 앱 버전과 회원 탈퇴를 제공한다.
- 서비스 정보의 `NalQ 가이드`는 `/profile/guide`로 이동해 자동 온보딩과 같은 세 장을 수동으로 보여준다. 수동 가이드 진입·열람·이탈은 자동 온보딩 표시값을 읽거나 변경하지 않는다.
- 이용약관·개인정보처리방침·문의하기·오픈소스 라이선스는 로그인 여부와 무관한 공개 기준 경로를 사용한다.
- 첫 배포에는 광고·마케팅 이메일과 선택 동의 기능을 제공하지 않으며 마케팅 동의 메뉴·상태·입력을 노출하지 않는다.
- 회원 탈퇴 진입점은 `계정설정` 하단의 구분된 위험 영역에 두며 탈퇴 영향, 명시적 확인과 처리 결과를 보여준다.
- 회원 탈퇴 본인확인은 현재 비밀번호 재입력으로 제한하고, 정확한 확인 문구 `회원탈퇴` 입력과 삭제 영향에 대한 최종 확인을 모두 거친다.
- 비밀번호를 잊은 사용자는 탈퇴 화면 안의 이메일 코드로 우회하지 않고 기존 비밀번호 재설정 흐름과 새 비밀번호 재로그인을 완료한 뒤 탈퇴를 처음부터 다시 진행한다.
- 경험치·레벨·랭킹, 친구, 상점·포인트, 캐릭터·방 꾸미기와 학습 통계는 기능 정책과 데이터가 확정되기 전 마이페이지에 빈 카드나 잠금 메뉴로 노출하지 않는다.
- 마이페이지의 화면 제목, 계정 요약, 계정관리, 앱 정보처럼 인접한 컴포넌트 그룹 사이의 과도한 세로 간격을 현재의 절반 수준으로 줄인다.

### 설계 가정

- 프로필 이미지 저장 계약이 없으므로 상단에는 중립적인 기본 계정 아이콘을 사용한다. 닉네임 첫 글자 아바타는 구현 전 접근성과 다국어 표시를 검토한 뒤 대안으로 선택할 수 있다.
- 계정 관리 상세는 닉네임 변경과 이메일 조회를 제공한다. 이메일과 비밀번호 변경은 각각의 정책과 계약이 승인된 뒤 활성화한다.
- 서비스 이용약관과 개인정보 처리방침은 승인된 전문을 보여주는 공개 읽기 화면으로 이동한다. 기준 경로와 문서 공통 구조는 [공개 서비스 정보와 푸터](screen-public-service-information.md)를 따른다.
- 문의하기는 공개 이메일 `kimdohyun032@gmail.com`의 메일 앱 열기와 주소 복사 대안을 제공하는 공개 화면으로 이동한다.
- 앱 버전은 이동하지 않는 보조 정보로 표시한다. 웹과 앱 셸의 버전이 다르면 사용자에게 의미 있는 배포 버전을 우선하고 상세 표기 규칙은 구현 원장에서 정한다.
- 기존 사용자에게 닉네임이 없으면 이메일을 대표 식별 정보로 보여주고 `닉네임 미설정`과 보완 행동을 제공한다. 임의 닉네임을 만들지 않는다.

### 후순위 범위와 미결정 사항

- 미래에 마케팅을 도입하려면 별도 제품·법률 검토를 거쳐 목적과 채널, 선택 동의 UI, 동의·철회 이력과 철회 후 발송 중단 기준을 새 범위로 정의한다.
- 회원 탈퇴 후 법령상 별도 보존이 필요한 구체적인 항목, 보존 근거와 기간
- 이메일과 비밀번호 변경을 초기 계정 관리에 포함할지
- 기존 사용자의 일회성 닉네임 완료를 첫 출시 범위에 포함할지
- 문의 응답 가능 시간과 목표 응답 기간

## 사용자 목표

- 이 화면에 들어온 사용자는 자신의 계정을 확인하고 서비스·동의 정보를 찾으며 세션과 계정 종료를 스스로 관리한다.
- 사용자가 원하는 메뉴의 현재 상태를 이해하고, 필요한 변경을 완료하거나 실패 원인과 복구 행동을 확인하면 화면의 목적을 달성한 것으로 본다.

## 진입과 이탈

- 진입점: 로그인 후 하단 `마이페이지` 탭, 계정 관련 안내의 관리 링크
- 다음 화면: 계정 관리, NalQ 가이드, 이용약관, 개인정보 처리방침, 문의하기, 회원 탈퇴
- 뒤로 가기: 하위 전체 페이지에서는 마이페이지로 한 단계 돌아간다.
- 하단 탭: 마이페이지 메인에서 유지하고 `마이페이지`를 현재 위치로 전달한다. 회원 탈퇴 같은 하위 전체 페이지에서는 하단 탭을 숨기고 명확한 뒤로가기를 제공할 수 있다.
- 로그인 조건: 활성 로그인 세션이 필요하다. 세션 만료는 계정 정보가 사라진 상태로 표현하지 않고 재로그인을 안내한다.
- 탈퇴 성공: 모든 로그인 상태와 개인 캐시를 제거하고 로그인 화면으로 이동한다. 뒤로가기로 보호 화면을 다시 열 수 없어야 한다.

## 마이페이지 정보 구조

위에서 아래 순서를 유지한다.

1. **화면 제목**: `마이페이지`로 현재 위치를 알린다.
2. **계정 요약**: 기본 계정 아이콘, 닉네임, 이메일을 보여준다. 내부 사용자 ID와 정상 계정 상태는 노출하지 않는다.
3. **계정**: `계정 관리`와 `로그아웃`을 제공한다. 로그아웃은 다른 페이지로 이동하는 행이 아니라 세션 종료 행동이다.
4. **서비스 정보**: `NalQ 가이드`, 서비스 이용약관, 개인정보 처리방침, 문의하기, 오픈소스 라이선스와 앱 버전을 제공한다. 이동 행은 각각 `/profile/guide`, `/terms`, `/privacy`, `/support`, `/open-source-licenses`를 사용한다.
5. **계정 종료**: `계정설정` 하단에서 `회원 탈퇴`를 닉네임 폼과 구분하고 결과를 되돌리기 어려운 행동임을 문구로 알린다.
6. **하단 내비게이션**: `홈`, `학습`, `마이페이지` 중 `마이페이지`를 현재 위치로 표시한다.

반복 메뉴는 카드 여러 개로 만들지 않고 섹션 제목, 여백과 그룹형 목록으로 구분한다. 이동 가능한 행 전체가 하나의 링크 또는 버튼이며 trailing chevron은 이동 가능성을 보조한다. 로그아웃, 앱 버전과 회원 탈퇴는 동일한 chevron 문법을 기계적으로 적용하지 않는다.

### 밀도와 간격

- 마이페이지 메인의 화면 제목 → 계정 요약 → 계정관리 → 구분선 → 앱 정보 사이 반복 간격은 SEED `x4`(16px)를 기준으로 한다. 기존처럼 각 블록 사이에 `x8`(32px)을 반복하지 않는다.
- 계정 요약의 아이콘과 텍스트는 `x3`(12px), 섹션 제목과 목록은 `x2`(8px)를 기준으로 가까운 한 그룹으로 묶는다.
- 목록 행 자체는 세로 여백을 줄이더라도 최소 44×44 CSS px 터치 영역을 유지한다. 현재 56px 수준의 행 높이를 간격 축소 대상으로 오해해 줄이지 않는다.
- 계정관리와 앱 정보의 구분은 큰 빈 공간 대신 한 번의 subtle divider와 `x4` 간격으로 전달한다.
- 로딩 Skeleton도 완료 화면과 같은 압축된 리듬을 사용해 로딩 완료 때 큰 레이아웃 점프를 만들지 않는다.

## 로그아웃

- 로그아웃 선택 시 `이 기기에서 로그아웃할까요?` 확인을 제공한다.
- 확인 전에는 세션이나 개인 캐시를 제거하지 않는다.
- 서버 응답의 성공 여부와 관계없이 현재 기기의 로그인 정보와 개인 캐시를 제거하고 로그인 화면으로 이동한다.
- 서버 세션 종료를 확인하지 못한 경우에도 개인 화면을 유지하지 않는다. 필요한 경우 공개 화면에서 재로그인 또는 세션 상태 안내를 제공한다.
- 다른 기기의 세션까지 종료하는 기능은 회원 탈퇴 또는 별도 `모든 기기에서 로그아웃` 정책의 책임이며 현재 로그아웃에 암시하지 않는다.

## 회원 탈퇴

### 흐름

1. 사용자가 `마이페이지 > 계정설정` 하단의 `회원 탈퇴`를 선택한다.
2. 전체 페이지에서 탈퇴 즉시 계정 접근과 모든 세션이 종료되고, 직접 계정 식별정보·자격정보는 즉시 처리되며 학습자료·퀴즈·풀이 기록과 연결·백업 데이터는 가능한 한 신속히, 최대 30일 이내 삭제 또는 비식별화됨을 설명한다. 30일은 보관기간이 아니라 최대 처리 기한임을 함께 알린다.
3. 사용자는 영향과 복구 가능 여부를 확인한 뒤 `회원 탈퇴 계속`을 선택한다.
4. 현재 비밀번호를 다시 입력해 계정 소유를 확인한다. 비밀번호를 기억하지 못한 사용자는 탈퇴 흐름을 나가 기존 비밀번호 재설정과 새 비밀번호 재로그인을 완료한 뒤 1단계부터 다시 진행한다. 탈퇴 화면 안에서는 이메일 코드를 제공하지 않는다.
5. 사용자는 정확한 확인 문구 `회원탈퇴`를 입력한다. 띄어쓰기나 다른 문자가 포함되면 다음 단계로 진행하지 않는다.
6. 삭제 영향을 다시 확인하고 최종 `회원 탈퇴` 행동을 명시적으로 선택한다.
7. 성공하면 모든 세션과 로컬 개인 상태를 제거하고 로그인 화면에서 탈퇴 완료를 안내한다.

탈퇴 데이터는 가능한 한 신속히 처리하되 최대 30일 이내 삭제·비식별화를 완료한다. `30일 동안 보관`, `30일 뒤 삭제`, `언제든 복구`처럼 보관 또는 복구 유예로 오인할 수 있는 문구는 사용하지 않는다. 탈퇴 완료 뒤 같은 이메일로 즉시 가입할 수 있지만 새 계정으로 생성되고 이전 기록은 이어지지 않음을 안내한다.

## 반응형·WebView 동작

- 작은 화면에서는 한 개의 세로 스크롤과 전체 너비 그룹형 목록을 사용한다.
- 작은 화면과 넓은 화면 모두 메인 콘텐츠 그룹의 반복 간격은 `x4`를 기준으로 유지한다. 넓은 화면이라는 이유로 `x8` 이상의 간격을 다시 늘리지 않는다.
- 넓은 화면에서도 계정 정보와 위험 행동의 읽기 순서를 바꾸지 않고 적절한 최대 읽기 너비 안에 둔다. 여러 열의 설정 대시보드로 확장하지 않는다.
- 하단 내비게이션 높이와 WebView에서 전달된 유효 하단 inset만큼 마지막 콘텐츠 여백을 확보한다. 웹에서 불필요한 safe-area 여백을 추가하지 않는다.
- 하위 전체 페이지에서 키보드가 열리면 비밀번호 입력과 최종 행동이 가려지지 않아야 한다.
- 긴 약관명, 이메일, 오류 문구와 큰 글자에서 행 높이가 늘어나도록 하며 텍스트를 고정 높이로 자르지 않는다.
- `prefers-reduced-motion: reduce` 또는 앱 셸의 모션 감소 설정에서는 큰 수평 push 이동을 제거하거나 짧은 비이동 전환으로 대체한다.

## 접근성

- 화면 제목은 하나의 `h1`, 섹션 제목은 순서가 맞는 하위 제목으로 제공한다.
- 목록 행 전체가 하나의 초점 대상이며 장식용 chevron을 중복 낭독하지 않는다.
- 회원 탈퇴와 오류는 색상만으로 위험·실패를 전달하지 않고 문구, 위치와 확인 단계로 구분한다.
- 로그아웃·탈퇴의 성공과 실패는 적절한 live region 또는 검증된 SEED 피드백 컴포넌트로 전달한다.
- 확인 대화상자에서 취소로 닫으면 최초 실행 요소로 포커스를 돌린다.

## 데이터와 계약

- 현재 표시 가능: 현재 사용자 닉네임, 이메일, 이메일 인증 여부와 계정 상태. 정상 마이페이지에서는 닉네임과 이메일만 기본 노출한다.
- 현재 행동 가능: 현재 세션 로그아웃, 닉네임 변경과 `/profile/guide`의 수동 NalQ 가이드 열람.
- 계약 확정: 현재 비밀번호 기반 회원 탈퇴 본인확인·전 세션 폐기·데이터 처리 결과는 인증 API·사용자 데이터 계약을 따른다.
- 사용자 입력: 현재 비밀번호, 정확한 확인 문구 `회원탈퇴`, 탈퇴 최종 확인.
- 개인정보: 이메일은 필요한 화면과 목적에서만 표시하고 분석 사건에 원문을 넣지 않는다. 비밀번호 원문은 저장·로그·분석하지 않는다.
- 법률 문서: 실제 이용약관과 개인정보 처리방침은 공개 서비스명 `NalQ`, 개인 운영자 `김도현`과 공개 문의 이메일 `kimdohyun032@gmail.com`을 일관되게 표시하고 승인된 버전과 목적지를 사용한다. 미제공 주소를 임의로 채우지 않으며 이 화면 명세의 예시는 법률 확정본이 아니다.
- mock 경계: 탈퇴 mock은 시각 검토에만 사용하며 실제 저장·세션 폐기·데이터 처리 완료처럼 운영 상태를 오인시키지 않는다.

## 인수 조건

- [ ] 로그인한 사용자는 하단 탭과 화면 제목에서 `마이페이지`를 식별할 수 있다.
- [ ] 사용자는 닉네임과 이메일을 확인하고 계정·서비스 정보·계정 종료 영역을 구분할 수 있다.
- [ ] 서비스 정보의 `NalQ 가이드` 행을 선택하면 `/profile/guide`에서 같은 세 장을 다시 볼 수 있고, 닫기와 뒤로 가기는 마이페이지로 돌아간다.
- [ ] 수동 가이드를 열고 탐색하거나 닫아도 신규 사용자 자동 온보딩의 로컬 표시값은 조회·생성·변경·삭제되지 않는다.
- [ ] 서비스 정보에서 로그인 없이 접근 가능한 이용약관·개인정보처리방침·문의하기·오픈소스 라이선스 기준 경로를 열 수 있다.
- [ ] 오픈소스 라이선스 행은 공개 `/open-source-licenses`로 연결되고 SEED의 저작권·Apache-2.0·NOTICE 고지를 확인할 수 있다.
- [ ] 마이페이지 메인의 인접 콘텐츠 그룹 간 반복 간격이 `x4`(16px) 수준이고, 섹션 제목과 목록 간격은 `x2`(8px) 수준이며 `x8`(32px)이 반복되지 않는다.
- [ ] 간격을 줄여도 모든 메뉴 행은 최소 44×44 CSS px 터치 영역과 줄바꿈 가능한 높이를 유지한다.
- [ ] 이동 가능한 행 전체를 선택할 수 있고 첫 배포 화면에 마케팅 수신 동의 메뉴·상태·입력이 나타나지 않는다.
- [ ] 로그아웃은 확인 뒤 서버 응답과 무관하게 현재 기기의 인증 정보·개인 캐시를 제거하고 보호 화면 재진입을 막는다.
- [ ] 회원 탈퇴 전에 접근 중단, 최대 30일의 데이터 처리 기한과 재가입 경계를 이해할 수 있는 안내와 현재 비밀번호 확인을 제공한다.
- [ ] 현재 비밀번호가 일치하지 않으면 탈퇴를 진행하지 않고, 탈퇴 화면 안에서 이메일 코드나 다른 재인증 수단을 제공하지 않는다.
- [ ] 현재 비밀번호를 기억하지 못한 사용자는 탈퇴 흐름을 나가 기존 비밀번호 재설정과 새 비밀번호 재로그인을 완료한 뒤 탈퇴를 처음부터 다시 진행할 수 있다.
- [ ] 현재 비밀번호 확인 뒤 정확한 `회원탈퇴`를 입력하고 삭제 영향을 최종 확인하기 전에는 탈퇴되지 않는다.
- [ ] 탈퇴 성공 시 모든 세션이 종료되고, 실패 시 계정이 유지됐음을 확인할 수 있다.
- [ ] 로딩, 부분 오류, 전체 오류와 세션 만료가 서로 구분되며 정상 동작하는 다른 메뉴는 불필요하게 숨기지 않는다.
- [ ] 작은 WebView, 큰 글자, 키보드 탐색과 모션 감소 설정에서도 핵심 행동을 완료할 수 있다.

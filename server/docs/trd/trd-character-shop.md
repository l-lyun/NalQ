# [TRD · Server] 캐릭터 상점과 퀴즈 완료 보상

## 책임과 원장

이 문서는 [학습 보상 상점 PRD](../../../docs/prd/prd-character-shop.md)와 [캐릭터 상점 API 계약](../../../docs/contracts/contract-api-character-shop.md)을 구현하는 서버의 영속 모델과 트랜잭션 경계를 설명한다. 가격, 보상량, 카탈로그 ID와 공개 오류 의미는 계약이 원장이다.

## 영속 모델

- `character_profiles`: 사용자별 1행으로 코인 잔액과 캐릭터·방·모자·옷 장착 ID를 저장한다. 최초 접근 또는 최초 보상 때 0코인과 기본 장착으로 생성한다.
- `character_owned_items`: 구매한 유료 아이템만 저장하며 `(user_id, item_id)`를 고유하게 제한한다. 무료 기본 아이템은 서버 카탈로그에서 항상 보유한 것으로 계산한다.
- `quiz_coin_rewards`: 지급한 사용자·퀴즈 세트·완료 회차·금액을 저장한다. `(user_id, quiz_set_id)`와 `attempt_public_id`를 각각 고유하게 제한한다. 퀴즈 세트 삭제가 지급 원장과 잔액을 지우지 않도록 `quiz_set_id`에는 외래 키를 두지 않는다.
- 세 테이블은 사용자 물리 삭제 시 정리되도록 `users` 외래 키에 cascade를 두며, 현재의 tombstone 기반 탈퇴에서는 `CharacterAccountLifecycle`이 같은 DB 트랜잭션 안에서 명시적으로 삭제한다.

## 카탈로그와 상태

`CharacterCatalogItem`이 공개 ID, category, 이름, 가격, asset key의 서버 원장이다. 구매 가격과 슬롯 category는 요청 값으로 받지 않는다. 장착 저장은 네 ID를 모두 검증한 뒤 한 번에 변경한다.

## 트랜잭션과 잠금 순서

구매·장착·일반 퀴즈 제출·일반 퀴즈 서술형 자기평가·회원 탈퇴는 먼저 `users`의 해당 행을 `PESSIMISTIC_WRITE`로 잠근다. 이후 필요한 `quiz_sets` 또는 `quiz_attempts` 행을 잠근다. 공통 순서는 `user -> quiz_set/attempt`이며 같은 계정의 잔액 변경, 구매, 보상, 탈퇴를 직렬화한다.

즉시 완료되는 일반 퀴즈는 제출 트랜잭션에서, 서술형이 있는 일반 퀴즈는 마지막 자기평가 트랜잭션에서 보상을 판단한다. 복습 경로는 보상 서비스를 호출하지 않는다. 지급 판단은 다음 순서로 수행한다.

1. 같은 사용자·세트의 지급 원장이 있으면 종료한다.
2. 현재 회차를 제외한 과거 `COMPLETED MAIN` 회차를 잠금 조회한다. 존재하면 기능 도입 전 완료 또는 재풀이이므로 지급하지 않는다.
3. 프로필 잔액에 10을 더하고 지급 원장을 저장한다.

완료 상태 전환, 잔액 증가와 지급 원장 저장은 같은 트랜잭션이다. 사용자 잠금과 DB 고유 제약이 동시 완료·재전송의 중복 지급을 함께 방지한다.

## 검증 기준

- 빠른 테스트는 카탈로그 응답, 구매 멱등성, 잔액 부족, 슬롯·보유 검증, 완료 경로 연결과 탈퇴 수명주기 호출을 검증한다.
- MySQL 통합 테스트는 같은 상품 동시 구매의 단일 차감, 잔액이 하나의 상품만 살 수 있을 때의 경쟁, 같은 세트 동시 완료의 단일 지급, 마이그레이션 제약과 탈퇴 트랜잭션 삭제를 검증한다.

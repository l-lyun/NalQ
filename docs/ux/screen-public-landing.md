# [Screen Spec] 로그인 전 공개 랜딩

> 이 문서는 인증되지 않은 사용자가 NalQ의 가치를 짧게 이해하고 로그인 또는 회원가입으로 이동하는 공개 첫 화면을 정의한다. 인증 정책과 가입 절차는 [이메일 기반 자체 인증](../prd/prd-local-authentication.md)이 책임지고, 가입 뒤 안내는 [첫 진입 온보딩과 NalQ 가이드](screen-onboarding.md)가 책임진다.

## 문서 정보

- 화면명: 로그인 전 NalQ 공개 랜딩
- 문서 상태: `approved`
- 대상 플랫폼: 반응형 웹과 앱 WebView
- 관련 제품 기반: [NalQ 제품 기반](../product.md)
- 관련 기능: [이메일 기반 자체 인증](../prd/prd-local-authentication.md)
- 관련 흐름: [인증 흐름](flow-authentication.md)
- 관련 화면: [회원가입](screen-signup.md), [첫 진입 온보딩과 NalQ 가이드](screen-onboarding.md)
- 최종 수정일: 2026-09-03

## 요구사항 구분

### 확정 사항

- 인증되지 않은 사용자가 기본 주소 `/`에 진입하면 이 화면을 보여준다. 인증된 사용자의 `/`는 홈이다.
- 인증 상태를 확인하는 동안에는 랜딩이나 온보딩을 먼저 노출하지 않는다. 세션 없음이 확인된 뒤에만 랜딩을 보여준다.
- 랜딩은 한 화면의 미니멀 Hero만 사용한다. Hero 아래에 추가 기능 섹션, 카드, 사진과 긴 사용법을 두지 않는다.
- 상단에는 제품명 `NalQ`와 `로그인` 행동을 제공한다.
- Hero에는 승인된 제목·설명과 primary `가입하고 시작하기`, 보조 로그인 문구를 제공한다.
- 로그인 전 화면에는 홈·학습·마이페이지 하단 내비게이션을 표시하지 않는다.
- 웹과 앱 WebView는 같은 웹 랜딩을 사용한다. 앱은 스플래시와 WebView 인증 확인을 마친 뒤 비인증이면 이 화면, 인증 상태면 홈을 보여준다.

### 설계 가정

- Hero는 한 개의 읽기 열과 충분한 여백으로 구성하며, 장식보다 제목과 가입 행동이 먼저 읽히게 한다.
- 상단과 Hero의 로그인 행동은 같은 로그인 화면으로 이동하되, 각각 아래에 승인된 짧은 링크와 보조 문장 문구를 사용한다.

### 미결정 사항

- 없음. 정확한 여백, 폭, 글자 크기와 SEED 컴포넌트 API는 승인된 정보·행동 위계를 유지하는 범위에서 구현 단계가 검증한다.

## 사용자 목표

- 로그인 전 사용자는 NalQ가 읽은 글을 문제로 풀어 오래 기억하도록 돕는 서비스임을 이해한다.
- 가입하려는 사용자는 회원가입으로, 기존 사용자는 로그인으로 이동하면 화면 목적을 달성한다.

## 진입과 이탈

- 진입점: 세션 없음이 확인된 웹의 기본 주소 `/`, 앱 스플래시 뒤 WebView의 세션 없음 결과, 명시적 로그아웃 완료
- 다음 화면: `가입하고 시작하기`는 `/sign-up`, 두 `로그인` 행동은 `/login`
- 뒤로 가기: 브라우저 또는 앱에 유효한 이전 이력이 있으면 플랫폼의 일반 뒤로 가기를 따른다. 랜딩이 첫 문서이면 Android 시스템 뒤로 가기는 앱 기본 종료 동작을 방해하지 않는다.
- 로그인·권한 조건: 비인증 사용자에게만 표시한다. 인증된 사용자가 `/`에 진입하면 홈을 보여준다.
- 보호 URL 직접 접근: 이 랜딩을 경유하지 않고 로그인으로 이동하며, 안전한 원래 내부 URL은 로그인 성공 뒤 복귀할 수 있게 보존한다.

## 정보 구조와 확정 카피

위에서 아래 순서를 유지한다.

1. **상단**
   - 제품명: `NalQ`
   - 보조 행동: `로그인`
2. **Hero**
   - 짧은 도입 문구: `읽은 내용을 내 것으로 만드는 방법 ✍️`
   - 주 제목: `읽은 것을 문제로 풀어보면 더 오래 남아요.`
   - 설명: `노션에 정리해둔 글이나 텍스트를 복사해서 가져오세요.`
   - Primary: `가입하고 시작하기`
   - 보조 로그인 문구: `이미 계정이 있나요? 로그인`

이 항목 뒤에 기능 목록, 온보딩 세 장의 요약, 자동 채점·서술형 자기평가 설명, 고객 사례, 사진과 장식 카드를 추가하지 않는다.

## 행동

| 우선순위 | 행동 | 발생 조건 | 결과 | 실패 시 |
| --- | --- | --- | --- | --- |
| Primary | `가입하고 시작하기` | 비인증 랜딩 | `/sign-up`으로 이동 | 랜딩을 유지하고 다시 시도할 수 있게 한다. |
| Secondary | 상단 `로그인` | 비인증 랜딩 | `/login`으로 이동 | 랜딩을 유지한다. |
| Secondary | `이미 계정이 있나요? 로그인` | 비인증 랜딩 | 같은 `/login`으로 이동 | 랜딩을 유지한다. |

## 화면 상태

| 상태 | 진입 조건 | 보여줄 내용 | 가능한 행동 |
| --- | --- | --- | --- |
| 인증 확인 | 최초 문서 진입 뒤 세션 유무를 확인 중 | 랜딩 카피가 먼저 보이지 않는 중립 로딩 상태 | 기다리기 |
| 기본 | 세션 없음 확인 | 승인된 상단과 Hero | 가입, 로그인 |
| 인증됨 | 유효한 세션 확인 | 랜딩을 노출하지 않음 | 홈으로 이동 |
| 인증 확인 실패 | 세션 유무를 판정할 수 없는 네트워크·서버 오류 | 비로그인으로 단정하지 않는 설명 | 다시 시도 |

별도 빈 상태와 콘텐츠 데이터 오류는 없다. 랜딩 자체는 개인 데이터나 원격 학습 데이터를 요구하지 않는다.

## 반응형·WebView 동작

- 320px의 작은 화면부터 한 열로 읽히며 가로 스크롤이 생기지 않는다.
- 작은 화면에서는 Hero가 한 뷰포트에 가능한 범위에서 들어오게 하되, 작은 높이와 큰 글자에서 문구를 자르지 않고 세로 스크롤을 허용한다.
- 넓은 화면에서도 추가 열, 기능 카드나 사진을 만들지 않고 읽기 폭과 바깥 여백만 조정한다.
- 앱 WebView는 네이티브 스플래시와 문서 로딩 뒤 웹이 세션을 판정한다. 네이티브 셸이 랜딩이나 인증 화면을 별도로 복제하지 않는다.
- safe area가 있는 WebView에서는 상단 제품명과 마지막 로그인 행동이 시스템 영역에 가리지 않아야 한다.

## 접근성

- 제품명, 하나의 주 제목, 두 설명, primary와 보조 행동 순서가 시각 순서와 낭독 순서에서 같다.
- 두 로그인 행동은 모두 목적지가 분명한 접근 가능한 이름을 가진다.
- 이모지는 제목의 일부로 읽힐 수 있으나 같은 의미를 별도 장식 대체 텍스트로 중복 낭독하지 않는다.
- 모든 행동은 키보드로 접근할 수 있고 visible focus와 최소 44×44 CSS px 터치 영역을 가진다.
- 인증 상태가 바뀌어 홈으로 이동할 때 랜딩을 잠깐 표시하거나 포커스를 랜딩에 두지 않는다.

## SEED 컴포넌트 매핑

정확한 컴포넌트 이름·props·토큰은 구현 직전 현재 SEED Docs에서 검증한다.

| UI 책임 | SEED 구성 후보 | 상태·접근성 요구 | 검증 상태 |
| --- | --- | --- | --- |
| 페이지와 Hero 배치 | layout primitive와 `Text` | 단일 읽기 순서, 모바일 우선 반응형 | 구현 시 확인 |
| 가입 행동 | `ActionButton` brand 역할 | 화면의 유일한 prominent CTA, 로딩·focus 상태 | 구현 시 확인 |
| 로그인 행동 | 링크 또는 낮은 위계 행동 | 같은 내부 로그인 목적지, 명확한 이름 | 구현 시 확인 |
| 인증 확인·실패 | 중립 loading, `ResultSection` 후보 | 랜딩 flash 방지, 재시도 제공 | 구현 시 확인 |

## 데이터와 계약

- 필요한 표시 데이터와 사용자 입력은 없다.
- 세션 유무와 인증 실패 의미는 [인증 API](../contracts/contract-api-authentication.md)를 따른다.
- 랜딩은 토큰, 이메일, 사용자 학습정보를 표시하거나 분석 속성으로 요구하지 않는다.

## 인수 조건

- [ ] 비인증 사용자가 `/`에 진입하면 승인된 상단과 Hero만 보이며 추가 기능 섹션·카드·사진이 없다.
- [ ] 인증 상태 확인 중에는 랜딩 또는 온보딩 카피가 먼저 보이지 않고, 인증되면 홈으로 이동한다.
- [ ] 보호 URL의 비인증 직접 접근은 랜딩이 아니라 로그인으로 이동하며 안전한 원래 URL을 보존한다.
- [ ] `가입하고 시작하기`는 회원가입으로, 상단과 Hero의 로그인 행동은 로그인 화면으로 이동한다.
- [ ] 명시적 로그아웃 뒤 개인 정보 없이 공개 랜딩에 도착하고 뒤로 가기로 보호 화면을 다시 볼 수 없다.
- [ ] 앱은 스플래시와 WebView 인증 확인 뒤 비인증이면 같은 랜딩, 인증 상태면 홈을 보여준다.
- [ ] 320px, 큰 글자, 키보드와 WebView safe area에서도 모든 카피와 행동을 사용할 수 있다.

- 공개 가격, 무료 사용량, 통계와 게임 요소

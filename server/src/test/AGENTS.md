# Server Test Guide

이 지침은 `server/src/test/` 아래의 모든 테스트에 적용된다. 상위 `server/AGENTS.md`도 함께 따른다.

## 테스트 책임

- PRD의 인수 조건과 관찰 가능한 동작을 검증한다.
- 순수 도메인·서비스 분기와 값 변환은 빠른 단위 테스트를 우선한다.
- MVC 직렬화, 입력 검증, 보안 필터, 오류 응답은 필요한 Spring 슬라이스에서 검증한다.
- 저장소 쿼리, 트랜잭션과 외부 의존성 의미는 필요한 범위에서 통합 테스트로 검증한다.
- 시간·난수·네트워크를 통제하고 각 테스트가 독립적으로 반복 실행되게 한다.

## Testcontainers 판단 기준

Testcontainers는 다음처럼 운영 의존성의 실제 의미가 결과를 바꿀 때 사용한다.

- MySQL 고유 SQL·타입·인덱스·제약 조건·트랜잭션 동작을 검증할 때
- Redis TTL·원자 연산·자료구조·직렬화 또는 실제 연결 설정을 검증할 때
- 인메모리 대체재나 mock이 운영 동작과 달라 회귀를 놓칠 가능성이 클 때

다음 경우에는 사용하지 않는다.

- 순수 서비스 로직, 매퍼, 검증기, 단순 분기 테스트
- 저장소나 외부 포트를 대역으로 충분히 검증할 수 있는 경우
- 단지 테스트를 실제 환경처럼 보이게 만들기 위한 경우

도입 시 컨테이너 수명주기, 데이터 초기화와 테스트 격리를 명확히 하고 필요한 테스트 의존성만 추가한다. Docker를 사용할 수 없으면 실패를 숨기지 말고 실행 제약을 보고한다.

## 외부 AI·문서 연동

- 테스트에서 OpenAI, Notion 또는 다른 외부 실서비스를 호출하지 않는다.
- mock, stub, fake server 또는 결정적인 fixture를 사용한다.
- 실제 API 키, 사용자 토큰과 운영 데이터를 테스트 설정이나 fixture에 기록하지 않는다.

독립 테스트 작업을 맡은 경우 `server/src/main/**`을 수정하지 않는다. 프로덕션 결함은 재현 테스트와 기대·실제 결과로 보고한다.

# [Screen Spec] 프로필

> 이 문서는 이전 `프로필` 설계의 역사 기록이며 현행 구현 기준이 아니다. 아래의 탈퇴·마케팅·문의 관련 미결정 표현을 구현 근거로 사용하지 않고, 현재 사용자 노출 명칭과 모든 현행 정책은 [마이페이지 화면 명세](screen-mypage.md)를 따른다.

## 문서 정보

- 문서 상태: `superseded`
- 요구사항 상태: 현행 요구사항은 [마이페이지 화면 명세](screen-mypage.md)로 이전 완료
- 대상 플랫폼: 반응형 웹과 앱 WebView, 모바일 우선
- 관련 내비게이션: [제품 기반의 전역 내비게이션](../product.md#전역-내비게이션)
- 관련 인증 흐름: [인증 흐름](flow-authentication.md)

## 목표와 범위

### 사용자 목표

- 자신의 계정임을 확인하고 계정·서비스 관련 메뉴를 짧게 탐색한다.
- 홈에 있던 로그아웃을 프로필에서 예측 가능하게 찾는다.
- 현재는 단순한 기본 이미지로 시작하되 향후 사진이나 캐릭터 꾸미기가 들어와도 프로필의 중심 구조가 바뀌지 않는다.

### 완료 조건

사용자가 프로필에서 계정 정보를 식별하고 필요한 계정 또는 서비스 정보 행을 선택하거나 로그아웃을 완료하면 화면의 주 목적을 달성한다.

### 범위

- 화면 상단 중앙 프로필 이미지 슬롯
- 닉네임과 이메일
- 계정 관리
- 서비스 정보와 문의
- 로그아웃과, 정책 확정 후 회원 탈퇴 진입
- 로딩, 부분 오류, 세션 만료와 행동 처리 상태
- `홈`·`학습`·`프로필` 하단 내비게이션

### 비범위

- 프로필 사진 업로드·삭제·크롭
- 캐릭터, 프레임, 방 꾸미기와 상점
- 학습 통계, 경험치, 레벨, 랭킹과 친구
- 소셜 로그인과 외부 학교·포털 인증
- 계정 탈퇴의 데이터 보존·복구 정책 자체

## 요구사항 구분

### 확정 사항

- 프로필 이미지는 상단 정보 영역의 가로 중앙에 배치한다.
- 이미지 아래에는 닉네임을 주 정보, 이메일을 보조 정보로 중앙 정렬한다.
- 홈에서 제거한 로그아웃은 프로필의 `계정 관리`에 둔다.
- 사진이나 캐릭터 기능이 없어도 고정 크기의 기본 프로필 이미지를 제공한다.
- 프로필은 계정 관리와 서비스 정보 정도의 단순 구조를 유지하고 잠긴 게임화 메뉴를 미리 노출하지 않는다.
- 각 설정 행의 chevron은 행 전체 높이의 세로 중앙에 둔다.

### 설계 결정

- 초기 기본 이미지는 중립적인 원형 avatar 또는 닉네임 기반 fallback이다. 현재 편집 기능이 없으면 이미지 위에 카메라·연필 아이콘이나 `꾸미기` 버튼을 표시하지 않는다.
- 프로필 슬롯은 미래에 `사진/캐릭터 본체 → 선택적 프레임 → 상태 배지` 레이어를 수용하되, 장식 레이어는 사용자 이름 낭독을 방해하지 않는다.
- 메뉴는 개별 카드가 아니라 섹션 제목 아래 세로 목록으로 묶는다. 얇은 구분과 충분한 여백을 사용하고 그림자를 반복하지 않는다.
- `로그아웃`은 일반 목록에서 찾을 수 있게 하되 계정 정보 변경과 시각적으로 구분한다. 로그아웃은 다시 로그인할 수 있으므로 별도 확인 대화상자를 기본으로 강제하지 않는다.
- `회원 탈퇴`는 위험 행동으로 마지막에 분리하고, 정책·API와 확인 흐름이 준비되기 전에는 비활성 행이 아니라 화면에서 숨긴다.
- 앱 버전처럼 이동하지 않는 값에는 chevron을 사용하지 않는다.

### 미결정 사항

- 닉네임·이메일을 이 화면에서 편집할지 별도 계정 정보 화면에서 편집할지
- 회원 탈퇴의 재인증, 유예 기간, 학습자료·풀이 데이터 삭제 범위와 복구 정책
- 마케팅 수신동의를 초기 설정으로 제공할지와 동의 채널·철회 반영 시점
- 서비스 문의의 목적지: 이메일, 웹 폼 또는 외부 고객지원 도구
- 프로필 사진·캐릭터 꾸미기의 출시 시점, 저장 모델, 공개 범위와 기본 자산

## 진입과 이탈

### 진입점

- 로그인 후 하단 `프로필` 탭

### 이탈 목적지

| 행동 | 목적지 또는 결과 | 비고 |
| --- | --- | --- |
| `계정 정보` | 계정 정보 확인·편집 화면 | 실제 편집 범위가 있을 때만 노출 |
| `로그아웃` | 현재 세션 폐기 후 로그인 화면 | 처리 중 중복 선택 방지, 실패 시 현재 화면 유지 |
| `회원 탈퇴` | 위험 행동 확인·재인증 흐름 | 정책·API 확정 후 노출 |
| `서비스 이용약관` | 현재 약관 문서 | 외부 브라우저라면 복귀 가능해야 함 |
| `개인정보처리방침` | 현재 개인정보 문서 | 버전과 시행일은 문서 책임 |
| `마케팅 수신동의` | 동의 조회·변경 화면 | 기능이 실제 제공될 때만 노출 |
| `서비스 이용 문의하기` | 확정된 문의 채널 | 전송 실패나 앱 복귀 경로 제공 |
| 하단 `홈`·`학습` | 해당 최상위 화면 | 탭 전환 |

## 모바일 우선 화면 구조

```text
프로필
├─ 화면 헤더: 프로필
├─ 중앙 프로필 영역
│  ├─ 원형 프로필 이미지 슬롯
│  ├─ {nickname}님
│  └─ {email}
├─ 계정 관리
│  ├─ 계정 정보 (기능이 있을 때)
│  ├─ 로그아웃
│  └─ 회원 탈퇴 (정책·API가 있을 때만)
├─ 서비스 정보
│  ├─ 서비스 이용약관
│  ├─ 개인정보처리방침
│  ├─ 마케팅 수신동의 (기능이 있을 때)
│  ├─ 서비스 이용 문의하기
│  └─ 앱 버전 · {version}
├─ 하단 콘텐츠 여백
└─ 홈·학습·프로필 하단 내비게이션
```

- 첨부 화면의 간단한 계정·앱 정보 구성을 참고하되 학교·포털 인증, 시간표, 공지사항처럼 NalQ 범위가 아닌 항목은 가져오지 않는다.
- 상단 프로필 영역은 중앙 정렬하고, 목록 영역은 읽기 효율을 위해 좌측 정렬한다.
- 프로필 화면 자체에 별도의 설정 탭이나 중첩 대시보드를 만들지 않는다.

## 영역별 콘텐츠와 행동

### 1. 프로필 이미지와 계정 요약

- 원형 이미지 슬롯은 시각적 기준점이며 닉네임과 이메일보다 앞에 온다.
- 이미지가 없으면 기본 avatar를 표시한다. 깨진 이미지 아이콘이나 빈 원을 노출하지 않는다.
- 향후 사진이나 캐릭터가 추가되어도 이미지 외곽 크기와 닉네임·이메일의 위치는 유지한다.
- 장식 프레임과 상태 배지는 사진을 가리거나 의미 없는 애니메이션으로 시선을 독점하지 않는다.
- 편집 기능이 생기면 이미지와 별도의 명시적 `프로필 꾸미기` 행동을 제공한다. 이미지 자체만 모호하게 탭하게 하지 않는다.

### 2. 계정 관리

- `계정 정보`는 실제로 확인하거나 변경할 하위 화면이 준비된 경우에만 표시한다.
- `로그아웃`은 현재 기기의 세션을 폐기한다. 처리 중에는 행에 진행 상태를 보이고 중복 요청을 막는다.
- 로그아웃 실패 시 프로필을 유지하고 실패 이유와 `다시 시도`를 인접하게 제공한다.
- `회원 탈퇴`는 다른 행과 충분히 떨어뜨리고 위험 의미를 텍스트로 함께 전달한다. 단순한 로그아웃과 같은 스타일·흐름으로 처리하지 않는다.

### 3. 서비스 정보

- 법적 문서는 현재 유효한 버전으로 연결한다.
- 문의하기는 지원 채널이 정해진 경우에만 노출한다.
- 앱 버전은 값 표시 행이며 링크나 chevron이 아니다. 업데이트 행동을 제공하는 경우에만 별도 링크 의미를 부여한다.

### 4. 목록 행과 chevron

- 이동 행 전체가 하나의 링크 또는 버튼이고 chevron은 별도 포커스 대상이 아니다.
- trailing 영역은 텍스트와 분리하며 chevron은 전체 행의 세로 중앙에 정렬한다.
- 긴 문구와 큰 글자에서 행 높이가 늘어나도 chevron이 제목 첫 줄에 붙거나 텍스트와 겹치지 않는다.
- 현재 값이 있는 설정은 레이블과 값을 함께 읽을 수 있게 하고 색으로만 상태를 구분하지 않는다.

## 상태

| 상태 | 표시 | 복구·행동 |
| --- | --- | --- |
| 프로필 로딩 | 중앙 avatar와 계정 텍스트, 목록 윤곽의 중립 Skeleton | 하단 탭 유지 |
| 정상 계정 | 기본 또는 실제 이미지, 닉네임·이메일, 사용할 수 있는 메뉴만 표시 | 행별 이동 |
| 이미지 실패 | 기본 avatar로 교체 | 나머지 프로필 유지 |
| 일부 메뉴 데이터 실패 | 성공한 메뉴 유지, 해당 영역에 설명 | 영역 재시도 |
| 로그아웃 중 | 로그아웃 행 진행 상태, 중복 선택 방지 | 성공 시 로그인 화면 |
| 로그아웃 실패 | 현재 세션과 프로필 유지 | 오류 설명과 다시 시도 |
| 세션 만료 | 개인 정보 제거 | 로그인 화면으로 이동 |

## 반응형·WebView

- `base`는 한 열과 세로 스크롤이다. 프로필 이미지·닉네임·이메일은 중앙, 메뉴는 좌측 정렬한다.
- 320 CSS px와 큰 글자에서도 이메일과 메뉴명이 잘리지 않고 행 높이가 늘어난다.
- `md` 이상에서도 하나의 읽기 열을 유지하며 바깥 여백만 늘린다. 중앙 프로필 영역과 목록을 서로 다른 대시보드 열로 나누지 않는다.
- 하단 내비게이션과 홈 인디케이터에 마지막 행이 가리지 않게 콘텐츠 여백을 둔다. 앱 셸과 웹 중 한 계층만 safe-area를 소유한다.
- 프로필과 홈·학습 사이의 하단 탭 이동은 [제품 기반의 최상위 탭 전환](../product.md#최상위-탭-전환)을 따른다. 진입과 이탈 모두 WebView와 네이티브 셸의 별도 모션 없이 즉시 바뀐다.

## 접근성

- `프로필`은 하나의 `h1`, `계정 관리`와 `서비스 정보`는 순서에 맞는 하위 제목이다.
- 프로필 이미지의 대체 텍스트는 `{nickname}님의 프로필 이미지`처럼 계정 식별에 도움이 될 때만 제공한다. 장식 프레임·배지는 숨긴다.
- 기본 avatar가 닉네임과 같은 정보를 중복 전달하면 장식으로 처리한다.
- 목록 행은 한 번의 탭 정지점이며 native 링크·버튼 키보드 동작과 visible focus를 유지한다.
- `로그아웃`, `회원 탈퇴`, 처리 중과 실패 상태를 색이나 아이콘만으로 구분하지 않는다.
- 터치 대상은 최소 44×44 CSS px이며 글자 확대 시 고정 높이로 자르지 않는다.

## SEED 컴포넌트 역할 후보

정확한 props·import와 아이콘 이름은 구현 단계에서 현재 설치 버전과 SEED Docs로 다시 검증한다.

| UI 책임 | 후보 | 사용 원칙 |
| --- | --- | --- |
| 화면·중앙 프로필 배치 | `Box`, `VStack`, `Text`와 현재 avatar primitive 후보 | 원형 슬롯과 중앙 정렬, 실제 avatar 컴포넌트 존재 여부 재검증 |
| 설정·문서 이동 행 | `List`, `ListLinkItem` 또는 `ListButtonItem`, 필요 시 `ListDivider` | 전체 행 한 행동, chevron 장식 처리 |
| 로그아웃 | 목록형 버튼 행 | 현재 화면의 prominent CTA로 과장하지 않음 |
| 회원 탈퇴 확인 | `AlertDialog` 후보 | 정책 확정 후 focus trap·안전한 기본 행동 제공 |
| 로딩 | 중립 `Skeleton` | 최종 구조와 유사한 윤곽 |
| 오류 | `ResultSection`, 필요 시 인라인 오류 조합 | 실패 영역과 복구 행동을 인접하게 제공 |

## 필요한 데이터·계약 영향

### 현재 MVP에 필요한 값

- `GET /api/v1/users/me`의 `nickname`, `email`, 세션 상태
- 앱 버전
- 노출 가능한 약관·개인정보처리방침·문의 목적지

### 후속 기능에서 계약이 필요한 값

- `profileImageUrl` 또는 캐릭터·프레임 식별자는 프로필 꾸미기 기능을 승인할 때 사용자 데이터 계약에 추가한다. 현재 MVP 화면을 위해 빈 필드를 선행 추가하지 않는다.
- 닉네임·이메일 변경, 마케팅 수신동의 변경, 회원 탈퇴는 각 정책과 API 계약이 확정된 뒤 행을 노출한다.
- 회원 탈퇴는 학습자료·QuizSet·attempt·review session의 삭제 또는 비식별화 의미를 공유 계약에 기록하기 전 구현하지 않는다.

## 관찰 가능한 수용 기준

- [ ] 프로필 이미지 슬롯, 닉네임과 이메일이 화면 상단 중앙에 정렬된다.
- [ ] 실제 이미지가 없어도 기본 avatar가 표시되고 깨진 이미지나 빈 영역이 보이지 않는다.
- [ ] 편집 기능이 없을 때 카메라·연필·꾸미기 affordance를 노출하지 않는다.
- [ ] 홈에는 로그아웃이 없고 프로필의 계정 관리에서 로그아웃할 수 있다.
- [ ] 화면에는 실제로 이동하거나 변경할 수 있는 메뉴만 보이며 준비되지 않은 기능은 비활성 행으로 나열하지 않는다.
- [ ] 회원 탈퇴는 정책·API·확인 흐름이 준비된 경우에만 일반 메뉴와 구분해 노출된다.
- [ ] 앱 버전처럼 이동하지 않는 행에는 chevron이 없다.
- [ ] 이동 행의 chevron은 전체 행 높이의 세로 중앙이며 별도 포커스 대상이 아니다.
- [ ] 320 CSS px와 큰 글자에서 이미지·텍스트·chevron이 겹치거나 가로 스크롤이 생기지 않는다.
- [ ] 로그아웃 중·실패와 세션 만료 상태를 텍스트로 이해하고 복구할 수 있다.
- [ ] 홈·학습과 프로필 사이의 양방향 탭 이동은 수평 이동·불투명도·reduced motion 대체 애니메이션 없이 즉시 전환된다.
- [ ] 프로필 탭을 벗어났다가 돌아와도 스크롤·처리 상태·유효한 계정 캐시가 탭 이동 때문에 초기화되지 않는다.

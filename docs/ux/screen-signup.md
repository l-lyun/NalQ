# [Screen Spec] 회원가입

## 문서 정보

- 화면명: 이메일 회원가입
- 문서 상태: `draft`
- 대상 플랫폼: `both` (웹·WebView 공통 화면 우선)
- 관련 기능: [이메일 기반 자체 인증](../prd/prd-local-authentication.md)
- 관련 흐름: [인증 흐름](flow-authentication.md)
- 관련 계약: [인증 API](../contracts/contract-api-authentication.md)
- 최종 수정일: 2026-08-20

## 요구사항 구분

### 확정 사항

- 이메일 가입은 `계정 확인`과 `가입 정보 설정`의 2단계다.
- 1단계에는 이메일, 인증 코드 발송·확인, 비밀번호, 비밀번호 확인을 둔다.
- 인증 메일 발송 후에는 이 화면에서 이메일을 변경할 수 없다. 이메일을 바꾸려면 로그인 화면으로 돌아가 회원가입을 다시 시작한다.
- 이메일 인증이 완료되고 두 비밀번호가 정책에 맞게 일치해야 2단계로 이동할 수 있다.
- 2단계에는 닉네임 입력·중복 확인, 필수 서비스 이용약관과 개인정보 수집·이용 동의를 둔다.
- 닉네임 규칙과 중복 의미는 [자체 인증 PRD의 핵심 규칙](../prd/prd-local-authentication.md#핵심-규칙)을 따른다.
- 필수 약관을 모두 동의하고 현재 닉네임의 중복 확인이 유효해야 가입 완료 행동이 활성화된다.
- 가입 성공 시 자동 로그인하고 홈으로 이동한다.
- MVP에는 소셜 로그인 버튼을 노출하지 않는다.
- 향후 소셜 신규가입은 제공자 인증 뒤 비밀번호 없이 2단계 화면을 재사용한다.

### 설계 가정

- 화면 상단에 `1/2 계정 확인`, `2/2 가입 정보 설정`처럼 현재 위치를 텍스트와 진행 상태로 함께 알린다.
- 비밀번호와 비밀번호 확인에는 각각 보기·숨기기 행동을 제공한다.
- 2단계에서 뒤로 가면 같은 화면 세션 안에서는 1단계 입력과 이메일 인증 완료 상태를 보존한다.
- 전체 동의는 현재 노출된 두 필수 항목을 함께 선택·해제하는 편의 기능이며 별도의 동의 항목으로 기록하지 않는다.
- 약관 전문 끝까지 스크롤해야 동의할 수 있도록 강제하지 않는다. 항목별 체크가 명시적 동의 행동이다.

### 미결정 사항

- 새로고침·앱 종료 뒤 1단계 완료 상태와 비밀번호 입력을 어디까지 복구할지
- 가입 계속 자격의 유효시간이 끝났을 때 1단계 전체를 다시 할지 이메일 인증만 다시 할지
- 법률 검토가 끝난 실제 약관 전문, 식별자·버전과 동의 철회·보존 정책
- 닉네임 금칙어, 변경 주기와 재사용 대기시간
- 향후 소셜 가입 도중 이탈한 사용자의 장기 재진입 화면

## 사용자 목표

- 이 화면에 들어온 사용자가 해결하려는 일: 이메일 소유를 확인하고 안전한 비밀번호, 고유한 닉네임과 필수 동의를 설정해 계정을 만든다.
- 완료 조건: 별도 로그인 없이 홈에 도착하고 본인의 학습 기능을 사용할 수 있다.

## 진입과 이탈

- 진입점: 로그인 화면의 `회원가입` 행동
- 1단계 다음 화면: 2단계 가입 정보 설정
- 2단계 다음 화면: 가입 성공 시 홈
- 1단계 뒤로 가기: 로그인 화면
- 2단계 뒤로 가기: 현재 화면 세션의 1단계 상태를 보존해 계정 확인 단계로 이동
- 로그인·권한 조건: 로그아웃 사용자만 진입한다. 이미 로그인한 사용자는 홈으로 보낸다.

## 정보 구조

### 공통 상단

1. 이전 행동: 로그인 또는 이전 가입 단계로 돌아간다.
2. 화면 제목: `회원가입`
3. 단계 표시: 현재 단계와 전체 2단계를 숫자와 텍스트로 전달한다.
4. 짧은 안내: 현재 단계에서 완료할 일을 한 문장으로 설명한다.

### 1단계: 계정 확인

1. 이메일: 항상 보이는 레이블, 이메일 입력, `인증 코드 받기` 행동
2. 인증 코드: 발송 성공 후 나타나는 6자리 입력, 남은 유효시간 안내, `확인`, `재발송`
3. 비밀번호: 정책 안내, 입력, 보기·숨기기
4. 비밀번호 확인: 입력, 보기·숨기기, 사용자가 입력을 시작한 뒤 일치 여부 안내
5. 주 행동 `다음`: 이메일 인증 완료, 비밀번호 정책 충족과 두 값 일치 시 활성화
6. 보조 문구와 로그인 이동: `이미 계정이 있나요? 로그인`

### 2단계: 가입 정보 설정

1. 닉네임: 입력, 규칙 안내, 입력 오른쪽 또는 바로 아래의 `중복 확인`
2. 닉네임 결과: 확인 중, 사용 가능, 이미 사용 중, 오류와 재시도 상태
3. 약관 동의: `전체 동의`, `[필수] 서비스 이용약관`, `[필수] 개인정보 수집·이용 동의`, 각 항목의 `보기`
4. 임시 약관 고지: MVP 전문이 법률 검토 전 임시 내용임을 개발·검수 환경에서 식별할 수 있게 한다. 사용자에게 확정 약관처럼 오인시키는 문구는 쓰지 않는다.
5. 주 행동 `가입하고 시작하기`: 유효한 닉네임 확인과 두 필수 동의 완료 시 활성화

### 약관 전문

- 작은 화면·WebView: 제목과 닫기 행동이 있는 전체 화면형 상세 화면
- 넓은 웹 화면: 읽기 영역을 충분히 확보한 대화상자
- 긴 임시 문자열은 내부 스크롤 영역에서 읽을 수 있고 텍스트 확대 시 잘리거나 행동을 가리지 않는다.
- 닫으면 회원가입 입력과 동의 상태를 유지한다.

## 행동과 상태

| 우선순위 | 행동 | 발생 조건 | 결과 | 실패 시 |
| --- | --- | --- | --- | --- |
| Primary | 인증 코드 받기 | 이메일 형식 유효 | 코드 입력 영역과 재발송 가능 시각 노출 | 이메일 유지, 재시도 안내 |
| Primary | 인증 코드 확인 | 6자리 입력 완료 | 이메일 인증 완료 상태 표시 | 코드 유지, 오류·만료에 맞는 복구 제공 |
| Primary | 다음 | 인증 완료, 비밀번호 정책 충족·일치 | 2단계로 이동 | 현재 입력 유지 |
| Primary | 닉네임 중복 확인 | 닉네임 형식 유효 | 현재 입력값에 대한 사용 가능 여부 표시 | 닉네임 유지, 다시 확인 제공 |
| Secondary | 약관 보기 | 각 약관 행 선택 | 해당 전문 열기 | 가입 상태 유지, 다시 열기 |
| Primary | 가입하고 시작하기 | 중복 확인 유효, 필수 동의 완료 | 처리 중 중복 제출 차단 후 홈 이동 | 입력·동의 유지, 문제 필드로 복귀 |

### 닉네임 확인 상태 규칙

| 상태 | 표시와 행동 |
| --- | --- |
| 빈 값·형식 오류 | 규칙을 안내하고 중복 확인을 비활성화한다. |
| 확인 전 | `중복 확인이 필요해요.`를 안내한다. |
| 확인 중 | 입력과 버튼의 중복 조작을 막고 진행 상태를 전달한다. |
| 사용 가능 | `사용할 수 있는 닉네임이에요.`를 텍스트로 표시한다. |
| 사용 중 | `이미 사용 중인 닉네임이에요.`를 표시하고 입력에 포커스를 돌린다. |
| 확인 후 입력 변경 | 기존 성공 결과를 즉시 폐기하고 확인 전으로 돌아간다. |
| 최종 제출 전 선점 | 다른 입력과 약관 상태를 보존하고 사용 중 상태로 돌아간다. |
| 네트워크 오류 | 닉네임을 유지하고 `다시 확인`을 제공한다. |

### 주 행동 비활성 조건

- 1단계 `다음`: 이메일 미인증, 비밀번호 정책 위반, 비밀번호 확인 미입력 또는 불일치 중 하나라도 해당할 때
- 2단계 `가입하고 시작하기`: 닉네임 형식 위반, 현재 값의 중복 확인 없음, 필수 약관 하나 이상 미동의 중 하나라도 해당할 때
- 비활성 상태만으로 이유를 전달하지 않고 해당 필드 가까이에 충족해야 할 조건을 안내한다.

## 반응형·WebView 동작

- 모바일은 한 열의 문서형 폼으로 구성하고, 넓은 화면에서도 입력 읽기 폭을 제한해 한 열을 유지한다.
- 키보드가 열려도 현재 입력과 주 행동으로 스크롤할 수 있어야 하며, 고정 행동 영역이 입력·오류 문구를 가리지 않는다.
- WebView의 안전 영역과 시스템 뒤로 가기를 보존한다. 2단계 시스템 뒤로 가기는 앱 종료가 아니라 1단계 이동으로 처리한다.
- 긴 약관과 오류 문구, 200% 텍스트 확대에서도 가로 스크롤 없이 읽을 수 있어야 한다.

## 접근성

- 제목, 단계 안내, 필드 순서가 시각 순서와 보조기기 읽기 순서에서 같다.
- 모든 입력은 placeholder와 별개인 레이블을 가진다.
- 비밀번호 보기·숨기기, 코드 재발송, 닉네임 중복 확인은 현재 상태를 이름과 텍스트로 전달한다.
- 동적 성공·오류 안내는 적절한 live region으로 전달하되 입력마다 과도하게 반복 읽지 않는다.
- 약관의 체크 행동과 보기 행동은 별도의 포커스 가능한 컨트롤이다.
- 키보드만으로 입력, 인증, 중복 확인, 약관 열람·닫기와 가입 완료가 가능하다.
- 성공·오류·비활성 상태를 색상만으로 구분하지 않는다.

## 데이터와 계약

- 사용자 입력: 이메일, 인증 코드, 비밀번호, 비밀번호 확인, 닉네임, 약관별 동의
- 서버 전송 제외: 비밀번호 확인, 전체 동의 자체의 선택값
- 서버 전송: 비밀번호 한 값, 현재 닉네임, 동의한 필수 약관의 식별자·버전, 가입 계속 자격
- 민감정보: 비밀번호·인증 코드·가입 계속 자격은 분석 사건, URL과 일반 영속 저장소에 남기지 않는다.
- MVP 임시 약관 전문은 프론트엔드 콘텐츠이며 서버에 전문 문자열을 보내지 않는다.
- 현재 서버와 목표 계약의 차이는 [회원가입 계약 전환 상태](../contracts/contract-api-authentication.md#회원가입-계약-전환-상태)를 따른다.

## 인수 조건

- [ ] 이메일 인증과 비밀번호 확인이 완료되기 전에는 2단계로 이동할 수 없다.
- [ ] 닉네임을 바꾸면 성공했던 중복 확인 상태가 즉시 무효화된다.
- [ ] 두 필수 약관 중 하나라도 동의하지 않으면 가입을 완료할 수 없다.
- [ ] 닉네임 선점과 네트워크 오류에도 수정할 필요 없는 입력과 동의 상태가 유지된다.
- [ ] 가입 성공 시 자동 로그인된 상태로 홈에 도착한다.
- [ ] MVP 화면에 소셜 로그인 버튼과 마케팅 수신 동의를 노출하지 않는다.
- [ ] 작은 화면, 키보드 탐색과 텍스트 확대에서 핵심 행동을 완료할 수 있다.

## 비범위

- 소셜 제공자 선택과 인증 화면
- 소셜 가입 미완료 사용자의 장기 재진입
- 실제 법률 약관 작성과 검토
- 닉네임 변경·신고·금칙어 관리
- 서버·클라이언트 상태관리와 정확한 컴포넌트 구현

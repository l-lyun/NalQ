# [Data Contract] 학습자료와 퀴즈

- 소유 영역: 서버 학습자료·퀴즈·복습 도메인
- 관련 기능명세: [학습자료 만들기](../prd/prd-content-import.md), [퀴즈 생성·풀이·결과·복습](../prd/prd-quiz-learning.md)
- 관련 API: [학습자료·퀴즈·복습 API](contract-api-quiz-learning.md)

## 목적과 경계

학습자료와 원문 출처, 문제 세트와 평가 근거, 본 퀴즈 회차와 복습 상태가 웹·앱·서버에서 같은 의미로 사용되도록 데이터의 소유권, 생명주기와 추적 범위를 정의한다. 물리 테이블, 컬럼과 인덱스 자체는 서버 구현 결정이며 이 계약의 의미와 생명주기를 위반할 수 없다.

## 공유 개념

- **학습자료와 원문 출처:** 사용자가 소유한 학습 원문과 출처 정보다. 문제 세트 생성이 접수된 뒤의 본문 잠금과 제목 수정 가능 여부는 PRD 정책을 따른다.
- **문제 세트와 문제:** 한 번 생성된 문제 세트, 문제, 정답 기준과 원문 근거는 불변이다. 단답형은 결과 설명용 대표 답안과 자동 판정용 허용 답안 목록을 구분한다.
- **본 퀴즈 회차(attempt):** 최종 제출마다 생기는 사용자 소유의 학습 기록이다. 제출 답안과 제출 시 자동 판정은 불변이며, 사용자 수정이 허용된 값은 별도 현재 상태로 다룬다.
- **복습 세션:** 한 source attempt의 복습 대상 문항을 생성 시점에 snapshot한 기록이다. 문항별 해결 상태를 저장하지만 source attempt의 제출 답안이나 최초 자동 판정을 바꾸지 않는다.
- **생성·채점 근거:** 생성·채점에 사용한 모델과 평가 근거는 사용자에게 공개하는 학습 정보와 내부 추적 정보를 구분한다.

이 문서는 현재 상태, 불변성과 보존 경계의 원장이다. HTTP 필드 모양과 오류는 [학습자료·퀴즈·복습 API](contract-api-quiz-learning.md)가 책임진다.

## 본 퀴즈 회차와 채점 결과

### 제출 시 불변 값

- `submittedAnswer`: 사용자가 최종 제출한 원문이다. 단답형 판정 수정으로 바뀌지 않는다.
- `automaticOutcome`: 제출 시 서버가 계산한 최초 문항 판정이다. 단답형 사용자 수정과 복습 뒤에도 바뀌지 않는다.
- `automaticGrading`: 객관식·빈칸·단답형의 `automaticOutcome`만 집계한 제출 시점 점수다. 이후 사용자 수정으로 다시 계산하지 않는다.

### 단답형 현재 판정

- `userOverrideOutcome`: 사용자가 마지막으로 저장한 `CORRECT|INCORRECT`다. 수정 전에는 없다.
- 현재 `outcome`: `userOverrideOutcome`이 있으면 그 값이고, 없으면 `automaticOutcome`이다.
- `gradingSource`: 현재 판정이 최초 자동 판정이면 `AUTOMATIC`, 사용자 판정이면 `USER_OVERRIDE`다.
- `gradingRevision`: 최초 자동 판정 직후 `0`이며, 현재 판정이 실제로 바뀌는 사용자 수정마다 1 증가한다. 같은 현재 판정의 no-op 저장은 증가시키지 않는다.
- `correctedAt`: 최신 사용자 판정이 실제로 저장된 시각이며 수정 전에는 없다. no-op 저장으로 갱신하지 않는다.

MVP에서는 전체 사용자 수정 이력을 보존하지 않는다. 제출 시 불변 값과 최신 `userOverrideOutcome`, `gradingRevision`, `correctedAt`만 보존한다. 사용자 판정은 해당 사용자·attempt·question 결과에만 적용하며 문제의 허용 답안이나 다른 attempt에 전파하지 않는다.

### 현재 요약

- `summary.scoredGrading`: 객관식·빈칸의 자동 판정과 단답형의 현재 `outcome`을 집계한 조회 시점 채점 점수다. 제출 시점의 `automaticGrading`과 의미가 다르다.
- `summary.revision`: attempt 전체 요약의 순서를 나타낸다. attempt 생성 시 `0`이며 단답형 현재 판정, 서술형 자기평가 집계 또는 복습 해결 상태처럼 공개 요약 값이 실제로 바뀔 때 증가한다.
- 문항별 `gradingRevision`은 한 단답형 판정의 동시성을, `summary.revision`은 attempt 전체 요약의 최신성을 나타낸다. 두 revision은 서로 대신할 수 없다.

## 복습 snapshot

- 복습 세션은 생성 시 source attempt의 복습 대상 문항과 당시 `summary.revision`을 snapshot한다.
- 활성 세션의 문항 목록은 생성 뒤 고정된다. source attempt의 단답형 현재 판정이 바뀌어도 진행 중 문항을 추가하거나 제거하지 않는다.
- 판정 수정으로 바뀐 복습 대상 여부는 다음 복습 세션을 생성할 때 반영한다.
- 따라서 source attempt의 현재 `reviewQuestionCount`와 활성 세션의 남은 문항 수는 일시적으로 다를 수 있으며 같은 값으로 해석하지 않는다.

## 생명주기

- 제출 답안, 최초 자동 판정, 최신 사용자 판정과 revision은 해당 attempt의 일부로 같은 생명주기를 갖는다.
- 단답형 판정 수정의 멱등 처리 결과도 attempt가 보존되는 동안 함께 보존하며 attempt보다 먼저 독립 만료시키지 않는다.
- 향후 attempt 삭제·익명화 정책을 정하면 단답형 최신 판정과 멱등 결과도 같은 정책으로 처리한다. 현재 문서는 attempt 자체의 보존 기간을 새로 확정하지 않는다.

## 열린 질문

- 사용자 계정이나 학습자료를 삭제할 때 파생 문제 세트, 본 퀴즈 회차와 복습 상태를 함께 삭제할지 익명화하거나 별도 기간 보존할지
- Notion 원본 식별자와 연결 토큰을 어떤 범위와 기간으로 보관할지
- 학습자료 원문과 외부 LLM 요청·응답을 보관할지, 보관한다면 각각의 최소·최대 기간과 삭제 조건을 어떻게 정할지
- 생성·채점 모델의 제공자·모델·버전과 평가 근거를 어느 수준까지 추적해야 결과를 재현하고 감사할 수 있는지
- 본 퀴즈 회차 삭제와 복습 해결 상태의 삭제·보존을 어떻게 연계할지

위 질문은 데이터 보존과 개인정보 범위를 바꾸므로 서버 구현이나 운영 로그 정책에서 임의로 확정하지 않는다.

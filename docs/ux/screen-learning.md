# [Screen Spec] 학습 메인·내 학습자료·내 퀴즈

## 목표와 범위

로그인한 사용자가 학습 탭에서 최근 퀴즈와 복습할 퀴즈를 바로 이어서 학습하고, 새 문제를 만들거나, 별도 목록 화면에서 저장한 학습자료와 퀴즈를 검색·관리하도록 한다. 학습 메인은 다음 학습 행동과 진입에 집중하고 많은 항목의 탐색·편집은 `내 학습자료`, `내 퀴즈` 전체 페이지가 책임진다.

문제 생성 조건, 생성 오버레이, 문제 풀이·결과 화면의 상세 UI는 이 문서의 범위가 아니다. 제품 정책은 관련 PRD, 화면 간 중단·복구는 관련 Flow, 요청·응답과 오류 의미는 공유 Contract가 책임진다.

## 요구사항 구분

### 사용자 확정 사항

- 학습 메인은 위에서 아래로 `최근 퀴즈` → `새 문제 만들기` → `복습할 퀴즈` → `내 퀴즈 전체 보기` → `내 학습자료 전체 보기` 순서다.
- `내 학습자료`와 `내 퀴즈`는 각각 검색 가능한 별도 전체 페이지와 route를 가진다.
- `내 학습자료`는 검색 위에 전체 너비 `학습자료 추가하기`를 항상 제공하고, Bottom Sheet에서 `노션에서 가져오기`와 `직접 입력하기`를 선택한다.
- 학습자료 목록 항목은 터치하면 펼쳐지고, 펼친 영역 하단에 `퀴즈 만들기`, `학습자료 변경`을 제공한다.
- 학습자료의 제목과 본문을 수정할 수 있다. 같은 학습자료의 QuizSet이 `GENERATING`인 동안에도 제목은 수정할 수 있고 본문만 임시 잠근다.
- 퀴즈는 학습자료명과 다른 자체 제목을 갖고 사용자가 이름을 변경할 수 있다.
- 최근 퀴즈와 퀴즈 목록은 학습자료명이 아니라 퀴즈 제목을 주 제목으로 표시한다.
- `TCP/IP 기본 퀴즈`처럼 최근 퀴즈를 보여주는 카드에는 이전의 따뜻한 당근색 계열 배경 인상을 복구한다.
- 내 퀴즈 항목은 학습자료 카드와 같은 규칙으로 펼치며, 펼친 영역에는 `퀴즈 이름 변경`, `퀴즈 풀기`만 제공한다.

### UX 설계 결정

- 학습 메인에는 최근 퀴즈를 제외한 복습 후보를 최대 3개 보여주고 검색·페이지 이동·편집은 전체 목록 화면에서 제공한다.
- `최근 퀴즈`가 화면 제목 바로 다음에 오고, 해당 영역 다음에 유일한 prominent CTA인 `새 문제 만들기`를 둔다. 최근 퀴즈가 없을 때도 CTA 위치는 유지한다.
- 최근 퀴즈의 quiet surface는 하드코딩한 당근 palette 값이 아니라 SEED semantic `bg.brandWeak` 역할을 사용한다. 로딩·오류·빈 상태는 이 배경을 가짜 데이터 카드처럼 유지하지 않고 각각 중립 Skeleton과 상태 문구를 사용한다.
- `내 퀴즈 전체 보기`, `내 학습자료 전체 보기`는 복습 목록 아래의 낮은 위계 이동 행이며 각각의 목록 route로 이동한다.
- `내 학습자료`의 `학습자료 추가하기`는 이 화면의 유일한 prominent CTA다. 목록 로딩·오류·전체 0건·검색 결과 0건에도 같은 위치에서 사용할 수 있고 빈 상태 안에는 중복 CTA를 두지 않는다.
- 자료 추가 Bottom Sheet를 닫으면 검색어·페이지·펼친 카드·스크롤 위치를 유지하고 trigger로 focus를 돌린다. 목록에는 별도 노션 연결 관리 행동을 두지 않는다.
- 학습자료 확장 카드는 헤더 전체가 disclosure trigger다. 펼친 상태의 두 행동은 동등한 secondary 행동이며 카드 전체 이동과 중첩하지 않는다.
- 퀴즈 카드 header는 disclosure trigger이며 학습자료 카드의 여러 항목 동시 펼침과 검색·페이지·URL 상태 보존 규칙을 그대로 재사용한다. 펼친 행동 영역은 trigger 내부에 중첩하지 않는다.
- 퀴즈 제목 편집은 카드 안 inline 입력이 아니라 현재 제목을 채운 modal에서 수행한다. 저장·취소·검증·저장 중·실패 상태를 modal 안에 유지한다.
- 내 퀴즈는 검색·식별·이름 변경·새 본 퀴즈 시작에 집중한다. 최근 풀이 시각과 결과·복습·미완료 자기평가 행동은 표시하지 않고 학습 메인에 유지한다.
- 학습자료 편집은 긴 본문과 이탈 확인이 필요하므로 별도 전체 페이지에서 처리한다.
- chevron은 제목 행 기준이 아니라 카드/행의 주 콘텐츠 블록 세로 중앙에 둔다. 학습자료 disclosure의 chevron은 펼침 상태를 나타내며 장식 아이콘 자체는 별도 포커스 대상이 아니다.

### 설계 가정

- 목록은 제목 부분 일치 검색과 최근 수정 순을 기본으로 한다. 퀴즈 목록의 별도 정렬·필터는 현재 범위에 두지 않는다.
- 퀴즈 생성 완료 시 시스템이 임시 제목을 만든다고 가정한다. 정확한 기본 제목 규칙은 PRD와 Contract에서 확정해야 한다.
- 목록 페이지 크기는 기존 학습자료 계약과 맞춰 모바일 6개를 유지한다고 가정한다. 퀴즈 목록 계약을 만들 때 동일한 기본값을 검토한다.
- 복습 후보의 정확한 상위 3개는 전용 `GET /api/v1/quiz-reviews/candidates`가 전체 후보 집합에서 선별한 결과를 사용한다. `GET /api/v1/quiz-sets` 첫 페이지를 클라이언트에서 거르지 않는다.

### 확인된 구현 충돌

- 전역 원장은 홈·학습·마이페이지의 최상위 탭 전환을 앱 셸 한 계층이 소유하도록 정한다.
- 현재 공통 앱 셸은 홈→학습과 학습→홈 모두 같은 210ms 오른쪽 진입·왼쪽 이탈 모션을 적용하고 있다.
- 그러나 학습의 기본 route panel에도 별도 180ms 오른쪽 진입 모션이 적용돼 홈→학습에서는 두 모션이 중첩되고, 학습→홈에서는 공통 앱 셸 모션만 보인다. 이 중첩이 사용자가 양방향 전환을 다르게 느끼는 원인이다.
- UX 수정 기준은 최상위 탭 진입에서 학습 내부 route-enter를 재생하지 않고 앱 셸 모션만 한 번 보이게 하는 것이다. 학습 하위 route의 push/pop 모션은 최상위 탭 전환과 겹치지 않는 경우에만 별도 유지할 수 있다. 정확한 class·상태 분기는 웹 TRD와 구현이 책임진다.

## 정보 구조와 route

route 이름은 UX 목적을 식별하기 위한 제안이며 정확한 React Router 구성은 웹 TRD·구현에서 검증한다.

| 목적 | 제안 route | 뎁스 | 하단 내비게이션 | 진입 | 이탈 |
| --- | --- | ---: | --- | --- | --- |
| 학습 메인 | `/learning` | 0 | 표시, 학습 활성 | 하단 학습 탭 | 하위 관리/생성 화면 또는 다른 탭 |
| 내 학습자료 | `/learning/materials` | 1 | 숨김 | 학습 메인 `내 학습자료 전체 보기` | back으로 이전 맥락 |
| 학습자료 편집 | `/learning/materials/:materialId` | 2 | 숨김 | 학습자료 목록의 확장 카드 | 저장 또는 변경 없이 back |
| 내 퀴즈 | `/learning/quizzes` | 1 | 숨김 | 학습 메인 `내 퀴즈 전체 보기` | back으로 학습 메인 |
| 새 문제 만들기 | `/learning/new` | 1 | 숨김 | 학습 메인 CTA | 완료 또는 취소 후 이전 맥락 |
| 기존 자료로 퀴즈 만들기 | `/learning/:materialId/quiz` | 몰입형 | 숨김 | 확장 카드 `퀴즈 만들기` | 생성 흐름 규칙에 따름 |

직접 URL 진입에서도 각 전체 페이지는 필요한 데이터를 스스로 조회한다. 단, 뒤로갈 브라우저 기록이 없으면 앱 바 back은 `/learning`으로 이동한다.

## 1. 학습 메인

### 사용자 목표와 완료 조건

- 최근 퀴즈의 결과를 확인하거나 전체 문제를 다시 풀고, 남은 복습이 있으면 상태에 맞는 다음 행동을 시작한다.
- 최근 퀴즈가 아닌 QuizSet 중 복습이 필요한 항목을 찾아 복습 또는 자기평가를 이어간다.
- 새 문제 만들기를 시작한다.
- 학습자료 또는 퀴즈의 전체 목록과 특정 항목 관리로 이동한다.

### 정보 위계

1. `학습` 화면 제목
2. `최근 퀴즈`: 퀴즈 제목, 부모 학습자료명, 최근 활동 시점, 문제 수·회차, 상태별 다음 행동
3. `새 문제 만들기`: 화면의 유일한 prominent CTA
4. `복습할 퀴즈`: 최근 퀴즈와 중복되지 않는 최대 3개 복습 진입
5. `내 퀴즈 전체 보기`: 검색·관리 목록으로 이동하는 행
6. `내 학습자료 전체 보기`: 검색·관리 목록으로 이동하는 행
7. 하단 내비게이션

학습 메인은 카드 대시보드로 채우지 않는다. 최근 퀴즈만 맥락과 두 행동을 묶는 `bg.brandWeak` 역할의 따뜻한 quiet surface를 허용하고, 복습 후보와 두 전체 보기 진입은 여백과 구분선 중심의 행으로 표현한다.

### 행동

| 위치 | 행동 | 결과 |
| --- | --- | --- |
| 최근 퀴즈 | `전체 문제 다시 풀기` | 같은 QuizSet 전체를 새 `MAIN` 회차로 시작 |
| 최근 퀴즈 | 상태별 `채점이 남았어요`, `틀린 문제 복습하기`, `결과 보기` | 해당 퀴즈의 가장 우선인 후속 흐름으로 이동 |
| 최근 퀴즈 | 퀴즈 제목/맥락 보기 | `/learning/quizzes`에서 해당 항목으로 포커스하거나 관리 맥락을 연다 |
| 최근 퀴즈 다음 | 새 문제 만들기 | `/learning/new` |
| 복습할 퀴즈 | 상태별 `채점이 남았어요`, `틀린 문제 복습하기` | 해당 QuizSet의 미완료 서술형 채점 또는 복습 흐름으로 이동 |
| 내 퀴즈 전체 보기 | 이동 | `/learning/quizzes` |
| 내 학습자료 전체 보기 | 이동 | `/learning/materials` |

### 상태

| 영역/상태 | 보여줄 내용 | 복구·행동 |
| --- | --- | --- |
| 최초 로딩 | 제목과 CTA 위치를 유지하고 각 데이터 영역에 중립 Skeleton | 기다리기 |
| 최근 퀴즈 있음 | `quizTitle`을 주 제목, `materialTitle`을 보조 정보로 표시 | 가능한 학습 행동 |
| 완료한 최근 퀴즈 없음 | `아직 완료한 퀴즈가 없어요`와 완료 뒤 이어서 학습할 수 있다는 안내 | 바로 아래 CTA |
| 복습 목록 있음 | 활성 복습 우선, 이후 최근 학습 활동 순으로 최대 3개 | 항목별 상태 행동 |
| 복습 목록 없음 | `복습할 퀴즈가 없어요`와 현재 학습이 정리됐다는 짧은 안내 | 내 퀴즈 전체 보기 또는 새 문제 만들기 |
| 일부 영역 오류 | 성공한 다른 영역은 유지하고 실패 영역만 안내 | 영역별 다시 시도 |
| 인증 만료 | 콘텐츠가 삭제된 것처럼 표현하지 않음 | 재인증 |

## 2. 내 학습자료

### 진입·이탈과 정보 구조

1. back과 `내 학습자료` 제목
2. 전체 너비 prominent CTA `학습자료 추가하기`
3. 항상 보이는 `학습자료 제목 검색` 입력
4. 검색 결과 수 또는 현재 페이지 맥락
5. 최근 수정 순 학습자료 확장 카드 목록
6. `이전 · 현재/전체 · 다음` 페이지 이동

목록에서 여러 카드를 동시에 펼칠 수 있다. 사용자가 비교하거나 연속으로 행동할 수 있고, 한 카드 펼침이 다른 카드의 내용을 갑자기 접는 부수 효과를 만들지 않기 위해 accordion 단일 펼침 규칙은 쓰지 않는다.

### 학습자료 추가 Bottom Sheet

- 제목: `학습자료 추가하기`
- 안내: `자료를 가져올 방법을 선택해 주세요.`
- 첫 항목: `노션에서 가져오기` / `노션 페이지 하나를 복사해 확인·수정해요` / `/learning/import/notion`
- 둘째 항목: `직접 입력하기` / `제목과 본문을 직접 작성해요` / `/learning/materials/new`
- 닫기: backdrop·취소·시스템 back으로 닫으며 목록의 query·page·expanded·스크롤을 유지하고 trigger로 focus를 돌린다.

목록에서 시작한 두 route에는 안전한 내부 목록 복귀 목적지를 전달한다. `자료 저장` 성공 뒤 새 자료 상세로 이동하며 상세 back은 원래 목록 맥락으로 돌아간다. 저장 전 `저장하지 않고 나가기`도 같은 목록으로 돌아가고, `저장하고 퀴즈 만들기`는 기존처럼 새 자료가 선택된 퀴즈 생성 조건으로 이동한다.

### 학습자료 확장 카드

#### 접힘

- 제목
- 출처(`직접 입력`/`Notion에서 가져옴`)와 수정 시각
- 생성 중이면 `문제 생성 중`
- 카드 주 콘텐츠 세로 중앙의 펼침 chevron

#### 펼침

- 접힌 정보 유지
- 본문 전체가 아닌 2~3줄 미리보기와 전체 글자 수
- `퀴즈 만들기`: 해당 자료가 선택된 문제 생성 조건으로 이동
- `학습자료 변경`: 전체 편집 페이지로 이동

두 하단 행동은 기본 너비에서 같은 크기의 2열 secondary 버튼이다. 320px 또는 큰 글자에서 레이블이 자연스럽게 들어가지 않으면 의미 순서를 유지해 세로로 쌓는다. 생성 중에도 `학습자료 변경`은 가능하며 편집 페이지에서 제목만 수정할 수 있음을 안내한다. `퀴즈 만들기`는 같은 자료에 활성 생성이 있으면 비활성 이유를 텍스트로 제공한다.

### 검색·페이지 상태

- 검색은 서버가 가진 현재 사용자의 전체 학습자료 제목을 대상으로 한다. 검색어 변경 시 1페이지로 돌아간다.
- 검색 결과에서 편집 후 돌아오면 검색어, 페이지, 펼친 카드 ID를 현재 탐색 세션에서 복원한다.
- 전체 0건과 검색 결과 0건을 구분한다. 검색 결과 없음에는 입력한 검색어와 `검색어 지우기`를 제공한다.
- 페이지 이동 중에는 기존 목록을 유지한다. 실패해도 검색어·페이지·펼침 상태를 잃지 않는다.
- 삭제 등으로 현재 페이지가 유효하지 않으면 마지막 유효 페이지로 복구한다. 정확한 캐시·재조회 방식은 구현 원장이 책임진다.

## 3. 학습자료 편집

### 정보 구조와 행동

1. back과 `학습자료 변경` 제목
2. 출처, 생성·수정 시각
3. 필수 제목 입력
4. 필수 본문 입력과 `현재/20,000자`
5. `이미 만든 퀴즈와 결과는 바뀌지 않아요. 다음에 만드는 퀴즈부터 반영돼요.` 안내
6. 유일한 prominent CTA `변경사항 저장`

| 상태 | 제목 | 본문 | 행동·안내 |
| --- | --- | --- | --- |
| 기본 | 편집 가능 | 편집 가능 | 변경사항 저장 |
| QuizSet 생성 중 | 편집 가능 | 읽기 전용 | 생성 종료 뒤 다시 편집할 수 있음을 본문과 연결 |
| 저장 중 | 현재 값 유지 | 현재 값 유지 | 반복 저장 방지, 진행 상태 |
| 입력 오류 | 값 유지 | 값 유지 | 해당 입력 가까이에 이유와 해결 방법 |
| 저장 실패 | 수정값 유지 | 수정값 유지 | 같은 내용 다시 시도 |
| 상세 조회 실패 | 삭제로 단정하지 않음 | 삭제로 단정하지 않음 | 다시 시도 또는 back |

미저장 변경이 있을 때 back을 누르면 `계속 편집`, `변경사항 버리기`를 제공한다. 저장 성공 뒤 자료 목록으로 돌아갈 때 갱신된 제목·수정 시각을 보여주며 성공을 과도하지 않은 live region 또는 Snackbar로 알린다.

## 4. 내 퀴즈

### 진입·이탈과 정보 구조

1. back과 `내 퀴즈` 제목
2. 전체 너비 prominent CTA `퀴즈 만들기`
3. 항상 보이는 `퀴즈 제목 검색` 입력
4. 검색 결과 수 또는 현재 페이지 맥락
5. 최근 수정 순 퀴즈 disclosure 목록
6. 페이지 이동

`퀴즈 만들기`는 Bottom Sheet 없이 `/learning/new`로 이동한다. 목록·로딩·오류·전체 0건·검색 0건에서도 같은 위치에 항상 노출하고 빈 상태 안에 생성 CTA를 중복하지 않는다. 목록에서 시작하면 현재 `query`, `page`, `expanded`와 가능한 스크롤 위치를 안전한 내부 복귀 맥락으로 전달하며, 생성 접수 전 취소·back으로 돌아올 때 이를 복원한다. `/learning/new` 직접 진입의 기존 학습 메인 복귀와 생성 접수 이후의 이탈 정책은 유지한다.

### 퀴즈 disclosure 카드

- 주 제목: 사용자가 수정 가능한 `quizTitle`
- 보조 정보: 부모 `materialTitle`, 문제 수 또는 생성 상태
- 접힌 header: 퀴즈명·보조 정보·펼침 chevron
- 펼친 행동: `퀴즈 이름 변경`, `퀴즈 풀기`

카드 header 전체가 하나의 disclosure trigger이며 `aria-expanded`와 상세 영역의 관계를 전달한다. 여러 카드를 동시에 펼칠 수 있고 펼침 상태는 학습자료 카드의 검색·페이지·URL 보존 규칙을 재사용한다. 펼친 두 행동은 trigger와 분리된 독립 버튼으로 제공한다.

`READY`에서는 두 행동을 활성화한다. `GENERATING`은 펼칠 수 있지만 카드 콘텐츠 최상단에 옅은 비상호작용 overlay를 두고 두 행동을 모두 비활성화한다. Activity Indicator와 `문제 생성 중`을 함께 사용하며 overlay는 header의 펼치기·접기 조작을 막지 않는다. `FAILED` QuizSet은 서버에 유지하지만 이 목록에는 표시하지 않고 [알림 목록](screen-notifications.md)에서 실패 결과와 재생성 진입을 제공한다.

### 이름 변경 상태

1. `퀴즈 이름 변경`을 선택하면 현재 제목이 채워진 modal을 열고 제목 입력으로 focus를 이동해 전체 선택한다.
2. `저장`, `취소`를 제공하고 Enter는 저장, Escape는 취소로 동작한다. 모바일 키보드 완료 행동도 저장과 같은 결과다.
3. 공백뿐이거나 계약의 최대 길이를 넘으면 입력 가까이에 오류를 보여주고 현재 값을 유지한다.
4. 저장 중에는 modal을 유지하고 중복 저장과 해당 카드의 행동을 막으며 진행 상태를 전달한다.
5. 성공하면 modal을 닫고 새 제목을 카드와 학습 메인·홈의 최근 퀴즈에 반영한 뒤 해당 카드의 `퀴즈 이름 변경`으로 focus를 돌린다.
6. 실패하면 서버에 저장된 기존 제목을 유지하되 입력값과 오류를 modal에 남겨 다시 시도할 수 있게 한다.

### 퀴즈 목록 상태

| 상태 | 보여줄 내용 | 가능한 행동 |
| --- | --- | --- |
| `READY` | 퀴즈 제목, 부모 자료명, 문제 수 | 펼치기·접기, 이름 변경, 새 `MAIN` 회차 시작 |
| `GENERATING` | 퀴즈 제목, 부모 자료명, 옅은 overlay, Activity Indicator와 `문제 생성 중` | 펼치기·접기; 이름 변경·퀴즈 풀기 비활성 |
| `FAILED` | 내 퀴즈 목록에 항목을 만들지 않음 | 우측 상단 알림에서 실패 확인·원본 자료 생성 조건으로 이동 |
| 전체 없음 | `아직 만든 퀴즈가 없어요` | 화면 상단 `퀴즈 만들기` |
| 검색 결과 없음 | 검색어와 일치하는 퀴즈 없음 | 검색어 지우기 |
| 페이지 이동/갱신 | 기존 목록·검색 맥락 유지 | 기다리기 또는 다시 시도 |
| 전체 오류 | 퀴즈가 삭제된 것처럼 표현하지 않음 | 다시 시도, back |

## 새 문제 만들기 진입

기존 route stack의 핵심 흐름은 유지한다.

```text
학습 메인 → 새 문제 만들기
  ├─ 기존 학습자료로 만들기 → 학습자료 선택 → 문제 생성 조건
  └─ 새 학습자료로 만들기
       ├─ Notion에서 가져오기 → 확인·수정 → 저장 → 문제 생성 조건
       └─ 직접 입력하기 → 저장 → 문제 생성 조건
```

`내 학습자료` 확장 카드의 `퀴즈 만들기`는 기존 학습자료 선택 단계를 건너뛰고 해당 자료가 선택된 문제 생성 조건으로 이동한다. 미저장 입력, 생성 접수 응답 유실, 생성 중 이탈은 관련 Flow의 복구 규칙을 따른다.

## 반응형·WebView 동작

- `base`는 320px 이상 한 열이다. 학습 메인과 목록의 의미 순서를 바꾸지 않는다.
- 학습자료 펼침 카드의 두 행동은 기본적으로 2열이며 320px·큰 글자에서 잘리면 세로로 쌓는다.
- `md` 이상에서 학습자료·퀴즈 목록은 탐색 효율이 실제로 개선될 때만 2열을 허용한다. 검색·페이지 이동은 목록 전체 너비를 사용하고 카드 의미 순서는 유지한다.
- 긴 한국어 제목은 최대 두 줄까지 자연스럽게 늘어난다. 이름 변경 modal은 작은 화면에서 가로 여백과 키보드 공간을 보장하고 입력값·오류·저장 행동을 함께 볼 수 있게 한다.
- 하위 전체 페이지에서는 하단 전역 내비게이션을 숨기고 명확한 back을 제공한다.
- 키보드가 열린 동안 검색·이름·본문 입력과 오류, 저장 행동이 가려지지 않게 스크롤한다.
- 터치 대상은 SEED recipe가 더 크게 보장하지 않을 때도 최소 44×44 CSS px다.
- `prefers-reduced-motion`에서는 route push와 카드 펼침의 큰 이동 애니메이션을 제거한다.
- 학습 메인과 홈·마이페이지 사이의 하단 탭 이동은 [제품 기반의 최상위 탭 전환 모션](../product.md#최상위-탭-전환-모션)을 따른다. 내 학습자료·내 퀴즈·문제 풀이처럼 하단 탭이 숨겨지는 하위 route의 push/pop과 중복 재생하지 않는다.
- 학습 메인이 최상위 탭의 목적지일 때는 앱 셸만 전환을 소유하고 학습 기본 route panel의 자체 진입 모션은 재생하지 않는다. 홈→학습과 학습→홈에서 같은 수의 콘텐츠 전환이 보여야 한다.

## 접근성

- 각 route에는 하나의 `h1`을 두고 학습 메인의 섹션 제목은 순서에 맞는 하위 heading으로 제공한다.
- `전체 보기`의 접근 가능한 이름은 `내 학습자료 전체 보기`, `내 퀴즈 전체 보기`처럼 목적을 포함한다.
- 학습자료와 퀴즈 카드 trigger는 `aria-expanded`와 펼쳐지는 영역의 관계를 전달한다. chevron은 장식이며 별도 포커스 대상으로 만들지 않는다.
- 펼친 카드 내부 버튼은 disclosure trigger 안에 중첩하지 않는다. trigger와 행동 영역은 DOM과 포커스 순서에서 분리한다.
- 퀴즈 이름 변경 modal은 제목·입력 label·오류를 연결하고 focus trap을 제공한다. 열릴 때 입력으로 이동하며 취소·Escape·저장 성공 뒤 원래 `퀴즈 이름 변경` 버튼으로 돌아간다.
- 검색 입력에는 항상 보이는 label 또는 프로그램적으로 연결된 label을 제공한다. 결과 수와 페이지 변경은 과도하지 않은 live region으로 알린다.
- 생성 중 overlay는 색과 움직임에만 의존하지 않고 `문제 생성 중` 상태명을 함께 제공한다. 실패 결과는 내 퀴즈 카드가 아니라 알림의 문구와 읽지 않음 상태로 전달한다.
- 로딩 중 기존 콘텐츠를 유지하는 경우 `aria-busy`를 영역 단위로 전달한다.
- 페이지 이동 뒤 새 목록의 제목 또는 첫 항목으로 예측 가능한 탐색 맥락을 제공한다.

## API·데이터 계약 영향

### 기존 계약으로 가능한 범위

- 학습자료 목록 검색·페이지 이동·상세·수정은 기존 `GET/PATCH /api/v1/learning-materials` 계약을 따른다.
- 생성 중 본문 잠금과 제목 수정 가능 정책은 기존 `contentEditStatus` 및 학습자료 수정 계약을 따른다.
- 특정 학습자료로 퀴즈 만들기는 기존 자료별 QuizSet 생성 흐름을 사용한다.
- 내 퀴즈는 기존 `GET /api/v1/quiz-sets`의 `quizTitle`, `materialTitle`, `status`, `questionCount`만 화면 판단에 사용한다. 목록 응답은 `FAILED`를 제외하며, 응답의 풀이·복습 관련 필드는 학습 메인 등 기존 소비자를 위해 유지하지만 내 퀴즈에는 표시하지 않는다.
- 이름 변경은 기존 `PATCH /api/v1/quiz-sets/{quizSetId}`를 사용한다. 계약이 `GENERATING`·`FAILED` 변경도 허용하더라도 내 퀴즈 화면은 사용자 확정에 따라 `READY`에서만 행동을 활성화하고 숨겨진 `FAILED`에 관리 행동을 만들지 않는다.
- 성공 알림 진입은 `focusQuizSetId`로 해당 `READY` QuizSet이 포함된 page를 불러온 뒤 카드로 focus한다. 알림과 읽음 동작은 [알림 API](../contracts/contract-api-notifications.md)가 책임진다.
- `퀴즈 풀기`는 기존 QuizSet 풀이 조회를 새 `MAIN` 시작 intent로 사용하며 과거 회차·결과·복습 기록을 변경하지 않는다.

### 학습 메인 복습 후보 계약

`GET /api/v1/quiz-sets`는 `updatedAt DESC`로 페이지네이션하고 이름 변경도 `updatedAt`에 반영되므로, 첫 페이지를 클라이언트에서 거르면 전체 후보 집합의 상위 3개를 보장할 수 없다. 학습 메인은 [학습·퀴즈 API Contract](../contracts/contract-api-quiz-learning.md#학습-메인-복습-후보)의 전용 조회를 사용한다.

- 서버는 최근 퀴즈와 같은 QuizSet을 제외하고, QuizSet별 최신 완료 `MAIN`에서 미해결 문항이 있는 후보를 선별한다.
- 활성 복습 우선, 이후 `lastLearningActivityAt DESC`, 동일 시각 `quizSetId ASC`로 정렬해 최대 3개를 반환한다.
- 후보는 화면 행동에 필요한 `sourceAttemptId`, `pendingSelfAssessmentAttemptId`, `activeReviewSessionId`를 함께 제공한다.
- `POST /api/v1/review-sessions`는 전달받은 회차가 해당 QuizSet의 사용자 최신 완료 `MAIN`인지 서버에서 다시 검증한다.

## 인수 조건

- [ ] 학습 메인은 `최근 퀴즈` → `새 문제 만들기` → `복습할 퀴즈` → `내 퀴즈 전체 보기` → `내 학습자료 전체 보기` 순서다.
- [ ] 최근 퀴즈에는 `전체 문제 다시 풀기`와 상태별 맥락 행동을 함께 제공하며, 최근 퀴즈는 복습 목록에서 중복 노출되지 않는다.
- [ ] 복습 목록은 미해결 문항이 있는 QuizSet만 최대 3개를 활성 복습 우선·최근 학습 활동 순으로 표시하고 미해결 0개가 되면 제거한다.
- [ ] 미완료 서술형 채점은 복습보다 먼저 `채점이 남았어요`로 노출되고, 복습 상태는 `틀린 문제 복습하기`로 통일된다.
- [ ] 학습자료와 퀴즈는 각각 검색 가능한 별도 전체 페이지와 직접 URL을 가진다.
- [ ] `/learning/quizzes`는 모든 목록 상태에서 검색 위에 전체 너비 `퀴즈 만들기`를 표시하고 `/learning/new`로 바로 이동하며, 생성 전 이탈 시 안전한 목록 URL과 탐색 맥락을 복원한다.
- [ ] `/learning/materials`는 모든 목록 상태에서 검색 위에 전체 너비 `학습자료 추가하기`를 표시하고 Bottom Sheet에서 `노션에서 가져오기`, `직접 입력하기`만 제공한다.
- [ ] Bottom Sheet를 닫으면 검색어·페이지·펼친 카드·스크롤과 focus 맥락이 유지되며 빈 상태 안에 동일한 CTA가 중복되지 않는다.
- [ ] 목록에서 시작한 자료 추가는 저장 전 이탈과 상세 back에서 원래 목록 URL로 복귀하고, 목록 오류가 추가 행동을 막지 않는다.
- [ ] `내 퀴즈 전체 보기`와 `내 학습자료 전체 보기` 행이 각각 올바른 목록 route로 이동한다.
- [ ] 최근 퀴즈와 퀴즈 목록은 `quizTitle`을 주 제목, `materialTitle`을 보조 정보로 구분한다.
- [ ] `TCP/IP 기본 퀴즈`를 포함한 최근 퀴즈 정상 카드가 semantic `bg.brandWeak` 역할의 따뜻한 배경을 사용하고, 복습 목록 행과 전체 보기 행에는 같은 강조 배경을 적용하지 않는다.
- [ ] 학습자료 카드는 펼침 상태와 관계를 접근 가능하게 전달하고 하단에 `퀴즈 만들기`, `학습자료 변경`을 제공한다.
- [ ] 학습자료 제목·본문을 수정할 수 있고 생성 중에는 본문만 잠긴다.
- [ ] 퀴즈 카드는 학습자료 카드와 같은 규칙으로 여러 항목을 동시에 펼칠 수 있고 검색·페이지·URL 전환 뒤 유효한 펼침 상태를 보존한다.
- [ ] `READY`의 펼친 카드에는 `퀴즈 이름 변경`, `퀴즈 풀기`만 나타나며 최근 풀이·결과·복습·미완료 자기평가 행동은 나타나지 않는다.
- [ ] 퀴즈 이름 변경은 inline 입력이 아닌 modal에서 저장·취소·검증·로딩·실패·포커스 복귀 상태를 가진다.
- [ ] `퀴즈 풀기`는 같은 QuizSet의 새 `MAIN` 회차를 시작하고 기존 회차·결과·복습 기록을 유지한다.
- [ ] `GENERATING` 카드는 옅은 overlay 아래 두 행동이 모두 비활성화되고 Activity Indicator와 상태 문구를 제공하며, `FAILED` QuizSet은 목록에 나타나지 않고 알림에서 실패와 복구 진입을 제공한다.
- [ ] 상태 overlay가 있어도 카드 header를 펼치거나 접을 수 있고 상태명이 색이나 움직임 없이도 전달된다.
- [ ] 전체 없음과 검색 결과 없음을 구분하고 로딩·부분 오류·인증 만료·페이지 실패에서도 탐색 맥락을 보존한다.
- [ ] 320px, 큰 글자, 키보드, safe area, reduced motion과 44×44 CSS px 터치 영역을 고려한다.
- [ ] 정확한 복습 후보 선별·정렬·제한과 선택한 QuizSet의 복습 시작 계약을 사용한다.
- [ ] `/learning`은 뎁스 0, `/learning/materials`·`/learning/quizzes`·`/learning/new`는 뎁스 1, `/learning/materials/:materialId`는 뎁스 2로 동작하고 뎁스 1 이상에서 하단 내비게이션이 숨겨진다.
- [ ] 홈·마이페이지와 학습 메인 사이의 양방향 이동에 일관된 탭 전환이 적용되고, 하위 학습 route의 push/pop과 중복되지 않는다.
- [ ] 홈→학습과 학습→홈 모두 앱 셸 전환이 정확히 한 번만 재생되고, 학습 기본 route panel의 별도 진입 모션이 최상위 탭 전환에 중첩되지 않는다.
- [ ] 탭 전환은 학습 메인의 스크롤·검색·펼침 상태와 유효한 서버 캐시를 보존하며 불필요한 재요청을 만들지 않는다.

# [Screen Spec] 마이페이지와 계정 관리

> 이 문서는 마이페이지의 화면 구조와 사용자에게 보이는 상태를 정의한다. 마케팅 동의와 회원 탈퇴의 제품 정책은 [마이페이지 계정 관리 PRD](../prd/prd-mypage-account-management.md)가 책임지며, 요청·응답과 데이터 보존 의미는 후속 인증 Contract가 책임진다.

## 문서 정보

- 화면명: 마이페이지, 마케팅 수신 동의, 회원 탈퇴
- 문서 상태: `draft`
- 요구사항 상태: 마이페이지 명칭과 필수 메뉴는 사용자 확정, 법률 문구와 탈퇴 데이터 처리 기한은 미확정
- 대상 플랫폼: 반응형 웹과 앱 WebView, 모바일 우선
- 관련 기능: [마이페이지 계정 관리](../prd/prd-mypage-account-management.md), [이메일 기반 자체 인증](../prd/prd-local-authentication.md)
- 관련 흐름: [인증 흐름](flow-authentication.md)
- 관련 계약: [인증 API](../contracts/contract-api-authentication.md), [사용자·인증 데이터](../contracts/contract-data-authentication.md)
- 최종 수정일: 2026-09-01

## 현재 구현 단계

- PR #38은 마이페이지 메인, 계정 설정의 닉네임 변경, 로그아웃과 각 후속 메뉴의 안전한 진입 상태를 구현한다.
- 승인된 운영용 개인정보처리방침, 마케팅 동의 계약과 회원 탈퇴 계약은 아직 없으므로 해당 화면은 완료된 기능으로 오인되지 않는 준비 중 상태를 보여준다.
- 아래 마케팅 동의·회원 탈퇴 상세와 인수 조건은 후속 구현의 기준이며 PR #38의 인수 범위에서는 제외한다.

## 요구사항 구분

### 확정 사항

- 로그인 후 세 번째 하단 탭의 사용자 표시 명칭은 `프로필`이 아니라 `마이페이지`다.
- 마이페이지 상단은 현재 사용자의 닉네임과 이메일을 보여준다.
- 마이페이지에는 계정 관리, 로그아웃, 서비스 이용약관, 개인정보 처리방침, 마케팅 수신 동의, 문의하기, 앱 버전과 회원 탈퇴를 제공한다.
- 마케팅 수신 동의는 필수 약관과 분리된 선택 항목이며 사용자가 현재 상태를 확인하고 동의하거나 철회할 수 있다.
- 회원 탈퇴는 일반 설정과 구분된 위험 행동이며 탈퇴 영향, 명시적 확인과 처리 결과를 보여준다.
- 경험치·레벨·랭킹, 친구, 상점·포인트, 캐릭터·방 꾸미기와 학습 통계는 기능 정책과 데이터가 확정되기 전 마이페이지에 빈 카드나 잠금 메뉴로 노출하지 않는다.

### 설계 가정

- 프로필 이미지 저장 계약이 없으므로 상단에는 중립적인 기본 계정 아이콘을 사용한다. 닉네임 첫 글자 아바타는 구현 전 접근성과 다국어 표시를 검토한 뒤 대안으로 선택할 수 있다.
- 계정 관리 상세는 닉네임 변경과 이메일 조회를 제공한다. 이메일과 비밀번호 변경은 각각의 정책과 계약이 승인된 뒤 활성화한다.
- 초기 마케팅 채널은 가입 시 검증한 이메일 하나다. 푸시와 SMS는 실제 발송 기반과 별도 동의 정책이 생기기 전 노출하지 않는다.
- 마케팅 동의 상세는 현재 상태, 수신 이메일, 목적, 최근 변경일과 동의 문구를 보여주고 명시적인 저장 행동으로 변경을 확정한다.
- 서비스 이용약관과 개인정보 처리방침은 앱 안의 읽기 화면 또는 승인된 외부 문서로 이동한다. 목적지가 확정되지 않은 링크를 동작하는 메뉴처럼 노출하지 않는다.
- 문의하기는 승인된 이메일, 웹 문의 폼 또는 고객지원 채널 중 하나가 확정된 뒤 활성화한다.
- 앱 버전은 이동하지 않는 보조 정보로 표시한다. 웹과 앱 셸의 버전이 다르면 사용자에게 의미 있는 배포 버전을 우선하고 상세 표기 규칙은 구현 원장에서 정한다.
- 회원 탈퇴 전 계정 소유 재확인은 현재 비밀번호를 기본으로 하고, 비밀번호를 기억하지 못한 사용자는 검증된 이메일 코드로 재인증하는 안을 제안한다. 실제 수단과 오류 경계는 구현 전 제품·계약 승인이 필요하다.
- 탈퇴 확정 뒤 계정 접근을 즉시 차단하고 모든 로그인 세션을 종료하는 안을 제안한다.
- 기존 사용자에게 닉네임이 없으면 이메일을 대표 식별 정보로 보여주고 `닉네임 미설정`과 보완 행동을 제공한다. 임의 닉네임을 만들지 않는다.

### 미결정 사항

- 마케팅 이메일의 정확한 목적, 발송 범위, 법률 검토를 마친 동의 문구와 이력 보존 기간
- 마케팅 동의 변경을 즉시 반영하는 스위치로 할지, 값을 고른 뒤 저장하는 명시적 제출로 할지. 이 초안은 오조작 복구가 쉬운 명시적 저장을 제안한다.
- 회원 탈퇴 후 학습자료·퀴즈·풀이 기록의 삭제 또는 비식별화 완료 기한과 법적·운영상 예외 보존 범위
- 탈퇴 처리 중 같은 이메일 재가입을 막을지, 언제 새 계정 재가입을 허용할지
- 이메일과 비밀번호 변경을 초기 계정 관리에 포함할지
- 회원 탈퇴 재인증을 현재 비밀번호만으로 제한할지, 검증된 이메일 코드 같은 대체 수단을 함께 제공할지
- 기존 사용자의 일회성 닉네임 완료를 첫 출시 범위에 포함할지
- 문의하기의 실제 채널과 운영 응답 범위

## 사용자 목표

- 이 화면에 들어온 사용자는 자신의 계정을 확인하고 서비스·동의 정보를 찾으며 세션과 계정 종료를 스스로 관리한다.
- 사용자가 원하는 메뉴의 현재 상태를 이해하고, 필요한 변경을 완료하거나 실패 원인과 복구 행동을 확인하면 화면의 목적을 달성한 것으로 본다.

## 진입과 이탈

- 진입점: 로그인 후 하단 `마이페이지` 탭, 마케팅 안내의 설정 링크, 계정 관련 안내의 관리 링크
- 다음 화면: 계정 관리, 이용약관, 개인정보 처리방침, 마케팅 수신 동의, 문의하기, 회원 탈퇴
- 뒤로 가기: 하위 전체 페이지에서는 마이페이지로 한 단계 돌아간다. 저장하지 않은 마케팅 변경이 있으면 버릴지 확인한다.
- 하단 탭: 마이페이지 메인에서 유지하고 `마이페이지`를 현재 위치로 전달한다. 마케팅 동의와 회원 탈퇴 같은 하위 전체 페이지에서는 하단 탭을 숨기고 명확한 뒤로가기를 제공할 수 있다.
- 로그인 조건: 활성 로그인 세션이 필요하다. 세션 만료는 계정 정보가 사라진 상태로 표현하지 않고 재로그인을 안내한다.
- 탈퇴 성공: 모든 로그인 상태와 개인 캐시를 제거하고 로그인 화면으로 이동한다. 뒤로가기로 보호 화면을 다시 열 수 없어야 한다.

## 마이페이지 정보 구조

위에서 아래 순서를 유지한다.

1. **화면 제목**: `마이페이지`로 현재 위치를 알린다.
2. **계정 요약**: 기본 계정 아이콘, 닉네임, 이메일을 보여준다. 내부 사용자 ID와 정상 계정 상태는 노출하지 않는다.
3. **계정**: `계정 관리`와 `로그아웃`을 제공한다. 로그아웃은 다른 페이지로 이동하는 행이 아니라 세션 종료 행동이다.
4. **서비스 정보**: 서비스 이용약관, 개인정보 처리방침, 현재 상태를 포함한 마케팅 수신 동의, 문의하기와 앱 버전을 제공한다.
5. **계정 종료**: `회원 탈퇴`를 일반 목록에서 간격과 제목으로 분리하고 결과를 되돌리기 어려운 행동임을 문구로 알린다.
6. **하단 내비게이션**: `홈`, `학습`, `마이페이지` 중 `마이페이지`를 현재 위치로 표시한다.

반복 메뉴는 카드 여러 개로 만들지 않고 섹션 제목, 여백과 그룹형 목록으로 구분한다. 이동 가능한 행 전체가 하나의 링크 또는 버튼이며 trailing chevron은 이동 가능성을 보조한다. 로그아웃, 앱 버전과 회원 탈퇴는 동일한 chevron 문법을 기계적으로 적용하지 않는다.

## 대표 텍스트 와이어프레임

와이어프레임은 정보 순서와 행동 위계를 검토하기 위한 것이며 정확한 색·크기·아이콘을 확정하지 않는다.

## 마케팅 수신 동의 상세

### 정보 구조

1. 뒤로가기와 `마케팅 수신 동의` 제목
2. 현재 상태 `동의` 또는 `미동의`와 최근 변경일
3. 수신 채널 `이메일`과 수신 주소
4. 마케팅의 목적과 포함되는 안내 예시
5. 서비스 운영에 필요한 필수 안내는 이 동의와 무관하다는 설명
6. 법률 검토를 마친 선택 동의 문구와 전문 보기
7. 동의 상태 입력과 `변경사항 저장` 행동

### 변경 규칙

- 화면 진입만으로 상태를 바꾸지 않는다.
- 사용자가 값을 변경하고 저장을 선택해야 서버 상태를 변경한다.
- 저장 중에는 반복 제출을 막고 기존 확정 상태와 아직 저장하지 않은 선택을 구분한다.
- 저장 성공 뒤 서버가 확정한 상태와 변경 시각을 보여주고 보조기기에 완료를 알린다.
- 저장 실패 시 이전 서버 상태를 현재 값으로 유지하며 사용자의 선택을 가능한 범위에서 보존해 다시 시도할 수 있게 한다.
- 동의 철회는 가입, 로그인, 퀴즈 풀이 같은 핵심 서비스 이용을 막지 않는다.

### 상태

| 상태 | 보여줄 내용 | 가능한 행동 |
| --- | --- | --- |
| 로딩 | 제목과 항목 위치를 유지하는 Skeleton | 기다리기, 뒤로가기 |
| 동의 | 이메일 수신 동의, 최근 변경일, 현재 문구 | 철회 선택 후 저장 |
| 미동의 | 이메일 수신 미동의, 최근 변경일 | 동의 선택 후 저장 |
| 저장 중 | 현재 확정 상태와 처리 중 안내 | 기다리기 |
| 저장 실패 | 변경되지 않았다는 안내와 사용자 선택 | 다시 저장, 원래 값으로 복귀, 뒤로가기 |
| 조회 실패 | 상태를 추측하지 않는 오류 | 다시 시도, 뒤로가기 |

## 로그아웃

- 로그아웃 선택 시 `이 기기에서 로그아웃할까요?` 확인을 제공한다.
- 확인 전에는 세션이나 개인 캐시를 제거하지 않는다.
- 서버 응답의 성공 여부와 관계없이 현재 기기의 로그인 정보와 개인 캐시를 제거하고 로그인 화면으로 이동한다.
- 서버 세션 종료를 확인하지 못한 경우에도 개인 화면을 유지하지 않는다. 필요한 경우 공개 화면에서 재로그인 또는 세션 상태 안내를 제공한다.
- 다른 기기의 세션까지 종료하는 기능은 회원 탈퇴 또는 별도 `모든 기기에서 로그아웃` 정책의 책임이며 현재 로그아웃에 암시하지 않는다.

## 회원 탈퇴

### 흐름

1. 사용자가 마이페이지 하단의 `회원 탈퇴`를 선택한다.
2. 전체 페이지에서 탈퇴 즉시 계정 접근과 모든 세션이 종료되고, 학습자료·퀴즈·풀이 기록은 확정된 정책에 따라 삭제 또는 비식별화 대상이 됨을 설명한다.
3. 사용자는 영향과 복구 가능 여부를 확인한 뒤 `회원 탈퇴 계속`을 선택한다.
4. 승인된 방법으로 계정 소유를 재확인한다. 현재 제안은 현재 비밀번호이며, 비밀번호를 기억하지 못한 사용자는 검증된 이메일 코드로 전환한다. 비밀번호와 인증 코드는 화면을 벗어나면 보존하지 않는다.
5. 최종 확인에서 `회원 탈퇴`를 명시적으로 선택한다.
6. 성공하면 모든 세션과 로컬 개인 상태를 제거하고 로그인 화면에서 탈퇴 완료를 안내한다.

탈퇴 데이터 처리 기한과 재가입 가능 시점이 확정되기 전에는 `즉시 완전 삭제`, `30일 뒤 삭제`, `언제든 복구` 같은 문구를 사용하지 않는다. 이 두 정책은 구현 전에 반드시 확정되어야 한다.

### 상태와 복구

| 상태 | 보여줄 내용 | 가능한 행동 |
| --- | --- | --- |
| 영향 안내 | 잃게 되는 접근과 데이터 처리 정책, 재가입 경계 | 계속, 취소 |
| 재인증 | 승인된 재인증 입력과 목적 | 확인, 뒤로가기 |
| 비밀번호 불일치·분실 | 계정 존재 여부를 추가로 드러내지 않는 오류 | 재입력, 승인 시 검증된 이메일 코드로 전환 |
| 최종 확인 | 되돌리기 어려운 결과와 명시적 탈퇴 행동 | 탈퇴, 취소 |
| 처리 중 | 화면 이탈과 중복 제출을 막는 진행 상태 | 기다리기 |
| 처리 실패 | 계정이 탈퇴되지 않았다는 안내 | 다시 시도, 마이페이지로 돌아가기 |
| 처리 성공 | 탈퇴 완료와 세션 종료 | 로그인 또는 가입 화면 이동 |

## 마이페이지 화면 상태

| 상태 | 진입 조건 | 보여줄 내용 | 가능한 행동 |
| --- | --- | --- | --- |
| 로딩 | 사용자 또는 동의 요약 조회 중 | 제목, 계정 요약과 목록 구조 Skeleton | 기다리기 |
| 기본 | 사용자와 메뉴 조회 성공 | 닉네임, 이메일, 메뉴와 동의 상태 | 각 메뉴 선택 |
| 동의 요약 부분 오류 | 사용자 조회 성공, 동의 조회 실패 | 계정과 다른 메뉴 유지, 동의 상태 확인 실패 | 동의 상태 다시 시도 |
| 전체 오류 | 사용자 조회 실패이나 인증 만료로 확정되지 않음 | 계정이 사라졌다고 표현하지 않는 오류 | 다시 시도 |
| 세션 만료 | 인증 만료가 확정됨 | 로그인이 필요하다는 안내 | 로그인 |
| 닉네임 미설정 | 기존 사용자 닉네임이 없음 | 이메일을 대표 정보로 표시하고 `닉네임 미설정` 안내 | 승인된 일회성 닉네임 완료 또는 계정 관리 |
| 긴 닉네임·이메일 | 작은 화면 또는 큰 글자 | 줄바꿈 가능한 계정 요약 | 계정 관리에서 전체 값 확인 |

## 반응형·WebView 동작

- 작은 화면에서는 한 개의 세로 스크롤과 전체 너비 그룹형 목록을 사용한다.
- 넓은 화면에서도 계정 정보와 위험 행동의 읽기 순서를 바꾸지 않고 적절한 최대 읽기 너비 안에 둔다. 여러 열의 설정 대시보드로 확장하지 않는다.
- 하단 내비게이션 높이와 WebView에서 전달된 유효 하단 inset만큼 마지막 콘텐츠 여백을 확보한다. 웹에서 불필요한 safe-area 여백을 추가하지 않는다.
- 하위 전체 페이지에서 키보드가 열리면 비밀번호 입력과 최종 행동이 가려지지 않아야 한다.
- 긴 약관명, 이메일, 오류 문구와 큰 글자에서 행 높이가 늘어나도록 하며 텍스트를 고정 높이로 자르지 않는다.
- `prefers-reduced-motion: reduce` 또는 앱 셸의 모션 감소 설정에서는 큰 수평 push 이동을 제거하거나 짧은 비이동 전환으로 대체한다.

## 접근성

- 화면 제목은 하나의 `h1`, 섹션 제목은 순서가 맞는 하위 제목으로 제공한다.
- 목록 행 전체가 하나의 초점 대상이며 장식용 chevron을 중복 낭독하지 않는다.
- 마케팅 동의 행은 레이블뿐 아니라 현재 `동의` 또는 `미동의` 상태를 이름에 포함한다.
- 동의 입력은 현재 값과 저장되지 않은 변경을 보조기기가 구분할 수 있어야 한다.
- 회원 탈퇴와 오류는 색상만으로 위험·실패를 전달하지 않고 문구, 위치와 확인 단계로 구분한다.
- 로그아웃·동의 변경·탈퇴의 성공과 실패는 적절한 live region 또는 검증된 SEED 피드백 컴포넌트로 전달한다.
- 확인 대화상자에서 취소로 닫으면 최초 실행 요소로 포커스를 돌린다.

## 데이터와 계약

- 현재 표시 가능: 현재 사용자 닉네임, 이메일, 이메일 인증 여부와 계정 상태. 정상 마이페이지에서는 닉네임과 이메일만 기본 노출한다.
- 현재 행동 가능: 현재 세션 로그아웃과 닉네임 변경.
- 추가 계약 필요: 마케팅 동의 상태·최근 변경일·문구 버전·변경, 회원 탈퇴 재인증·전 세션 폐기·데이터 처리 결과.
- 사용자 입력: 마케팅 동의 상태, 승인된 탈퇴 재인증 값, 탈퇴 최종 확인.
- 개인정보: 이메일과 동의 이력은 필요한 화면과 목적에서만 표시하고 분석 사건에 원문을 넣지 않는다. 비밀번호 원문은 저장·로그·분석하지 않는다.
- 법률 문서: 실제 이용약관, 개인정보 처리방침과 마케팅 동의 문구는 승인된 버전과 목적지를 사용한다. 이 화면 명세의 예시는 법률 확정본이 아니다.
- mock 경계: 동의·탈퇴 mock은 시각 검토에만 사용하며 실제 저장·세션 폐기·데이터 처리 완료처럼 운영 상태를 오인시키지 않는다.

## 인수 조건

- [ ] 로그인한 사용자는 하단 탭과 화면 제목에서 `마이페이지`를 식별할 수 있다.
- [ ] 사용자는 닉네임과 이메일을 확인하고 계정·서비스 정보·계정 종료 영역을 구분할 수 있다.
- [ ] 이동 가능한 행 전체를 선택할 수 있고 현재 마케팅 동의 상태를 행에서 확인할 수 있다.
- [ ] 마케팅 동의 상세에서 채널·목적·현재 상태·최근 변경일을 확인하고 동의 또는 철회를 명시적으로 저장할 수 있다.
- [ ] 마케팅 동의 저장 실패 시 이전 확정 상태가 유지되고 다시 시도할 수 있다.
- [ ] 로그아웃은 확인 뒤 서버 응답과 무관하게 현재 기기의 인증 정보·개인 캐시를 제거하고 보호 화면 재진입을 막는다.
- [ ] 회원 탈퇴 전에 접근 중단, 데이터 처리와 재가입 경계를 이해할 수 있는 안내와 승인된 계정 재인증을 제공한다.
- [ ] 현재 비밀번호를 기억하지 못한 사용자는 승인된 대체 재인증 또는 실제 이용 가능한 복구 행동을 통해 탈퇴 흐름이 막히지 않는다.
- [ ] 탈퇴 성공 시 모든 세션이 종료되고, 실패 시 계정이 유지됐음을 확인할 수 있다.
- [ ] 로딩, 부분 오류, 전체 오류와 세션 만료가 서로 구분되며 정상 동작하는 다른 메뉴는 불필요하게 숨기지 않는다.
- [ ] 작은 WebView, 큰 글자, 키보드 탐색과 모션 감소 설정에서도 핵심 행동을 완료할 수 있다.

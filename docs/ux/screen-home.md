# [Screen Spec] 홈

## 문서 정보

- 문서 상태: `draft`
- 요구사항 상태: 핵심 역할과 하단 탭은 확인됨, 다음 행동 우선순위·동률 처리·오늘의 지표는 UX 초안
- 대상 플랫폼: 반응형 웹과 앱 WebView, 모바일 우선
- 관련 기능: [홈 PRD](../prd/prd-home.md)
- 관련 내비게이션: [제품 기반의 전역 내비게이션](../product.md#전역-내비게이션)
- 관련 흐름: [문제 생성과 풀이](flow-quiz-solving.md), [학습자료 가져오기](flow-content-import.md)
- 공통 용어: [제품 기반의 용어](../product.md#용어)

> 동기화 주의: 이 화면 초안의 새 학습 입력 방식, 제출 전 풀이 세션, 복습 범위 관련 내용은 최신 [학습자료 PRD](../prd/prd-content-import.md), [퀴즈 PRD](../prd/prd-quiz-learning.md), [학습자료 흐름](flow-content-import.md), [퀴즈 흐름](flow-quiz-solving.md)과 아직 동기화되지 않았다. 해당 부분은 구현 기준으로 사용하지 않으며 후속 화면 명세 개정이 필요하다.

## 목표와 범위

### 사용자 목표

- 앱을 열었을 때 현재 학습 상태를 해석하느라 탐색하지 않고 가장 가치 있는 다음 행동을 시작한다.
- 중단한 풀이, 필요한 복습 또는 아직 문제를 만들지 않은 자료의 맥락을 잃지 않고 이어 간다.
- 필요한 경우 지원되는 입력 방식으로 새 학습자료를 가져온다.

### 완료 조건

사용자가 홈 진입 후 대표 행동이나 새 학습 방법을 한 번 선택하여, 선택한 자료·문제 세트·풀이 위치가 유지된 다음 흐름으로 이동하면 홈의 주 목적을 달성한 것으로 본다.

### 범위

- 대표 `다음 학습 행동` 한 개
- 복습 요약과 복습 진입
- 최근 학습자료 요약과 상세 진입
- 새 학습자료 가져오기 진입
- 오늘의 학습 활동 요약
- 첫 방문, 로딩, 빈 상태, 부분 오류, 전체 오류와 권한 제한
- 로그인 후 `홈`·`학습`·`프로필` 하단 내비게이션

### 비범위

- 전체 학습자료 관리와 검색·정렬
- 문제 생성 조건, 풀이, 채점 결과의 상세 화면
- 복습 대상 산정 알고리즘
- 상세 통계, 경험치, 랭킹, 친구, 상점과 캐릭터·방 꾸미기
- Notion 인증, 파일 파싱과 LLM 생성의 내부 처리

## 요구사항 구분

### 확정 사항

- 같은 홈 정보 구조를 반응형 웹과 앱 WebView에 제공한다.
- 최상위 하단 내비게이션은 `홈`, `학습`, `프로필` 세 영역으로 시작한다.
- 학습자료, 복습과 문제 만들기는 별도 하단 탭으로 분리하지 않고 `학습` 영역에서 함께 다룬다.
- 홈의 첫 번째 강조 요소는 기능 목록이나 통계가 아니라 사용자 상태에 맞는 `다음 학습 행동`이다.
- 홈에는 새 학습 진입, 복습 요약, 최근 학습자료, 오늘의 학습 요약이 필요하다.
- 복습과 학습자료는 홈에서 요약만 제공하고 상세 탐색은 `학습` 영역으로 연결한다.
- 일부 데이터가 실패해도 영향을 받지 않은 홈 행동은 계속 사용할 수 있어야 한다.
- 첫 방문에서는 의미 없는 빈 카드나 빈 통계를 나열하지 않고 학습자료 가져오기를 안내한다.

### 설계 결정

- 대표 다음 행동 위에 고정된 `지금 할 일` 레이블을 별도로 표시하지 않는다. 상태에 따라 바뀌는 대표 카드 제목 자체가 접근 가능한 섹션 제목이 된다.
- 대표 다음 행동만 `bg.neutralWeak` 역할의 quiet surface로 강조한다. 복습, 최근 학습자료, 새 학습과 오늘의 학습은 반복 카드로 감싸지 않고 같은 `bg.layerDefault` 콘텐츠 면에서 여백과 필요한 구간의 `stroke.neutralSubtle` 구분선으로 나눈다.
- 하단 내비게이션의 홈·학습·프로필에는 의미를 보조하는 아이콘과 필수 텍스트 레이블을 함께 둔다. 아이콘만으로 목적지나 현재 위치를 전달하지 않는다.
- 웹에서는 디스플레이 컷아웃이나 edge-to-edge 조건이 없는 한 safe-area 여백을 추가하지 않는다. 앱 WebView에서는 네이티브 셸과 웹 중 한 계층만 유효 safe-area를 책임져 이중 패딩을 만들지 않는다.
- 홈은 최신 `DESIGN.md`에서 승인한 전역 Pretendard-first family를 웹과 WebView에서 상속한다. 화면별 폰트 예외를 만들지 않고 SEED `textStyle`이 크기·행간·굵기를 계속 담당한다.
- 화면 제목과 대표 다음 행동 사이에는 큰 hero 공백을 두지 않는다. 현재 구현처럼 더 조밀한 화면 제목→첫 콘텐츠 리듬을 유지하되, 이 명세에서 특정 `x*` 토큰을 고정하지 않는다.

### 설계 가정

- 다음 행동은 한 번에 하나만 강조하고 `ActionButton`의 `brandSolid` 표현은 이 행동에만 사용한다.
- 대표 행동은 `미완료 풀이 → 복습 대상 → 문제가 없는 학습자료 → 최근 학습 → 첫 학습 시작` 순서로 선택한다.
- 기본 섹션 순서는 `대표 다음 행동 → 복습 → 최근 학습자료 → 새 학습 → 오늘의 학습`이다. 첫 방문에서는 대표 다음 행동과 새 학습을 하나의 시작 영역으로 합치고 데이터가 없는 나머지 섹션을 숨긴다.
- 새 학습은 홈에서 `Notion`, `.txt`/`.md` 파일, 텍스트 붙여넣기의 세 방법을 직접 선택한다.
- 최근 학습은 MVP에서 `학습자료` 기준 최대 3개를 표시하고, 항목 선택 시 자료 상세로 이동한다.
- 오늘의 요약은 경험치 대신 `푼 문제 수`와 `채점이 확정된 정답 수/채점 수`만 사용한다. 정답률은 분모가 있을 때만 보조 수치로 계산한다.
- 최상위 홈에서는 하단 내비게이션을 유지하고, 몰입형 문제 풀이 하위 흐름에서는 숨길 수 있다.

### 미결정 사항

- 복습 대상의 발생 기준과 복습 큐 내 우선순위
- 같은 우선순위의 후보가 여러 개일 때 사용할 최종 동률 처리 규칙
- 최근 학습을 학습자료 기준으로 볼지 문제 세트 기준으로 볼지
- `오늘`의 시간대, 날짜 경계와 집계 대상; 이 문서의 지표 구성도 제품 검토가 필요하다.
- 홈에서 세 입력 방법을 직접 노출할지, `학습`의 가져오기 화면을 한 번 거쳐 선택하게 할지
- 여러 미완료 풀이를 홈에서 교체 탐색할 수 있게 할지, 대표 한 개만 제공할지
- 경험치·연속 학습일 같은 게임화 정보를 MVP 홈에 포함할지
- 정확한 데스크톱 콘텐츠 최대 너비와 다크 모드 노출 정책

## 진입과 이탈

### 진입점

- 로그인 완료 후의 기본 화면
- 하단 `홈` 탭
- 자료 가져오기, 문제 생성, 풀이 또는 결과 확인을 마친 뒤 명시적으로 `홈으로`를 선택한 경우

### 이탈 목적지

| 홈 행동 | 이동 목적지 | 유지해야 할 맥락 |
| --- | --- | --- |
| `이어서 풀기` | 기존 풀이 세션 | 문제 세트, 현재 문항, 저장된 답안 |
| `복습 시작` | 복습 풀이 | 선택된 복습 범위 또는 대표 복습 큐 |
| `문제 만들기` | 해당 자료의 생성 조건 설정 | 학습자료 식별자와 제목 |
| `최근 학습 보기` | 최근 학습자료 상세 | 학습자료 식별자 |
| `Notion에서 가져오기` | Notion 연결·선택 흐름 | 선택한 입력 방식 |
| `파일에서 가져오기` | `.txt`/`.md` 파일 선택 흐름 | 선택한 입력 방식 |
| `텍스트 붙여넣기` | 본문 입력 흐름 | 선택한 입력 방식 |
| 복습 `전체 보기` | `학습`의 복습 목록 상태 | 홈에서 보던 필터 맥락이 있으면 유지 |
| 최근 자료 `전체 보기` | `학습`의 자료 목록 | 기본 자료 목록 상태 |

로그인 세션이 필요하다. 세션이 만료된 경우 인증 흐름으로 이동하되, 홈에서 새로 작성 중인 입력은 없으므로 별도 초안 복원 UI를 만들지 않는다. 최상위 홈에서 시스템·WebView 뒤로 가기는 컨테이너 정책을 따르며 임의로 로그인 화면을 다시 노출하지 않는다.

## 모바일 우선 화면 구조

```text
홈 화면
├─ 환경별 유효 상단 inset(필요한 경우만)
├─ 화면 헤더: 홈
├─ 대표 다음 행동 quiet surface
│  ├─ 상태별 대표 제목(h2, 별도 섹션 레이블 없음)
│  ├─ 상태 설명과 최소 맥락
│  └─ 대표 행동 1개
├─ 여백 또는 subtle divider
├─ 복습
│  └─ 복습 수량·범위 요약 / 전체 보기
├─ 여백 또는 subtle divider
├─ 최근 학습자료
│  └─ 최근 자료 최대 3개 / 전체 보기
├─ 여백 또는 subtle divider
├─ 새 학습
│  └─ Notion / 파일 / 텍스트 붙여넣기
├─ 여백 또는 subtle divider
├─ 오늘의 학습
│  └─ 푼 문제 / 정답 현황
├─ 하단 콘텐츠 여백
└─ 홈·학습·프로필 하단 내비게이션 + 환경별 유효 하단 inset
```

- 화면은 단일 세로 스크롤이며 DOM 순서와 시각 순서를 위 구조와 일치시킨다.
- 대표 다음 행동만 조용한 강조 surface를 사용한다. 나머지 섹션은 같은 콘텐츠 면에서 제목·여백·`List`를 우선하고, 여백만으로 경계가 불분명한 인접 섹션 사이에만 subtle divider를 둔다. 모든 섹션을 카드로 감싸거나 그림자를 반복하지 않는다.
- 화면 헤더에는 `홈` 제목만 필수로 둔다. 설정이나 프로필 아이콘을 중복 배치하지 않는다.
- 화면 제목 다음에는 대표 다음 행동이 한 흐름으로 이어져 보일 정도의 보통 간격을 사용한다. 온보딩 hero처럼 과도한 상단 공백을 만들지 않으며 정확한 spacing token은 구현에서 전역 리듬과 맞춘다.
- 첫 방문에서는 대표 다음 행동 surface 안에 세 입력 방법 목록을 이어서 배치하고 별도 `새 학습` 섹션, 복습, 최근 자료와 오늘 요약은 표시하지 않는다.
- 오늘의 요약은 가장 낮은 정보 위계에 두고 첫 화면 진입 시 대표 행동보다 먼저 보이도록 고정하지 않는다.

## 영역별 콘텐츠와 기능

### 1. 화면 헤더

| 항목 | 내용 |
| --- | --- |
| 제목 | `홈` |
| 선택 정보 | 사용자 이름을 안정적으로 제공하는 계약이 생기면 짧은 인사를 검토하되, 현재는 필수 데이터로 두지 않는다. |
| 기능 | 현재 위치를 알리고 문서의 최상위 제목을 제공한다. 별도 행동은 없다. |

### 2. 대표 다음 행동

모든 정상 상태에서 한 개의 대표 행동만 보여준다. `지금 할 일` 같은 고정 레이블은 두지 않고, 아래 상태별 제목 자체를 `h2`로 제공해 이 surface의 접근 가능한 이름으로 사용한다. 제목, 상황을 설명하는 한 문장, 필요한 최소 맥락, 명시적인 행동 버튼으로 구성한다.

| 후보 상태 | 제목 예시 | 표시 데이터 | 대표 행동 |
| --- | --- | --- | --- |
| 미완료 풀이 | `{자료명} 문제를 이어서 풀어보세요` | `현재 문항/전체 문항`, 마지막 활동 시각 | `이어서 풀기` |
| 복습 있음 | `다시 확인할 문제가 {n}개 있어요` | 복습 대상 수, 범위가 확정되면 대표 자료명 | `복습 시작` |
| 문제 없는 자료 | `{자료명}으로 첫 문제를 만들어보세요` | 자료명, 가져온 시각, 입력 출처 레이블 | `문제 만들기` |
| 최근 학습만 있음 | `{자료명}을 다시 살펴보세요` | 자료명, 마지막 학습 시각 | `최근 학습 보기` |
| 첫 방문 | `학습할 글을 가져와 시작해보세요` | 지원 형식 `Notion · .txt/.md · 텍스트` | 아래 세 입력 방법 중 하나 선택 |

- 자료명은 우선 줄바꿈하며 모바일에서 임의로 한 줄 축약하지 않는다. 영역 전체 높이는 제목 길이에 따라 늘어난다.
- 진행 정보는 `3/10문제`처럼 현재 위치와 전체를 함께 쓴다. 진행률을 색상이나 원형 그래프만으로 전달하지 않는다.
- 상대 시각을 쓰면 보조기기용 이름 또는 인접 텍스트에 날짜·시각의 의미가 모호하지 않게 전달되어야 한다.
- 대표 행동 이동이 시작되면 버튼에 로딩 상태를 표시하고 중복 이동을 막는다. `loading`만으로 비활성화가 보장되지 않으므로 실제 구현에서는 중복 실행 방지 상태도 함께 적용한다.

### 3. 복습

| 상태 | 표시 내용 | 행동 |
| --- | --- | --- |
| 복습 있음 | `복습할 문제 {n}개`, 범위가 확정된 경우 대표 자료명 또는 가장 가까운 복습 시점 | 행 선택은 복습 목록, `복습 시작`은 복습 풀이. 대표 다음 행동이 이미 복습이면 섹션 안의 강조 버튼은 반복하지 않는다. |
| 복습 없음 | `지금 복습할 문제는 없어요`와 새 학습 또는 최근 학습을 계속할 수 있다는 짧은 설명 | 별도 강조 행동 없음 |
| 불러오기 실패 | 이 영역의 데이터만 불러오지 못했다는 설명 | `다시 시도` |

복습 대상 산정 규칙이 확정되기 전에는 `오늘 마감`, `밀림`, `예정`처럼 일정 알고리즘을 전제하는 문구를 사용하지 않는다.

### 4. 최근 학습자료

- 최대 3개의 학습자료를 최근 활동 순서로 표시한다는 것이 현재 설계 가정이다.
- 각 행은 `자료명`, `마지막 학습 시각`, `문제 있음/문제 없음` 또는 `미완료 풀이 있음` 중 계약으로 확인 가능한 상태 하나를 제공한다.
- 자료의 입력 출처는 식별에 도움이 될 때 `Notion`, `파일`, `붙여넣기` 텍스트로 보조 표시한다. 아이콘만으로 출처를 구분하지 않는다.
- 행 전체는 하나의 행동으로 자료 상세로 이동한다. 행 안에 별도의 중첩 버튼을 두지 않는다.
- 섹션 헤더의 `전체 보기`는 `학습`의 자료 목록으로 이동한다.
- 항목이 없으면 첫 방문 시작 영역이 이미 역할을 대신하므로 빈 최근 목록을 별도 표시하지 않는다.

### 5. 새 학습

| 입력 방법 | 설명 | 목적지 |
| --- | --- | --- |
| `Notion에서 가져오기` | `Notion에서 페이지를 선택해 가져와요` | Notion 연결 또는 페이지 선택 |
| `파일에서 가져오기` | `.txt, .md 파일을 가져와요` | 기기 파일 선택 |
| `텍스트 붙여넣기` | `복사한 글을 바로 붙여넣어요` | 본문 입력 |

- 세 방법은 우열 없는 `ListButtonItem` 행으로 제공한다. 세 개의 solid 버튼이나 장식 카드로 경쟁시키지 않는다.
- 선택 즉시 해당 입력 흐름으로 이동하며, 홈에서 파일 선택기나 Notion 권한 요청을 직접 띄우는지는 각 가져오기 흐름이 담당한다.
- WebView 또는 계정 정책으로 특정 방법을 쓸 수 없으면 해당 행에 이유를 텍스트로 표시하고 비활성화한다. 사용할 수 있는 다른 방법은 유지한다.

### 인터랙티브 행 affordance 결정

#### 패턴 비교와 결정

| 후보 | 판단 | 이유 |
| --- | --- | --- |
| 모든 섹션을 카드로 감싸기 | 사용하지 않음 | 반복 카드가 정보 위계를 평평하게 만들고 `DESIGN.md`의 문서형 화면·여백·목록 우선 원칙과 충돌한다. |
| 최근 자료와 새 학습의 각 항목을 개별 카드로 만들기 | 사용하지 않음 | 항목마다 별도 떠 있는 surface와 radius가 반복되어 대표 다음 행동 카드와 경쟁하고 목록 스캔이 느려진다. |
| 강한 `ActionButton`을 항목 수만큼 반복하기 | 사용하지 않음 | 대표 `brandSolid` CTA의 우선순위를 약화하고, 제목과 상세 설명을 함께 읽는 콘텐츠 행에 맞지 않는다. |
| 하나의 약한 경계 안에 인터랙티브 행을 묶기 | **채택** | 목록의 스캔 효율을 유지하면서 경계, 내부 여백, trailing 방향 아이콘과 상태 변화로 클릭 가능성을 지속적으로 전달한다. |

채택 패턴은 `그룹형 인터랙티브 리스트`다. 섹션 자체는 카드가 아니며, 목록 한 묶음만 `bg.layerDefault` 위의 subtle boundary와 recipe radius로 감싼다. 그림자, 떠 있는 elevation, 강한 solid 배경은 사용하지 않는다. 첫 방문의 quiet surface 안에 새 학습 목록이 들어갈 때도 같은 행 문법을 유지하되 중첩 카드처럼 보이지 않는 inset group으로 표현한다.

#### 공통 행 구조와 상태

- 행 전체가 하나의 클릭·탭·키보드 초점 영역이다. 제목이나 trailing 아이콘만 따로 누르게 하지 않고 내부에 중첩 버튼을 두지 않는다.
- 두 줄짜리 제목·설명 행은 기본적으로 56 CSS px 이상의 높이를 확보하고, 어떤 상태에서도 44 CSS px 터치 목표보다 작아지지 않는다. 큰 글자에서는 고정 높이로 자르지 않고 세로로 늘어난다.
- 행 콘텐츠에는 SEED 목록 recipe에 맞는 충분한 좌우·상하 padding을 둔다. 현재처럼 글자가 경계에 붙거나 투명한 일반 텍스트 행으로 보이지 않아야 하며, 정확한 token·prop은 publisher가 현재 SEED Docs MCP와 설치 버전으로 결정한다.
- 목록 전체에는 약한 background/border/radius 조합을 사용하고 인접 행은 `ListDivider` 또는 동일 역할의 subtle separator로 구분한다. 각 행마다 별도 border, radius와 그림자를 반복하지 않는다.
- 이동 가능한 행 끝에는 오른쪽 진행 방향을 나타내는 trailing chevron 계열 아이콘을 둔다. 정확한 SEED 아이콘 이름·크기·import는 publisher가 검증하고, 아이콘은 텍스트 행동을 보조할 뿐 단독 레이블이 되지 않는다.
- pointer 환경의 `hover`, 직접 조작의 `pressed`, 키보드의 `focus-visible`을 서로 구분한다. hover·pressed는 약한 semantic background 변화로, focus-visible은 충분한 대비의 focus ring으로 전달하며 그림자나 이동 애니메이션으로 띄우지 않는다.
- disabled 행은 눌리지 않고, disabled 색상과 설명 문구로 사용할 수 없는 이유를 함께 전달한다. trailing chevron은 비활성 의미에 맞게 약화하거나 제거하며 색상만으로 상태를 전달하지 않는다.
- 로딩으로 특정 행의 이동을 막아야 하면 해당 행만 중복 실행할 수 없게 한다. 다른 행과 대표 CTA는 무관한 요청 때문에 함께 비활성화하지 않는다.

#### 최근 자료와 새 학습의 공통점·차이

| 영역 | 공통 행 문법 | 영역별 콘텐츠 차이 |
| --- | --- | --- |
| 최근 학습자료 | grouped `List` 안의 전체 행 클릭, trailing chevron, hover·pressed·focus-visible 상태 | 자료명을 주 제목으로, 마지막 학습 시각과 `미완료 풀이 있음`·`문제 없음` 등 확인 가능한 학습 상태를 상세로 보여준다. 행은 자료 상세로 이동한다. |
| 새 학습 | grouped `List` 안의 전체 행 클릭, trailing chevron, hover·pressed·focus-visible·disabled 상태 | `Notion에서 가져오기`, `파일에서 가져오기`, `텍스트 붙여넣기`를 주 제목으로, 입력 출처·지원 형식 설명을 상세로 보여준다. 행은 선택한 가져오기 흐름을 시작한다. |

두 영역은 클릭 가능성을 학습하는 비용을 줄이기 위해 같은 외형 문법을 사용한다. 다만 최근 자료는 `대상 탐색`, 새 학습은 `새 흐름 시작`이므로 제목·상세 정보와 disabled 가능 여부는 다르게 유지한다. 별도의 색상 테마나 카드 종류로 차이를 과장하지 않는다.

### 6. 오늘의 학습

현재 제안 지표는 아래 둘뿐이며 지표와 일자 기준은 미결정 사항이다.

| 지표 | 표시 규칙 |
| --- | --- |
| 푼 문제 | 오늘 제출 처리된 문제 수 `n문제` |
| 정답 현황 | 확정 채점된 결과만 `정답 c / 채점 g`로 표시. `g > 0`일 때만 보조로 정답률을 표시한다. |

- 불확실한 주관식 채점은 확정 정답 수에 포함하지 않는다.
- 풀이가 없으면 `오늘은 아직 푼 문제가 없어요` 한 문장으로 표현하고 `0%` 차트는 만들지 않는다.
- 경험치, 연속 학습일, 랭킹과 잠긴 지표는 노출하지 않는다.

### 7. 하단 내비게이션

- `홈`, `학습`, `프로필`을 항상 텍스트 레이블과 함께 표시하고 `홈`을 현재 위치로 전달한다.
- 각 목적지에는 의미를 보조하는 아이콘을 함께 두되 텍스트 레이블을 생략하지 않는다. 정확한 SEED 아이콘 이름과 상태별 표현은 publisher가 구현 직전 현재 SEED Docs MCP로 검증한다.
- 홈 탭을 다시 선택했을 때의 스크롤 상단 이동·새로고침 동작은 전역 내비게이션 정책이 정해지기 전까지 추가하지 않는다.
- 현재 SEED React 문서에서 전용 bottom-navigation 컴포넌트가 확인되지 않았으므로, 구현 시 `nav`와 SEED layout·text·icon primitive를 조합한 접근 가능한 공용 내비게이션으로 설계한다.

## 다음 행동 결정 규칙 제안

### 후보 우선순위

| 순위 | 조건 | 대표 행동 |
| ---: | --- | --- |
| 1 | 제출 전인 풀이 세션이 하나 이상 있음 | `이어서 풀기` |
| 2 | 복습 대상이 하나 이상 있음 | `복습 시작` |
| 3 | 가져왔지만 생성된 문제 세트가 없는 학습자료가 있음 | `문제 만들기` |
| 4 | 완료했거나 열어본 최근 학습자료가 있음 | `최근 학습 보기` |
| 5 | 위 조건이 모두 없음 | `첫 학습 시작` |

이 순서는 [제품 기반의 전역 내비게이션 UX 초안](../product.md#홈의-다음-행동-우선순위-제안)을 화면으로 구체화한 것이며 제품 결정으로 확정되지 않았다.

### 임시 동률 처리

동률 규칙이 확정되기 전까지 화면 mock과 임시 구현에서만 아래 순서를 사용한다. 서버 계약이 추천 항목을 직접 제공하면 클라이언트에서 다시 정렬하지 않는다.

1. 미완료 풀이끼리는 마지막 활동 시각이 가장 최근인 세션을 선택한다.
2. 복습 후보끼리는 복습 기준 시각이 제공될 때 가장 이른 항목을 선택하고, 기준 시각이 없거나 같으면 마지막 오답·학습 시각이 오래된 항목을 선택한다.
3. 문제 없는 자료끼리는 가져온 시각이 가장 최근인 자료를 선택한다.
4. 최근 학습끼리는 마지막 학습 시각이 가장 최근인 자료를 선택한다.
5. 위 비교값까지 같으면 안정적인 식별자 순서를 사용해 화면이 진입할 때마다 바뀌지 않게 한다. 식별자 자체는 사용자에게 노출하지 않는다.

위 다섯 규칙 모두 **미확정 임시 처리**다. 특히 복습 기준이 확정되면 2번을 함께 다시 검토해야 한다.

### 추천 판단 데이터가 일부 누락된 경우

- 실패한 데이터가 후보 우선순위에 영향을 주지 않는 섹션 데이터라면 확인된 대표 행동은 유지하고 실패한 섹션만 오류 처리한다.
- 더 높은 우선순위 후보의 존재 여부를 확인할 수 없다면 남은 후보를 `가장 우선인 추천`이라고 단정하지 않는다. 대표 영역을 `학습 시작`으로 바꾸고 새 학습 진입과 `다시 시도`를 제공한다.

## 주요·보조 행동 위계

| 위계 | 행동 | 표현 원칙 |
| --- | --- | --- |
| Primary | 대표 다음 행동 | 화면에서 한 개의 `ActionButton brandSolid`; 모바일에서 영역 너비에 맞춤 |
| Secondary | 새 학습 방법 선택, 최근 자료 선택, 복습 요약 선택 | 약한 경계의 grouped `List` 안에서 전체 행이 동작하고 trailing chevron과 상태 피드백을 제공하는 `ListButtonItem`/`ListLinkItem` |
| Tertiary | `전체 보기`, 섹션 `다시 시도` | 작은 ghost action 또는 텍스트 링크 역할의 명시적 컨트롤 |

카드 전체 클릭과 내부 버튼을 동시에 제공해 중첩된 행동을 만들지 않는다. 대표 영역의 surface는 설명 컨테이너이고 실제 행동은 레이블이 있는 버튼이다.

| 문제 없는 자료 | 앞선 후보가 없고 문제 세트 없는 자료가 있음 | 대표 자료명과 `문제 만들기`를 표시한다. | 해당 자료의 생성 설정 |
| 최근 학습만 있음 | 미완료·복습·문제 없는 자료가 없고 최근 자료가 있음 | 최근 자료를 대표로 표시하고 완료 안내를 과장하지 않는다. | 자료 상세, 새 학습 |
| 오늘 활동 없음 | 자료는 있으나 오늘 집계가 0 | `오늘은 아직 푼 문제가 없어요` 한 문장을 낮은 위계로 표시한다. | 다른 학습 행동 유지 |
| 부분 오류: 보조 섹션 | 복습·최근·오늘 중 일부만 실패 | 정상 섹션과 대표 행동은 유지한다. 실패 영역 안에 간단한 설명과 `다시 시도`를 둔다. | 정상 행동, 섹션 재시도 |
| 부분 오류: 추천 불완전 | 우선순위 판단에 필요한 후보 일부를 확인할 수 없음 | 페이지 수준 안내로 추천이 완전하지 않음을 알리고 대표 영역을 `학습 시작`으로 바꾼다. | 새 학습, 전체 재시도, 로드된 보조 행동 |
| 전체 오류 | 홈 추천·요약을 모두 불러오지 못함 | `ResultSection`으로 상황과 `다시 시도`를 제공한다. 아래에는 서버 요약과 무관하게 가능한 새 학습 방법을 유지한다. | 전체 재시도, 가능한 새 학습, 하단 탭 |
| 권한 제한 | 특정 입력 방식의 권한 또는 WebView 기능을 사용할 수 없음 | 영향받은 행에 원인과 해결 가능 여부를 표시한다. 설명 없이 숨기지 않는다. | 재연결 또는 다른 입력 방식 |
| 행동 처리 중 | 이동·재시도 요청 진행 중 | 선택한 컨트롤에 loading을 표시하고 같은 요청의 중복 실행을 막는다. 다른 무관한 탐색을 막을지는 흐름별 정책을 따른다. | 취소가 정의된 경우 취소, 그 외 중복 실행 불가 |
| 갱신 성공 | 재시도 또는 홈 복귀 후 데이터 갱신 완료 | 섹션 내용을 최신 데이터로 교체하고 필요한 경우 짧은 `Snackbar`로 완료를 알린다. | 갱신된 행동 |
| 세션 만료 | 인증 세션이 유효하지 않음 | 만료 이유를 알리고 로그인 흐름으로 이동한다. 로그인 전 하단 탭은 표시하지 않는다. | 로그인 |

## SEED 구성 매핑

### 화면 영역별 컴포넌트 조합

이 표는 화면을 어떤 단위로 조립할지를 정의한다. SEED 컴포넌트 이름과 명시한 variant·상태는 현재 문서에서 확인된 것만 사용한다. 시맨틱 요소와 SEED primitive를 결합하는 정확한 방법, 설치 버전, props와 import 경로는 구현 단계에서 다시 확인한다.

| 화면 영역·역할 | 검증된 SEED 컴포넌트 또는 primitive 조합 | 검증된 variant·상태 | 콘텐츠·행동 규칙 |
| --- | --- | --- | --- |
| 화면 셸과 스크롤 컨테이너 | 배포 환경의 스크롤 컨테이너 안에 semantic `main` + `Box` + `VStack` | 별도 전용 화면 셸 컴포넌트는 확인하지 않음 | 헤더부터 오늘의 학습까지 단일 열로 스크롤한다. 웹에는 불필요한 safe-area 여백을 만들지 않고, WebView에는 셸이 전달한 유효 inset만 한 번 적용한다. 하단 내비게이션 자체 높이만큼 마지막 콘텐츠 여백은 항상 확보한다. |
| 화면 헤더 | semantic `header` + `Text`로 표현한 `h1`; 행동이 추가될 때만 짧은 행에 `HStack` | `Text`의 화면 제목 방향은 `t12Bold` | 필수 콘텐츠는 `홈` 한 개다. 프로필·설정 행동은 하단 탭과 중복하므로 현재 넣지 않는다. 대표 다음 행동과의 간격은 과도한 hero 여백이 아닌 조밀한 화면 리듬을 유지하고, 구체 token은 구현에서 전역 기준과 맞춘다. |
| 대표 다음 행동 surface | semantic `section` + `Box` + `VStack` + `Text` | quiet grouping surface 역할에 SEED semantic `bg.neutralWeak` 사용 | 전용 `Card`를 만들거나 가정하지 않는다. 별도 고정 레이블 없이 상태별 대표 제목을 `h2`이자 section name으로 삼고 자료명, 진행·시각의 최소 맥락과 대표 CTA 한 개를 담는다. surface 전체를 클릭 영역으로 만들지 않는다. |
| 대표 다음 행동 CTA | `ActionButton` | `brandSolid`; 요청 중 `loading`과 중복 실행 방지용 `disabled` 상태 | 정상 홈에서 가장 강한 버튼은 한 개다. 상태에 따라 `이어서 풀기`, `복습 시작`, `문제 만들기`, `최근 학습 보기` 중 하나만 표시한다. |
| 주요 섹션 사이 구분 | 충분한 `VStack` 간격, 경계가 더 필요할 때 SEED `Divider` | `stroke.neutralSubtle` 역할 | 복습·최근 자료·새 학습·오늘 요약을 각각 카드로 감싸지 않는다. 여백을 먼저 사용하고, 서로 다른 섹션이 붙어 보이는 구간에만 subtle divider를 한 번 둔다. 그림자나 강한 테두리를 반복하지 않는다. |
| 복습 섹션 | semantic `section` + `VStack`; 제목·`전체 보기` 행은 `Text` + `HStack`; 요약 행동은 `List` + `ListButtonItem` 조합 | `전체 보기` 또는 섹션 재시도는 `ActionButton` `ghost` 방향 | 대상 수와 확정된 범위만 표시한다. 대표 CTA가 이미 `복습 시작`이면 이 섹션에서 solid 버튼을 반복하지 않는다. 대상이 없으면 `Text`로 완료 문장을 보여주고 비어 있는 목록은 만들지 않는다. |
| 최근 학습자료 섹션 헤더와 `전체 보기` | semantic `section` 안의 `HStack` + `Text` + `ActionButton` | `전체 보기`는 `ghost` | `최근 학습자료`를 `h2`로 전달하고 `전체 보기`는 `학습`의 자료 목록으로 이동한다. 큰 글자에서 한 행이 맞지 않으면 제목 다음 줄로 자연스럽게 이동한다. |
| 최근 학습자료 목록과 행 | subtle boundary의 group container + `List` + `ListButtonItem` 또는 `ListLinkItem` + `ListDivider` + trailing SEED icon primitive | enabled·hover·pressed·focus-visible; 정확한 recipe·suffix API는 구현 전 확인 | 최대 3개를 세로로 표시한다. 각 행은 충분한 padding과 최소 높이를 가지며 자료명, 마지막 학습 시각, 확인 가능한 상태 하나를 담는다. 행 전체가 자료 상세로 이동하는 단일 행동이고 오른쪽 chevron이 방향을 보조한다. |
| 새 학습 목록과 행 | semantic `section` + `VStack` + `Text` + subtle boundary의 group container + `List` + `ListButtonItem` + `ListDivider` + trailing SEED icon primitive | enabled·hover·pressed·focus-visible·disabled; 정확한 recipe·suffix API는 구현 전 확인 | 세 입력 방법을 같은 위계의 세로 행으로 제공한다. 각 행은 충분한 padding과 최소 높이를 가지며 행 전체가 흐름을 시작한다. 사용할 수 없는 방법은 disabled 상태와 이유를 함께 표시하고 다른 행은 활성 상태로 유지한다. |
| 오늘의 학습 수치 | semantic `section`과 `dl`/`dt`/`dd`를 `VStack`, 짧은 `HStack` 또는 필요한 `Flex` 줄바꿈 조합과 `Text`로 표현 | 별도 chart·progress variant 사용 안 함 | `푼 문제`와 `정답/채점`을 레이블·값 쌍으로 읽히게 한다. 분모가 없으면 정답률을 생략하고, 0인 날은 빈 차트 대신 한 문장을 표시한다. 넓은 화면에서도 읽기 순서를 바꾸지 않는다. |
| 로딩 | 실제 영역 구조 안의 `Skeleton` + `Box`/`VStack` | `Skeleton` `tone="neutral"` | AI 생성 상태가 아니므로 `magic` tone을 쓰지 않는다. 대표 다음 행동, 복습, 최근 자료, 오늘 요약의 최종 윤곽과 비슷하게 배치하고 컨테이너에 로딩 의미를 전달한다. 독립적인 새 학습 행동은 가능하면 실제 컨트롤로 유지한다. |
| 부분 오류: 한 섹션만 실패 | 실패한 semantic `section` 안의 `ResultSection` 또는 `Box` + `VStack` + `Text` + `ActionButton` | 재시도는 `ghost` 또는 `neutralWeak`; `ResultSection`의 정확한 size·action API는 구현 전 확인 | 오류 설명과 해당 섹션 `다시 시도`만 제공한다. 정상인 대표 행동과 다른 섹션을 가리거나 비활성화하지 않는다. |
| 부분 오류: 추천 판단 불완전 | `PageBanner` + 안전한 시작 영역의 `Box`/`VStack` + `ActionButton` | 배너의 정확한 tone·props는 설치 API 확인 후 의미에 맞게 선택 | 더 높은 우선순위 후보를 확인하지 못했음을 페이지 수준으로 알린다. 남은 후보를 완전한 추천으로 단정하지 않고 `새 학습`과 전체 재시도를 제공한다. |
| 전체 오류 | `ResultSection` + 아래쪽의 새 학습 `List` | `ResultSection`의 primary action으로 `다시 시도`; 정확한 action props는 구현 전 확인 | 오류 원인 또는 현재 상황, 전체 재시도를 한 영역에 제공한다. 서버 요약과 무관하게 가능한 세 가져오기 행과 하단 탭은 유지한다. |
| 재시도·갱신 성공 알림 | `Snackbar` | 성공 의미의 구체 tone·지속 시간·props는 구현 전 확인 | 사용자가 시작한 갱신이 끝났을 때만 짧게 알리고, 동시에 화면 데이터를 최신 상태로 교체한다. 영구 상태나 오류 설명을 Snackbar에만 의존하지 않는다. |
| 하단 내비게이션 | semantic `nav` + 목록/링크 요소 + `Box`/`HStack` + `Text` + 검증된 SEED icon primitive | 전용 bottom-navigation 컴포넌트와 정확한 icon 이름은 미확인; 현재 탭은 `aria-current` 등 semantic 상태 사용 | 홈·학습·프로필마다 의미를 보조하는 아이콘과 필수 텍스트를 함께 둔다. publisher가 현재 SEED Docs MCP에서 아이콘을 검증한다. 링크 하나가 하나의 목적지만 가지며 유효 하단 inset을 한 번만 적용하고 콘텐츠를 가리지 않는다. |

### 현재 문서에서 검증한 후보

아래 이름과 역할은 2026-08-19 현재 SEED React 문서에서 확인했다. 정확한 패키지 버전·props·import는 구현 시 설치 상태와 다시 대조한다.

| UI 책임 | SEED 구성 | 선택 이유와 사용 규칙 |
| --- | --- | --- |
| 페이지·섹션 배치 | `Box`, `VStack`, 행 단위 `HStack`, 필요한 경우 `Flex`의 줄바꿈 조합 | 화면 너비와 관계없이 단일 읽기 열을 유지한다. `HStack`은 섹션 제목과 보조 행동처럼 짧은 한 행에만 쓰고, 인라인 정보가 좁은 너비에서 넘칠 수 있으면 DOM 순서를 유지한 채 줄바꿈한다. |
| 제목·본문·수치 | `Text` | `textStyle`로 위계를 만들고 사용자 글자 크기 확대를 따른다. 화면 제목은 `t12Bold`, 주요 섹션은 `t10Bold`, 본문은 기본 `t5Regular` 방향을 따른다. |
| 대표 행동 | `ActionButton` `brandSolid` | 한 개의 가장 중요한 행동을 명확히 한다. loading과 disabled는 서로 별도 상태이므로 중복 실행 방지를 함께 설계한다. |
| 약한 보조 행동 | `ActionButton` `ghost` 또는 `neutralWeak` | `전체 보기`, `다시 시도`처럼 대표 행동과 경쟁하지 않는 컨트롤에 사용한다. |
| 가져오기·최근 자료 행 | grouped `List`, `ListHeader`, `ListButtonItem`/`ListLinkItem`, `ListDivider`, 검증된 trailing icon primitive | 약한 그룹 경계, 충분한 내부 여백, 전체 행 클릭과 상태 피드백으로 affordance를 제공한다. `List`의 기본 `<ul>` 의미와 대표 CTA보다 낮은 위계를 유지한다. |
| 주요 섹션 경계 | 여백과 필요 시 `Divider` | 반복 카드 대신 평평한 콘텐츠 면을 유지하고, `stroke.neutralSubtle` 역할의 약한 경계만 사용한다. |
| 로딩 | `Skeleton` | 최종 구조와 비슷한 윤곽을 제공하며 일반 홈 로딩은 `neutral` tone을 사용한다. AI 생성이 아니므로 `magic` tone을 사용하지 않는다. |
| 영역·전체 결과 | `ResultSection` | 전체 오류나 영역 단위 결과에서 설명과 복구 행동을 함께 제공한다. |
| 페이지 수준 안내 | `PageBanner` | 추천 판단이 불완전한 부분 오류처럼 화면 전체의 해석에 영향을 주는 메시지에 사용한다. |
| 일시적 완료 알림 | `Snackbar` | 재시도 후 갱신처럼 사용자가 시작한 작업의 짧은 성공 피드백에 사용한다. 영구 오류 설명을 대신하지 않는다. |

### 구현 단계에서 추가 확인할 항목

- 전용 하단 내비게이션 React 컴포넌트 존재 여부. 현재 Docs 목록에서는 확인되지 않았다.
- 홈·학습·프로필에 사용할 정확한 아이콘 이름, 선택·비선택 상태와 import. publisher가 구현 직전 SEED Docs MCP icon search로 검증하며 이 문서에서 추측하지 않는다.
- 인터랙티브 행의 정확한 SEED List snippet, group boundary·radius·padding props, trailing chevron 아이콘과 suffix 조합. publisher가 현재 SEED Docs MCP와 설치 패키지로 검증한다.
- `PageBanner`, `ResultSection`, `Snackbar`의 프로젝트 설치 버전과 실제 지원 props
- 표준 웹, edge-to-edge 웹과 앱 WebView를 구분하는 환경 신호 및 safe-area의 단일 소유자. 네이티브 셸이 처리한 inset을 웹이 다시 적용하지 않도록 앱 셸 계약 또는 TRD에서 정한다.
- 승인된 전역 Pretendard family를 적용할 정확한 package, import, CSS selector, 웹폰트·앱 번들 방식, 필요한 weight, fallback, 로딩 성능과 글꼴 교체 시 레이아웃 안정성. 이는 홈 UX가 아니라 각 애플리케이션 TRD와 구현 책임이다.
- `ListButtonItem`/`ListLinkItem`의 긴 제목·상세 줄바꿈, 큰 글자 모드, hover·pressed·focus-visible·disabled 동작

### DESIGN.md와의 정합성

- 한 개의 대표 행동, 평평한 문서형 레이아웃, 반복 항목의 `List` 사용, semantic token과 모바일 우선 원칙에 맞춘다.
- `DESIGN.md`는 홈을 다음 행동 뒤에 복습과 최근 자료가 따르는 구조로 안내한다. 이 명세의 모바일 섹션 순서도 그 방향을 따른다.
- 여백을 우선하고 필요할 때만 subtle divider를 쓰며 반복 카드와 그림자를 피하는 결정은 `DESIGN.md`의 평평한 문서형 원칙과 일치한다.
- 인터랙티브 항목을 개별 카드나 반복 solid 버튼으로 바꾸지 않고 하나의 약한 그룹 경계를 가진 `ListButtonItem`/`ListLinkItem`으로 만드는 결정은 `DESIGN.md`의 navigable row·목록 우선 원칙과 일치한다.
- 환경에 필요한 유효 inset만 보호한다는 결정은 `DESIGN.md`의 safe-area 보호 목적을 유지하면서 웹의 불필요한 여백과 이중 패딩을 방지하는 구체화다.
- 폰트 가족은 전역 기준이다. 최신 `DESIGN.md`가 웹·WebView의 Pretendard-first family를 승인했으므로 홈은 이를 그대로 상속하고, SEED `textStyle`의 크기·행간·굵기 체계는 변경하지 않는다.
- 전용 bottom-navigation 컴포넌트와 정확한 아이콘은 여전히 구현 전 확인 사항이다.

## 접근성

- `홈`을 문서의 `h1`로 제공한다. 대표 다음 행동은 고정 레이블 없이 상태별 대표 제목을 `h2`이자 section name으로 사용하고, 이후 섹션 제목도 순차적인 `h2`로 제공한다.
- 키보드·보조기기 탐색 순서는 화면 헤더, 대표 다음 행동, 복습, 최근 자료, 새 학습, 오늘 요약, 하단 내비게이션 순서와 같다.
- 대표 surface 전체를 모호한 클릭 영역으로 만들지 않고 `이어서 풀기`, `복습 시작`처럼 결과가 드러나는 컨트롤 레이블을 사용한다.
- `ListButtonItem`/`ListLinkItem`은 행 전체가 하나의 행동일 때만 사용한다. 행 안에 별도 버튼을 중첩하지 않고 키보드 탭 정지점도 하나만 만든다.
- 자료 상세처럼 실제 목적지로 이동하면 링크 의미를, 파일 선택·Notion 연결처럼 동작을 시작하면 버튼 의미를 우선한다. 버튼 행은 `Enter`와 `Space`, 링크 행은 `Enter` 등 선택한 native semantic의 기본 키보드 동작을 보존한다.
- 목록은 접근 가능한 그룹 이름을 갖는 semantic list로 제공한다. 제목과 상세 설명이 행의 접근 가능한 이름·설명에 포함되고 trailing chevron은 중복 낭독되지 않는 보조 시각 요소로 처리한다.
- 모바일 WebView에서는 행의 패딩을 포함한 전체 너비·높이가 터치 영역이다. 큰 글자에서 행을 고정 높이로 자르지 않으며 제목·상세와 chevron이 겹치지 않게 세로로 늘어난다.
- 하단 탭 아이콘은 텍스트 레이블을 보조한다. 장식으로 중복되는 아이콘은 보조기기에서 중복 낭독되지 않게 하고, 현재 상태는 색뿐 아니라 텍스트와 `aria-current` 등 플랫폼에 맞는 상태 속성으로 전달한다.
- 로딩은 `aria-busy` 또는 동등한 상태로 묶고 Skeleton 각각을 불필요하게 읽지 않게 한다. 완료 시 페이지 전체로 포커스를 강제로 이동하지 않는다.
- 오류와 재시도 결과는 보조기기에 전달하되 페이지 진입이나 갱신 때마다 공격적인 alert로 반복하지 않는다.
- 진행, 정답, 권한과 오류는 색이나 아이콘만으로 구분하지 않고 텍스트와 수치를 함께 제공한다.
- SEED recipe가 더 큰 크기를 보장하지 않는 모든 인터랙션은 최소 44×44 CSS px 터치 영역을 가진다.
- 키보드 포커스 링을 제거하지 않고 WebView의 외부 키보드 탐색에서도 논리적 순서를 유지한다.

## 반응형·긴 텍스트·WebView 규칙

### `base`와 작은 WebView

- 작은 웹 viewport와 앱 WebView 모두 단일 열과 세로 스크롤을 사용하고 좌우 기본 gutter는 SEED semantic spacing을 우선한다.
- 대표 행동은 가용 너비를 사용하되 긴 버튼 레이블을 자르지 않고 높이가 늘어나게 한다.
- 자료명과 한국어 설명은 줄바꿈한다. 최근 목록처럼 반복되는 메타데이터만 제한적으로 말줄임할 수 있으며, 전체 자료명은 상세 화면에서 확인 가능해야 한다.
- 320 CSS px 수준의 좁은 너비와 큰 글자 설정에서도 가로 스크롤을 만들지 않는다.

### `md` 이상

- 대표 다음 행동은 계속 첫 번째이자 가장 넓은 영역으로 유지한다.
- 모바일과 같은 단일 열, 섹션 순서와 DOM 순서를 유지한다. 넓어진 공간은 바깥 여백과 섹션 내 읽기 여유에 사용한다.
- 섹션 제목과 `전체 보기` 같은 짧은 행은 `HStack` 계열 조합을 사용할 수 있다. 메타데이터가 한 행에 들어가지 않으면 `Flex` 계열의 줄바꿈 조합으로 자연스럽게 다음 줄에 배치하며 의미 순서를 바꾸지 않는다.
- 새 학습 세 방법은 비교 카드로 과장하지 않고 모바일과 같은 세로 목록을 유지한다.
- 화면이 넓어져도 읽기 선을 무한히 늘리지 않으며 정확한 최대 너비는 미결정 사항으로 남긴다.

### 안전 영역과 고정 UI

- 안전 영역의 목적은 노치, 디스플레이 컷아웃, 홈 인디케이터와 edge-to-edge 앱 셸에 콘텐츠·고정 내비게이션이 가려지는 것을 막는 것이다. 모든 환경에 고정 여백을 더하는 장식 규칙이 아니다.
- 일반 브라우저 웹에서 viewport가 이미 안전한 사각형이고 edge-to-edge가 아니면 상·하단 safe-area 추가값은 0으로 취급한다. 콘텐츠 gutter와 하단 내비게이션 자체 높이에 필요한 여백만 유지한다.
- 앱 WebView가 노치나 홈 인디케이터 아래까지 확장되고 네이티브 셸이 inset을 처리하지 않을 때만 웹 계층이 유효 상·하단 inset을 적용한다.
- 네이티브 앱 셸이 이미 safe-area padding을 적용한 WebView라면 웹은 같은 inset을 다시 더하지 않는다. 네이티브와 웹 중 한 계층만 safe-area를 소유한다.
- PWA나 edge-to-edge 웹처럼 일반 웹에서도 실제 디스플레이 컷아웃이 노출되는 환경은 유효 inset을 적용할 수 있다. 환경 판별과 값 전달 방식은 앱 셸 계약 또는 각 애플리케이션 TRD에서 정한다.
- 하단 내비게이션은 자신이 소유한 유효 하단 inset과 내비게이션 높이를 포함하고, 스크롤 콘텐츠 끝에는 내비게이션 전체 높이와 `spacingY.screenBottom` 역할의 여백을 확보한다.
- 마지막 목록 행과 오늘 요약이 하단 내비게이션에 가리지 않아야 한다.
- 키보드가 열리는 하위 입력 흐름에서 홈의 하단 탭이 키보드 위로 불필요하게 떠오르지 않도록 앱 셸 정책을 적용한다.
- WebView 뒤로 가기, 앱 탭 이동과 브라우저 history는 같은 이동을 중복 실행하지 않아야 한다.

## 타이포그래피와 폰트 방향

- 홈의 웹과 WebView 콘텐츠는 최신 `DESIGN.md`에서 승인한 `Pretendard Variable` 우선 family와 한국어 지원 시스템 fallback을 상속한다. 홈 화면만의 font-family override를 만들지 않는다.
- SEED의 scalable `Text` 스타일은 정보 위계와 글자 크기의 기준으로 유지한다. Pretendard는 glyph와 fallback을 담당하고, `t*` 스타일은 크기·행간·굵기, 사용자 글자 확대와 실제 heading 의미를 계속 담당한다.
- 한국어 본문과 자료명은 필요한 굵기에서 획이 뭉개지지 않고, 웹과 앱 WebView에서 줄 높이·줄바꿈 차이가 과도하지 않아야 한다.
- 정확한 package, import, CSS selector, 폰트 파일, subset, preload, fallback 선언과 로딩 중 글꼴 교체 전략은 각 애플리케이션 TRD와 구현에서 정한다.

## 필요한 데이터 경계

화면은 아래 의미의 데이터를 필요로 한다. 정확한 필드명, 실패 코드, 시간대와 캐시 정책은 API·데이터 계약에서 정의하며 이 명세의 이름을 서버 필드로 간주하지 않는다.

- 인증된 사용자와 세션 유효성
- 제출 전 풀이 세션: 연결된 자료·문제 세트, 현재/전체 문항, 마지막 활동 시각
- 복습 요약: 대상 수, 대표 범위, 복습 기준 시각과 로드 성공 여부
- 문제 세트가 없는 학습자료: 자료명, 가져온 시각, 입력 출처
- 최근 학습자료: 자료명, 마지막 학습 시각, 풀이·문제 보유 상태
- 오늘의 집계: 제출 문제 수, 확정 채점 수, 확정 정답 수, 집계 시간대·기간
- 입력 방법별 사용 가능 여부와 권한 제한 사유
- 추천 항목을 서버가 결정한다면 대표 항목과 결정 버전; 후보를 내려준다면 우선순위 판단에 필요한 상태와 시각
- 섹션별 독립 로딩·성공·오류 상태

## 관찰 가능한 수용 기준

- [ ] 로그인한 사용자는 화면 제목과 `홈`·`학습`·`프로필` 하단 탭을 식별하고 이동할 수 있다.
- [ ] 정상 상태의 홈에는 `brandSolid` 수준의 대표 행동이 정확히 한 개 표시된다.
- [ ] 대표 다음 행동에는 별도의 `지금 할 일` 레이블이 없고, 상태별 대표 제목이 heading과 접근 가능한 section name 역할을 한다.
- [ ] 화면 제목과 대표 다음 행동 사이에 과도한 hero 공백이 생기지 않고 하나의 시작 흐름으로 인식되는 조밀한 간격을 유지한다.
- [ ] 미완료 풀이와 다른 후보가 함께 있으면 `이어서 풀기`가 대표 행동이며 기존 문제 세트·문항·답안으로 복원된다.
- [ ] 미완료 풀이가 없고 복습 대상이 있으면 복습 수량과 `복습 시작`이 표시된다.
- [ ] 앞선 후보가 없고 문제 없는 자료가 있으면 해당 자료명이 포함된 `문제 만들기`가 표시되고 자료 맥락이 생성 설정에 전달된다.
- [ ] 첫 방문 사용자는 빈 복습·최근·통계 카드 없이 Notion, `.txt`/`.md` 파일, 텍스트 붙여넣기 중 하나를 선택할 수 있다.
- [ ] 최근 자료 행은 자료명과 최근 맥락을 보여주고 선택 시 해당 자료 상세로 이동한다.
- [ ] `Notion에서 가져오기`, `파일에서 가져오기`, `텍스트 붙여넣기`는 한 개의 약한 경계를 가진 그룹형 목록 안에서 충분한 내부 여백·최소 높이·trailing chevron을 갖는 전체 행 버튼으로 인식된다.
- [ ] 최근 학습자료의 각 행도 같은 grouped-list affordance를 사용하되 자료명·마지막 학습 시각·학습 상태를 보여주며, 각 항목이 개별 떠 있는 카드처럼 반복되지 않는다.
- [ ] pointer hover, pressed, keyboard focus-visible 상태가 서로 구별되고, focus ring이 group boundary에 잘리지 않으며, 행의 어느 콘텐츠 영역을 선택해도 동일한 목적지 또는 동작이 실행된다.
- [ ] 사용할 수 없는 새 학습 방법은 disabled 상태와 이유를 함께 보여주고 실행되지 않으며, 사용할 수 있는 나머지 방법은 계속 동작한다.
- [ ] 최근 자료와 새 학습의 행은 brand/neutral solid 버튼처럼 보이지 않아 대표 `brandSolid` CTA보다 낮은 시각 위계를 유지한다.
- [ ] 키보드 사용자는 각 행을 한 번만 탭으로 방문해 native 의미에 맞는 키로 실행할 수 있고, 스크린리더는 행 제목·상세·disabled 상태를 이해하며 장식 chevron을 중복 낭독하지 않는다.
- [ ] 오늘의 정답 현황은 확정 채점만 사용하고 분모가 0이면 정답률을 표시하지 않는다.
- [ ] 보조 섹션 하나가 실패해도 대표 행동, 새 학습과 성공한 섹션은 사용할 수 있다.
- [ ] 더 높은 우선순위 후보의 로드가 실패하면 남은 항목을 완전한 추천이라고 표시하지 않고 재시도를 제공한다.
- [ ] 전체 오류에서도 전체 재시도, 가능한 새 학습과 하단 탭을 사용할 수 있다.
- [ ] 로딩 중에는 최종 구조와 유사한 Skeleton이 보이고 하단 탭이 사라지거나 레이아웃이 크게 이동하지 않는다.
- [ ] 사용할 수 없는 입력 방식은 이유가 텍스트로 전달되고 다른 입력 방식은 계속 사용할 수 있다.
- [ ] 대표 다음 행동 외의 주요 섹션은 반복 카드나 그림자로 감싸지 않으며, 여백과 필요한 subtle divider로 경계가 식별된다.
- [ ] 하단 내비게이션의 세 목적지는 각각 보조 아이콘과 텍스트 레이블을 함께 제공하고 현재 탭을 색상 외 상태로 전달한다.
- [ ] 320 CSS px 너비와 큰 글자 설정에서 주요 문구·버튼이 잘리거나 가로 스크롤이 생기지 않는다.
- [ ] 일반 웹에는 불필요한 상·하단 safe-area 공백이 없고, edge-to-edge WebView에서는 마지막 콘텐츠와 하단 내비게이션이 시스템 UI에 가리지 않으며 네이티브·웹 이중 패딩이 없다.
- [ ] 승인된 전역 폰트와 SEED scalable text style을 사용했을 때 웹과 앱 WebView의 한국어 제목·본문이 잘리거나 과도하게 다르게 줄바꿈되지 않는다.
- [ ] 키보드와 보조기기에서 제목 순서, 포커스 순서, 현재 탭, 로딩·오류·진행 의미를 식별할 수 있다.

## 사용자 검토가 필요한 결정

1. 이 문서의 다음 행동 우선순위와 임시 동률 처리를 제품 규칙으로 채택할지
2. 홈에서 새 학습 세 방법을 바로 노출할지, `학습`의 가져오기 화면을 거치게 할지
3. 최근 학습을 학습자료 기준 최대 3개로 정의할지, 문제 세트 기준으로 바꿀지
4. 오늘의 지표를 `푼 문제`와 `정답/채점`으로 정할지, 날짜 경계를 어떤 시간대로 계산할지
5. 여러 미완료 풀이가 있을 때 대표 하나만 보여줄지 사용자가 다른 세션을 선택할 수 있게 할지
